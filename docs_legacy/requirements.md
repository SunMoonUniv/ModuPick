## 1. 제품 정의

> 모두가 납득하는 유쾌한 선택 — 팀 의사결정을 실시간 미니게임으로

조별 과제·스터디·사내 TF에서 **팀장 정하기·역할 분담**에 드는 시간과 눈치를 없앤다.
링크 하나로 모여 미니게임 6종 중 하나를 돌리면, **결과는 서버가 정하고 모두에게 똑같이 보인다.**
로그인도 설치도 없다.

```
표지 ──[MODU-427132]──▶ 대기방 ──[게임 선택·설정]──▶ 3초 가이드 ──▶ 게임 ──▶ 결과 ──▶ 이미지 저장
      방 만들기 / 코드 입장   2~10명 · 참가자 전원 준비 완료                  전원 동시 확인
```

### 1.1 이 제품이 지키는 3가지

| 원칙 | 뜻 |
|---|---|
| **공정** | 결과는 서버가 정한다. 클라이언트 화면·네트워크 속도가 결과를 바꾸지 못한다. |
| **동시** | 전원이 같은 결과를 같은 순간에 본다. 먼저 아는 사람이 없다. |
| **가벼움** | 로그인·설치·개인정보 수집이 없다. 링크와 닉네임이면 끝난다. |

## 2. 용어

| 용어 | 뜻 |
|---|---|
| **방(Room)** | 참가자가 모이는 단위. 방 제목·정원과 6자리 코드(`MODU-427132`)를 가진다. |
| **방장(Host)** | 방을 만든 사람. 게임 선택·설정·시작·재실행 권한을 가진다. 권한은 **다른 사람에게 넘어가지 않고**, 방장이 나가면 방이 사라진다(US-205). |
| **참가자(Member)** | 방에 들어온 사람. 방장도 참가자에 포함된다. |
| **소개 태그** | 닉네임 옆에 붙는 한 줄 소개(GitHub 아이디 등). 선택 입력. |
| **주제(Topic)** | 이 게임으로 **무엇을 정하는지** 나타내는 문구. 템플릿 칩 또는 직접 입력. |
| **명단 스냅샷** | 게임 시작 순간의 참가자 목록. 게임이 끝날 때까지 바뀌지 않는다. |
| **판정창** | 두 입력을 "동시"로 볼지 가르는 시간 폭. 눈치게임에서만 쓴다. |
| **서버 도착 시각** | 참가자 입력이 서버에 닿은 시각. 모든 시간 판정의 유일한 기준. |
| **안전 확정** | 눈치게임에서 혼자 눌러 후보에서 빠진 상태. 다시 판정받지 않는다. |
| **무효 라운드** | 눈치게임에서 생존자 전원이 같은 판정창에 눌러 아무도 안전 확정하지 못한 라운드. |

## 3. 미니게임 6종 공통 기준

이 절이 6종 전체를 관통하는 규격이다. 개별 게임 규칙(§3.5)은 이 규격을 어길 수 없다.

### 3.1 공통 규칙

| # | 규칙 |
|---|---|
| G-1 | 방 정원은 **2~10명**이고, 방장이 방을 만들 때 제목과 정원을 정한다. |
| G-2 | **결과는 서버가 확정**하고 전원에게 동일하게 전달된다. 클라이언트 애니메이션은 이미 정해진 결과로 수렴할 뿐이다. |
| G-3 | **방장을 제외한 참가자 전원이 준비 완료**여야 방장이 게임을 시작할 수 있다. 방장은 준비 상태를 갖지 않는다. |
| G-4 | 게임 시작 직후 **3초간 규칙 가이드**를 띄운다. 게임 중에도 다시 열어볼 수 있다. 다시 하기·결선·무효 라운드 재시작에서는 띄우지 않는다. |
| G-5 | 게임이 시작되면 **참가자 명단이 스냅샷으로 고정**된다. 참가자가 도중 이탈해도 후보에 남고 결과에도 표시된다. 방장 이탈은 예외이며 G-16을 따른다. |
| G-6 | **재접속은 불가**하다. 나갔다 다시 들어오면 새 참가자로 취급한다. 즉 **끊긴 사람은 돌아올 수 없지만 후보에는 남아** 미입력 처리된다. |
| G-7 | 입력하지 않은 참가자는 **게임별 기본값으로 자동 처리**된다(기권·최하위 등). 게임은 멈추지 않는다. |
| G-8 | 시간과 순서 판정은 **서버 도착 시각** 기준이다. 클라이언트 시계와 네트워크 지연은 결과에 영향을 주지 않는다. |
| G-9 | **같은 입력이 여러 번 도착해도 1회만 인정**하고, 이미 끝난 판에 도착한 입력은 버린다. |
| G-10 | 투표·입력이 진행되는 동안 **중간 집계를 아무에게도 보여주지 않는다.** |
| G-11 | 결과 연출이 끝난 뒤 **3초** 후에 결과 화면으로 넘어간다. |
| G-12 | 결과 화면은 **전원이 이미지로 저장**할 수 있다. |
| G-13 | 결과와 난수 시드는 **방이 살아 있는 동안 서버에 보관**되고, 방이 사라질 때 함께 삭제된다. |
| G-14 | 방장은 결과 확인 후 **같은 설정으로 다시 돌릴 수 있다.** |
| G-15 | 모든 게임은 **주제**를 하나 가진다. 주제가 이 판이 무엇을 정하는 판인지 설명한다. |
| G-16 | **방장이 나가거나 연결이 끊기면 방이 즉시 사라진다.** 게임 도중이면 판은 결과 없이 끝나고 전원이 표지 화면으로 돌아간다. |

### 3.3 주제 템플릿

주제는 **템플릿 칩**을 누르거나 **맨 오른쪽 `+ 직접 입력`**으로 방장이 직접 쓴다.
직접 입력은 **최대 12자**, 공백만 입력할 수 없다.

**A. 사람 1명을 정하는 게임** — 운명의 룰렛 · 시간초 잡기 · 눈치게임

```
[ 팀장 ] [ 발표자 ] [ 자료 조사 ] [ PPT 제작 ] [ + 직접 입력 ]
```

**B. 전원에게 역할을 나누는 게임** — 사다리타기 (세트를 고르면 항목이 한 번에 채워진다)

| 세트 | 항목 |
|---|---|
| **조별과제** | 팀장 · 자료 조사 · PPT 제작 · 발표 · 디자인 · 최종 정리 |
| **개발팀** | 팀장 · 프론트엔드 · 백엔드 · DB·배포 · 문서 · QA |

```
[ 조별과제 ] [ 개발팀 ] [ + 직접 입력 ]
```

**C. 안건 1개를 정하는 게임** — 킹메이커

```
[ 팀명 ] [ 발표 주제 ] [ 프로젝트 이름 ] [ + 직접 입력 ]
```

**D. 질문으로 사람을 정하는 게임** — 익명 저격 (질문 문장이 곧 주제다)

```
[ 발표를 제일 잘할 것 같은 사람은? ]
[ PPT 장인일 것 같은 사람은? ]
[ + 직접 입력 ]
```

질문형 직접 입력만 **최대 30자**를 허용한다(문장이라서).

### 3.5 게임별 규칙

#### 3.5.1 운명의 룰렛 · 사람 1인

참가자 전원이 **동일한 크기의 조각**을 하나씩 갖는다.

1. 방장이 `PICK!`을 누른다.
2. 서버가 당첨자와 난수 시드를 먼저 정하고, 그 결과를 전원에게 보낸다.
3. 룰렛이 3~5초 회전한 뒤 **정해진 조각에서 멈춘다.** 애니메이션이 결과를 바꾸지 않는다.

- 조각 배치 순서는 참가자 입장 순서를 따른다.
- 참가자는 조작하지 않고 지켜본다.
- 동점·미입력이 발생할 수 없는 유일한 게임이다.

#### 3.5.2 사다리타기 · 전원 배정

세로선 수는 **참가자 수와 같다.** 도착 항목 수도 **참가자 수와 같게 강제**한다.

1. 방장이 항목 세트를 고르거나 직접 입력한다.
2. 항목이 참가자보다 **적으면 `X`로 자동 채우고, 많으면 뒤에서부터 잘라낸다.** 방장에게 어떻게 맞춰졌는지 보여준다.
3. 방장이 `START`를 누르면 서버가 가로선 배치를 생성한다.
4. **전원의 경로가 동시에** 그려지고 도착한 항목이 각자의 역할로 확정된다.

- 참가자는 세로선(레인)을 직접 고르지 않는다. **입장 순서대로** 자동 배치된다.
- 가로선은 인접한 두 세로선 사이에만 놓이고, 같은 높이에서 겹치지 않는다.
- 서로 다른 참가자가 같은 항목에 도착하는 일은 없다(1:1 대응).
- `X`를 받은 참가자는 배정된 역할이 없다는 뜻이다.
- 진행 속도는 애니메이션 길이만 바꾸고 결과에는 영향을 주지 않는다.

#### 3.5.3 킹메이커 · 안건 1개

사람이 아니라 **아이디어**를 정하는 유일한 게임이다.

1. **제출 단계(2분)** — 각자 주제에 맞는 안건을 **익명으로 1개** 낸다. **최대 120자.**
2. **투표 단계(1분)** — 제출된 안건이 섞여서 표시된다. **자기가 낸 안건에는 투표할 수 없다.**
3. **개표** — 최다 득표 안건이 확정된다.

- **안건을 내지 않은 사람도 투표에 참여한다.** 제출은 권리이지 투표의 조건이 아니다.
- 제출된 안건이 **0개면** 게임을 성립시킬 수 없으므로 설정 화면으로 되돌린다.
- 제출된 안건이 **1개면** 투표 없이 그 안건으로 확정한다.
- 전원이 제출을 마치면 시간이 남아도 즉시 투표 단계로 넘어간다. 투표도 마찬가지다.
- 1인 투표 수가 2표 이상이면 서로 다른 안건에만 나눠 줄 수 있다(한 안건에 몰아줄 수 없다).
- 최다 득표가 **동점이면 동점 안건만 남겨 결선 투표(30초)를 반복한다.** 단독 최다 득표가 나올 때까지 계속하고, 후보를 다시 제출하지는 않는다.
- 제출자 실명은 설정이 `실명`일 때 **개표 후에만** 공개된다. 투표 중에는 누구도 알 수 없다.

#### 3.5.4 시간초 잡기 · 사람 1인

1. 각자 `START`를 눌러 자기 타이머를 시작한다.
2. **2초까지만 숫자가 보이고 이후 가려진다.**
3. 목표 시간이라고 느낀 순간 `STOP`을 **한 번** 누른다. 되돌릴 수 없다.
4. 목표 시간과의 **오차**로 순위를 매긴다.

```
절대 오차 = |정지 시간 − 목표 시간|      ← 판정용
시간 차이 = 정지 시간 − 목표 시간        ← 화면 표시용(부호 포함)
```

- 판정 기준이 `가장 가까운 사람`이면 절대 오차 최소가, `가장 먼 사람`이면 최대가 뽑힌다.
- 시간은 **정수 밀리초**로 기록한다.
- 게임 시작 후 **10초** 안에 타이머를 시작하지 않으면 최하위로 처리한다.
- 타이머를 시작한 뒤 제한 시간은 **목표 시간 + 3초**다. 그때까지 누르지 않으면 최하위로 처리한다.
- 제한 시간이 지나 도착한 `STOP`은 인정하지 않는다.
- 정지 시간은 **서버가 `START`·`STOP` 신호를 받은 시각의 차이**로 계산한다. 참가자 기기가 보낸 시작·종료 시각은 판정에 쓰지 않는다(G-8).
- 절대 오차가 밀리초까지 같으면 **동점자끼리 다시 한 판** 진행한다. 단독 승자가 나올 때까지 반복한다.
- 다른 사람의 진행 상황은 "완료/대기"만 보이고 기록은 보이지 않는다.

#### 3.5.5 익명 저격 · 사람 1인

1. 질문과 투표 시간이 공개된다.
2. 각자 후보 중 **한 명을 지목**한다. **자기 자신은 지목할 수 없다.**
3. 가장 많이 지목된 사람이 뽑힌다.

- 중복 투표 설정이 `가능`이면 한 사람이 **여러 명을 지목**할 수 있다. 기본값은 `불가`(1인 1표)다.
- 지목하지 않으면 **기권**으로 처리한다. 기권은 어떤 후보의 표도 늘리지 않는다.
- 최다 득표가 **동점이면 동점자만 후보로 남겨 전원이 재투표**한다. 단독 최다 득표가 나올 때까지 반복한다.
- 전원이 기권해 유효표가 0이면 난수로 한 명을 정하고 **표가 없었음을 결과에 표시한다.**
- 결과 연출은 지목선이 후보에게 뻗어 나가는 형태다. 지목자 공개가 `비공개`(기본)면 **선의 출발점을 가리고 피격 수만** 보여준다.
- 지목자 공개가 `공개`면 결과 화면에서 누가 누구를 지목했는지 드러난다.

#### 3.5.6 눈치게임 · 사람 1인

**혼자 누를수록 유리한 구조다.** 혼자 누른 사람은 후보에서 빠져 안전해지고, 겹친 사람과 안 누른 사람이 남아 다시 붙는다.

1. 라운드가 시작되면 제한 시간이 흐른다.
2. 각자 원하는 순간 `UP!`을 **한 번** 누른다.
3. **혼자 누른 사람은 안전 확정**되어 후보에서 빠진다.
4. **판정창 안에 둘 이상이 누르면 그들은 남는다.** 제한 시간까지 누르지 않은 사람도 남는다.
5. 남은 사람들끼리 다음 라운드를 진행하고, 마지막 한 명이 남으면 그 사람이 뽑힌다.

- 판정 기준은 서버 도착 시각이다. 동시 입력 그룹의 **최초 클릭 시각부터 판정창(0.3초 또는 0.5초) 안**에 들어온 입력을 같은 그룹으로 본다.
- 라운드마다 한 번만 누를 수 있고, 안전 확정된 사람의 추가 입력은 무시한다.
- **생존자 전원이 같은 판정창에 눌러 아무도 안전 확정하지 못하면 무효 라운드**다. 이때 방장이 `다시 시작`과 `대기방으로`를 고른다.
- 라운드가 길어질수록 배경이 붉게 점멸하고 텍스트가 흔들려 압박을 준다.
- 결과 화면에는 **라운드별 전원의 판정 기록**(안전 확정·동시 입력·미입력·최후 1인)과 서버 기준 입력 시각이 남는다.

**판정 예시** (판정창 0.3초 · 5명)

| 라운드 | 참가자 | 입력 | 판정 |
|---|---|---|---|
| 1 | 지호 | 2.10초 | 혼자 → 안전 확정 |
| 1 | 서연 | 5.40초 | 혼자 → 안전 확정 |
| 1 | 민준 | 7.00초 | 하늘과 동시 → 남음 |
| 1 | 하늘 | 7.12초 | 민준과 동시 → 남음 |
| 1 | 도윤 | 미입력 | 남음 |
| 2 | 민준 | 1.80초 | 혼자 → 안전 확정 |
| 2 | 하늘 | 4.00초 | 혼자 → 안전 확정 |
| 2 | 도윤 | 미입력 | **최후 1인 → 뽑힘** |

## 4. 사용자 스토리

번호대는 `features.md`의 `F-` 번호대와 대응한다.

| 번호대 | 영역 |
|---|---|
| US-1xx | 방 만들기 · 입장 |
| US-2xx | 대기방 |
| US-3xx | 게임 선택 · 설정 |
| US-4xx | 게임 진행 (401~409 공통, 41x~46x 게임별) |
| US-5xx | 결과 · 저장 |
| US-6xx | 공통 · 오류 |

### 4.1 방 만들기 · 입장 (US-1xx)

#### US-101 방 만들기
> **As a** 팀 리더 **/ I want** 로그인 없이 방을 만들고 싶다 **/ so that** 준비 없이 바로 팀원을 모을 수 있다

1. Given 표지 화면에서, When `방 만들기`를 누르면, Then 방 제목·정원과 내 닉네임·아바타를 정하는 화면이 뜬다.
2. Given 방 제목을 비워 두면, Then `ModuPick 방`이 기본값으로 들어간다. 최대 30자다.
3. Given 정원을 정하면, Then **2~10명** 범위에서만 고를 수 있고 기본값은 10명이다.
4. Given 입력을 마치고 `만들기`를 누르면, Then `MODU-` + 숫자 6자리 코드가 발급되고 **방장 자격**으로 대기방에 들어간다.
5. Given 방이 만들어졌을 때, Then 회원가입·로그인·개인정보 입력을 한 번도 요구하지 않는다.

#### US-102 코드로 입장
> **As a** 팀원 **/ I want** 코드를 입력해 방에 들어가고 싶다 **/ so that** 링크가 없어도 합류할 수 있다

1. Given 표지 화면에서, When 6자리 코드를 입력하고 `입장`을 누르면, Then 닉네임 설정을 거쳐 해당 방의 대기방에 들어간다.
2. Given 없는 코드를 입력하면, Then `없는 방이에요` 안내가 뜨고 입력값이 유지된다.
3. Given 정원이 찬 방 코드를 입력하면, Then `방이 가득 찼어요` 안내가 뜨고 입장하지 않는다.
4. Given 이미 게임이 진행 중인 방 코드를 입력하면, Then `게임이 진행 중이에요` 안내와 함께 **관전 없이 입장이 거절**된다.
5. Given 초대 코드는, Then 방이 사라질 때까지 계속 유효하다.

#### US-103 링크로 입장
> **As a** 팀원 **/ I want** 받은 링크를 눌러 바로 들어가고 싶다 **/ so that** 코드를 옮겨 적지 않아도 된다

1. Given 초대 링크를 열면, Then 코드가 자동 입력된 상태로 닉네임 설정 화면이 뜬다.
2. Given 링크로 들어왔을 때, Then US-102의 거절 조건(없는 방·정원 초과·진행 중)이 동일하게 적용된다.

#### US-104 프로필 정하기
> **As a** 참가자 **/ I want** 닉네임·아바타·소개를 정하고 싶다 **/ so that** 결과에서 나를 알아보고 서로를 파악할 수 있다

1. Given 입장 직전 화면에서, When 닉네임을 입력하면, Then **1~8자**만 허용하고 공백만 입력하면 진행 버튼이 비활성이다.
2. Given 같은 방에 동일한 닉네임이 있으면, Then 자동으로 뒤에 숫자를 붙여(`지호2`) 구분한다.
3. Given 아바타를 고르지 않으면, Then 남은 아바타 중 하나가 자동 배정된다.
4. Given **소개 태그**를 입력하면, Then 최대 24자까지 허용하고 대기방 참가자 목록에 함께 보인다. 비워 둘 수 있다.
5. Given 프로필은 입장 절차(PENDING) 중에 **최초 한 번만** 확정할 수 있고, Then 대기방에 들어간 뒤(ACTIVE 상태)에는 닉네임·아바타·소개를 **다시 바꿀 수 없다.**

#### US-105 초대 링크 공유
> **As a** 방장 **/ I want** 링크를 한 번에 복사하고 싶다 **/ so that** 단톡방에 바로 붙여넣을 수 있다

1. Given 대기방에서, When `초대하기`를 누르면, Then 링크가 클립보드에 복사되고 복사됐다는 표시가 뜬다.
2. Given 공유 API를 지원하는 환경이면, Then 시스템 공유 시트를 함께 제공한다.

### 4.2 대기방 (US-2xx)

#### US-201 참가자 실시간 확인
> **As a** 참가자 **/ I want** 누가 들어오고 나가는지 바로 보고 싶다 **/ so that** 다 모였는지 알 수 있다

1. Given 대기방에 있을 때, When 누군가 입장하면, Then **1초 안에** 목록에 나타나고 인원수가 갱신된다.
2. Given 목록에는, Then 닉네임·아바타·소개 태그·준비 상태가 함께 보인다.
3. Given 참가자가 나가면, Then 목록에서 사라지고 안내 메시지가 남는다.
4. Given 방장이 나가면, Then 목록을 갱신하는 대신 **방이 사라졌다는 안내**와 함께 전원이 표지 화면으로 이동한다(US-205).

#### US-202 대기방 채팅
> **As a** 참가자 **/ I want** 대기하면서 대화하고 싶다 **/ so that** 게임 전에 상황을 맞출 수 있다

1. Given 대기방에서, When 메시지를 보내면, Then 전원에게 **1초 안에** 전달된다.
2. Given 메시지를 보낼 때, Then **200자**를 넘을 수 없다.
3. Given 입퇴장·게임 시작 같은 사건이 일어나면, Then 시스템 메시지로 채팅에 남는다.
4. Given 채팅은 **서버 DB에 저장하지 않고 각자 브라우저에 보관**한다.
5. Given 게임을 마치고 대기방으로 돌아오면, Then **이전 대화가 그대로 보인다.**

#### US-203 준비 완료
> **As a** 방장 **/ I want** 전원이 준비됐을 때만 시작하고 싶다 **/ so that** 화면을 안 보고 있던 사람이 판을 망치지 않는다

1. Given 대기방에서, When **방장이 아닌 참가자**가 `준비`를 누르면, Then 전원의 화면에 준비 표시가 반영된다. **방장에게는 준비 버튼이 뜨지 않는다.**
2. Given 방장을 제외한 참가자 중 준비하지 않은 사람이 한 명이라도 있으면, Then **시작 버튼이 비활성**이고 몇 명이 남았는지 보인다.
3. Given 참가자가 준비를 다시 눌러, Then 준비 상태를 해제할 수 있다.
4. Given 방장을 제외한 참가자 전원이 준비를 마치면, Then 방장이 게임을 시작할 수 있다.

#### US-204 참가자 내보내기
> **As a** 방장 **/ I want** 잘못 들어온 사람이나 반응 없는 사람을 내보내고 싶다 **/ so that** 그 사람 때문에 게임을 못 시작하지 않는다

1. Given 대기방에서, When 방장이 참가자를 내보내면, Then 확인 절차를 거친 뒤 그 참가자는 표지 화면으로 이동한다.
2. Given 내보내진 참가자가 같은 코드로 다시 입장하면, Then **새 참가자로 대기방에 들어갈 수 있다.** 방장이 다시 내보내기 전까지는 재입장을 막지 않는다.
3. Given 그 사이 게임이 시작돼 진행 중이면, Then 다른 입장 시도와 마찬가지로 거절된다(US-102).
4. Given 게임이 진행 중이면, Then 내보내기를 할 수 없다(명단 스냅샷 고정 · G-5).

#### US-205 방장 이탈 처리
> **As a** 참가자 **/ I want** 방장이 나가면 방이 곧바로 정리되길 원한다 **/ so that** 진행할 사람이 없는 방에 남아 기다리지 않는다

1. Given 방장이 방을 나가거나 연결이 끊기면, When 남은 참가자가 있어도, Then **방이 즉시 삭제**되고 전원이 이유 안내와 함께 표지 화면으로 이동한다.
2. Given 게임 진행 중에 방장이 나가면, Then **게임은 결과 없이 중단**되고 1과 똑같이 처리된다. 그 판의 결과는 남기지 않는다.
3. Given 방장 권한은, Then **다른 참가자에게 넘어가지 않는다.**
4. Given 방장이 아닌 참가자가 나가면, Then 방은 그대로 유지된다(US-201 · US-403).
5. Given 방이 삭제되면, Then 초대 코드가 즉시 무효가 되고 참가자·결과·시드가 함께 지워진다(US-206 · G-13).

#### US-206 방 정리
> **As a** 참가자 **/ I want** 버려진 방이 쌓이지 않길 원한다 **/ so that** 코드가 헛돌지 않는다

1. Given 방장이 나가면, Then 남은 사람이 있어도 방이 즉시 삭제된다(US-205).
2. Given 마지막 참가자가 나가면, Then 방이 즉시 삭제된다.
3. Given 방에 사람이 남아 있어도 **10분간 아무 요청이 없으면**, Then 방이 삭제된다.
4. Given 방이 삭제되면, Then 참가자·결과·시드가 함께 삭제되고 초대 코드가 무효가 된다.
5. Given 방이 삭제되어 화면에서 밀려나면, Then 어떤 이유로 사라졌는지 함께 알린다(US-602).

### 4.3 게임 선택 · 설정 (US-3xx)

#### US-301 게임 고르기
> **As a** 방장 **/ I want** 6종 중 하나를 고르고 싶다 **/ so that** 상황에 맞는 방식으로 정할 수 있다

1. Given 대기방에서, Then 6종이 이름·한 줄 설명·필요 인원과 함께 보인다.
2. Given 현재 인원이 최소 인원에 못 미치는 게임은, Then 선택할 수 없고 `3명부터 가능해요`처럼 이유가 표시된다.
3. Given 방장이 게임을 고르면, Then 전원의 화면에 선택된 게임이 반영된다.

#### US-302 랜덤 게임 선택
> **As a** 방장 **/ I want** 어떤 게임을 할지도 운에 맡기고 싶다 **/ so that** 게임 고르는 것부터 눈치 보지 않는다

1. Given 대기방에서, When `랜덤 선택`을 누르면, Then 시작 가능한 게임 중 하나가 무작위로 선택된다.
2. Given 현재 인원으로 시작할 수 없는 게임은, Then 후보에서 빠진다.
3. Given 랜덤으로 뽑힌 뒤에도, Then 방장은 설정을 조절하거나 다시 뽑을 수 있다.

#### US-303 게임 규칙 확인
> **As a** 참가자 **/ I want** 규칙을 확인하고 싶다 **/ so that** 몰라서 지지 않는다

1. Given 게임이 선택된 상태에서, When 규칙 보기를 누르면, Then 한 줄 요약·진행 단계·판정 기준이 보인다.
2. Given 방장뿐 아니라 **모든 참가자**가 규칙을 열어볼 수 있다.
3. Given 게임이 시작되면, Then **3초간 가이드가 자동으로** 표시된다.
4. Given 게임 화면에서도, Then 가이드를 다시 열어볼 수 있다.
5. Given 다시 하기·결선 투표·무효 라운드 재시작이면, Then 가이드를 표시하지 않는다.

#### US-304 주제 정하기
> **As a** 방장 **/ I want** 무엇을 정하는 판인지 지정하고 싶다 **/ so that** 결과가 무슨 뜻인지 모두가 안다

1. Given 설정 화면에서, Then 게임 종류에 맞는 **템플릿 칩**(§3.3)이 보이고 맨 오른쪽에 `+ 직접 입력`이 있다.
2. Given `+ 직접 입력`을 누르면, When 문구를 입력하면, Then **12자**(질문형은 30자)까지 허용하고 공백만으로는 확정할 수 없다.
3. Given 주제를 바꾸면, Then 전원의 화면에 즉시 반영된다.
4. Given 게임을 다른 종류로 바꾸면, Then 주제를 포함한 모든 설정이 **기본값으로 초기화**된다.

#### US-305 게임별 세부 설정
> **As a** 방장 **/ I want** 시간·표 수·공개 범위를 조절하고 싶다 **/ so that** 우리 팀에 맞게 굴릴 수 있다

1. Given 설정 화면에서, Then §3.4 표의 항목만 노출되고 그 외 값은 조절할 수 없다.
2. Given 설정을 바꾸면, Then 전원의 화면에 즉시 반영된다.
3. Given 참가자는 설정을 볼 수는 있으나 **바꿀 수 없다.**
4. Given 저격 투표 시간을 직접 입력하면, Then **5~60초** 범위만 허용한다.

#### US-306 사다리 항목 맞추기
> **As a** 방장 **/ I want** 역할 수가 인원과 안 맞아도 알아서 맞춰지길 원한다 **/ so that** 숫자를 세지 않아도 된다

1. Given 항목이 참가자보다 적으면, Then 부족한 만큼 **`X`**가 자동으로 채워지고 그 사실이 화면에 표시된다.
2. Given 항목이 참가자보다 많으면, Then 뒤에서부터 잘리고 잘린 항목이 표시된다.
3. Given 방장이 항목을 직접 편집하면, Then 항목 하나당 12자까지 허용하고 최소 1개는 있어야 한다.

#### US-307 게임 시작
> **As a** 방장 **/ I want** 전원이 준비되면 바로 시작하고 싶다 **/ so that** 눈치 보는 시간을 없앨 수 있다

1. Given **방장을 제외한 참가자 전원**이 준비 완료이고 인원·설정이 유효할 때, When 방장이 `시작`을 누르면, Then **참가자 명단이 스냅샷으로 고정**되고 전원이 동시에 게임 화면으로 넘어간다.
2. Given 방장을 제외한 참가자 중 준비하지 않은 사람이 있거나 최소 인원에 못 미치면, Then 시작 버튼이 눌리지 않고 이유가 표시된다.
3. Given 게임이 시작되면, Then 그 방은 새 입장을 받지 않는다.
4. Given 게임이 시작되면, Then 3초 가이드가 표시된 뒤 서버 기준으로 게임이 시작된다.

### 4.4 게임 진행 (US-4xx)

#### 공통 (US-401~409)

##### US-401 결과의 공정성 보장
> **As a** 참가자 **/ I want** 내 기기나 인터넷 속도가 결과를 바꾸지 않길 원한다 **/ so that** 결과에 승복할 수 있다

1. Given 어떤 게임이든, Then 승자·배정·순위는 **서버가 계산**하고 클라이언트는 전달받은 결과만 그린다.
2. Given 참가자별 네트워크 지연이 달라도, Then 동일한 입력 순서에 대해 동일한 결과가 나온다.
3. Given 클라이언트 시계를 조작해도, Then 판정은 **서버 도착 시각**으로만 이뤄져 영향이 없다.
4. Given 같은 입력이 여러 번 도착하면, Then **최초 1회만** 인정한다.
5. Given 이미 끝난 판에 입력이 도착하면, Then 판정에 반영하지 않는다.

##### US-402 진행 상황 확인
> **As a** 참가자 **/ I want** 지금 누가 남았는지 보고 싶다 **/ so that** 얼마나 기다려야 할지 안다

1. Given 입력형 게임(킹메이커·시간초·저격·눈치)에서, Then 참가자별 **완료/대기 상태**가 보인다.
2. Given 진행 중일 때, Then 다른 사람의 **입력 내용·기록·중간 집계는 보이지 않는다.**
3. Given 제한 시간이 있는 단계에서, Then 남은 시간이 전원에게 동일하게 보인다.
4. Given 전원이 입력을 마치면, Then 시간이 남아도 즉시 다음 단계로 넘어간다.

##### US-403 이탈·미입력 처리
> **As a** 참가자 **/ I want** 참가자가 나가도 게임이 멈추지 않길 원한다 **/ so that** 처음부터 다시 하지 않아도 된다

1. Given 게임 도중 **참가자**가 나가거나 연결이 끊기면, Then 그 사람은 **후보에 그대로 남고** 게임은 계속된다.
2. Given 나간 사람은 **다시 들어올 수 없다.** 재입장하면 새 참가자이고 진행 중인 판에는 낄 수 없다.
3. Given 제한 시간이 끝날 때까지 입력하지 않은 사람이 있으면, Then §3.2의 미입력 처리 규칙이 적용된다.
4. Given 나간 사람이 결과에 뽑히면, Then 결과 화면에 **이탈 표시와 함께** 그대로 표시된다.
5. Given 게임 도중 **방장**이 나가면, Then 방이 삭제되어 판이 결과 없이 끝난다(US-205 · G-16). 게임이 멈추는 경우는 이것뿐이다.

#### 운명의 룰렛 (US-41x)

##### US-411 룰렛 돌리기
> **As a** 참가자 **/ I want** 룰렛이 도는 걸 다 같이 보고 싶다 **/ so that** 결과가 극적으로 느껴진다

1. Given 게임 화면에서, Then 참가자 수만큼 **같은 크기의 조각**이 그려지고 각자 자기 조각이 강조된다.
2. Given 방장이 `PICK!`을 누르면, Then 전원의 룰렛이 **동시에** 돌기 시작한다.
3. Given 3~5초 뒤, Then 룰렛이 **서버가 정한 조각**에서 멈추고 전원이 같은 결과를 본다.
4. Given 참가자는 룰렛을 조작할 수 없다.

#### 사다리타기 (US-42x)

##### US-421 사다리 타고 내려가기
> **As a** 참가자 **/ I want** 내 경로가 어디로 가는지 보고 싶다 **/ so that** 배정이 조작되지 않았다고 믿을 수 있다

1. Given 게임 화면에서, Then 위에는 참가자, 아래에는 도착 항목이 **같은 개수**로 표시되며, 참가자는 **입장 순서대로 자동 배치**되어 레인을 직접 고르지 않는다.
2. Given 방장이 `START`를 누르면, Then 서버가 만든 가로선이 공개되고 **전원의 경로가 동시에** 그려진다.
3. Given 경로가 그려질 때, Then 참가자별 고유 색으로 구분되고 가로선을 만나면 반드시 꺾인다.
4. Given 애니메이션이 끝나면, Then 참가자와 항목이 **1:1로** 확정된다.
5. Given 화면 크기가 달라도, Then 최종 배정 결과는 모두 같다.

#### 킹메이커 (US-43x)

##### US-431 안건 익명 제출
> **As a** 참가자 **/ I want** 아이디어를 익명으로 내고 싶다 **/ so that** 눈치 보지 않고 말할 수 있다

1. Given 제출 단계에서, Then **2분**의 제한 시간이 전원에게 동일하게 보인다.
2. Given 안건을 입력하면, Then **120자**까지 허용하고 **1인 1건**만 낼 수 있다.
3. Given 제출한 뒤, Then 제한 시간이 남아 있어도 **수정·취소할 수 없다.**
4. Given 제출 단계 동안, Then 누가 무엇을 냈는지는 **아무에게도 보이지 않는다.**
5. Given 전원이 제출을 마치면, Then 시간이 남아 있어도 즉시 투표 단계로 넘어간다.
6. Given 시간이 끝날 때까지 제출하지 않으면, Then 의견이 없는 것으로 본다.

##### US-432 안건 투표
> **As a** 참가자 **/ I want** 마음에 드는 안건을 고르고 싶다 **/ so that** 팀의 뜻으로 결정된다

1. Given 투표 단계에서, Then **1분**의 제한 시간과 섞인 안건 목록이 보인다.
2. Given **안건을 내지 않은 사람도** 투표할 수 있다.
3. Given 자기가 낸 안건은, Then 선택할 수 없도록 비활성으로 표시된다.
4. Given 1인 투표 수가 2표 이상이면, Then 서로 다른 안건에만 나눠 줄 수 있다.
5. Given 허용된 표보다 많이 행사하려 하면, Then 서버가 거절한다.
6. Given 시간이 끝날 때까지 투표하지 않으면, Then **기권**으로 처리된다.
7. Given 투표 중에는, Then 중간 집계가 아무에게도 보이지 않는다.

##### US-433 개표와 확정
> **As a** 참가자 **/ I want** 표가 어떻게 갈렸는지 보고 싶다 **/ so that** 결과를 납득할 수 있다

1. Given 투표가 끝나면, Then 안건별 득표가 **많은 순으로** 공개되고 최다 득표 안건이 확정된다.
2. Given 설정이 `실명`이면, Then 개표 후에 제출자 이름이 함께 공개된다. `익명`이면 끝까지 공개되지 않는다.
3. Given 최다 득표가 동점이면, Then 동점 안건만 남긴 **결선 투표 30초**를 진행한다. 기존 표는 초기화하고 후보를 다시 제출하지는 않는다.
4. Given 결선에서도 동점이면, Then **단독 최다 득표가 나올 때까지 결선을 반복한다.**
5. Given 제출된 안건이 1개뿐이면, Then 투표를 건너뛰고 그 안건으로 확정한다.
6. Given 제출된 안건이 0개면, Then 게임을 중단하고 설정 화면으로 되돌린다.

#### 시간초 잡기 (US-44x)

##### US-441 목표 시간 맞추기
> **As a** 참가자 **/ I want** 감으로 시간을 맞춰 보고 싶다 **/ so that** 짧고 긴장감 있게 정할 수 있다

1. Given 게임 화면에서, Then 목표 시간과 판정 기준이 먼저 안내된다.
2. Given `START`를 누르면, Then **내 타이머만** 시작되고 다른 사람과 무관하게 흐른다.
3. Given 시작 후 2초가 지나면, Then 숫자가 가려지고 더 이상 보이지 않는다.
4. Given `STOP`을 누르면, Then 입력이 **즉시 확정**되고 다시 누를 수 없다.
5. Given 게임 시작 후 **10초** 안에 타이머를 시작하지 않으면, Then 최하위로 자동 처리된다.
6. Given 타이머 시작 후 **목표 시간 + 3초**가 지나면, Then 최하위로 자동 처리되고 이후 도착한 `STOP`은 인정하지 않는다.

##### US-442 오차로 순위 정하기
> **As a** 참가자 **/ I want** 누가 얼마나 가까웠는지 보고 싶다 **/ so that** 결과가 납득된다

1. Given 전원의 입력이 끝나면, Then 참가자별 **정지 시간·시간 차이(부호 포함)·절대 오차·순위**가 공개된다.
2. Given 판정 기준이 `가장 가까운 사람`이면 절대 오차 최소가, `가장 먼 사람`이면 최대가 뽑힌다.
3. Given 시간은, Then 정수 밀리초로 기록된다.
4. Given 절대 오차가 밀리초까지 같으면, Then **동점자끼리 한 판을 다시** 하고 단독 승자가 나올 때까지 반복한다.
5. Given 정지 시간은, Then 참가자 기기가 보낸 시작·종료 시각이 아니라 **서버가 START·STOP 신호를 받은 시각의 차이**로 계산된다(G-8).

#### 익명 저격 (US-45x)

##### US-451 익명으로 지목하기
> **As a** 참가자 **/ I want** 아무도 모르게 지목하고 싶다 **/ so that** 솔직하게 고를 수 있다

1. Given 게임 화면에서, Then 질문과 투표 시간, 그리고 **나를 제외한** 참가자 목록이 보인다.
2. Given **자기 자신은 후보에 나타나지 않으며 지목할 수 없다.**
3. Given 중복 투표가 `불가`(기본)면, Then 한 명만 고를 수 있고 고르는 즉시 확정된다.
4. Given 중복 투표가 `가능`이면, Then **여러 명을 지목**할 수 있다.
5. Given 시간이 끝날 때까지 고르지 않으면, Then 기권으로 처리된다.
6. Given 투표 중에는, Then 중간 집계가 아무에게도 보이지 않는다.

##### US-452 최다 피격자 공개
> **As a** 참가자 **/ I want** 결과가 어떻게 갈렸는지 보고 싶다 **/ so that** 웃고 넘어갈 수 있다

1. Given 투표가 끝나면, Then 지목선 연출과 함께 후보별 피격 수가 공개되고 최다 득표자가 뽑힌다.
2. Given 지목자 공개가 `비공개`(기본)면, Then **선의 출발점을 가려** 누가 지목했는지 드러나지 않는다.
3. Given 지목자 공개가 `공개`면, Then 결과 화면에서 누가 누구를 지목했는지 보인다.
4. Given 최다 득표가 동점이면, Then 동점자만 후보로 남기고 **전원이 재투표**한다. 단독 최다 득표가 나올 때까지 반복한다.
5. Given 전원이 기권해 유효표가 0이면, Then 난수로 한 명을 정하고 **표가 없었음을 결과에 표시한다.**

#### 눈치게임 (US-46x)

##### US-461 타이밍 재기
> **As a** 참가자 **/ I want** 남들과 겹치지 않게 눌러 빠져나가고 싶다 **/ so that** 마지막까지 긴장을 즐길 수 있다

1. Given 라운드가 시작되면, Then 제한 시간과 남은 인원이 전원에게 동일하게 보인다.
2. Given `UP!`을 누르면, Then 라운드당 **한 번만** 입력되고 취소할 수 없다.
3. Given 내가 누른 뒤에는, Then 판정 결과가 나올 때까지 대기 상태로 표시된다.
4. Given 라운드가 길어질수록, Then 배경이 붉게 점멸하고 텍스트가 흔들려 압박을 준다.

##### US-462 동시 입력 판정
> **As a** 참가자 **/ I want** 동시에 누른 게 정확히 판정되길 원한다 **/ so that** 억울하게 남지 않는다

1. Given **혼자 누른 사람**은, Then 안전 확정되어 후보에서 빠진다.
2. Given 두 명 이상의 입력이 **판정창 안**에 들어오면, Then 그들은 **남아서 다음 라운드로** 간다.
3. Given 판정은 동시 입력 그룹의 **최초 클릭 시각부터 판정창 안**에 들어온 입력을 같은 그룹으로 묶는다.
4. Given 제한 시간까지 누르지 않은 사람도, Then 남아서 다음 라운드로 간다.
5. Given 안전 확정된 사람의 추가 입력은, Then 무시한다.
6. Given 남은 사람이 한 명이 되면, Then 그 사람이 뽑히고 게임이 끝난다.

##### US-463 무효 라운드 처리
> **As a** 방장 **/ I want** 아무도 빠지지 못한 판을 어떻게 할지 정하고 싶다 **/ so that** 분위기를 보고 판단할 수 있다

1. Given 생존자 전원이 같은 판정창에 눌러 **아무도 안전 확정하지 못하면**, Then 무효 라운드로 처리하고 방장에게 선택을 요구한다.
2. Given 방장이 `다시 시작`을 고르면, Then 같은 인원으로 라운드를 다시 시작한다. 가이드는 띄우지 않는다.
3. Given 방장이 `대기방으로`를 고르면, Then 전원이 대기방으로 돌아간다.
4. Given 참가자는, Then 방장의 선택을 기다린다.

##### US-464 라운드 기록 보기
> **As a** 참가자 **/ I want** 매 라운드 무슨 일이 있었는지 보고 싶다 **/ so that** 판정에 이의가 없다

1. Given 게임이 끝나면, Then **라운드별로 전원의 판정**(안전 확정·동시 입력·미입력·최후 1인)이 표로 보인다.
2. Given 각 판정에는, Then 서버 기준 입력 시각과 동시 입력 그룹이 함께 표시된다.

### 4.5 결과 · 저장 (US-5xx)

#### US-501 결과 동시 확인
> **As a** 참가자 **/ I want** 모두가 같은 결과를 같은 때에 보길 원한다 **/ so that** 먼저 알고 빠지는 사람이 없다

1. Given 게임이 끝나면, Then 게임 화면에서 결과 연출이 먼저 재생된다.
2. Given 연출이 끝나 결과가 공개된 시점부터 **3초 후**, Then 전원의 화면이 결과 화면으로 전환된다.
3. Given 결과 화면에는, Then 주제·게임 이름·뽑힌 대상이 크게 보인다.
4. Given 게임에 따라, Then 결과 형태가 §3.2의 4종(승자형·배정형·개표형·기록형) 중 하나로 표시된다.

#### US-502 결과 이미지 저장
> **As a** 참가자 **/ I want** 결과를 이미지로 저장하고 싶다 **/ so that** 단톡방에 올려 증거로 남길 수 있다

1. Given 결과 화면에서, When `이미지 저장`을 누르면, Then 결과 화면이 **PNG 파일로 저장**된다.
2. Given 이미지에는, Then 주제·게임 이름·결과·참가자·날짜가 포함된다.
3. Given **방장뿐 아니라 모든 참가자**가 저장할 수 있다.
4. Given 공유 API를 지원하는 환경이면, Then 저장 대신 바로 공유하는 선택지도 제공한다.

#### US-503 다시 하기
> **As a** 방장 **/ I want** 결과가 나온 뒤 다시 돌리고 싶다 **/ so that** 한 번 더 하자는 요청에 바로 응할 수 있다

1. Given 결과 화면에서, When 방장이 `다시 하기`를 누르면, Then **같은 게임·같은 설정**으로 새 판이 시작되고 가이드는 띄우지 않는다.
2. Given 결과 화면에서, When 방장이 `대기방으로`를 누르면, Then 전원이 대기방으로 돌아가고 다른 게임을 고를 수 있다.
3. Given 참가자는 다시 하기를 실행할 수 없고, Then 방장의 다음 동작까지 결과 화면에서 대기한다.

#### US-504 결과 데이터 보관
> **As a** 참가자 **/ I want** 방이 살아 있는 동안은 결과와 시드가 안전하게 남아 있길 원한다 **/ so that** 방이 갑자기 사라지지 않는 한 판정 근거가 유지된다

1. Given 게임이 끝나면, Then 결과와 난수 시드가 **방이 살아 있는 동안** 서버에 보관된다.
2. Given 결과 화면을 벗어나 대기방으로 돌아오면, Then **그 판의 결과는 다시 열어볼 수 없다.** 서버에는 남아 있지만 참가자에게 다시 보여주지 않는다.
3. Given 방이 삭제되면, Then 결과와 시드가 함께 삭제된다.

### 4.6 공통 · 오류 (US-6xx)

#### US-601 모바일에서 쓰기
> **As a** 참가자 **/ I want** 휴대폰으로 불편 없이 쓰고 싶다 **/ so that** 자리에서 바로 참여할 수 있다

1. Given 360px 폭 화면에서, Then 가로 스크롤 없이 모든 화면을 쓸 수 있다.
2. Given 세로·가로 방향 어느 쪽이든, Then 결과와 입력 요소가 잘리지 않는다.

#### US-602 오류 상황 안내
> **As a** 참가자 **/ I want** 문제가 생겼을 때 뭘 해야 할지 알고 싶다 **/ so that** 막힌 채로 기다리지 않는다

1. Given 서버 연결이 끊기면, Then 끊겼다는 사실과 **재입장해야 한다**는 것을 알린다(재접속 불가 · G-6).
2. Given 방이 사라졌으면, Then 표지 화면으로 안내하고 이유(**방장 이탈**·마지막 참가자 이탈·10분 무활동)를 알린다.
3. Given 진행 중인 방에 들어가려 하면, Then 게임이 끝날 때까지 기다려야 한다고 안내한다.

### 9.2 바꾸는 순서

스펙을 바꿀 때는 **이 문서를 먼저** 고치고 `features.md`로 전파한다.

```
requirements.md (§3 기준 · §4 스토리 · §6 결정)
      ↓
features.md (F-xxx · 담당 레이어 · 상태)
```

`plan.md`는 대조 자료로만 둔다. 어긋나면 이 문서가 이긴다.

### 9.3 정합성 점검

```bash
# 1. 모든 US가 features.md에 대응 기능을 갖는지
#    3자리만 뽑아 'US-1xx' 같은 번호대 표기를 걸러낸다
grep -oE 'US-[0-9]{3}' docs/requirements.md | sort -u > /tmp/us-r.txt
grep -oE 'US-[0-9]{3}' docs/features.md     | sort -u > /tmp/us-f.txt
diff /tmp/us-r.txt /tmp/us-f.txt && echo "OK: US 집합 일치"

# 2. 번호 중복 확인 (출력이 없으면 중복 없음)
grep -oE '^#{4,5} US-[0-9]+' docs/requirements.md | grep -oE 'US-[0-9]+' | sort | uniq -d
grep -oE '^\| F-[0-9]+' docs/features.md | grep -oE 'F-[0-9]+' | sort | uniq -d
grep -oE '^\| D-[0-9]+' docs/requirements.md | grep -oE 'D-[0-9]+' | sort | uniq -d

# 3. 게임 6종이 모든 표에 빠짐없이 있는지
for g in 룰렛 사다리 킹메이커 시간초 저격 눈치; do
  echo "$g: $(grep -c "$g" docs/requirements.md)"
done
```
