# 실시간 소켓 이벤트 명세 요약

> 원본: `실시간 소켓 이벤트 명세.md` (수정본 7/30)

## 연결 수명주기
- 참여자: 방 입장(멤버 등록) 응답 받는 즉시 핸드셰이크, `PENDING` 상태
- 방장: 프로필 확정 직후 핸드셰이크, `hostToken` 사용
- 연결 직후 서버가 `room:snapshot` 1회 전송 (초기 렌더용, 이후는 부분 갱신)
- 프로필 확정(`ACTIVE`) 순간에만 `member:joined` 브로드캐스트 — 소켓 연결 시점과 다름
- 소켓 끊기면 즉시 퇴장, **재접속 없음** (새로고침=퇴장, 이탈 경고 필요)
- 15초 내 미핸드셰이크시 슬롯 자동 해제
- 룸: `room:{code}`(6자리 숫자). 인증 실패시 `SESSION_EXPIRED`. 모든 S→C는 공통 응답 규격 + `roomVersion` 포함(순서 판단용). 방장 전용 이벤트 오용시 `NOT_HOST`(브로드캐스트 없음)

## 대기방 C→S (8개)
| 이벤트 | 발신자 | 요점 |
|---|---|---|
| `member:ready` | 참여자 | 준비 토글 |
| `member:kick` | 방장 | 강퇴, 대상은 `KICKED`+강제종료 |
| `chat:send` | 전원 | 1~200자, 서버가 messageId/sentAt 붙여 되돌림 |
| `chat:typing` | 전원 | 저장 안함, 3초 무갱신시 클라가 false 처리 |
| `game:select` | 방장 | gameId 6종 중 하나 |
| `game:config` | 방장 | 200~300ms 디바운스 권장 |
| `game:random` | 방장 | 서버가 뽑음(클라 뽑으면 결과 엇갈릴 위험) |
| `game:start` | 방장 | ACTIVE 2명↑ 필요, roundMembers 고정, `다시하기`도 재사용 |

## 대기방 S→C (11개)
`room:snapshot`(members는 ACTIVE만, messages 최근 50건, game 미선택시 null) / `member:joined` / `member:left`(reason: LEAVE·KICK·DISCONNECT, 방장 이탈은 대신 `room:closed`) / `member:ready_changed`(readyCount/activeCount 서버값 사용) / `chat:message` / `chat:typing` / `game:selected` / `game:config_changed` / `game:started`(roundMembers 고정, 라운드 끝까지 불변) / `room:closed`(HOST_LEFT·EXPIRED) / `error`(발신자에게만)

## 게임 진행 (S-05~S-10)
- 공용 이벤트 + type 분기 방식
- C→S `game:action` `{roundId, type, payload}` — 1회 제한 액션 중복시 `ALREADY_SUBMITTED`, 탈락자 시도시 `ELIMINATED`, 퇴장자 시도시 `SESSION_EXPIRED`
  - type별: `roulette.pick`(방장), `ladder.pick`(전원,laneIndex), `king.opinion`/`king.vote`(전원), `timer.start`/`timer.stop`(전원), `snipe.vote`(전원), `nunchi.up`(생존자만)
  - targetMemberId 자기자신이면 `SELF_VOTE_NOT_ALLOWED`
- S→C: `game:phase`(READY→PLAYING→TIE→RESULT 전환) / `game:tick`(눈치게임 타이머 동기화, 첫 tick만 오차보정 권장) / `game:progress`(중간집계, 익명게임은 누가 뭘 선택했는지 안 넣음) / `game:tie`(동점자, 같은 roundId 안 TIE phase 재투표) / `game:result`(roundMembers 기준 계산, 이탈자도 포함 가능) / `round:closed`(방장이 대기방 복귀시키면 전원에게, PLAYING→WAITING)

## 이탈자 처리 핵심 규칙
게임 도중 게스트 이탈 → `roundMembers`/역할/후보/결과 명단서 제거 안 함, 새 입력만 차단. 방장 이탈 = 방 종료(예외 없음).

## 확정된 결정사항 (10개, 원본 하단)
1. 룰렛/사다리: 서버 사전 확정 후 애니메이션만 재생
2. 시간초=클라 전송시각 / 눈치게임=서버시간
3. roundMembers 고정 정책 (위 이탈자 규칙)
4. 동점 재투표 횟수 제한 없음
5. 가이드 팝업 노출여부는 로컬스토리지 저장
6. 준비완료(READY)는 게임 시작 필수조건
7. `configSchema`는 REST로 받았으면 소켓에서 생략 가능
8. 익명게임 실명공개 여부는 방장이 설정에서 결정
9. 채팅 과거 이력 서버 미저장(로컬스토리지만), 대기방→게임→결과 전환시엔 로컬에 남아있어 불러오기 가능
10. 대기방 복귀 트리거 이벤트명은 `round:close`로 확정

## 프론트 구현 주의사항
- `roomVersion` 순서 검증 필수
- `game:action` type별 payload 형태 다름
- 이탈자도 결과 화면에 남기는 로직 필요
- READY 필수조건 반영
