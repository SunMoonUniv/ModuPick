# 작업 인수인계

코드·명령어·규칙은 `CLAUDE.md`에, 프레임 옮기는 법과 검증 방법도 거기 있다.
**여기에는 코드를 읽어서는 알 수 없는 것만 적는다** — 확정된 결정, 밟으면 아픈 함정, 아직 답을 못 받은 질문.

> 최종 갱신: 2026-08-05

## 1. 현재 상태

기능은 전부 동작한다. 홈 → 방 생성/입장 → 프로필 → 대기방 → 미니게임 6종 → 결과 → 다시하기/대기방 복귀가
임시 서버(`local-server/`)와 실제 소켓 통신으로 끝까지 돌아간다. 남은 일은 **Figma 디자인을 화면 단위로 얹는 것**이다.

- **적용 완료** — 토큰(`543:13`), 공통 컴포넌트, 홈(`542:195`), 방 만들기(`542:1922`), 대기방(`542:422`/`542:2783`),
  프로필(`542:642` + 캐릭터 타일 시트 `618:5799`), 인게임 공통 껍데기 + 룰렛(`542:1289`) + 사다리(`542:935`) + 시간초(`542:2995`)
  + 익명 저격(`542:1432`) + 눈치게임(`542:3142`),
  당첨자 발표 결과(`542:1119`), 역할 배분 결과(`542:2049`), 기록 순위 결과(`542:2292`),
  저격 결과(`542:2476`), 눈치 결과(`542:2619`),
  킹메이커 의견 제출 단계(`878:1750`) + 투표 단계(`878:684`), 득표 집계 결과(`878:2320` 익명 / `878:5221` 실명)
- **미적용 (색과 컴포넌트는 맞지만 배치가 추정)** — 코드 입장(`/join`), 눈치 전원 탈락(`542:3525`)

**게임 6종과 결과 화면은 전부 프레임이 적용됐다.** 남은 미적용은 코드 입장 화면과 눈치 전원 탈락 화면뿐이다.

**한 번에 한 화면씩** 진행한다 (사용자 요청). 화면 하나를 끝내면 위 목록을 갱신한다.

킹메이커의 일부 단계만 아직 `KingmakerGame.module.css`의 `.legacyStage`로 감싸 예전 레이아웃을 살려둔 상태다 —
깨져 보이지 않지만 프레임과는 다르다. 프레임을 적용할 때 그 화면을 `.legacyStage` 밖으로 빼고 좌표로 직접 배치할 것.

**킹메이커부터 프레임이 오토 레이아웃으로 다시 그려졌다** (`878:xxx`. 예전 `542:796`은 버린다).
바깥 골격은 좌표가 아니라 flex + gap 그대로 옮기면 되고, 시작 y만 공통 껍데기의 제목 블록 높이(73)에 맞춰 141로 고정한다.
남은 화면도 오토 레이아웃 판이 오면 같은 방식으로 옮길 것.

## 2. 함정

**아바타 파일 순서.** `src/assets/avatars/a01~a30.png`의 번호는 Figma 캐릭터 시트(`618:5799`)의 나열 순서와 **일치하지 않는다**
(시트 25번째 칸은 박쥐인데 `a25.png`는 물범 광대). 시트에서 뽑은 값을 **인덱스로 배정하면 30종이 전부 어긋난다** — 캐릭터를 보고 짝지어야 한다.
확정된 매핑은 `src/constants/avatarTiles.ts`에 캐릭터 이름 주석과 함께 들어 있다.

**`--color-stage: #2e1a63`** (게임 무대 배경) 은 프레임을 뽑지 않고 스크린샷을 눈으로 맞춘 **추정치**다. 정확한 fill로 교정 필요.

**6인 화면 검증.** 프레임은 전부 6인 기준이라 탭 두 개로는 검증이 안 된다. 브라우저 탭이 방을 만들고(방장),
나머지 5명은 스크립트로 붙이면 된다 — `POST /api/rooms/:code/members`로 토큰을 받고 `PATCH .../members/me`로 닉네임·소개를 확정한 뒤
`auth: { code, token }`으로 소켓을 열고 `member:ready`를 쏜다. 소켓을 열어둔 채 프로세스를 살려두면 그대로 6인 방이 된다.
두 가지를 틀리면 조용히 실패한다 — 소켓 `auth.code`는 표시용 `MODU-147098`이 아니라 **입장 응답의 `code`(`147098`)** 여야 하고,
`avatarId`는 **대문자 `A01`**이다. 어느 쪽이 틀려도 REST는 통과했는데 소켓만 거절돼 "명단에는 있는데 READY 0"이 된다.
스크립트로 게임 입력까지 흉내 낼 거라면 `game:action`에 **`roundId`를 반드시 실어야 한다** — 빠뜨리면 서버가
`ROUND_ALREADY_ENDED`로 조용히 되돌려서 "아무도 투표를 안 한 판"이 된다. 결과 화면으로 넘어가긴 해서 눈치채기 어렵다.
대기방으로 돌아오면 서버가 READY를 전부 내리므로, 봇은 `round:closed`를 받고 `member:ready`를 다시 쏴야 연달아 검증할 수 있다.

## 3. 결정된 사항

**프레임이 파운데이션 시트보다 우선한다.**
시트(`543:13`)에서 가져올 것 — 색 팔레트, 테두리 두께(카드5/컨트롤4/얇은3), 하드 그림자, 라디우스.
프레임(`542:xxx`)에서 가져올 것 — 레이아웃, 폰트 패밀리, 폰트 크기.
`tokens.css`의 `--font-size-*`는 강제 규격이 아니라 참고값이다. 프레임이 다른 값을 쓰면 화면 CSS에서 그 값을 써도 된다.

**게임은 가이드 5초 뒤 방장 조작 없이 스스로 시작한다** (`local-server/server.js`의 `GUIDE_MS`).
룰렛의 "돌리기", 사다리의 "사다리 타기" 버튼은 없어졌고 두 엔진의 `begin()`이 판정까지 바로 끝낸다.
`GameActionPayload`의 `roulette.pick` / `ladder.start`는 **타입에 남아 있다** — API 명세서 계약을 그대로 옮긴 것이라 임의로 지우지 않았다.
클라이언트는 더 이상 보내지 않고 임시 서버는 받으면 `INVALID_ACTION`을 돌려준다. 실제 백엔드 계약을 고칠 때 같이 정리할 것.

**시간초 잡기만 가이드 대기가 없다.**
6종 중 시간초만 참가자가 각자 `START`를 누른다. 가이드 5초 동안은 서버가 `game:action`을 `아직 시작 전입니다`로 거절해서,
그 사이 START를 누르면 클라이언트 타이머만 돌고 서버엔 출발 기록이 없어 이어지는 STOP까지 거절당한다 — 기록이 통째로 날아갔다.
그래서 `startRound()`가 `gameId === 'timer'`면 `guideEndsAt`을 null로 두고 곧바로 PLAYING을 연다.
가이드 팝업은 자동으로 뜨지 않을 뿐 제목 줄의 `?` 버튼으로는 볼 수 있다. 클라이언트도 `phase !== 'PLAYING'`이면 START를 잠근다.

**표지의 움직임은 프레임에 없는 것을 사용자 요청으로 얹은 것이다.**
아래 슬라이더가 오른쪽으로 계속 흐르고(카드에 마우스를 올리면 관성 있게 멈춘다), 카드를 누르면 오른쪽 패널이 그 게임으로 바뀐다.
미리보기는 게임당 9초짜리 연출이 반복되는 **가짜**다 — 등장인물·결과가 전부 상수라서 서버와 무관하고, 실제 게임 화면과도 다르다.
`DemoPanel`의 시계로 `performance.now()`가 아니라 **`document.timeline.currentTime`** 을 쓴 이유가 있다:
탭을 벗어나면 CSS 애니메이션만 멈추고 실제 시각은 흘러서, 돌아왔을 때 "결과는 떴는데 원판은 아직 도는 중"으로 영구히 어긋난다.

**창 크기 대응은 확대·축소 한 방으로 끝냈다.** (사용자 요청)
화면은 여전히 1920×1080 좌표로만 그리고, `Viewport`가 무대 전체에 `min(창너비/1920, 창높이/1080)` 배율을 먹인다.
브레이크포인트를 새로 만들거나 화면별로 반응형을 넣지 말 것 — 배율 하나로 비율이 유지된다.
대신 `vh`/`vw`는 transform을 무시하고 실제 창을 기준으로 재므로, 무대에 비례해야 하는 값은 1080/1920 기준 px로 쓴다.

**주소는 고정하고 화면만 바뀐다.** `main.tsx`가 `BrowserRouter`가 아니라 **`MemoryRouter`**를 쓴다.
의도된 부작용이라 "버그"로 고치지 말 것 — 브라우저 뒤로가기 안 먹음, 새로고침하면 무조건 홈(=방에서 나가짐), `/room` 딥링크 불가.
되돌리려면 `main.tsx` 한 줄만 바꾸면 된다.

**무활동 10분 방 삭제는 없앴다.** `server.js`의 `withRoom()`과 5초 스위퍼에서 만료 삭제 분기를 뺐다 (pending 슬롯 2분 회수는 유지).
`ROOM_IDLE_MS` 상수와 `expiresAt` / `roomExpiresInMs` 필드는 API 계약이 요구해서 **남겨뒀고 값도 계속 채워 보낸다.**

**오토 레이아웃 프레임을 옮길 때 줄높이를 먼저 맞춘다.**
브라우저의 `line-height: normal`은 Figma의 텍스트 박스보다 한 줄마다 5~6px 크다. 세로 스택에서는 이게 그대로 쌓여
아래로 갈수록 프레임과 어긋난다. Figma 값은 Black Han Sans = 글자 크기의 **1.265배**, Nanum Gothic Coding = **1.0배**,
Gothic A1 = 1.25배다 (`get_metadata`의 text 노드 height로 확인). 스택 컨테이너에 이 값을 먼저 박고 시작할 것.

**킹메이커 투표 중 득표수는 계약을 넓혀서 풀었다.**
프레임(`878:684`)의 실시간 득표 막대를 그리려고 `game:progress`에 **`optionVotes`(항목별 익명 카운트)** 를 선택 필드로 추가했다.
기획안이 막는 건 *투표자 신원*이지 득표수가 아니라서 "누가 뭘 골랐는지 아무도 몰라요"는 그대로 지켜진다.
**실제 백엔드도 이 필드를 내려줘야 이 화면이 살아 있다** — 안 주면 막대가 전부 0으로 굳는다.

**투표 화면에서 프레임과 다르게 간 두 곳.**
① 컷오프 선 — 프레임 문구는 "여기까지 생존 · 4위부터 탈락"인데 킹메이커에는 탈락이 없다(최다 득표 즉시 확정, 동점이면 결선).
그래서 선은 남기되 실제로 데이터가 갈리는 자리, 즉 **득표한 항목과 아직 0표인 항목 사이**에 긋고 문구도 그렇게 바꿨다.
한쪽이 비면 선을 감춘다.
② "내 제출" 표시 — 서버가 투표 단계에서 제시자를 감춰 보내(`options`에 `authorMemberId`가 없다) 어느 안건이 내 것인지 알 수 없다.
그래서 **내가 제출할 때 보낸 본문을 컴포넌트가 기억했다가 본문이 같은 줄을 잠근다.** 서버도 자기 안건 투표는 `SELF_VOTE_NOT_ALLOWED`로 막으므로 판정은 어긋나지 않는다.

**집계 결과 화면은 킹메이커와 익명 저격이 같이 쓴다.**
`variant: 'tally'`를 내는 엔진이 둘이라 프레임의 킹메이커 문구("팀명 후보", "우리 팀 이름")는 게임에 안 묶이게 일반화했다
("후보 N개", "{주제} 확정"). 킹메이커에서만 나오는 건 띠 오른쪽의 "🔒 아이디어 제안자는 항상 비공개" 알약 하나뿐이다.
익명/실명은 설정값을 따로 받지 않고 **서버가 `voterNicknames`를 실어 보냈는지**로 가른다 — 결과 payload만 보고 판단할 수 있어서다.
실명 판의 투표자 얼굴은 `voterNicknames`(닉네임뿐)를 라운드 참가자 명단과 닉네임으로 이어 붙여 찾는다.
방 안 닉네임은 서버가 중복 시 번호를 붙여 유일하므로 안전하다.

**기록 결과(`542:2292`)에서 프레임과 일부러 다르게 간 두 곳.**
① 정확도 막대 길이 — 프레임의 픽셀값에서 역산되는 배율(오차 1.176초에서 0이 되는 선형식)의 근거를 알 수 없어,
`1 - 오차/그 판의 최대 오차`로 정했다. 꼴찌가 항상 빈 막대이고 1위가 거의 꽉 차는 문법은 같지만, 한 명이 크게 빗나가면 나머지가 촘촘해진다.
② 순위표의 닉네임 칸 — 프레임은 2자 기준 40px인데 닉네임은 8자까지 들어와서 88px + 말줄임으로 넓혔다.
그만큼 오른쪽 막대·알약이 프레임보다 약 60px 오른쪽에 놓인다.

**익명 저격 결과는 킹메이커 득표표를 더 이상 같이 쓰지 않는다.**
저격에도 전용 프레임(`542:2476`)이 있어서, 같은 `tally` 결과라도 저격은 최다 피격자 카드(`SnipeResultView`),
킹메이커는 득표표(`TallyResultView`)로 갈라진다. 판단 기준은 `gameId === 'snipe'` 하나뿐이다.
프레임에는 사람별 득표수가 아예 없는데, 그러면 게임이 만들어낸 정보가 통째로 사라져서
아래 "비껴간 사람" 알약에만 `세이프! · N표`로 덧붙였다 (0표면 그냥 `세이프!`).
당첨자 카드와 아래 띠는 당첨자 발표(`542:1119`)와 판이 같아 `SafeBand`·`confetti.tsx`로 공통화했다.

**저격 화면에서 프레임과 다르게 간 세 곳.**
① 조준경 — 프레임은 바깥 링·중간 링·아바타 원판이 5~13px씩 어긋나 있다(손으로 놓은 흔적). 동심원으로 맞췄고
십자 조준선도 링 바깥에 대칭으로 붙였다. ② HUD 오른쪽 알약 — 프레임 문구는 "동점 시 서든데스 미니 룰렛"인데
엔진은 동점자끼리 결선 투표를 반복하므로("`ctx.tie`") 문구를 그렇게 고쳤다. ③ 버튼 — 프레임엔 "발사!" 하나뿐이라
아무도 안 고른 상태에서는 같은 자리가 "기권하기"(잉크색)로 바뀐다. 서버는 빈 배열을 기권으로 받는다.
총알 궤적은 **장식이다** — 실제 투표와 이어붙이면 누가 누굴 쐈는지가 드러나므로 발사된 *개수*만큼만 켠다.

**눈치게임 결과를 그리려고 계약을 넓혔다.**
프레임(`542:2619`)은 라운드마다 통과·탈락자를 시각·사유와 함께 표로 펼치는데,
기존 `WinnerResult.detail`은 문장 배열이라 그걸 갈라 그릴 수 없었다. 그래서 **`WinnerResult.rounds`(`NunchiRoundLog[]`)** 를
선택 필드로 추가했다 (킹메이커 `optionVotes`와 같은 판단). **실제 백엔드도 이 필드를 내려줘야 이 화면이 산다** —
안 주면 `ResultScreen`이 당첨자 카드(`542:1119`)로 되돌아간다. `detail`은 계약대로 그대로 둔다.
요약 카드의 마지막 타일은 프레임 문구가 "제한시간 초과 탈락"인데, 마지막 한 명·연결 끊김 탈락까지 세지 않으면
합이 참가자 수와 안 맞아서 **동시 입력 외 전부**를 세고 문구도 "제한시간·순서 탈락"으로 바꿨다.

**눈치 인게임에서 프레임과 다르게 간 두 곳.**
① 남은 초 — 프레임은 게이지 막대 *안*에 넣는데, 게이지가 줄면 글자가 잉크색 띠 위로 나와 안 읽힌다.
그래서 위쪽 설명 줄에 "남은 N초 · 제한시간 M초"로 합쳤다. ② "눌린 순서"의 시각 —
**서버는 완료/대기만 보내고 누른 시각을 안 준다.** 그래서 `game:progress`가 도착하는 순서를 클라가 쌓아 순번을 매기고,
시각은 첫 도착 대비 상대값으로 잰다(단계가 바뀔 때 서버가 progress를 비워 보내서 라운드마다 저절로 초기화된다).
순서 자체는 서버 판정 순서라 정확하지만 초 단위는 클라 관측값이다 — 백엔드가 눌린 시각을 주면 그쪽으로 바꿀 것.

**참가자가 6명을 넘으면 두 화면 모두 스스로 줄어든다.**
프레임은 전부 6인 기준인데 정원은 10명이다. 저격은 조준경 격자를 3열→4열로 늘리고 칸 전체에 `scale`을 먹이고,
눈치는 참가자 카드 폭을 줄여 한 줄에 밀어 넣는다. 6명일 때는 두 경우 다 프레임 값이 그대로 들어간다.

**결과 화면의 "사다리 소요"는 클라이언트가 잰 값이다.** 서버가 라운드 소요 시간을 안 보내줘서 `roomStore`가
`game:started`~`game:result` 사이를 직접 재 `result.elapsedMs`에 담는다 (가이드 5초 포함). 백엔드가 내려주면 그쪽으로 바꿀 것.
