# 04 개인정보와 데이터 수명

> **대상**: 최소 수집 범위 · 저장 항목과 위치와 수명 · 삭제 시점 · 채팅 서버 미저장 · 결과 이의 제기 시 재현 근거가 사라지는 문제와 그에 대한 설계 판단
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §5 NFR-08·NFR-09 · §4.4 US-464 · §4.5 US-501~504 · §6 D-02·D-13·D-38·D-40 · git 529e312 docs/db.md §2(DB가 저장하는·저장하지 않는 데이터) · §10(실시간 상태·연결 종료) · §18(로그 금지 항목) · [../01_overview/06_design_decisions.md](../01_overview/06_design_decisions.md) D-01·D-12·D-42·D-44·D-45·D-46

ModuPick의 3원칙 중 **가벼움**을 데이터 축에서 못박은 것이 이 문서다. 로그인이 없으므로 수집할 것이 거의 없고, 수집하지 않은 정보는 새지 않는다. 무엇을 보관하는지 한 줄로 셀 수 있어야 "링크와 닉네임이면 끝난다"는 약속이 검증 가능해진다.

**보관 범위가 좁다는 것은 대가를 동반한다.** 방이 사라지면 판정 근거도 함께 사라지므로 사후에 결과를 재현할 수 없다. 이 문서는 그 대가를 감추지 않고, 대신 무엇으로 그 자리를 메우는지를 확정한다.

## 최소 수집 범위

| 구분 | 항목 | 필수 여부 | 성격 |
|------|------|:--------:|------|
| **수집한다** | 닉네임 | 필수 | 결과 화면에서 자기를 알아보기 위한 표시 이름 |
| | 아바타 | 필수(목록에서 택1) | 방 안에서 선점되며 중복되지 않는다 |
| | 소개 태그 | 선택 | 대기 시간을 아이스브레이킹으로 바꾸기 위한 자유 입력 |
| | 게임 입력 | 게임별 | 안건 본문 · 투표 대상 · 입력 도착 시각 |
| | 확정 결과와 난수 시드 | 자동 | 판정 재현과 결과 화면 표시 |
| **수집하지 않는다** | 이메일 · 전화번호 · 계정 · 비밀번호 | — | 로그인을 두지 않는다(D-01·D-46) |
| | 결제 정보 · 위치 · 연락처 · 기기 식별자 | — | 제품 기능이 요구하지 않는다 |
| | 전적 · 통계 · 방 이력 | — | 계정이 없어 귀속시킬 주체가 없다 |

- **프로필은 입장 절차 중 한 번만 확정하고 대기방 진입 뒤에는 바꿀 수 없다**(D-02). 게임 도중 이름이 바뀌면 결과 기록과 화면이 갈리기 때문이다.
- 닉네임·소개 태그·안건 본문은 자유 입력이므로 **사용자가 스스로 개인정보를 적을 수 있다.** 길이 상한과 출력 이스케이프로 표현을 제한하고, 방 수명과 함께 삭제해 그 위험을 방 안에 가둔다. 표현 내용을 걸러 내는 기능은 이 문서군의 범위 밖이며 현행 설계처럼 서술하지 않는다.

## 저장 항목·위치·수명

**상태 경계가 곧 저장 경계다.** 진행 중 상태는 서버 인메모리에 두고, 방·참가자·라운드·선택지·투표·확정 결과는 MySQL에 기록한다. 밀리초 판정 경로에 DB 왕복을 넣지 않는다.

| 항목 | 위치 | 수명 | 사라지는 계기 |
|------|------|------|--------------|
| 방 — 제목 · 정원 · 초대 코드 · 상태 | MySQL | 방 수명 | 방 삭제 |
| 참가자 — 닉네임 · 아바타 · 소개 태그 · 방장 여부 · 입퇴장 시각 | MySQL | 방 수명 | 방 삭제 시 함께 삭제 |
| 라운드 · 선택지 · 투표 · 확정 결과 · 난수 시드 | MySQL | 방 수명 | 방 삭제 시 함께 삭제 |
| 준비 상태 · 현재 소켓 · 라운드 단계 · **입력 도착 시각** · **판정창 그룹핑** · 생존자 명단 | 서버 인메모리 | 라운드·연결 수명 | 연결 종료 · 라운드 종료 · 방 삭제 · **프로세스 재시작** |
| 채팅 메시지 | 각자 브라우저의 로컬 저장소 | 사용자가 지울 때까지 | 퇴장·방 삭제 이벤트에서 방별 키를 제거한다 |
| 결과 이미지 | 사용자 기기의 내려받은 파일 | 제품이 관리하지 않는다 | 사용자가 지운다 |
| 요청 제한 카운터(IP·세션 단위) | 서버 인메모리 | 짧은 시간 창 | 시간 창이 지나면 소멸한다 |

- **인메모리 상태는 복구하지 않는다.** 백엔드는 단일 인스턴스·워커 1개이고 프로세스가 재시작되면 진행 중이던 방 상태가 사라진다. 스냅샷 복구를 시도하지 않고 연결을 종료한다 — 부분 복원된 상태로 판정을 이어 가면 결과가 어긋나기 때문이다.
- **결과에 담아 저장하는 것과 인메모리에만 두는 것을 구분한다.** 눈치게임의 라운드별 판정과 서버 기준 입력 시각은 결과 화면이 표시해야 하므로(US-464) **확정 결과의 일부로 저장한다.** 반면 판정 중에만 쓰이는 그룹핑 중간 상태는 저장하지 않는다.
- **IP를 참가자 데이터로 저장하지 않는다.** 다만 초대 코드 무차별 대입을 막는 요청 제한이 IP·세션 단위 카운터를 쓰므로 그 값이 짧은 시간 동안 서버 메모리에 존재한다. 또한 웹 서버·배포 플랫폼 수준의 접속 로그는 애플리케이션 설계와 별개로 존재할 수 있다 — 이 문서는 **애플리케이션이 저장하는 것**을 확정하며 인프라 계층의 로그까지 통제한다고 주장하지 않는다.

### 로그에 남기지 않는 것

| 항목 | 이유 |
|------|------|
| 초대 코드 전체 | 로그 열람자가 임의의 방에 들어갈 수 있게 된다 |
| 투표자 식별값 | 익명 2종의 핵심 결합을 로그가 재현하게 된다 |
| 안건 본문 원문 | 익명 제출의 내용이 방 밖에 남는다 |
| 소개 태그 원문 | 자유 입력이라 개인정보가 실릴 수 있다 |
| DB 접속 정보 | 자격 증명이 로그로 유출된다 |

## 삭제 시점

방은 **세 조건 중 먼저 오는 것**으로 삭제된다(D-12).

| 조건 | 시점 |
|------|------|
| 방장 이탈 | 즉시. 진행 중이던 판은 결과 없이 끝난다 |
| 마지막 참가자 이탈 | 즉시 |
| 10분 무활동 | 마지막 활동으로부터 10분 |

- 방이 삭제되면 **초대 코드가 즉시 무효**가 되고 참가자·라운드·선택지·투표·결과·시드가 함께 삭제된다. 하위 데이터는 방 삭제에 연쇄한다.
- 삭제는 지연 처리하지 않는다. "보관 후 일괄 삭제"를 두면 그 보관 기간이 곧 새로운 개인정보 보관 범위가 된다.
- 강퇴된 참가자는 같은 코드로 다시 들어올 수 있다. 영구 차단 목록을 만들지 않는 것은 그 목록 자체가 방 수명을 넘겨 남는 개인 데이터이기 때문이다.

## 채팅 — 서버에 저장하지 않는다

- 채팅은 **방 전 구간**에서 열린다 — 대기방·게임 중·결과 화면 어디서나 쓸 수 있고 단계별 예외를 두지 않는다(D-45).
- 서버는 메시지를 **중계만 하고 저장하지 않는다.** 각 클라이언트가 자기 브라우저의 로컬 저장소에 방별 키로 보관하므로, 게임을 마치고 대기방으로 돌아오면 이전 대화가 그대로 보인다.
- 퇴장·방 삭제 이벤트에서 해당 방의 키를 제거한다.
- 서버 저장을 하지 않는 이유는 대화 기록이 쌓이면 방 수명과 무관한 개인정보가 남기 때문이다. 채팅을 방 전 구간에서 열더라도 이 판단은 바뀌지 않는다 — 어디서 오간 말이든 서버에 남기지 않는다.
- **대가는 명확하다.** 브라우저를 바꾸거나 저장소를 지우면 대화가 사라지고, 나중에 대화를 확인할 방법이 없다. 채팅은 판정 근거가 아니므로 이 대가를 받아들인다.

## 결과 이의 제기와 재현 근거

### 문제

판정에 이의가 제기되면 근거를 다시 보여 줄 수 있어야 한다. 그런데 이 제품에서 **판정 근거는 방보다 오래 살지 않는다.** 방이 사라지는 순간 시드·투표·라운드 기록이 함께 삭제되고, 방장 이탈은 예고 없이 즉시 일어난다.

계정이 없다는 사실이 문제를 한 겹 더한다(D-01). 나중에 결과를 다시 열어 볼 **주체를 식별할 수단이 없고**, 이의를 제기한 사람이 그 판의 참가자였음을 증명할 방법도 없다. 보관을 늘려도 그 데이터를 안전하게 돌려줄 대상이 없다.

**보관 창과 열람 창이 다르다는 점도 함께 적는다.** 서버는 결과를 방 수명 동안 보관하지만, 참가자가 결과를 다시 볼 수 있는 창은 **결과 화면에 머무는 동안뿐**이다 — 대기방으로 돌아오면 지난 판의 결과를 다시 보여주지 않는다(D-44). 실질적인 이의 제기 창은 결과 화면이 열려 있는 동안이다.

### 설계 판단

**보관 기간을 늘리지 않는다. 사후 재현을 지원하지 않는다.**

| 근거 | 내용 |
|------|------|
| 이의의 성격 | 이 제품의 이의 제기는 "지금 이 자리에서 납득할 수 있는가"이다. 판이 20~90초이고 결정은 그 자리에서 실행된다. 며칠 뒤 재현해서 뒤집을 대상이 없다 |
| 돌려줄 주체 부재 | 계정이 없어 열람 요청자를 인증할 수 없다. 보관된 판정 근거는 **누구에게도 안전하게 돌려줄 수 없는 데이터**가 된다 |
| 보관의 대가 | 보관을 늘리면 닉네임·소개 태그·안건 원문의 보관 범위가 함께 늘어난다. 판정 근거만 골라 남길 수 없다 — 근거는 누가 무엇을 했는가이기 때문이다 |
| 대안의 비용 | 사후 열람을 지원하려면 결과에 접근 권한을 붙여야 하고, 그 권한은 계정이다. 계정을 도입하면 3원칙의 가벼움이 무너진다 |

### 그 자리에서 납득하게 만드는 장치

사후 재현을 포기하는 대신 **결과가 나온 자리에서 판정을 눈으로 확인할 수 있게** 만든다.

| 장치 | 내용 |
|------|------|
| 눈치게임 라운드 기록 | 결과 화면에 라운드별 전원의 판정(안전 확정 · 동시 입력 · 미입력 · 최후 1인)과 **서버 기준 입력 시각**, 동시 입력 그룹을 표로 보여준다(US-464) |
| 시간초 잡기 기록 | 전원의 기록과 목표 시간과의 차이를 부호까지 함께 보여준다 |
| 킹메이커·익명 저격 개표 | 안건별 득표·후보별 피격 수를 많은 순으로 공개한다 |
| 룰렛·사다리 | 서버가 확정한 결과로 연출이 수렴하며, 사다리는 전원 경로를 동시에 그린다 |
| 결과 이미지 저장 | 전원이 결과 화면을 이미지로 저장한다(D-42). **방 밖으로 나가는 유일한 보존 수단이다** |
| 시드 보관 | 방이 살아 있는 동안 시드로 판정을 다시 돌려 같은 결과가 나오는지 확인할 수 있다 |

**결과 이미지는 판정 근거가 아니라 결과의 스냅샷이다.** 시드도 서버 도착 시각 전량도 담기지 않으므로 이미지로는 판정을 재계산할 수 없고, 남는 것은 "그때 이런 결과였다"뿐이다. 이 한계를 근거로 이미지를 판정 증거처럼 서술하지 않는다.

**결과가 확정되기 전에 방장이 나가면 그 판에는 남는 것이 없다.** 확정 결과가 저장되지 않은 채 방이 삭제되므로 근거도 이미지도 없다. 이 경로에 대한 판단은 [03_anti_cheat.md](./03_anti_cheat.md)의 방 폭파 절을 따른다.
