# 공정성 (11_fairness)

> **대상**: ModuPick의 제1 가치인 공정성을 설계가 어떻게 담보하는지 — 서버 판정 권위 · 익명성 · 치팅 방지 · 개인정보 수명 · 위협 모델
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §1.1(3원칙) · §3.1(G-1~16) · §4.4 US-401~403·431~433·451~452·461~464 · §5 NFR-04·05·08·09 · §6 D-04~D-10·D-22·D-26·D-27·D-29 · git 529e312 docs/db.md §10·§12·§17·§18 · git 529e312 docs/api.md(연결 수명주기·공통 규칙·game:progress) · frontend/src/games/(프로토타입 실측) · [../README.md](../README.md)(전역 불변식)

ModuPick이 파는 것은 미니게임이 아니라 **모두가 납득하는 결정**이다. 결과에 승복하지 못하면 제품이 성립하지 않으므로, 공정성은 기능 하나가 아니라 다른 모든 설계가 어길 수 없는 상위 규칙이다. 본 폴더는 그 규칙이 **무엇을 어디까지 보장하고 무엇을 보장하지 않는지**를 확정한다.

**보장하지 않는 것을 함께 적는 것이 이 폴더의 성격이다.** 공정성 문서가 지키지 못할 약속을 하면 그 문장을 읽고 만든 구현이 곧 취약점이 되고, 발표에서 인용된 문장이 거짓이 된다. 각 문서는 통제가 닿는 경계를 그리고, 경계 밖의 것을 잔여 위험 또는 대응하지 않기로 한 위협으로 등재한다.

## 3원칙과 그것을 담보하는 장치

3원칙의 정의는 docs_legacy/requirements.md §1.1이 원천이고 [../README.md](../README.md)의 전역 불변식이 정본이다. 본 표는 **각 원칙이 어떤 구조로 담보되는가**를 한 장으로 모은 개괄이며, 각 장치의 상세는 오른쪽 열이 가리키는 문서가 확정한다.

| 원칙 | 뜻 | 담보하는 장치 | 상세 |
|------|-----|--------------|------|
| **공정** | 결과는 서버가 정한다. 화면·기기·네트워크 속도가 결과를 바꾸지 못한다 | 서버 단독 판정(D-05) · 서버 도착 시각 기준(D-06) · 시드 기반 결정적 난수 · 클라이언트 페이로드의 발신자 식별자 미신뢰 · 입력 멱등(D-08) · 명단 스냅샷(D-15) | [01](./01_server_authority.md) · [03](./03_anti_cheat.md) |
| **동시** | 전원이 같은 결과를 같은 순간에 본다. 먼저 아는 사람을 만들지 않는다 | 중간 집계 비공개(D-09) · 익명 해제는 개표 후에만(D-10) · 단일 인스턴스의 단일 브로드캐스트 · 결과 전환 지연 3초(D-41) · 방장에게도 열람 특권을 주지 않음 | [01](./01_server_authority.md) · [02](./02_anonymity.md) |
| **가벼움** | 로그인·설치·개인정보 수집이 없다. 링크와 닉네임이면 끝난다 | 계정 부재(D-01) · 수집 항목 3개로 한정(D-46) · 방 수명과 데이터 수명 일치(D-12·D-44) · 채팅 서버 미저장(D-45) | [04](./04_privacy_data_lifecycle.md) |

**가벼움은 공정성을 깎는 방향으로도 작용한다.** 계정이 없으면 같은 사람이 여러 기기로 들어와 표를 늘리는 것을 신원으로 막을 수 없다. 이 맞바꿈은 은폐하지 않고 [05_threat_model.md](./05_threat_model.md)의 대응하지 않기로 한 위협에 등재한다.

## 공정성 불변식 요약

전역 불변식의 정본은 [../README.md](../README.md)다. 본 표는 공정성 축만 뽑은 개괄이다.

| 항목 | 규칙 | 예외 |
|------|------|------|
| 판정 주체 | 승자·배정·순위·시드는 서버가 계산한다. 클라이언트는 이미 정해진 결과로 수렴하는 연출을 그린다 | 없다 |
| 판정 기준 시각 | 시간·순서 판정은 서버 도착 시각이다 | **시간초 잡기의 경과 시간 하나뿐**이며 서버가 허용 범위를 검증한다(D-07) |
| 발신자 식별 | 요청자 신원은 서버가 현재 소켓 연결에 바인딩한 값에서 꺼낸다. 페이로드에 실린 식별자를 신뢰하지 않는다 | 없다 |
| 멱등 | 같은 입력은 최초 1회만 인정한다. 끝난 판·지난 라운드의 입력은 버린다 | 없다 |
| 중간 집계 | 진행 중에는 아무에게도 보이지 않는다. 방장도 같다 | 없다 |
| 익명 해제 | 방장 설정이 공개일 때, 개표가 끝난 뒤에만 풀린다 | 없다 |
| 명단 | 게임이 시작되면 고정된다. 이탈해도 후보로 남는다 | 방장 이탈은 방 삭제로 이어진다(D-11) |
| 반복 종료 | 결선·재대결은 최대 3회이며 초과하면 방장이 고른다(D-26) | 없다 |

**표의 예외 열이 비어 있다는 것은 현재 설계에 예외가 없다는 뜻이며, 새 예외를 두려면 이 표와 [../README.md](../README.md)를 같은 변경 단위에서 고쳐야 한다.**

## 이 폴더가 보장하는 것과 보장하지 않는 것

공정성 서술에서 가장 위험한 문장은 "서버가 판정하므로 공정하다"이다. 그 문장은 절반만 참이다 — 서버 판정은 **클라이언트가 값을 꾸며 내는 것**을 막지만 **전송 경로가 만드는 시각 왜곡**은 막지 못한다. 둘은 다른 위협이고 전자만 해결된다.

| 축 | 보장한다 | 보장하지 않는다 |
|----|---------|----------------|
| 판정값 | 클라이언트가 보낸 시각·순서·결과를 판정에 쓰지 않는다 | 참가자 간 네트워크 지연 차이가 눈치게임의 그룹핑에 들어가는 것 — 폭은 [01](./01_server_authority.md)이 게임별로 밝힌다 |
| 신원 | 입력이 다른 참가자 이름으로 접수되는 것을 막는다 | 같은 사람이 여러 기기로 별개 참가자가 되는 것 |
| 익명 | 개표 전 어떤 경로로도 제출자·지목자 식별 정보를 내려보내지 않는다 | **3명 규모에서 득표 분포만으로 지목 관계가 복원되는 것** — 범위는 [02](./02_anonymity.md)가 밝힌다 |
| 이탈 | 참가자가 창을 닫아 판정을 피하는 것을 막는다 | 방장이 나가 판 전체를 무효화하는 것 — 판단 근거는 [03](./03_anti_cheat.md)에 있다 |
| 담합 | 담합이 지배 전략이 되지 않게 규칙을 설계한다(D-38 — 겹치면 손해다). 서버는 조율에 쓸 정보를 주지 않는다(중간 집계 비공개) | **참가자끼리의 조율 자체.** 채팅은 방 전 구간에서 열리고(D-45) 같은 자리에 모인 팀은 육성으로도 조율한다 |
| 기록 | 방이 살아 있는 동안 시드와 결과로 판정을 재현할 수 있다 | 방이 사라진 뒤의 사후 재현 — 판단 근거는 [04](./04_privacy_data_lifecycle.md)에 있다 |
