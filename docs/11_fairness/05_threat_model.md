# 05 위협 모델

> **대상**: 공격자 유형 · 보호 자산 · 위협과 대응 22항 · 잔여 위험 8항 · 대응하지 않기로 한 위협 8항 · 검증 게이트
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §3.1 G-5·G-6·G-8·G-9·G-10·G-16 · §4.4 US-401~403 · §5 NFR-04·05·07·08·09 · §6 D-04~D-10 · git 529e312 docs/db.md §17(데이터 무결성 경계) · §18(권한·보안·개인정보) · git 529e312 docs/api.md(핸드셰이크 인증·권한 검증) · 본 폴더 [01](./01_server_authority.md)~[04](./04_privacy_data_lifecycle.md)

ModuPick의 고위험 자산은 **판정의 무결성 · 익명 결합 · 중간 집계 · 방 접근**이다. 위협 모델은 이 자산이 훼손되는 경로를 정의하고, 각 경로를 무엇이 막는지 구조 지점으로 적는다.

**최종 방어는 언제나 서버다.** 클라이언트는 판정하지 않고 저장하지 않으며, 화면에서 무언가를 감추는 것은 통제로 세지 않는다.

## 핵심 원칙

**1. 통제는 규약이 아니라 구조여야 한다.** "그렇게 하지 않는다"는 통제가 아니다. 각 위협의 대응 칸에는 그것을 할 수 없게 만드는 구조 지점을 적는다.

**2. 값을 보내고 가리는 것은 유출이다.** 익명 정보·개표 전 결과는 화면에서 감추는 것이 아니라 **페이로드에 넣지 않는 것**으로 막는다.

**3. 규칙으로 막을 수 없으면 이득을 없앤다.** 담합과 이탈은 탐지할 수 없으므로 담합해도 이득이 없고 이탈해도 유리해지지 않도록 규칙을 짠다.

**4. 잔여 위험과 포기한 위협을 숨기지 않는다.** 로그인을 두지 않기로 한 선택은 막을 수 없는 것을 만들었고, 그 목록을 적는 것이 이 문서의 절반이다.

## 공격자 유형

| 유형 | 위치와 능력 | 동기 |
|------|-----------|------|
| 악의적 참가자 | 방 안에 있고 유효한 토큰을 가진다. 브라우저 개발자 도구로 자기 화면과 자기가 보내는 페이로드를 임의로 고칠 수 있다 | 자기가 뽑히지 않기 · 특정인이 뽑히게 하기 · 남의 익명 벗기기 |
| 방장 | 참가자의 능력에 진행 권한 전부를 더한다. 방의 존폐를 쥔다 | 위와 같음 · 불리한 판을 무효화하기 |
| 구경꾼 | 방 밖에 있다. 초대 코드를 전달받았거나 무작위로 맞혔거나, 물리적으로 참가자의 화면을 볼 수 있는 자리에 있다 | 남의 결정에 끼어들기 · 익명 엿보기 |
| 네트워크 | 경로상의 지연·변동·손실·재정렬. 전송 구간 암호화로 내용 열람과 변조는 배제된다 | 의도 없는 환경 요인 |
| 대량 요청자 | 방 생성·입장·소켓 연결을 반복한다 | 자원 소모 · 가용성 저하 |

**관전자 역할이 없다.** 게임이 시작되면 새 입장을 받지 않으므로 방에 있는 사람은 전부 후보이고, 방 안의 공격자는 언제나 판정 대상이기도 하다.

## 보호 자산

| 자산 | 위치 | 훼손 시 영향 |
|------|------|-------------|
| 판정의 무결성 | 서버 판정 경로 · 시드 · 도착 시각 | 결과에 승복하지 못한다. 제품이 성립하지 않는다 |
| 익명 결합 — 안건과 제출자 · 지목자와 대상 | 선택지·투표 행의 작성자·투표자 참조 | 솔직한 선택이 사라져 표가 뜻을 잃는다 |
| 중간 집계 | 서버 인메모리 집계 | 표 쏠림과 먼저 아는 사람이 생긴다 |
| 방 접근 | 초대 코드 · 참가자 토큰 | 모르는 사람이 팀의 결정에 참여한다 |
| 프로필 | 닉네임 · 아바타 · 소개 태그 | 방 밖으로 개인 표시 정보가 나간다 |
| 판정 근거 | 시드 · 확정 결과 · 눈치 라운드 기록 | 이의 제기에 답할 수 없다 |
| 가용성 | 단일 인스턴스·워커 1개 | 진행 중인 방 전체가 동시에 끊긴다 |

## 위협과 대응

| # | 위협 | 대응(구조 지점) |
|:-:|------|-----------------|
| 1 | 남의 이름으로 입력 보내기 | 요청자 신원을 **현재 소켓 연결에 바인딩한 값**에서 꺼낸다. 페이로드의 발신자 식별자를 판정에 쓰지 않는다 |
| 2 | 방장 전용 동작 무단 실행 | 방이 보유한 방장 멤버 식별자와 요청자를 대조한다. 실패는 **보낸 사람에게만** member.not_host로 통지한다 |
| 3 | 같은 입력 재전송으로 표·기록 부풀리기 | 요청 식별자 UNIQUE · (라운드 · 투표자 · 투표 순번) UNIQUE |
| 4 | 끝난 판·지난 라운드에 입력 밀어넣기 | 입력에 실린 라운드 식별자를 현재 라운드와 대조하고 game.round_already_ended로 버린다 |
| 5 | 클라이언트 시계를 바꿔 유리한 시각 주장 | 시간·순서 판정을 **서버 도착 시각**으로만 한다 |
| 6 | 서버 타이머 신호를 조작해 마감 연장 | 타이머 신호는 표시용이며 마감 통과 여부는 서버가 자기 시계로 판정한다 |
| 7 | 시간초 경과 시간 위조 | 서버가 관측한 START·STOP 도착 시각 차이와 **양방향 허용 범위**로 검증하고, 벗어나면 최하위군으로 처리한다 |
| 8 | 클라이언트에서 결과를 바꿔 다른 결과 주장 | 판정과 저장이 서버에 있어 자기 화면만 바뀐다. 다른 참가자의 화면과 저장 결과는 영향받지 않는다 |
| 9 | 허용된 표 수를 넘겨 행사 | 서버가 1인 표 수 상한과 분산 규칙을 검증하고 vote.limit_exceeded로 거부한다 |
| 10 | 자기 안건 투표 · 자기 지목 | 서버가 작성자·본인을 대조해 vote.self_not_allowed로 거부하고 **보낸 사람에게만** 통지한다 |
| 11 | 진행 중 중간 집계 엿보기 | 진행 이벤트에 선택 내용과 집계를 **넣지 않는다.** 나가는 것은 완료 인원 수·생존 인원 수뿐이다 |
| 12 | 개표 전 제출자·지목자 조회 | 개표 전 어떤 이벤트에도 식별 필드를 넣지 않는다. **방장에게도 같다** |
| 13 | 안건 표시 순서·식별자로 제출 순서 역추론 | 서버가 시드로 섞어 표시 순서를 만들고, 제출 순번을 그대로 식별자로 쓰지 않는다 |
| 14 | 진행 표시로 제출자·투표자 집합 역추론 | 익명 2종은 개인별 완료 표시 대신 **인원 집계만** 내보낸다 |
| 15 | 불리해지면 이탈해 판정 회피 | 명단 스냅샷 · 이탈자 후보 잔류 · 재접속 부재 · **이탈이 유리해지지 않는 미입력 기본값** |
| 16 | 진행 중 강퇴로 명단 조작 | 진행 상태에서 강퇴를 거부한다. 판정 대상이 판 도중 바뀌지 않는다 |
| 17 | 게임 중 새 참가자를 넣어 표 늘리기 | 진행 중인 방은 새 입장을 room.already_playing으로 거절한다 |
| 18 | 같은 토큰 다중 소켓으로 원 참가자 밀어내기 | 두 번째 핸드셰이크를 **거부하고 기존 연결을 유지**한다 |
| 19 | 초대 코드 무작위 대입 | 숫자 6자리 코드 · 실패 반복 시 IP·세션 단위 요청 제한과 지연 · 정원 상한 · 진행 중 입장 거절 · 방장 강퇴 |
| 20 | 가입만 하고 슬롯을 점유해 방 잠그기 | 가입 후 일정 시간 안에 핸드셰이크가 없으면 서버가 슬롯을 푼다 |
| 21 | 자유 입력으로 스크립트·질의 주입 | 닉네임·소개 태그·안건·항목의 길이를 API와 DB 양쪽에서 제한하고 출력 시 이스케이프한다. 질의는 파라미터 바인딩으로만 만든다 |
| 22 | 대량 요청으로 자원 소모 | 요청 제한 · 방 정원 상한 · 10분 무활동 삭제 · 마지막 참가자 이탈 시 즉시 삭제 |

## 잔여 위험

통제로 제거되지 않은 것을 그대로 적는다.

| # | 위험 | 근거 | 판단 |
|:-:|------|------|------|
| 1 | 시간초 잡기에서 **허용 범위 안의 신고값 조작**이 통한다 | 허용 범위는 지터가 만드는 정상적 어긋남을 흡수하려 존재하므로 그 안의 조작은 정상 입력과 구분되지 않는다 | **수용** — 범위를 좁히면 정상 입력의 오거부가 늘고, 대안(서버 도착 시각 사용)은 전원의 기록을 회선 변동에 맡긴다 |
| 2 | 눈치게임에서 **참가자 간 지연 차이가 그룹핑을 뒤집을 수 있다** | 서버가 관측하는 간격은 실제 간격에 지연 차이가 더해진 값이다. 실제 간격이 판정창 경계 근처면 뒤집힌다 | **수용** — 판정창을 수백 밀리초 단위로 둔 것이 완화책이다. 판정창이 실제 지연 차이보다 충분히 큰지는 배포 전 실측으로 확인한다 |
| 3 | 룰렛·사다리 결과가 **연출 전에 클라이언트에 내려가 있다** | 결과를 먼저 확정해 보내고 연출이 그 결과로 수렴한다 | **수용** — 두 게임은 참가자 입력이 결과에 개입하지 않아 미리 알아도 판정을 바꿀 수 없다. 알게 되는 것은 3~5초 뒤 공개될 값 하나다 |
| 4 | **3명 규모에서 익명이 성립하지 않는 경우가 있다** | 킹메이커 실명 공개 · 익명 저격 전원 지목 · 3명 결선에서 득표 분포가 지목 관계를 결정한다 | **구조적 한계** — 자기 지목 금지와 자기 안건 투표 금지의 수학적 귀결이며 구현으로 고칠 수 없다. 범위는 [02_anonymity.md](./02_anonymity.md)가 밝힌다 |
| 5 | **방장이 나가 판을 무효화할 수 있다** | 서버가 고의 이탈과 연결 끊김을 구분할 수 없고, 막으려면 진행 권한 이양이 필요하다 | **의식적 선택** — 근거는 [03_anti_cheat.md](./03_anti_cheat.md). 대응은 방 종료 사유를 전원에게 명시하는 것 하나이며 생략할 수 없다 |
| 6 | 프로세스가 재시작되면 **진행 중인 방 전체가 사라진다** | 방 상태가 단일 인스턴스의 프로세스 메모리에 있고 스냅샷 복구를 시도하지 않는다 | **수용** — 부분 복원된 상태로 판정을 이어 가면 결과가 어긋난다. 판이 20~90초로 짧아 다시 하는 비용이 복원 로직의 위험보다 작다 |
| 7 | 결과 확정 전에 방이 사라지면 **판정 근거가 남지 않는다** | 확정 결과가 저장되기 전이라 결과도 이미지도 없다 | **등재** — 사후 재현을 지원하지 않기로 한 판단([04_privacy_data_lifecycle.md](./04_privacy_data_lifecycle.md))의 귀결이다 |
| 8 | **소수 인원에서 담합이 결과를 결정한다** | 3명 방에서 두 사람의 사전 합의는 투표형 게임의 과반이다 | **수용** — 사전 합의와 우연한 일치를 서버가 구분할 수 없고, 팀의 뜻으로 정하는 게임에서 합의는 뜻의 한 형태다 |

## 대응하지 않기로 한 위협

로그인을 두지 않기로 한 선택(D-01)과 제품이 쓰이는 물리적 맥락 때문에 **막을 수 없거나 막지 않기로 한 것**들이다. 무엇을 포기했고 왜 그것이 허용 가능한지를 함께 적는다.

| # | 포기한 위협 | 왜 막을 수 없나 | 왜 허용 가능한가 |
|:-:|-----------|---------------|----------------|
| 1 | **같은 사람이 여러 기기·브라우저로 별개 참가자가 되어 표를 늘린다** | 계정이 없어 같은 사람임을 판정할 수단이 없다. 닉네임 중복 금지는 같은 이름만 막는다 | 초대 코드는 팀 안에서만 공유되고 그 팀은 대개 같은 자리에 있다. 인원 수가 눈에 띄게 어긋나면 방장이 알아채고 강퇴할 수 있다. 정원 상한(10명)이 규모도 제한한다 |
| 2 | **어깨 너머 관찰·화면 촬영으로 익명이 깨진다** | 웹 애플리케이션이 물리 공간을 통제할 수 없다 | 통제 수단이 아예 없다. 이 제품은 같은 자리에서 쓰이는 것이 전제이므로 익명 게임의 실질적 한계로 등재하고, 사용자가 화면을 가리는 것 외에 제품이 할 수 있는 일이 없음을 인정한다 |
| 3 | **참가자 사이의 담합** | 탐지 수단이 없고, 합의와 우연한 일치를 구분할 수 없다. 채팅은 방 전 구간에서 열려 있으며(D-45) 같은 자리에 모인 팀은 육성으로도 조율한다 | **조율 자체는 막지 않는다.** 서버가 하지 않는 것은 조율에 쓸 정보를 주는 것이다(중간 집계 비공개 · 진행 중 상세 미표시). 실질적 방어는 담합이 지배 전략이 되지 않게 한 규칙 설계다(D-38) |
| 4 | **응답 크기·처리 시간을 이용한 부수 채널 분석** | 완전히 제거하려면 응답을 균일화해야 하고 그 비용이 크다 | 대상이 2~10명·수십 초짜리 판이고 얻는 것이 한 판의 익명 일부다. 공격 비용이 이득을 크게 넘는다 |
| 5 | **초대 코드의 의도적 유출** | 코드를 받은 참가자가 남에게 전달하는 것을 막을 수 없다 | 초대 코드는 인증 수단이 아니라 방 검색 값이다. 사후 수단으로 방장 강퇴가 있고, 게임이 시작되면 새 입장이 막힌다 |
| 6 | **저장한 결과 이미지의 위조** | 서명·워터마크를 넣어도 편집 후 재배포를 막을 수 없다 | 이미지는 판정 증거가 아니라 공유용 스냅샷이다. 그 자리에 있던 전원이 결과를 이미 봤으므로 위조본이 합의를 되돌리지 못한다 |
| 7 | **방이 사라진 뒤의 결과 재현 요구** | 계정이 없어 열람 요청자를 인증할 수 없고, 보관을 늘리면 개인정보 보관 범위가 함께 늘어난다 | 이 제품의 이의 제기는 그 자리에서 납득하는 것이다. 대신 결과 화면이 판정 근거를 그 자리에서 보여준다([04_privacy_data_lifecycle.md](./04_privacy_data_lifecycle.md)) |
| 8 | **자동 입력 도구로 정확한 타이밍 만들기** | 사람의 입력과 도구의 입력을 서버가 구분할 수 없다. 패턴 분석은 오탐이 정상 참가자를 최하위로 떨어뜨린다 | 판돈이 팀 내 역할 하나이고, 도구를 쓴 사실이 드러나면 그 비용을 본인이 진다. 오탐의 피해가 공격의 피해보다 크다 |

**이 표에 없는 위협을 막고 있다고 서술하지 않는다.** 새로 포기하는 위협이 생기면 이 표에 등재하고, 등재하지 않은 채 통제 목록에서 빼지 않는다.

## 검증 게이트

각 항목은 **실제 조작 결과**로 판정한다. 코드를 읽는 것은 검증이 아니다. 인수 기준의 채번과 정본은 [../03_requirements/README.md](../03_requirements/README.md)가 소유하며 본 표는 공정성 축의 검증 항목 목록이다.

| # | 게이트 | 기대 판정 |
|:-:|--------|----------|
| 1 | 페이로드에 남의 식별자를 넣어 입력 전송 | 자기 입력으로 처리되거나 거부된다. 남의 입력이 되지 않는다 |
| 2 | 참가자가 방장 전용 동작 전송 | 보낸 사람에게만 거부. 브로드캐스트 없음 |
| 3 | 같은 입력 연속 전송 | 최초 1회만 반영 |
| 4 | 끝난 라운드 식별자로 입력 전송 | 폐기 |
| 5 | 클라이언트 시각을 앞뒤로 크게 바꾼 뒤 눈치·시간초 진행 | 판정 결과에 변화 없음 |
| 6 | 시간초 경과 시간을 목표 시간과 동일하게 위조 | 허용 범위를 벗어나면 최하위군 |
| 7 | 진행 중 이벤트 페이로드 전수 검사 | 선택 내용·집계·식별 필드 미포함 |
| 8 | 익명 설정에서 개표 후 결과 페이로드 검사 | 제출자·지목자 필드 미포함 |
| 9 | 킹메이커 제출 단계의 진행 표시 페이로드 검사 | 인원 집계만 포함. 개인별 완료 상태 미포함 |
| 10 | 게임 도중 이탈 후 재입장 시도 | 거절되고, 이탈자는 후보로 남아 결과에 이탈 표시와 함께 나타난다 |
| 11 | 진행 중 강퇴 시도 | 거부 |
| 12 | 같은 토큰으로 두 번째 소켓 핸드셰이크 | 거부되고 기존 연결이 유지된다 |
| 13 | 없는 초대 코드로 반복 입장 시도 | 요청 제한이 걸린다 |
| 14 | 방 삭제 후 참가자·결과·시드 조회 | 남아 있지 않다 |
| 15 | 방장 이탈로 방 종료 | 전원 화면에 **사유가 명시된** 종료 안내가 표시된다 |
| 16 | 로그 검사 | 초대 코드 전체·투표자 식별값·안건 원문·소개 태그 원문 미검출 |
