# 목표·범위

> **대상**: 전원·평가자
> **작성일**: 2026-08-02
> **원천**: [../CLAUDE.md](../CLAUDE.md)(범위 규약) · [../README.md](../README.md)(고정 기준) · [06_design_decisions.md](./06_design_decisions.md)(확정 제품 결정 D-01~48) · docs_legacy/requirements.md §7.5(문서에 넣지 않은 항목) · git 529e312 docs/draft_plan.md

ModuPick이 무엇을 하기로 하고 무엇을 하지 않기로 했는지를 확정한다. 본 문서의 **범위 밖 절은 범위 밖 항목을 명시적으로 열거하는 유일한 자리**다 — 다른 문서는 이 항목들을 현행 설계처럼 서술하지 않으며, 설계 설명상 불가피한 부정형 언급만 예외로 허용한다.

## 목표

| 축 | 목표 |
|----|------|
| 속도 | 링크를 연 순간부터 게임 시작까지 **30초 안**에 끝난다 — 로그인·설치·권한 요청을 거치지 않는다 |
| 공정 | 결과를 서버가 확정하고, 화면·기기·네트워크 속도가 결과를 바꾸지 못한다. 판정 근거가 서버에 남아 이의에 답할 수 있다 |
| 동시 | 전원이 같은 결과를 같은 순간에 본다. 중간 집계를 아무에게도 보여주지 않아 먼저 아는 사람을 만들지 않는다 |
| 종료 | 어떤 입력 조합에서도 유한 라운드 안에 판이 끝난다 — 종료가 보장되지 않는 반복 규칙을 두지 않는다 |
| 납득 | 결과를 이미지로 남겨 단톡방에 올릴 수 있고, 뽑힌 사람이 웃고 넘길 수 있다 |
| 가벼움 | 개인정보를 수집하지 않고, 방이 사라지면 보관한 것도 함께 사라진다 |

## 범위 밖

다음은 MVP에 넣지 않으며 현행 설계처럼 서술하지 않는다. **영구 제외**(제품 방향상 두지 않기로 확정한 것)와 **후속 검토**(지금 만들지 않을 뿐 방향이 닫히지 않은 것)를 구분한다.

| 항목 | 구분 | 근거 |
|------|:---:|------|
| 로그인·회원가입·계정 | **영구 제외** | D-01 — 가입 절차가 하나라도 끼면 그 자리에서 쓰이지 않는다 |
| 전적·통계·랭킹 | **영구 제외** | 계정이 없어 누구의 전적인지 식별할 주체가 없다(D-01 · D-46) |
| 재접속·상태 복구 | **영구 제외** | D-17 — 복원 로직이 판정과 어긋나는 순간 결과가 뒤집힌다. 판이 짧아 다시 하는 편이 싸다 |
| 관전 모드 | **영구 제외** | D-16 — 관전자에게 무엇을 보여줄지가 곧 중간 집계 노출(D-09) 문제로 되돌아온다 |
| 방 목록·공개 방 찾기 | **영구 제외** | 방은 아는 사람끼리 코드로 모이는 단위다. 목록을 열면 모르는 사람이 팀 결정에 들어온다 |
| 방장 권한 승계 | **영구 제외** | D-11 — 원치 않는 사람에게 진행 책임이 떠넘겨진다 |
| 채팅 서버 저장 | **영구 제외** | D-45 — 대화 기록이 쌓이면 방 수명과 무관한 개인정보가 남는다. 채팅 자체는 방 전 구간에서 열리되 서버에 남기지 않고 각자 브라우저에 보관한다 |
| 룰렛·사다리의 참가자 참여 장치 | **영구 제외** | D-27 — 결과에 영향을 주지 않는 입력은 착각만 만들고 그 착각이 이의로 되돌아온다 |
| 눈치게임 종료 방식 설정 | **영구 제외** | D-38 — 최후 1인 서바이벌 단일 방식으로 확정했다 |
| Slack 연동 | **후속 검토** | 구 기획안의 확장 항목이며 API·화면·공수 어디에도 설계가 없다. 팀 안에서 결정을 끝내는 것이 이 제품의 범위다 |
| QR 초대 | **후속 검토** | 링크 복사와 6자리 코드로 같은 일이 되며 카메라 권한 요청이 가벼움을 깎는다 |
| AI 팀명 추천 | **후속 검토** | 킹메이커가 담는 자리이며, 외부 모델 호출은 응답 시간과 비용을 판 진행에 끌어들인다 |
| 혐오 표현 필터링 | **후속 검토** | 아는 사람끼리 모인 짧은 방이라 필터의 오탐이 실사용을 더 해친다. 공개 방(범위 밖)이 생기면 함께 검토한다 |
| 결과 리포트·누적 기록 | **후속 검토** | D-44가 결과 보관을 방 수명으로 묶었다. 리포트는 보관 범위를 넓히는 결정이 먼저다 |
| 다크 모드 | **후속 검토** | 순수 편의 기능이며 핵심 흐름을 보완하지 않는다 |

설계를 설명하려면 위 항목의 **부정형 언급이 불가피한 경우**가 있다(예: "재접속 경로를 두지 않는다"). 이때는 부정형으로만 쓰고 현행 설계처럼 서술하지 않는다.

## 판단이 갈리기 쉬운 경계

| 경계 | 범위 안 | 범위 밖 |
|------|---------|---------|
| 채팅 | 방 전 구간 채팅(200자 · 로컬 보관) | 서버 저장 · 과거 메시지 추가 로드 |
| 입장 | 코드 입장 · 링크 입장 | 진행 중 방 입장 · 관전 입장 · 방 목록에서 찾아 들어가기 |
| 결과 보관 | 방 수명 동안 서버 보관 · PNG 저장 | 방 삭제 후 재열람 · 대기방 복귀 후 지난 판 재열람 · 계정별 누적 |
| 프로필 | 입장 절차 중 1회 확정 | 대기방 진입 후 변경 · 프로필 사진 업로드 |
| 접근성 | 색 외 구분 · 터치 표적 최소 크기(D-48) | 스크린 리더 전용 흐름 · 키보드 단독 조작 최적화 |

## 성공 기준

MVP가 성공했다고 말하려면 아래를 전부 만족해야 한다. 각 항목의 검증 가능한 형태는 [../03_requirements/10_acceptance_criteria.md](../03_requirements/10_acceptance_criteria.md)의 인수 기준이 확정한다.

| # | 기준 |
|---|------|
| 1 | 링크를 연 뒤 **30초 안**에 게임이 시작된다 — 로그인·설치·권한 요청을 거치지 않는다 |
| 2 | 게임 6종이 전부 동작하고, 각 게임이 **모든 입력 조합에서 유한 라운드 안에 끝난다** — 전원 미입력·전원 동시 입력·반복 동점을 포함한다 |
| 3 | 같은 입력에서 같은 결과가 나온다 — 클라이언트 시계를 조작해도 판정이 바뀌지 않는다 |
| 4 | 결과 전환 시각의 참가자 간 편차가 규정 범위 안이며 중간 집계가 어느 화면에도 노출되지 않는다 |
| 5 | 참가자가 도중 이탈해도 판이 멈추지 않고, 이탈자가 후보에 남아 결과에 표시된다 |
| 6 | 방장이 나가면 어느 단계에서든 방이 즉시 삭제되고 전원이 이유 안내와 함께 표지로 돌아간다 |
| 7 | **360px 폭에서 가로 스크롤 없이** 전 화면과 전 게임의 입력 요소를 조작할 수 있다 |
| 8 | 방이 사라지면 참가자·결과·시드가 함께 삭제되고 초대 코드가 무효가 된다 |
| 9 | 킹메이커 제출자와 저격 지목자의 신원이 설정·시점 조건 밖에서 어느 응답에도 실리지 않는다 |
| 10 | 결과 화면을 참가자 전원이 PNG로 저장할 수 있다 |
