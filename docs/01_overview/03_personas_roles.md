# 사용 맥락·역할

> **대상**: 전원·평가자
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §1(제품 정의) · §2(용어) · §4.2 US-203~205(준비·내보내기·방장 이탈) · [06_design_decisions.md](./06_design_decisions.md)(D-11~D-14 · D-27) · [../README.md](../README.md)(전역 불변식)

ModuPick이 쓰이는 자리와 그 자리에서의 역할 2종을 확정한다. 본 문서가 **방장·참가자 권한 모델의 정본**이며, 기능 단위의 권한 판정 상세는 [../02_features/README.md](../02_features/README.md)의 권한 매트릭스가 이어받는다.

## 사용 맥락

계정도 조직도 없는 제품이라 사용자를 신분이 아니라 **상황**으로 나눈다. 아래 셋이 실제 사용 자리다.

| 맥락 | 상황 | 정하는 것 | 특징 |
|------|------|-----------|------|
| 조별 과제 | 강의실·카페에 5~6명이 모여 있다. 서로 잘 모르는 사이다 | 팀장 · 발표자 · 자료 조사 · PPT 제작 | 아무도 나서지 않는다. **아무도 원망받지 않는 방식**이 필요해 서버 난수 게임이 맞는다 |
| 스터디 | 주 1회 모이는 3~8명. 서로 안다 | 발표 순서 · 간식 당번 · 벌칙 | 분위기를 띄우는 것이 목적의 절반이다. 실력·타이밍 게임이 맞는다 |
| 사내 TF | 직급이 섞인 4~10명. 회의 중이다 | 팀명 · 안건 · 역할 분담 | 목소리 큰 사람의 안이 통과하기 쉽다. **익명 제출·익명 투표**가 맞는다 |

세 맥락의 공통점이 제품의 제약을 만든다.

- **모두 오프라인에서 같이 있다.** 그래서 결과를 같은 순간에 봐야 하고(D-09 · D-41), 먼저 아는 사람이 있으면 그 자리에서 티가 난다.
- **손에 있는 것은 휴대폰이다.** 그래서 360px에서 입력 요소를 조작할 수 있어야 한다(D-47).
- **한 번 쓰고 흩어진다.** 그래서 계정·전적·재접속을 두지 않고 방이 사라지면 데이터도 사라진다(D-01 · D-17 · D-46).
- **판이 짧다.** 20~90초짜리 결정이라 한 판을 다시 하는 비용이 복구 로직의 위험보다 작다.

## 역할 2종

| 역할 | 정의 | 되는 방법 |
|------|------|-----------|
| **방장**(HOST) | 방을 만든 사람. 진행 권한 전체를 갖는다 | 표지에서 방 만들기를 눌러 방을 생성하면 자동으로 방장이 된다. 다른 경로가 없다 |
| **참가자**(MEMBER) | 방에 들어온 사람. **방장도 참가자에 포함된다** | 코드 또는 링크로 입장한다 |

역할 계층이 없다 — 방장은 참가자의 상위 등급이 아니라 **진행 권한이 추가로 붙은 참가자**다. 게임에서 방장은 다른 참가자와 똑같이 후보이며 똑같이 입력한다.

- 룰렛·사다리는 입력 주체가 방장뿐이라(D-27) 이 두 게임에서 참가자는 지켜보기만 한다. 그 대신 결과에 참가자 입력이 개입할 여지가 없어 판정 시비가 생기지 않는다.

## 방장의 책임

권한이 몰려 있는 만큼 방장이 지는 책임도 명시한다.

| 책임 | 내용 |
|------|------|
| 진행 | 게임을 고르고 설정을 맞추고 시작을 누른다. 방장이 움직이지 않으면 판이 진행되지 않는다 |
| 교착 해소 | 반응 없는 참가자를 내보내 대기방 잠김을 푼다(D-14). 무효 라운드와 반복 상한 도달 시 다음 동작을 고른다(D-26 · D-39) |
| 방 수명 | 방장이 나가면 방이 사라진다. 자리를 뜨기 전에 판을 마무리할 책임이 방장에게 있다 |

## 방장 권한 비이양 원칙

**방장 권한은 어떤 경우에도 다른 참가자에게 넘어가지 않는다.** 방장이 나가거나 연결이 끊기면 방이 즉시 삭제되고, 진행 중이던 판은 결과 없이 끝난 뒤 전원이 이유 안내와 함께 표지 화면으로 돌아간다(D-11).

**왜 승계를 두지 않는가**

| 이유 | 설명 |
|------|------|
| 책임 떠넘김 | 진행 권한은 특권이 아니라 부담이다. 자동 승계는 원치 않는 사람에게 그 부담을 지운다 |
| 규칙 증식 | 승계를 두면 승계 순서·거부 처리·거부 시 재승계·전원 거부 시 처리가 줄줄이 따라붙는다. 그 규칙들이 방 상태머신을 통째로 복잡하게 만든다 |
| 진행 중 판의 무결성 | 룰렛·사다리는 입력 주체가 방장뿐이다(D-27). 판 도중 방장이 바뀌면 새 방장이 이미 시작된 판의 어느 시점부터 조작할 수 있는지가 게임마다 달라진다 |
| 사용자 행동과의 일치 | 오프라인에서 같이 있는 사람들이라 방을 다시 만들고 코드를 다시 부르는 데 몇 초면 된다. 실제로 그렇게 행동한다 |

**어떤 파급을 받아들였는가**

- 방장이 실수로 창을 닫으면 진행 중이던 판이 사라진다. 이 손실을 받아들이는 대신 승계 규칙 전부를 없앴다.
- 방장 이탈은 **게임이 결과 없이 멈추는 유일한 경우**다. 참가자 이탈로는 판이 멈추지 않는다(D-18 · D-19).
- 이탈 사유를 화면에 구분해 안내한다 — 방장 이탈·마지막 참가자 이탈·10분 무활동은 서로 다른 문구를 쓴다(D-12).

## 참가자의 상태

참가자는 입장 절차와 대기방에서 서로 다른 상태를 갖는다. 상태값과 전이의 정본은 [../10_glossary/README.md](../10_glossary/README.md)의 enum·상태머신 문서이며 여기서는 권한에 닿는 부분만 적는다.

| 상태 | 언제 | 무엇이 가능한가 |
|------|------|-----------------|
| 입장 절차 중 | 코드·링크 입력 후 프로필 확정 전 | 닉네임·아바타·소개 태그를 **최초 한 번** 정한다. 확정하면 되돌릴 수 없다(D-02) |
| 대기 중 | 대기방에 있다 | 채팅·준비 토글·규칙 열람. 프로필은 바꿀 수 없다 |
| 게임 중 | 명단 스냅샷에 고정돼 있다 | 게임별 입력. 이탈해도 후보에 남는다(D-15 · D-18) |
| 이탈 | 나갔거나 연결이 끊겼다 | 돌아올 수 없다. 진행 중이던 판에서는 후보로 남아 미입력 처리된다(D-17 · D-19) |

- 닉네임이 같으면 뒤에 숫자를 붙여 구분한다. 아바타를 고르지 않으면 남은 것 중 하나가 자동 배정된다.
- 내보내진 참가자는 같은 코드로 다시 들어올 수 있다(D-14). 다만 게임이 이미 시작됐으면 다른 입장 시도와 똑같이 거절된다(D-16).
