# 단위와 시간

> **대상**: ModuPick 전 문서·구현이 공유하는 수치 단위·시각 표준·정밀도 규약
> **작성일**: 2026-08-02
> **원천**: [../README.md](../README.md)(전역 불변식) · docs_legacy/requirements.md §3.4 방장 설정 · §5 비기능 · git 529e312 docs/db.md §6 공통 컬럼·값 규칙 · frontend/src/lib/data.ts

시간이 결과를 정하는 제품이므로 단위가 흔들리면 판정이 흔들린다. 본 문서는 어떤 값이 어떤 단위로 저장·전달·표시되는지를 한 곳에 모은다. 다른 문서는 여기서 정한 단위를 인용만 하고 다시 정의하지 않는다.

## 시각 표준

| 항목 | 규약 |
|------|------|
| 저장 | UTC. MySQL은 TIMESTAMP(6)를 쓰고 서버·DB 세션 시간대를 UTC로 고정한다 |
| 전달 | ISO 8601 문자열에 타임존 오프셋을 포함한다 |
| 표시 | 사용자 브라우저의 지역 시간대로 변환해 보여준다. 변환은 표시 계층에서만 한다 |
| 판정 | **벽시계를 쓰지 않는다.** 시간·순서 판정은 서버 프로세스의 단조 시계 기준 경과 밀리초로 한다 |

**벽시계와 단조 시계를 구분한다.** 벽시계(시스템 시각)는 NTP 보정·시간대 변경·수동 조정으로 뒤로 갈 수 있어 경과 시간 측정에 쓰면 음수나 급변이 나온다. 판정에 쓰는 모든 경과 시간은 단조 시계로 잰다. 서버는 프로세스 단조 시계, 클라이언트는 performance.now를 쓴다.

## 시간 정밀도

| 항목 | 단위 | 비고 |
|------|------|------|
| 게임 판정 시각·경과 시간 | **정수 밀리초** | 부동소수점을 쓰지 않는다. DB 컬럼은 BIGINT |
| 판정창 | 밀리초 | 방장 설정은 0.3초·0.5초로 표시하되 내부 값은 300·500이다 |
| 제한 시간·목표 시간 | 초(설정) → 밀리초(내부) | 표시 단위와 계산 단위를 섞지 않는다 |
| 방 무활동 만료 | 분 | 10분 |
| 하트비트·이탈 유예 | 초 | 값의 정본은 [../04_architecture/02_realtime_websocket.md](../04_architecture/02_realtime_websocket.md) |

**초 단위 설정값을 내부에서 밀리초로 환산할 때 부동소수점 곱셈을 거치지 않는다.** 0.3초를 300으로 환산하는 과정에서 0.30000000000000004 같은 값이 나오면 판정창 경계가 흔들린다. 설정값은 처음부터 밀리초 정수로 보관하고 표시할 때만 초로 나눈다.

## 판정 기준 시각

| 게임 | 판정에 쓰는 값 | 근거 |
|------|---------------|------|
| 운명의 룰렛 | 없음(서버 난수) | 참가자 입력이 없다 |
| 사다리타기 | 없음(서버 난수) | 참가자 입력이 없다 |
| 킹메이커 | 서버 도착 시각(마감 판정만) | 순위가 아니라 마감 안팎만 가른다 |
| 시간초 잡기 | **클라이언트 단조 시계 경과 시간** + 서버 검증 | 유일한 예외. 아래 절 |
| 익명 저격 | 서버 도착 시각(마감 판정만) | 순위가 아니라 마감 안팎만 가른다 |
| 눈치게임 | **서버 도착 시각** | 판정창 그룹핑의 기준 |

## 시간초 잡기의 예외

원칙은 서버 도착 시각이지만 시간초 잡기의 **경과 시간**만 예외다.

```
클라이언트: elapsedMs = round(performance.now() 차이)    ← 측정
서버:       observedMs = STOP 도착 시각 − START 도착 시각  ← 관측
검증:       |elapsedMs − observedMs| ≤ 허용 오차 → 인정
                                     초과      → 거부
```

- 측정은 클라이언트가, **신뢰 판정은 서버가** 맡는다. 클라이언트가 값을 꾸며도 서버가 관측한 범위를 벗어나면 거부되므로 이득을 볼 수 있는 폭이 왕복 지연 안으로 제한된다.
- 예외를 두는 이유는 **네트워크 지터가 판정 해상도보다 크기 때문**이다. 이 게임은 밀리초로 순위를 가르는데 모바일 편도 지연은 50~100ms 수준이고, 두 메시지의 지연 차이가 그대로 기록 오차가 된다. 서버 도착 시각을 그대로 쓰면 감각이 아니라 회선 품질이 순위를 정한다.
- 허용 오차의 값과 근거는 [../05_game_rules/05_timer.md](../05_game_rules/05_timer.md)가 확정한다.
- **순서·마감 판정은 예외가 아니다.** 시작 지연 상한을 넘겼는지, 제한 시간 안에 도착했는지는 서버 도착 시각으로만 판정한다.

## 길이·개수 단위

| 항목 | 값 |
|------|-----|
| 방 정원 | 2~10명 |
| 방 제목 | 1~30자 |
| 닉네임 | 1~8자 |
| 소개 태그 | 0~24자(선택) |
| 채팅 메시지 | 1~200자 |
| 주제 직접 입력 | 최대 12자 |
| 질문형 주제 직접 입력 | 최대 30자 |
| 킹메이커 안건 | 최대 120자 |
| 사다리 항목 하나 | 최대 12자 |
| 초대 코드 | 숫자 6자리 |

- 글자 수는 **유니코드 코드 포인트**가 아니라 **자소 단위**로 센다. 한글 조합·이모지·결합 문자가 한 글자로 보이는데 두 글자로 세면 사용자가 이유를 알 수 없는 제한에 걸린다.
- 앞뒤 공백은 저장 전에 잘라 낸다. 공백만 입력한 값은 빈 값으로 취급해 거부한다.
- 상한은 클라이언트가 입력을 막고 서버가 다시 검증한다. 클라이언트 검증만으로 끝내지 않는다.

## 비율·점수

- 비율은 저장하지 않고 조회 시점에 산출한다.
- 득표 수·피격 수는 정수다. 동률 판정에 부동소수점 비교를 쓰지 않는다.
- 시간초 잡기의 절대 오차는 정수 밀리초이므로 동점 판정이 정확하다 — 근사 비교(epsilon)를 쓰지 않는다.

## 표시 규약

| 값 | 표시 형식 |
|----|----------|
| 경과·정지 시간 | 초 단위 소수점 둘째 자리(예: 5.08초). 내부 정수 밀리초를 100으로 나눠 반올림하지 않고 **잘라서** 표시한다 |
| 시간 차이(부호 포함) | 부호를 붙인다(예: +0.08초 · −0.12초) |
| 남은 시간 | 초 단위 정수. 0 아래로 내려가지 않는다 |
| 초대 코드 | MODU- 접두어를 붙여 표시한다. 저장값에는 접두어가 없다 |

**표시 반올림이 판정에 영향을 주지 않는다.** 화면에 5.08초로 같아 보여도 내부값이 5083과 5087이면 다른 기록이다. 결과 화면이 동점처럼 보이는데 순위가 갈리는 상황을 피하려면 동점자 표시에 내부 밀리초를 함께 보여준다.
