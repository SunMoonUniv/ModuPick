# 운명의 룰렛

> **대상**: 서버 난수로 참가자 1인을 뽑는 게임의 상태 머신·판정 알고리즘·회전 각도 규약·종료 증명·경계값
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §3.2 · §3.5.1 · §4.4 US-411 · §6 D-04·D-21 · git 529e312 docs/games.md §2 · git ecceb11 docs/05_game_rules/01_roulette.md · frontend/src/games/Roulette.tsx(프로토타입 실측) · [01_common.md](./01_common.md)

동점도 미입력도 발생하지 않는 유일한 게임이다. 참가자는 조작하지 않고 지켜보며, 방장의 실행 신호 하나가 유일한 입력이다. 따라서 이 게임의 설계 부담은 "누가 뽑히는가"가 아니라 **서버가 정한 당첨자와 화면이 멈추는 조각이 어떤 기기에서도 어긋나지 않게 하는 것**에 있다.

## 게임 개요

| 항목 | 값 |
|------|-----|
| 결정 대상 | 사람 1인 |
| 인원 | 2~10명 |
| 입력 주체 | 방장만(PICK 1회) |
| 판정 주체 | 서버 난수 |
| 목표 소요 | 20초 |
| 결과 화면 형태 | 승자형 |
| 방장 설정 | 주제 1항 — 판정에 영향을 주지 않는다 |

- 참가자 전원이 **동일한 크기의 조각**을 하나씩 갖는다. n명이면 각 조각의 중심각은 360/n도이고 당첨 확률은 1/n로 같다.
- 조각 배치 순서는 **명단 스냅샷 순서**(입장 순서)다. 조각 0이 12시 방향에서 시작해 시계 방향으로 이어진다.
- 도중에 참가자가 이탈해도 조각은 그대로 남고 당첨 후보에서 빠지지 않는다.

## 상태 머신

```
              방장 PICK / 자동 실행 마감(30초)
   [GUIDE] ──3초──▶ [ARMED] ─────────────────▶ [SPINNING]
                       │                             │
                       │                             │ 회전 5초 경과
                       │                             ▼
                       │                        [REVEAL] ──3초──▶ [RESULT]
                       │                             │                │
                       └──────── 방장 이탈 ──────────┴────────────────┘
                                                     ▼
                                                 [ABORTED]
```

- **GUIDE** — 3초 규칙 가이드. 다시 하기로 진입하면 이 상태를 건너뛰고 ARMED에서 시작한다(G-4).
- **ARMED** — 방장의 PICK을 기다린다. 진입 시각 + 30초를 **자동 실행 마감**으로 잡는다.
- **SPINNING** — 서버 상수 SPIN_MS(5000ms) 동안 회전한다. 전원이 같은 시각에 시작해 같은 시각에 멈춘다.
- **REVEAL** — 당첨 조각이 강조되고 3초 뒤 결과 화면으로 넘어간다(G-11).
- **RESULT** — 결과 화면. 방장의 다시 하기·대기방으로를 기다린다.
- **ABORTED** — 방장 이탈로 결과 없이 끝난 상태. 방이 삭제되므로 어떤 상태에서도 즉시 이 상태로 간다(G-16).

### 상태 × 이벤트

| 상태 ＼ 이벤트 | 가이드 3초 경과 | 방장 PICK 도착 | 자동 실행 마감(30초) | 회전 5초 경과 | REVEAL 3초 경과 | 참가자 입력 도착 | 참가자 이탈 | 방장 이탈 |
|---------------|----------------|---------------|---------------------|------------|----------------|-----------------|------------|----------|
| **GUIDE** | → ARMED | 버린다(가드: 아직 ARMED 아님) | 타이머 미기동 | 해당 없음 | 해당 없음 | 버린다(정의된 입력 없음) | 스냅샷 유지·상태 불변 | → ABORTED |
| **ARMED** | 해당 없음 | 판정 실행 → SPINNING | 판정 실행 → SPINNING | 해당 없음 | 해당 없음 | 버린다 | 스냅샷 유지·상태 불변 | → ABORTED |
| **SPINNING** | 해당 없음 | 버린다(멱등: 최초 1회만) | 타이머 해제됨 | → REVEAL | 해당 없음 | 버린다 | 스냅샷 유지·상태 불변 | → ABORTED |
| **REVEAL** | 해당 없음 | 버린다 | 타이머 해제됨 | 해당 없음 | → RESULT | 버린다 | 스냅샷 유지·결과 불변 | → ABORTED |
| **RESULT** | 해당 없음 | 버린다(다시 하기는 별도 이벤트) | 타이머 해제됨 | 해당 없음 | 해당 없음 | 버린다 | 스냅샷 유지·결과 불변 | → ABORTED |
| **ABORTED** | 해당 없음 | 버린다 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 상태 불변 | 상태 불변 |

- **버린다**는 서버가 입력을 받되 상태를 바꾸지 않고 에러도 올리지 않는다는 뜻이다(G-9 멱등).
- **해당 없음**은 그 상태에서 해당 이벤트가 발생할 수 없음을 뜻한다 — 타이머가 기동되지 않았거나 이미 해제됐다.
- 참가자 이탈은 어느 상태에서도 명단 스냅샷을 바꾸지 않는다(G-5). 화면에는 이탈 표시만 붙는다.

## 판정 알고리즘

판정은 ARMED에서 SPINNING으로 넘어가는 한 순간에 끝난다. 입력은 명단 스냅샷과 라운드 시드뿐이고 참가자 입력이 없으므로 도착 시각 배열이 비어 있다.

```
서버 상수:
  SPIN_TURNS = 5      # 회전 바퀴 수
  SPIN_MS    = 5000   # 회전 시간(밀리초)

입력:
  roster[0..n-1]   # 명단 스냅샷. 입장 순서로 고정된 배열
  seed             # 라운드 시드(64비트). 결과와 함께 저장된다
출력:
  winnerIndex      # 당첨자의 스냅샷 인덱스

judgeRoulette(roster, seed):
  n    = length(roster)
  prng = PRNG(seed)                       # 시드로 초기화한 결정적 생성기

  winnerIndex = randomBelow(prng, n)      # 거부 표본추출 — 01_common.md

  return { winnerIndex }
```

- **회전 바퀴 수와 회전 시간은 서버 상수다.** 라운드마다 다를 이유가 없다. 원 기획(docs_legacy/requirements.md §3.5.1 · US-411)은 "3~5초 회전"이라는 **범위 서술**이었고 바퀴 수는 정하지 않았으며, 프로토타입(frontend/src/games/Roulette.tsx)도 고정값이었다. 라운드별 난수 추출은 2026-08-02 재구성에서 생긴 것이다.
- **PRNG 소비는 1회다.** 뽑는 값이 winnerIndex 하나뿐이라 소비 순서가 결과에 영향을 주지 않는다.
- winnerIndex는 0 이상 n 미만의 균등 정수다. 나머지 연산 편향을 없애려 거부 표본추출을 쓴다 — n이 3·6·7·9일 때 편향이 실제로 생긴다.
- 서버는 winnerIndex를 SPINNING 전이와 **함께** 전원에게 보낸다([../07_api/03_socket_events.md](../07_api/03_socket_events.md)의 game:phase payload). 값이 같으므로 전원의 화면이 같은 각도에서 멈춘다.

### 당첨 인덱스와 회전 각도의 관계

클라이언트는 난수를 만들지 않는다. 서버가 준 winnerIndex에서 각도를 **결정적으로 계산**한다.

```
좌표계:
  포인터는 화면 상단 12시 방향에 고정한다. 휠만 회전한다.
  휠 자체 좌표계에서 조각 i는 [i · sliceDeg, (i+1) · sliceDeg) 구간을 시계 방향으로 차지한다.
  조각 0의 시작 변은 회전각 0일 때 12시 방향에 놓인다.

계산:
  sliceDeg   = 360 / n
  sliceMid   = (winnerIndex + 0.5) · sliceDeg      # 당첨 조각의 중심 각도
  finalAngle = 360 · SPIN_TURNS + (360 - sliceMid) # 휠을 시계 방향으로 돌릴 총 각도

검증:
  finalAngle mod 360 = 360 - sliceMid
  → 회전이 끝나면 조각 winnerIndex의 중심이 정확히 12시(포인터)에 온다.
```

- **화면 크기가 결과를 바꾸지 못하는 이유는 계산에 픽셀이 없기 때문이다.** finalAngle은 n과 winnerIndex만으로 정해지는 각도이고, 반지름·뷰포트·픽셀 밀도는 각도에 들어가지 않는다. 휠을 크게 그리든 작게 그리든 같은 각도만큼 돌면 같은 조각이 포인터 아래 온다.
- **애니메이션이 끊겨도 결과가 바뀌지 않는다.** 프레임 드랍·탭 전환·저사양 기기에서 중간 프레임이 건너뛰어도 종료 시점에 회전각을 finalAngle로 **스냅**한다. 애니메이션은 0에서 finalAngle까지의 보간일 뿐이며 결과를 만들지 않는다.
- 회전 중에는 조작이 차단되고 가이드만 열 수 있다.

## 종료 증명

**주장** — 어떤 입력 조합에서도 이 게임은 게임 시작으로부터 최대 41초 안에 RESULT 또는 ABORTED에 도달한다.

**논증** — 상태 전이도에 순환이 없다. GUIDE → ARMED → SPINNING → REVEAL → RESULT는 단방향 사슬이며, 각 전이의 트리거는 모두 서버가 소유한 타이머 또는 단발 입력이다.

| 상태 | 최대 체류 | 근거 |
|------|----------|------|
| GUIDE | 3초 | 서버 타이머 고정값(G-4) |
| ARMED | 30초 | 자동 실행 마감. 방장이 누르지 않아도 서버가 판정을 실행한다 |
| SPINNING | 5초 | 회전 상수 SPIN_MS가 5000ms |
| REVEAL | 3초 | 결과 전환 지연 고정값(G-11) |

3 + 30 + 5 + 3 = **41초**가 상한이다. 다시 하기로 진입하면 GUIDE를 건너뛰어 38초다.

### 반례 후보 검토

| 반례 후보 | 이 게임에서의 결과 | 왜 종료하는가 |
|----------|------------------|-------------|
| **동점** | 발생하지 않는다 | 판정 출력이 단일 정수 winnerIndex이므로 동점이라는 상태가 정의되지 않는다. 동점 처리 규칙도 두지 않는다 |
| **전원 미입력** | 참가자에게 입력이 없다 | 참가자 입력이 판정에 들어가지 않는다. 방장이 PICK을 누르지 않는 경우가 여기 대응하며, ARMED 진입 30초 뒤 서버가 자동 실행한다 |
| **전원 동시 입력** | 발생하지 않는다 | 참가자 입력이 정의되어 있지 않아 버려진다. 방장이 PICK을 연타해도 최초 1회만 인정한다(G-9) |
| 명단 전원 이탈 | 판정이 그대로 실행된다 | 스냅샷이 고정이므로 접속자 0명이어도 당첨자가 정해진다. 방장이 이탈하면 그 시점에 ABORTED로 끝난다 |
| 방장 이탈 | 결과 없이 종료 | ABORTED는 흡수 상태다. 어떤 이벤트도 이 상태를 벗어나지 못한다 |

**반복 규칙이 없으므로 반복 상한도 필요 없다.** 이 게임은 [01_common.md](./01_common.md)의 3회 상한 규칙을 쓰지 않는 두 게임 중 하나다(다른 하나는 사다리타기).

## 경계값 표

| 경계 | 동작 |
|------|------|
| **최소 인원 2** | 조각 2개, 각 180도, 확률 1/2. 정상 진행한다. sliceMid는 90도 또는 270도다 |
| **최대 인원 10** | 조각 10개, 각 36도, 확률 1/10. 조각 라벨이 겹치면 닉네임을 말줄임하되 조각 각도는 줄이지 않는다 |
| **전원 미입력** | 참가자 입력이 없는 게임이다. 방장이 30초간 PICK을 누르지 않으면 서버가 자동 실행하고 결과를 낸다 |
| **전원 동시 입력** | 참가자 입력이 정의되어 있지 않아 전부 버린다. 상태와 결과가 바뀌지 않는다 |
| **1명 잔류** | 도중 이탈로 접속자가 1명만 남아도 스냅샷 n은 그대로다. 이탈자도 당첨될 수 있고 결과 화면에 이탈 표시와 함께 나온다 |
| **도중 이탈로 유효 인원이 최소 미만** | 접속자가 0명이 되어도 판정은 실행된다. 최소 인원 2는 시작 시점에만 검사한다. 단 방장이 이탈하면 방이 삭제되어 ABORTED다 |
| 방 정원이 2인데 참가자가 1명 | 게임을 시작할 수 없다. 시작 버튼이 비활성이고 사유가 표시된다(최소 인원 2 미달) |

## 구현 대조

frontend/src/games/Roulette.tsx는 서버가 없는 프로토타입이며 아래 지점이 본 문서와 어긋난다. **문서가 정본이고 구현을 고친다.**

| 지점 | 프로토타입 | 본 문서 |
|------|-----------|--------|
| 당첨자 결정 | 클라이언트가 Math.random으로 뽑는다 | 서버가 시드 기반 PRNG로 뽑아 전원에게 보낸다 |
| 회전 시간 | 클라이언트 상수 4200ms | 서버 상수 5000ms |
| 자동 실행 마감 | 없다. 방장이 누르지 않으면 영원히 대기한다 | ARMED 진입 30초 뒤 서버가 자동 실행한다 |

## 인수 기준 후보

번호는 붙이지 않는다. 채번 정본은 [../03_requirements/10_acceptance_criteria.md](../03_requirements/10_acceptance_criteria.md)다.

- 참가자 6명이 입장 순서 A·B·C·D·E·F로 고정된 상태에서 게임을 시작하면 → 조각 6개가 각 60도로 그려지고 조각 순서가 A부터 시계 방향으로 배치된다.
- 서버가 winnerIndex 3을 보내면 → 전원의 휠이 5000ms 동안 1800 + (360 − 210) = 1950도 회전하고 조각 3의 중심이 12시에서 멈춘다.
- 폭 360px 기기와 폭 1280px 기기가 같은 판에 참여하면 → 두 기기의 최종 회전각이 같고 같은 조각에서 멈춘다.
- 회전 중 탭을 전환해 애니메이션 프레임이 누락된 뒤 돌아오면 → 회전각이 finalAngle로 스냅되고 당첨 조각이 동일하다.
- 방장이 PICK을 300ms 간격으로 5회 연타하면 → 최초 1회만 판정에 반영되고 회전이 1회만 실행된다.
- 방장이 게임 시작 후 30초 동안 PICK을 누르지 않으면 → 서버가 자동으로 판정을 실행하고 회전이 시작된다.
- 참가자가 회전 중 방을 나가고 그 참가자가 당첨되면 → 결과 화면에 그 참가자가 이탈 표시와 함께 당첨자로 표시된다.
- 참가자(비방장)가 PICK에 해당하는 입력을 보내면 → 서버가 상태를 바꾸지 않고 결과에도 반영하지 않는다.
- 같은 시드와 같은 명단으로 판정을 다시 실행하면 → winnerIndex가 같다.
- 방장이 회전 중 방을 나가면 → 방이 즉시 삭제되고 전원이 사유 안내와 함께 표지 화면으로 이동하며 그 판의 결과는 남지 않는다.
