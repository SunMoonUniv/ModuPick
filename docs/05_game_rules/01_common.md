게임별 규칙은 이 문서의 규격을 어길 수 없다. 게임 문서가 이 문서와 다르게 적으면 이 문서가 이기며, 게임별 예외가 필요하면 그 예외를 여기에 등재한 뒤 게임 문서가 참조한다. 현재 등재된 예외는 **시간초 잡기의 경과 시간 측정** 하나뿐이다.

## 전 게임 공통 규칙 16항

구 스펙의 G-1~G-16을 재서술한다. 이 16항은 요구사항 정본에서 **REQ-GLB 접두사로 승격**되며, 번호 채번은 [../03_requirements/README.md](../03_requirements/README.md)가 소유한다. 본 문서는 규칙의 내용을 확정하고 번호를 붙이지 않는다.

| 구 ID | 규칙 | 본 문서군의 서술 |
|:-----:|------|-----------------|
| G-1 | 방 정원 | 방 정원은 2~10명이며 방장이 방 생성 시 제목과 함께 정하고 이후 바꿀 수 없다. 게임별 최소 인원은 2 또는 3이다 |
| G-2 | 서버 판정 | 결과는 서버가 확정해 전원에게 동일하게 전달한다. 클라이언트 애니메이션은 이미 정해진 결과로 수렴할 뿐이다 |
| G-3 | 시작 조건 | 방장을 제외한 참가자 전원이 준비 완료여야 방장이 시작할 수 있다. 방장은 준비 상태를 갖지 않는다 |
| G-4 | 3초 가이드 | 게임 시작 직후 3초간 규칙 가이드를 띄우고 게임 중 다시 열 수 있다. **다시 하기·결선·재대결·무효 라운드 재시작에서는 띄우지 않는다** |
| G-5 | 명단 스냅샷 | 게임이 시작되면 참가자 명단이 고정된다. 도중 이탈해도 후보에 남고 결과에 표시된다. 방장 이탈만 예외다 |
| G-6 | 재접속 불가 | 나갔다 들어오면 새 참가자다. 진행 중인 판에는 낄 수 없고, 끊긴 사람은 후보로 남아 미입력 처리된다 |
| G-7 | 미입력 자동 처리 | 입력하지 않은 참가자는 게임별 기본값으로 자동 처리한다. 한 명 때문에 판이 멈추지 않는다 |
| G-8 | 서버 도착 시각 | 시간·순서 판정은 서버 도착 시각을 기준으로 한다. 클라이언트 시계와 네트워크 지연은 판정 기준이 되지 않는다. **유일한 예외는 시간초 잡기의 경과 시간이다**(아래 절) |
| G-9 | 멱등 | 같은 입력이 여러 번 도착해도 최초 1회만 인정하고, 끝난 판·지난 라운드에 도착한 입력은 버린다 |
| G-10 | 중간 집계 비공개 | 투표·입력이 진행되는 동안 중간 집계를 아무에게도 보여주지 않는다. 완료·대기 상태만 보인다 |
| G-11 | 결과 전환 지연 | 결과 연출이 끝나 결과가 공개된 시점부터 3초 뒤에 결과 화면으로 넘어간다 |
| G-12 | 이미지 저장 | 결과 화면은 방장뿐 아니라 전원이 이미지로 저장할 수 있다 |
| G-13 | 데이터 수명 | 결과와 난수 시드는 방이 살아 있는 동안 서버에 보관하고 방이 사라질 때 함께 삭제한다 |
| G-14 | 다시 하기 | 방장은 결과 확인 후 같은 게임·같은 설정으로 다시 돌릴 수 있다 |
| G-15 | 주제 | 모든 게임은 주제를 하나 가진다. 주제가 이 판이 무엇을 정하는 판인지 설명한다 |
| G-16 | 방장 이탈 | 방장이 나가거나 연결이 끊기면 방이 즉시 사라진다. 게임 도중이면 판은 결과 없이 끝나고 전원이 표지 화면으로 돌아간다 |

**게임이 결과 없이 끝나는 경로는 셋뿐이다** — 방장 이탈(G-16) · 킹메이커에서 제출된 안건이 0개인 경우 · 방장이 교착 해소·무효 라운드 선택에서 대기방으로를 고른 경우. 그 밖의 어떤 입력 조합에서도 게임은 결과를 낸다.

## 명단 스냅샷과 유효 인원

- 방장이 시작을 누르는 순간 참가자 명단이 **배열로 고정**된다. 배열 순서는 **입장 순서**이며 이 순서가 룰렛 조각 배치와 사다리 레인 배치의 기준이 된다.
- 스냅샷 인원은 게임이 끝날 때까지 줄지 않는다. 도중에 이탈하거나 연결이 끊겨도 후보에 남고 결과에 **이탈 표시와 함께** 나타난다.
- **도중 이탈로 접속 중인 인원이 게임 최소 인원 아래로 내려가도 게임은 계속된다.** 판정은 스냅샷을 기준으로 하므로 최소 인원 조건은 시작 시점에만 검사한다. 이탈자는 남은 모든 라운드에서 미입력으로 처리된다.
- 최소 인원 검사가 다시 필요한 자리는 **다시 하기**뿐이다. 다시 하기는 그 시점의 참가자로 새 스냅샷을 만들며, 인원이 최소 미만이면 다시 하기 버튼이 비활성이고 사유가 표시된다.
- **예외는 방장 이탈 하나다.** 방장이 나가면 방이 삭제되고 판은 결과 없이 끝난다.

## 미입력 처리

미입력은 결함이 아니라 **정의된 입력**이다. 게임마다 기본값이 다르고, 그 기본값이 판정에 어떻게 들어가는지가 게임 문서의 판정 알고리즘에 나온다.

| 게임 | 미입력의 의미 | 판정 반영 |
|------|--------------|----------|
| 운명의 룰렛 | 방장이 실행하지 않음 | 게임 시작 후 30초가 지나면 서버가 자동 실행한다 |
| 사다리타기 | 방장이 실행하지 않음 | 게임 시작 후 30초가 지나면 서버가 자동 실행한다 |
| 킹메이커 | 안건 미제출 · 투표 기권 | 미제출은 후보가 없는 것이고 투표권은 유지된다. 기권은 어떤 후보의 표도 늘리지 않는다 |
| 시간초 잡기 | 미시작 · 미정지 | 둘 다 최하위군이며 **승자 후보에서 제외**한다. 최하위군 안에서는 미정지가 미시작보다 앞선다 |
| 익명 저격 | 지목 기권 | 어떤 후보의 표도 늘리지 않는다 |
| 눈치게임 | 라운드 제한 시간 안에 누르지 않음 | 안전 확정되지 못하고 다음 라운드에 남는다 |

**시간초 잡기의 미입력자를 승자 후보에서 빼는 것은 본 문서군의 결정이다.** 판정 기준이 "가장 먼 사람"일 때 미입력자를 최하위로 두면서 승자 후보에 남기면, 아무것도 누르지 않는 것이 최적 전략이 되어 게임이 성립하지 않는다. 미입력은 순위표의 꼬리에만 나타나고 선정 대상이 되지 않는다.

## 반복 상한 3회와 교착 해소

**동점 결선 · 동점자 재대결은 최대 3회다.** 3회를 마치고도 단독 승자가 없으면 자동 반복을 멈추고 방장에게 선택을 요구한다. 구 스펙의 "단독 승자가 나올 때까지 반복(상한 없음, D-23)"은 폐기됐다.

### 상한 없는 반복이 종료하지 않는 조합

폐기의 근거는 세 개의 구체적 반례다. 셋 다 참가자가 규칙을 어기지 않고 같은 선호를 유지하기만 하면 영원히 같은 동점이 재생산된다.

| # | 게임 | 조합 | 왜 종료하지 않는가 |
|:-:|------|------|------------------|
| 1 | 킹메이커 | 4명 · 안건 4개 · 1인 3표 | 각자 자기 안건을 뺀 3개에 3표를 나눠 줄 수밖에 없다. 모든 안건이 정확히 3표가 되어 4중 동점이다. 결선 후보가 4개 그대로이므로 같은 계산이 반복된다 |
| 2 | 킹메이커 | 3명 · 안건 2개 · 1인 1표 · 미제출자 기권 | 안건 A의 제출자는 B에만, B의 제출자는 A에만 투표할 수 있고 미제출자가 기권하면 A·B가 각 1표로 동점이다. 결선 후보가 2개 그대로여서 같은 계산이 반복된다 |
| 3 | 익명 저격 | 3명 · 순환 지목 | A가 B를, B가 C를, C가 A를 지목하면 전원 1표로 3중 동점이다. 결선 후보가 3명 그대로이고 자기 지목 금지 아래 같은 선택이 유효하므로 반복된다 |

세 반례의 공통 구조는 **결선이 후보 집합을 줄이지 못하는 것**이다. 동점자 전원이 결선 후보가 되므로 후보 수가 감소하지 않고, 참가자 선호가 같으면 표 분포도 같다. 규칙 자체로는 수렴을 보장할 수 없으므로 상한을 두고 사람이 끊는다.

### 반복 횟수 세는 법

- **본선 1회 + 결선 최대 3회 = 최대 4회 투표**다. 재대결도 같다 — 본판 1회 + 재대결 최대 3회.
- 결선·재대결 횟수는 라운드 단위로 서버가 센다. 다시 하기로 새 판을 시작하면 0으로 초기화한다.
- 결선·재대결에서는 3초 가이드를 띄우지 않는다(G-4).

### 교착 해소 선택

3회를 소진하고도 단독 승자가 없으면 서버가 **교착 해소 모달**을 띄우고 자동 진행을 멈춘다. 눈치게임의 무효 라운드 처리(D-35)와 같은 패턴이다.

| 선택 | 동작 |
|------|------|
| 다시 시작 | 같은 게임·같은 설정으로 새 판을 시작한다. 반복 횟수는 0으로 초기화하고 가이드는 띄우지 않는다 |
| 대기방으로 | 결과 없이 끝내고 전원이 대기방으로 돌아간다 |

- 참가자 화면에서는 두 버튼이 비활성이고 방장이 고르는 중임이 표시된다.
- **다시 시작은 자동 반복이 아니다.** 방장이 매번 누르지 않으면 진행되지 않으므로 서버의 상태 기계는 항상 유한 단계 안에 정지한다. 종료 증명은 이 성질에 기댄다.
- 무작위 확정(서버가 동점 후보 중 하나를 난수로 뽑는 선택지)은 넣지 않았다. 킹메이커·저격은 팀의 뜻으로 결정하겠다는 게임이고, 난수 확정을 붙이면 룰렛과 구분되지 않기 때문이다. 다만 유효표가 0인 경우는 다르다 — 아래 절을 따른다.

### 유효표 0의 처리

투표형 게임에서 **아무도 유효표를 던지지 않으면 결선을 열지 않는다.** 결선을 열어도 같은 0표 동점이 재생산되기 때문이다. 이때는 서버가 후보 중 하나를 난수로 확정하고 **표가 없었음을 결과 화면에 표시**한다. 익명 저격의 원천 규칙(전원 기권 시 난수 확정)을 킹메이커에도 같게 적용한다.

## 판정의 결정성과 시드

- 서버는 라운드마다 **64비트 시드**를 하나 뽑고, 그 시드로 초기화한 결정적 의사난수 생성기(PRNG)에서 필요한 값을 정해진 순서로 소비한다. 같은 시드와 같은 입력이면 같은 결과가 나온다.
- 시드는 결과와 함께 저장되며 방이 사라질 때 함께 삭제된다(G-13). 저장된 시드로 판정을 다시 돌려 같은 결과가 나오는지 검증할 수 있다.
- **클라이언트는 판정에 쓰는 난수를 만들지 않는다.** 회전 각도·가로선 좌표처럼 화면에 그리는 값도 서버가 준 시드나 인덱스에서 결정적으로 계산하며, 클라이언트 자체 난수는 결과와 무관한 장식(파티클 등)에만 쓴다.
- 균등 분포가 필요한 자리(당첨자 선택·순열 추출)에서는 나머지 연산 편향을 피하려 **거부 표본추출**을 쓴다. 게임 문서의 의사코드가 이를 명시한다.

```
randomBelow(prng, n):
  # 0 이상 n 미만의 균등 정수. 나머지 연산 편향을 제거한다.
  limit = 2^32 - (2^32 mod n)
  loop:
    x = prng.nextUint32()
    if x < limit: return x mod n
```

## 서버 도착 시각과 유일한 예외

- **원칙**: 모든 시간·순서 판정은 서버가 입력을 받은 시각(단조 시계 기준 정수 밀리초)으로 한다. 클라이언트가 보낸 시각·순서는 판정에 쓰지 않는다.
- **예외는 시간초 잡기의 경과 시간 하나다.** 경과 시간은 클라이언트의 단조 시계(performance.now)가 재고, 서버는 자신이 관측한 START·STOP 도착 시각의 차이와 대조해 **허용 범위 안일 때만** 그 값을 인정한다. 범위 밖이면 거부한다.
- 예외를 두는 이유는 **네트워크 지터가 판정 해상도보다 크기 때문**이다. 시간초 잡기는 밀리초 단위 오차로 순위를 가르는데, 모바일 환경의 편도 지연은 50~100ms 수준이고 두 메시지의 지연 차이가 그대로 기록 오차가 된다. 서버 도착 시각을 그대로 쓰면 회선이 균일한 사람이 유리해진다.
- 예외의 범위·허용 오차·거부 처리는 [05_timer.md](./05_timer.md)가 확정한다. 다른 게임에는 이 예외를 적용하지 않는다 — 눈치게임의 입력 시각은 서버 도착 시각 그대로다.

## 진행 상황 표시

- 입력형 게임(킹메이커·시간초·저격·눈치)은 참가자별 **완료·대기 상태만** 보여준다. 입력 내용·기록·중간 집계는 보이지 않는다(G-10).
- 제한 시간이 있는 단계에서는 남은 시간이 전원에게 동일하게 보인다. 서버가 단계 마감 시각을 보내고 클라이언트가 그 시각까지 남은 시간을 그린다.
- **전원이 입력을 마치면 시간이 남아도 즉시 다음 단계로 넘어간다.** 여기서 "전원"은 명단 스냅샷 전원이며, 이탈자가 있으면 그 사람은 마감 시각까지 기다린 뒤 미입력으로 확정된다.
