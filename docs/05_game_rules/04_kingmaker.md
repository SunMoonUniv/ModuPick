# 킹메이커

> **대상**: 익명 제출과 투표로 안건 1개를 정하는 게임의 상태 머신·실효 투표 수·결선 규칙·개표 알고리즘·종료 증명·경계값
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §3.2 · §3.4 · §3.5.3 · §4.4 US-431~433 · §6 D-22·D-23·D-24·D-25·D-26 · git 529e312 docs/games.md §4 · git ecceb11 docs/05_game_rules/03_kingmaker.md · frontend/src/games/Kingmaker.tsx(프로토타입 실측) · [01_common.md](./01_common.md)

사람이 아니라 **아이디어**를 정하는 유일한 게임이다. 제출과 투표가 분리되어 있고 제출자를 숨긴 채 투표해야 하므로, 규칙의 부담이 익명성과 표 계산 양쪽에 걸린다. 특히 1인 투표 수와 후보 수의 조합에서 **표를 다 쓸 수 없는 경우**와 **결선이 동점을 재생산하는 경우**가 실제로 생기므로 그 둘을 명시적으로 정의한다.

## 게임 개요

| 항목 | 값 |
|------|-----|
| 결정 대상 | 안건 1개 |
| 인원 | 3~10명 |
| 입력 주체 | 전원(제출 1건 · 투표 1회) |
| 판정 주체 | 참가자 투표 |
| 목표 소요 | 3분 30초 |
| 결과 화면 형태 | 개표형 |
| 방장 설정 | 주제 · 1인 투표 수(1·2·3표) · 결과 실명 공개(익명·실명) 3항 |

| 단계 | 제한 시간 | 내용 |
|------|:--------:|------|
| 제출 | 120초 | 각자 주제에 맞는 안건을 익명으로 **1건**, 최대 **120자** 제출한다. 제출 뒤 수정·취소할 수 없다 |
| 투표 | 60초 | 제출된 안건이 섞여 표시된다. **자기가 낸 안건에는 투표할 수 없다** |
| 결선 | 30초 | 동점 안건만 남기고 다시 투표한다. 기존 표는 초기화한다. 후보를 다시 제출하지 않는다 |

- **안건을 내지 않은 사람도 투표한다.** 제출은 권리이지 투표의 조건이 아니다(D-25).
- 전원이 제출을 마치면 시간이 남아도 즉시 투표 단계로 넘어간다. 투표도 같다.
- 최소 인원이 3인 이유는 2명이면 서로의 안건에만 투표할 수 있어 반드시 1:1 동점이 되고 익명성도 성립하지 않기 때문이다.

### 익명성 규칙

- **투표는 후보 ID로 접수한다.** 참가자 ID로 받으면 후보와 제출자의 연결이 클라이언트에 드러나 익명성이 무너진다.
- 자기 안건 투표 금지는 **서버가 후보 ID → 제출자 매핑을 내부에서 대조해** 판정한다. 이 매핑은 어떤 경로로도 클라이언트에 내려가지 않는다. 클라이언트는 자기 안건이 어느 것인지 알려면 자기 제출 텍스트를 기억하는 수밖에 없고, 서버는 그 후보를 비활성으로 내려보낸다.
- **후보 표시 순서는 서버가 라운드 시드로 섞는다.** 제출 순서를 그대로 쓰면 "먼저 제출한 사람이 앞"이라는 정보가 제출자 힌트가 된다. 섞는 순서는 전원에게 동일하다.
- **공개 대상은 제출자뿐이다.** 결과 실명 공개가 실명이면 개표 후에만 안건별 제출자가 드러난다. **투표자는 어느 설정에서도 공개하지 않는다** — 누가 어디에 표를 줬는지는 서버 안에만 남는다.
- 투표가 진행되는 동안 중간 집계를 아무에게도 보여주지 않는다(G-10). 결선에 들어갈 때도 **동점 후보 목록만** 보여주고 득표 수는 최종 개표에서만 공개한다.

## 실효 투표 수

1인 투표 수 설정 V는 1·2·3표다. 그러나 **투표 가능한 후보 수가 V보다 적을 수 있다.** 자기 안건에는 투표할 수 없고 한 안건에 몰아줄 수도 없기 때문이다.

```
투표 가능 후보 수  Ci = |후보 집합| − (내가 낸 안건이 후보 집합에 있으면 1, 아니면 0)
실효 투표 수 상한  Qi = min(quota, Ci)
quota = 본선이면 V · 결선이면 1
```

| 규칙 | 결정 | 근거 |
|------|------|------|
| 표를 다 쓰지 않아도 되는가 | **된다.** 1표 이상 Qi표 이하면 유효한 투표다 | Qi가 V보다 작아지는 조합에서 V표를 강제하면 그 참가자는 투표를 완료할 수 없어 강제로 기권이 된다. 관심 없는 후보에 표를 채우게 만들면 결과가 왜곡된다 |
| 투표 수 상한을 두는가 | **둔다.** 서버가 Qi를 상한으로 강제하고 초과분은 요청 전체를 거절한다 | 상한을 클라이언트가 지키게 하면 서버가 검증하지 않는 값이 판정에 들어간다 |
| 0표 제출 | 받지 않는다. 아무것도 고르지 않고 마감되면 **기권**이다 | 기권과 0표 제출을 구분할 실익이 없고, 구분하면 화면에 완료 상태가 둘이 된다 |
| 같은 안건에 여러 표 | 거절한다. 서로 다른 안건에만 나눠 줄 수 있다 | 몰아주기를 허용하면 1인 3표가 3배 가중 1표가 되어 다표제의 의미가 사라진다 |
| 확정 조작 | V가 1이면 고르는 즉시 확정한다. V가 2 이상이면 고른 뒤 **제출**을 눌러야 확정된다 | 부분 투표를 허용하므로 "다 골랐다"를 알리는 조작이 필요하다 |

**설정 시점에는 V를 검증할 수 없다.** 후보 수는 제출 단계가 끝나야 정해지므로, 방장이 3표로 설정해도 안건이 2개만 나올 수 있다. 그래서 검증이 아니라 **개표 시점의 클램프**로 처리한다.

### 결선에서는 1표로 고정한다

결선의 quota는 방장 설정과 무관하게 **1**이다.

**근거** — 후보가 2개 남고 quota가 2면, 자기 안건이 없는 투표자는 반드시 두 후보에 1표씩 주게 되어 두 후보의 표가 같은 폭으로 늘어난다. 동점 상태에서 시작한 결선이 **구조적으로 동점을 재생산한다.** 후보 m개·quota t표에서 t가 m에 가까울수록 표가 균등해지는 압력이 커지며, m = t + 1이면 자기 안건이 없는 모든 투표가 상쇄적이다. 결선은 남은 후보 중 **단일 선호**를 묻는 단계이므로 다표제를 쓰지 않는다.

**결선에서 자기 안건이 후보에 남은 경우**는 그대로 자기 안건 투표 금지를 적용한다. 결선 후보는 정의상 2개 이상이고 1인이 낸 안건은 최대 1건이므로, 자기 안건을 빼도 최소 1개가 남는다. 따라서 결선에서 투표할 수 없는 참가자는 생기지 않는다.

## 상태 머신

```
[GUIDE] ──3초──▶ [SUBMIT] ──마감 120초 / 전원 제출──▶ 안건 수로 분기
                                                        ├─ 0개    ──▶ [VOID]
                                                        ├─ 1개    ──▶ [TALLY]
                                                        └─ 2개 이상 ──▶ [VOTE]

[VOTE]   ──마감 60초 / 전원 투표──▶ 개표
[RUNOFF] ──마감 30초 / 전원 투표──▶ 개표

개표 결과로 분기
   ├─ 단독 최다 · 유효표 0      ──▶ [TALLY] ──3초──▶ [RESULT]
   ├─ 동점 · 결선 3회 미만       ──▶ [TIE_NOTICE] ──3초──▶ [RUNOFF] ──▶ (개표로 되돌아감)
   └─ 동점 · 결선 3회 소진       ──▶ [DEADLOCK]
                                        ├─ 방장 선택: 다시 시작   ──▶ [SUBMIT]
                                        └─ 방장 선택: 대기방으로 ──▶ [VOID]

어느 상태에서든 방장 이탈 ──▶ [ABORTED]
```

- **VOID** — 결과 없이 끝난 상태. 안건 0개(설정 화면 복귀)와 방장이 대기방으로를 고른 경우가 여기 온다.
- **TALLY** — 안건별 득표를 많은 순으로 공개하고 최다 득표 안건을 확정하는 개표 연출. 3초 뒤 결과 화면으로 넘어간다(G-11).
- **DEADLOCK** — 결선 3회를 소진하고도 단독 최다가 없어 자동 진행을 멈춘 상태. 방장의 선택을 기다린다([01_common.md](./01_common.md)의 교착 해소).
- **결선 재진입은 최대 3회다.** RUNOFF → 개표 → TIE_NOTICE → RUNOFF 순환은 결선 카운터가 3에 닿으면 끊긴다.

- **SUBMIT의 분기**: 안건 0개 → VOID · 안건 1개 → TALLY(투표 없이 확정) · 2개 이상 → VOTE.
- **개표 완료의 분기**는 아래 판정 알고리즘이 결정한다. 이 이벤트는 서버 내부 이벤트이며 클라이언트가 발생시킬 수 없다.
- 다시 시작으로 SUBMIT에 재진입하면 결선 카운터를 0으로 초기화하고 가이드를 띄우지 않는다(G-4).

## 판정 알고리즘

투표에는 도착 시각 순서가 판정에 들어가지 않는다. 서버 도착 시각은 **마감 전후 판별과 멱등 처리에만** 쓴다.

```
입력:
  roster[0..n-1]        # 명단 스냅샷
  candidates            # 후보 목록. 각 원소는 { id, text, authorId }
  ballots               # voterId → 후보 ID 배열 (마감 시각 이전에 도착한 최초 1건)
  quota                 # 본선이면 설정값 V(1·2·3), 결선이면 1
  runoffCount           # 지금까지 실시한 결선 횟수(0..3)
  seed
출력:
  { kind: "확정", winnerId, tally, byRandom }        # byRandom은 유효표 0으로 난수 확정한 경우 참
  { kind: "결선", tiedIds }
  { kind: "교착", tiedIds }

# ── 접수 시 검증 — 하나라도 어기면 요청 전체를 거절한다 ──────────────
acceptBallot(voterId, picks, candidates, quota):
  Ci = |{ c in candidates : c.authorId != voterId }|
  Qi = min(quota, Ci)
  reject if 마감 시각 이후 도착
  reject if 이미 이 단계에서 확정된 투표가 있다        # 멱등 · 최초 1회
  reject if length(picks) == 0 or length(picks) > Qi
  reject if picks에 중복이 있다
  reject if picks의 어떤 원소가 candidates에 없다
  reject if picks의 어떤 원소의 authorId == voterId   # 자기 안건 금지
  accept

# ── 개표 ─────────────────────────────────────────────────────
judgeKingmaker(candidates, ballots, runoffCount, seed):
  for c in candidates: tally[c.id] = 0
  for (voterId, picks) in ballots:
      for cid in picks: tally[cid] += 1

  total = sum(tally)

  # 유효표 0 — 결선을 열어도 같은 0표 동점이 재생산되므로 난수로 끊는다
  if total == 0:
      prng = PRNG(seed)
      winner = candidates[ randomBelow(prng, |candidates|) ]
      return { kind: "확정", winnerId: winner.id, tally, byRandom: true }

  maxVotes = max over c of tally[c.id]
  top      = { c.id : tally[c.id] == maxVotes }

  if |top| == 1:            return { kind: "확정", winnerId: only(top), tally, byRandom: false }
  if runoffCount < 3:       return { kind: "결선", tiedIds: top }
  else:                     return { kind: "교착", tiedIds: top }
```

- **결정성** — 같은 후보 집합·같은 표 집합·같은 결선 횟수면 언제나 같은 출력이 나온다. 표를 세는 순서는 결과에 영향을 주지 않고(덧셈의 교환법칙), 동점 집합 top은 집합이므로 순서에 의존하지 않는다. 난수를 쓰는 자리는 유효표 0 하나뿐이며 그것도 시드로 재현된다.
- **결선 진입 시** 후보 집합을 top으로 줄이고 ballots를 비우며 runoffCount를 1 올린다. 후보를 다시 제출받지 않는다.
- **거절된 요청은 미투표 상태로 되돌린다.** 참가자는 마감 전이면 다시 시도할 수 있다. 마감까지 유효한 투표를 남기지 못하면 기권이다.

## 종료 증명

**주장** — 어떤 입력 조합에서도 서버는 유한 시간 안에 RESULT · VOID · ABORTED 중 하나에 도달하거나 DEADLOCK에서 정지한다. 자동으로 무한히 도는 구간이 없다.

**논증** — 자동 진행 구간의 각 상태에 마감 타이머가 있고, 유일한 순환인 RUNOFF 고리에 상한이 있다.

| 상태 | 최대 체류 | 최대 진입 횟수 | 소계 |
|------|:--------:|:-------------:|:----:|
| GUIDE | 3초 | 1 | 3초 |
| SUBMIT | 120초 | 1 | 120초 |
| VOTE | 60초 | 1 | 60초 |
| TIE_NOTICE | 3초 | 3 | 9초 |
| RUNOFF | 30초 | 3 | 90초 |
| TALLY | 3초 | 1 | 3초 |

합 **285초**(4분 45초)가 자동 진행의 상한이다. 목표 소요 3분 30초는 결선이 한 번도 열리지 않는 통상 경로의 값이다.

**순환이 끊기는 지점** — RUNOFF → 개표 → TIE_NOTICE → RUNOFF는 유일한 순환이다. 개표 함수는 runoffCount가 3에 닿으면 "결선"을 반환할 수 없고 "교착"을 반환한다. runoffCount는 결선 진입마다 단조 증가하고 감소하지 않으므로 순환은 최대 3회 돈다.

**DEADLOCK은 정지 상태다.** 타이머가 없고 방장 선택 이벤트만 받는다. 방장이 다시 시작을 고르면 SUBMIT에서 새 판이 시작되지만, 그것은 사람이 매번 누르는 행위이지 규칙의 자동 반복이 아니다. 서버의 상태 기계는 언제나 유한 단계 안에 정지한다.

### 반례 후보 검토

| 반례 후보 | 구체 조합 | 결과 |
|----------|----------|------|
| **동점 — 표를 다 쓸 수밖에 없는 구조** | 4명 · 안건 4개 · 1인 3표. 각자 자기 안건을 뺀 3개 전부에 줘야 하므로 모든 안건이 3표, 4중 동점 | 결선은 quota 1로 열리므로 표가 분산될 여지가 생긴다. 그래도 4명이 순환 선호를 유지하면 결선도 4중 동점이다. 3회 소진 후 DEADLOCK으로 정지한다 |
| **동점 — 후보 2개 상호 배제** | 3명 · 안건 A(P1)·B(P2) · P3 미제출 · 1인 1표. P1은 B만, P2는 A만 투표 가능. P3이 기권하면 1:1 | 결선 후보가 {A,B}로 줄지 않으므로 같은 계산이 반복된다. 3회 소진 후 DEADLOCK |
| **전원 미입력 — 제출** | 안건 0개 | 게임을 성립시킬 수 없으므로 VOID로 끝나고 설정 화면으로 되돌린다. 투표 단계에 들어가지 않는다 |
| **전원 미입력 — 투표** | 안건 3개 · 전원 기권 · total 0 | 결선을 열지 않고 서버가 후보 중 하나를 난수로 확정한다. 결과 화면에 표가 없었음을 표시한다 |
| **전원 동시 입력** | 전원의 투표가 같은 밀리초에 서버에 도착 | 도착 시각은 판정에 들어가지 않는다. 각각 1건으로 접수되고 표 합계가 같다. 순서 의존이 없으므로 결과가 흔들리지 않는다 |
| 안건 1개 | 제출자가 1명뿐 | 투표를 건너뛰고 그 안건으로 확정한다. 동점이 발생할 수 없다 |
| 안건 텍스트가 완전히 같음 | 서로 다른 두 사람이 같은 문구를 제출 | 후보 ID가 다르므로 별개 후보로 둔다. 동점이면 결선에서 다시 갈린다 |

## 경계값 표

| 경계 | 동작 |
|------|------|
| **최소 인원 3** | 안건이 최대 3개다. 1인 투표 수를 3표로 설정해도 실효 상한은 min(3, 2) = 2다 |
| **최대 인원 10** | 안건이 최대 10개다. 1인 3표에서도 실효 상한이 3이다. 후보 목록은 스크롤로 처리하고 후보 수 제한을 따로 두지 않는다 |
| **전원 미입력 — 제출** | 안건 0개 → VOID. 게임을 중단하고 설정 화면으로 되돌린다. 결과를 남기지 않는다 |
| **전원 미입력 — 투표** | 유효표 0 → 서버가 난수로 확정하고 표가 없었음을 결과에 표시한다 |
| **전원 동시 입력** | 투표 도착 시각이 모두 같아도 판정에 영향이 없다. 순서 의존이 없다 |
| **1명 잔류** | 접속자가 1명만 남아도 진행한다. 이탈자는 제출 단계에서 미제출, 투표 단계에서 기권으로 확정된다. 남은 1명의 표만으로 단독 최다가 나오면 그대로 확정한다 |
| **도중 이탈로 유효 인원이 최소 미만** | 접속자가 2명 이하가 되어도 진행한다. 최소 인원 3은 시작 시점에만 검사한다. 방장 이탈이면 ABORTED |
| 안건 1개 | 투표 단계를 건너뛰고 확정한다 |
| 제출이 마감 직후 도착 | 거절한다. 그 참가자는 미제출이다 |
| 투표가 마감 직후 도착 | 거절한다. 그 참가자는 기권이다 |
| 실효 상한 초과 투표 | 요청 전체를 거절한다. 일부만 반영하지 않는다 |

## 구현 대조

frontend/src/games/Kingmaker.tsx는 서버가 없는 프로토타입이며 아래 지점이 본 문서와 어긋난다. **문서가 정본이고 구현을 고친다.**

| 지점 | 프로토타입 | 본 문서 |
|------|-----------|--------|
| 결선 투표 | 단계가 없다. 동점이면 방장에게 대기방으로·동점자끼리 다시 모달을 띄운다 | 동점이면 30초 결선 투표를 자동으로 연다. 방장 개입은 3회 소진 후에만 있다 |
| 반복 상한 | 없다 | 결선 최대 3회. 소진하면 DEADLOCK |
| 1인 투표 수 | 설정값이 화면에 표시되지만 실제 투표는 1건만 받는다. 실효 상한 클램프가 없다 | 본선은 min(V, Ci), 결선은 1로 클램프한다 |
| 유효표 0 | 처리가 없다 | 난수로 확정하고 표가 없었음을 표시한다 |
| 안건 0개·1개 | 처리가 없다. 전원이 제출할 때까지 기다린다 | 0개는 VOID, 1개는 투표를 건너뛰고 확정 |
| 후보 순서 | 클라이언트가 섞는다 | 서버가 라운드 시드로 섞어 전원에게 같은 순서를 내려보낸다 |
| 결과 공개 범위 | 결과 행에 제출자와 **투표자 목록을 함께** 담는다 | 공개 대상은 제출자뿐이다. 투표자는 어느 설정에서도 내려보내지 않는다 |

**결과 공개 범위는 익명성 결함이다.** 투표자 목록이 클라이언트로 내려가면 실명 설정에서 누가 누구 안건에 투표했는지 드러나고, 이는 전역 불변식의 익명 항목과 어긋난다.

## 인수 기준 후보

번호는 붙이지 않는다. 채번 정본은 [../03_requirements/10_acceptance_criteria.md](../03_requirements/10_acceptance_criteria.md)다.

- 참가자 5명 중 5명이 안건을 제출하고 1인 1표로 투표해 안건 A가 3표·나머지가 각 1표를 받으면 → A가 단독 최다로 확정되고 득표 순으로 개표 화면이 표시된다.
- 참가자 5명 중 3명만 제출해 안건이 3개면 → 미제출자 2명도 투표할 수 있고 후보 3개가 섞인 순서로 표시된다.
- 참가자가 자기가 제출한 안건을 고르려 하면 → 그 후보가 비활성으로 표시되고 서버가 그 안건이 포함된 요청을 거절한다.
- 1인 투표 수가 3표이고 후보가 3개이며 그중 하나가 자기 안건이면 → 실효 상한이 2표가 되고 3표를 담은 요청은 거절된다.
- 1인 투표 수가 3표인데 참가자가 1표만 고르고 제출하면 → 유효한 투표로 접수된다.
- 1인 투표 수가 2표인 참가자가 같은 안건에 2표를 주려 하면 → 요청 전체가 거절되고 미투표 상태로 되돌아간다.
- 개표 결과 안건 A와 B가 같은 표로 최다면 → 30초 결선이 열리고 후보가 A·B만 남으며 기존 표가 초기화되고 **득표 수는 표시되지 않는다**.
- 결선에서 1인 투표 수 설정이 3표여도 → 결선 화면에서 고를 수 있는 후보가 1개로 제한된다.
- 결선을 3회 실시하고도 동점이면 → 자동 진행이 멈추고 방장에게 다시 시작·대기방으로 선택이 표시되며 참가자 화면에서는 두 버튼이 비활성이다.
- 제출된 안건이 0개인 채로 120초가 지나면 → 게임이 중단되고 설정 화면으로 돌아가며 결과가 남지 않는다.
- 제출된 안건이 1개면 → 투표 단계를 건너뛰고 그 안건이 확정된다.
- 전원이 기권해 유효표가 0이면 → 결선을 열지 않고 서버가 후보 중 하나를 확정하며 결과 화면에 표가 없었음이 표시된다.
- 결과 실명 공개가 익명이면 → 결과 화면과 서버 응답 어디에도 제출자와 투표자가 나타나지 않는다.
- 결과 실명 공개가 실명이면 → 개표 후에만 안건별 제출자가 표시되고 **투표자는 표시되지 않는다**.
- 투표 진행 중 다른 참가자의 화면을 보면 → 완료·대기 상태만 보이고 득표 수가 보이지 않는다.
- 같은 투표 요청이 3회 재전송되면 → 최초 1회만 반영되고 표가 늘지 않는다.
- 투표 마감 시각 이후에 도착한 투표는 → 거절되고 그 참가자는 기권으로 집계된다.
