# 눈치게임

> **대상**: 혼자 누르면 안전해지는 서바이벌 구조의 상태 머신·고립 판정 알고리즘·무효 라운드·최후 1인 확정·종료 증명·경계값
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §2(용어: 판정창·안전 확정·무효 라운드) · §3.2 · §3.4 · §3.5.6(판정 예시 포함) · §4.4 US-461~464 · §6 D-34·D-35 · §7.2 · §7.4 · git 529e312 docs/games.md §7 · git ecceb11 docs/05_game_rules/06_nunchi.md · frontend/src/games/Nunchi.tsx(프로토타입 실측) · [01_common.md](./01_common.md)

**혼자 누를수록 유리한 구조다**(D-34). 혼자 누른 사람은 안전 확정되어 후보에서 빠지고, 판정창 안에 겹친 사람과 누르지 않은 사람이 남아 다시 붙는다. 마지막 한 명이 뽑힌다. 구 기획안에 있던 "동시 입력자가 전원 탈락"하는 구조는 일부러 겹치는 것이 이득이 되어 게임이 성립하지 않으므로 폐기됐다.

이 문서의 판정 규칙은 **정본이며 현재 프로토타입 구현과 정반대다.** 구현을 고친다.

## 게임 개요

| 항목 | 값 |
|------|-----|
| 결정 대상 | 사람 1인 |
| 인원 | 3~10명 |
| 입력 주체 | 전원(라운드마다 UP 1회) |
| 판정 주체 | 참가자 타이밍 |
| 목표 소요 | 90초 |
| 결과 화면 형태 | 기록형 |
| 방장 설정 | 주제 · 판정창(0.3·0.5초) · 라운드 제한 시간(10·15·20초) 3항 |

1. 라운드가 시작되면 제한 시간이 흐른다.
2. 각자 원하는 순간 UP을 **한 번** 누른다. 취소할 수 없다.
3. **혼자 누른 사람은 안전 확정**되어 후보에서 빠진다. 다시 판정받지 않는다.
4. **판정창 안에 겹쳐 누른 사람은 남는다.** 제한 시간까지 누르지 않은 사람도 남는다.
5. 남은 사람들끼리 다음 라운드를 하고, 마지막 한 명이 남으면 그 사람이 뽑힌다.

- 판정 기준은 **서버 도착 시각**이다(G-8). 시간초 잡기의 예외는 이 게임에 적용하지 않는다.
- 라운드마다 한 번만 누를 수 있고, 안전 확정된 사람과 이미 누른 사람의 추가 입력은 무시한다(G-9).
- 라운드가 길어질수록 배경이 붉게 점멸하고 텍스트가 흔들려 압박을 준다. **연출은 판정에 영향을 주지 않는다.**
- 최소 인원이 3인 이유는 2명이면 한 명이 혼자 누르는 순간 남은 한 명이 자동으로 뽑혀 심리전이 성립하지 않기 때문이다.

## 고립 판정

### 무엇을 판정하는가

D-34가 정의하는 것은 "혼자 누른 사람"이다. **그룹이 아니다.** 그래서 판정은 각 입력에 대해 하나만 묻는다 — **내 입력 시각의 앞뒤 판정창 안에 다른 입력이 있는가.**

```
참가자 p의 입력 시각을 t(p)라 하고 판정창을 W라 할 때
p가 안전 확정될 조건:  다른 어떤 입력 q에 대해서도  |t(p) − t(q)| > W
```

정렬한 배열에서는 **바로 앞·바로 뒤 입력과의 간격만** 보면 된다. 정렬된 배열에서 인접하지 않은 입력과의 간격은 인접 간격보다 항상 크기 때문이다.

### 연쇄로 겹치는 경우 — 구현이 갈리는 지점

A가 2.00초 · B가 2.20초 · C가 2.40초에 누르고 판정창이 0.3초일 때, A-B는 0.20초 · B-C는 0.20초 · A-C는 0.40초다. 여기서 두 가지 판정이 갈린다.

| 방식 | A | B | C | 성질 |
|------|---|---|---|------|
| **앵커 방식** — 그룹 최초 입력에서 W 이내만 같은 그룹 | 겹침 | 겹침 | **단독** | 도착 순서에 의존한다. B와 C는 똑같이 0.20초 간격인데 B는 겹치고 C는 혼자가 된다 |
| **고립 판정(본 문서)** — 앞뒤 간격이 둘 다 W 초과여야 단독 | 겹침 | 겹침 | **겹침** | 대칭이다. 순서를 바꿔도 결과가 같다 |

**고립 판정을 채택한다.** 근거는 셋이다.

1. **규칙 문장과 일치한다.** "혼자 누른 사람은 안전 확정된다"는 문장에서 혼자의 뜻은 "내 옆에 아무도 없다"이지 "내가 속한 그룹의 크기가 1"이 아니다. C는 B와 0.20초 차이인데 혼자라고 부를 수 없다.
2. **앵커 방식은 판정을 게임과 무관한 축에 의존시킨다.** 같은 간격인데 먼저 누른 사람만 겹침으로 판정되면, 판정 결과가 "누가 그룹의 첫 번째였는가"라는 우연에 좌우된다. 그리고 그 우연은 네트워크 지연으로 바뀔 수 있다.
3. **원천의 그룹 개념은 폐기된 승패 구조의 잔재다.** "동시 입력 그룹의 최초 클릭 시각부터 판정창 안"이라는 서술은 동시 입력자를 전원 탈락시키던 구조에서 탈락 집합을 만들기 위해 필요했다. D-34로 구조가 뒤집힌 뒤에는 집합을 만들 필요가 없고 고립 여부만 필요하다.

**연쇄 그룹은 판정이 아니라 표시에만 쓴다.** 결과 화면에서 겹친 사람들을 묶어 보여줄 때는 인접 간격이 W 이하인 것끼리 이어 붙인 연결 성분을 쓴다. 이 연결 성분에서 **원소가 1개인 성분은 고립 판정의 안전 확정자와 정확히 일치한다** — 성분의 크기가 1이라는 것은 앞뒤 간격이 모두 W를 넘는다는 뜻이기 때문이다. 표시와 판정이 어긋나지 않는다.

## 라운드 결과의 네 갈래

라운드 판정이 끝나면 안전 확정자 집합 safe와 잔류자 집합 remain이 정해진다. 다음 동작은 두 집합의 크기로만 결정된다.

| 조건 | 다음 동작 | 근거 |
|------|----------|------|
| \|safe\| = 0 | **무효 라운드** — 방장이 다시 시작·대기방으로를 고른다 | 아무도 빠지지 못해 생존자 수가 줄지 않았다. 자동으로 다음 라운드를 열면 같은 상태가 반복될 수 있다(D-35) |
| \|safe\| ≥ 1 그리고 \|remain\| = 0 | **종료** — safe 중 **서버 도착 시각이 가장 늦은** 사람이 최후 1인 | 생존자 전원이 각자 혼자 눌러 아무도 남지 않은 경우다. 마지막까지 버틴 사람이 뽑히는 게임의 취지를 그대로 적용한다 |
| \|safe\| ≥ 1 그리고 \|remain\| = 1 | **종료** — remain의 유일한 참가자가 최후 1인 | 규칙이 정의하는 정상 종료다 |
| \|safe\| ≥ 1 그리고 \|remain\| ≥ 2 | **다음 라운드** — 생존자를 remain으로 줄이고 새 라운드를 연다 | 생존자 수가 최소 1 줄었으므로 진전이 있다 |

**생존자가 0이 되는 경우를 무효 라운드로 처리하지 않는 이유** — 그 라운드에서는 실제로 진전이 있었다(전원이 안전해졌다). 무효로 되돌리면 성공한 판을 무르는 셈이고, 방장 개입 횟수만 늘어난다. 늦게 누른 사람을 뽑는 것은 이 게임이 시종 "버티기"를 겨루는 규칙과 일관된다.

**동점 개념이 없다.** 서버 도착 시각이 정확히 같은 밀리초라도 간격이 0이라 판정창 안이므로 둘 다 겹침이다. 늦은 입력을 고를 때 같은 밀리초가 둘 이상이면 명단 스냅샷 인덱스가 큰 쪽을 고른다 — 결정성을 위한 규칙이며 다른 뜻은 없다.

## 무효 라운드

**정의** — 안전 확정자가 한 명도 나오지 않아 생존자 수가 줄지 않은 라운드다.

구 스펙은 "생존자 전원이 같은 판정창에 눌러"만 무효 라운드로 정의했고 전원 미입력을 정의하지 않았다. 본 문서는 **안전 확정자 0**으로 일반화한다 — 두 경우 모두 생존자 수가 그대로이고 자동으로 다음 라운드를 열면 같은 상태가 반복될 수 있다는 점에서 같기 때문이다.

| 사유 | 조건 | 안내 문구의 뜻 |
|------|------|--------------|
| 전원 겹침 | 생존자 전원이 눌렀고 아무도 고립되지 않았다 | 아무도 혼자 누르지 못했다 |
| 전원 미입력 | 생존자 중 아무도 누르지 않았다 | 아무도 누르지 않았다 |
| 혼재 | 일부는 겹치고 일부는 누르지 않았다 | 아무도 혼자 누르지 못했다 |

**처리는 셋 다 같다**(D-35). 방장에게 두 선택을 준다.

| 선택 | 동작 |
|------|------|
| 다시 시작 | 같은 생존자로 라운드를 다시 연다. 가이드는 띄우지 않는다(G-4) |
| 대기방으로 | 결과 없이 끝내고 전원이 대기방으로 돌아간다 |

참가자는 두 버튼이 비활성인 채 방장의 선택을 기다린다. **무효 라운드에는 횟수 상한을 두지 않는다** — 매 무효 라운드마다 방장이 직접 눌러야 진행되므로 자동 반복이 아니고, 종료 증명이 그 성질에 기댄다.

## 상태 머신

```
[GUIDE] ──3초──▶ [ROUND]

[ROUND] ──라운드 마감 / 생존자 전원 입력──▶ 판정 ──▶ [ROUND_RESULT] ──3초──▶ 분기

분기 (safe = 안전 확정자 · remain = 잔류자)
   ├─ safe 0                    ──▶ [VOID_ROUND]
   │                                   ├─ 방장 선택: 다시 시작   ──▶ [ROUND] (같은 생존자)
   │                                   └─ 방장 선택: 대기방으로 ──▶ [VOID]
   ├─ safe ≥ 1 · remain 0        ──▶ [REVEAL] ──3초──▶ [RESULT]   (가장 늦은 안전 확정자가 최후 1인)
   ├─ safe ≥ 1 · remain 1        ──▶ [REVEAL] ──3초──▶ [RESULT]   (잔류자가 최후 1인)
   └─ safe ≥ 1 · remain ≥ 2      ──▶ [ROUND] (생존자를 remain으로 줄인다)

어느 상태에서든 방장 이탈 ──▶ [ABORTED]
```

- **ROUND** — 입력을 받는다. 생존자 집합과 라운드 번호를 갖는다. 제한 시간은 방장 설정값이다.
- **ROUND_RESULT** — 그 라운드의 판정(안전 확정·동시 입력·미입력)을 3초간 공개한다. 서버 기준 입력 시각과 연결 성분 그룹을 함께 보여준다.
- **VOID_ROUND** — 무효 라운드 모달. 타이머가 없고 방장 선택만 받는다.
- **REVEAL** — 최후 1인을 공개하고 3초 뒤 결과 화면으로 넘어간다(G-11).
- **VOID** — 방장이 대기방으로를 골라 결과 없이 끝난 상태.

| 상태 ＼ 이벤트 | 가이드 3초 경과 | UP 도착 | 라운드 마감 타이머 | 생존자 전원 입력 | 판정 완료(내부) | 연출 3초 경과 | 방장 무효 라운드 선택 | 참가자 이탈 | 방장 이탈 |
|---------------|----------------|--------|-------------------|-----------------|----------------|--------------|---------------------|------------|----------|
| **GUIDE** | → ROUND | 버린다(가드: 라운드 전) | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 스냅샷 유지·상태 불변 | → ABORTED |
| **ROUND** | 해당 없음 | 생존자면 접수(라운드당 최초 1회)·안전 확정자와 재입력은 버린다 | 판정 실행 | 판정 실행 | → ROUND_RESULT | 해당 없음 | 버린다 | 미입력으로 확정·상태 불변 | → ABORTED |
| **ROUND_RESULT** | 해당 없음 | 버린다(라운드 종료) | 미기동 | 해당 없음 | 해당 없음 | → ROUND · REVEAL · VOID_ROUND 중 하나 | 버린다 | 스냅샷 유지·판정 불변 | → ABORTED |
| **VOID_ROUND** | 해당 없음 | 버린다 | 미기동(자동 진행 없음) | 해당 없음 | 해당 없음 | 해당 없음 | 다시 시작 → ROUND · 대기방으로 → VOID | 스냅샷 유지·상태 불변 | → ABORTED |
| **REVEAL** | 해당 없음 | 버린다(판 종료) | 미기동 | 해당 없음 | 해당 없음 | → RESULT | 버린다 | 스냅샷 유지·결과 불변 | → ABORTED |
| **RESULT** | 해당 없음 | 버린다 | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 스냅샷 유지·결과 불변 | → ABORTED |
| **VOID** | 해당 없음 | 버린다 | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 상태 불변 | → ABORTED |
| **ABORTED** | 해당 없음 | 버린다 | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 상태 불변 | 상태 불변 |

- **생존자 전원 입력**으로 라운드가 조기 마감되어도 판정이 흔들리지 않는다. 더 누를 사람이 없으므로 마지막 입력의 뒤 간격은 무한대로 확정된다.
- 다시 시작으로 ROUND에 재진입하면 라운드 번호를 1 올리고 입력 기록을 비운다. 생존자 집합은 그대로다.

## 판정 알고리즘

```
입력:
  survivors[0..m-1]   # 이 라운드의 생존자. 명단 스냅샷의 부분집합
  presses             # 참가자 → 서버 도착 시각(라운드 시작 기준 상대 정수 밀리초)
                      #   라운드 마감 이전에 도착한 최초 1회만 담긴다
  windowMs            # 판정창. 300 또는 500
출력:
  { safe, remain, verdicts, groups }

judgeNunchiRound(survivors, presses, windowMs):
  # ── 1) 입력을 시각 오름차순으로 정렬 ─────────────────────────────
  pressed = [ (p, presses[p]) for p in survivors if p in presses ]
  ordered = sort(pressed, by (t, snapshotIndex(p)))      # 같은 밀리초면 스냅샷 순
  k = length(ordered)

  # ── 2) 고립 판정 — 앞뒤 간격이 둘 다 판정창을 넘어야 안전 확정 ──────
  safe = []; remain = []
  for i from 0 to k-1:
      prevGap = (i == 0)     ? INFINITY : ordered[i].t − ordered[i-1].t
      nextGap = (i == k - 1) ? INFINITY : ordered[i+1].t − ordered[i].t
      if prevGap > windowMs and nextGap > windowMs:
          safe.append(ordered[i].p);    verdicts[ordered[i].p] = 안전 확정
      else:
          remain.append(ordered[i].p);  verdicts[ordered[i].p] = 동시 입력

  # ── 3) 미입력자는 남는다 ─────────────────────────────────────
  for p in survivors where p not in presses:
      remain.append(p);  verdicts[p] = 미입력

  # ── 4) 표시용 연결 성분 — 판정에는 쓰지 않는다 ───────────────────
  groups = []; cur = [ordered[0]]
  for i from 1 to k-1:
      if ordered[i].t − ordered[i-1].t <= windowMs: cur.append(ordered[i])
      else: groups.append(cur); cur = [ordered[i]]
  groups.append(cur)
  # 원소가 1개인 성분은 safe와 정확히 일치한다

  return { safe, remain, verdicts, groups }

# ── 라운드 결과에 따른 다음 동작 ────────────────────────────────
nextStep(safe, remain, ordered):
  if length(safe) == 0:      return { kind: "무효 라운드" }
  if length(remain) == 0:
      last = ordered[length(ordered) - 1].p     # 가장 늦게 누른 안전 확정자
      return { kind: "종료", loserId: last }
  if length(remain) == 1:    return { kind: "종료", loserId: remain[0] }
  return { kind: "다음 라운드", survivors: remain }
```

- **결정성** — 입력은 정수 밀리초 배열과 판정창 하나뿐이다. 정렬 키에 스냅샷 인덱스를 넣어 같은 밀리초의 순서까지 고정하므로, 같은 입력이면 safe·remain·groups가 언제나 같다.
- **복잡도는 정렬이 지배한다.** m ≤ 10이므로 라운드 판정은 상수 시간에 가깝고 DB를 거치지 않는다. 입력 도착 시각·생존자 명단·판정창 그룹핑은 서버 인메모리에 둔다(전역 불변식의 상태 경계).
- 안전 확정자는 다음 라운드의 survivors에 들어가지 않으므로 그 이후 입력은 전부 버려진다.

## 종료 증명

**주장** — 방장이 개입하지 않는 구간에서 이 게임은 유한 라운드 안에 최후 1인을 확정한다. 자동으로 무한히 도는 구간이 없다.

**논증** — 라운드 결과가 네 갈래뿐이고 그중 자동으로 다음 라운드를 여는 갈래는 하나이며, 그 갈래는 생존자 수를 반드시 줄인다.

1. **각 라운드는 반드시 마감된다.** 라운드 마감 타이머가 방장 설정값(10·15·20초)으로 고정되어 있고, 생존자가 전원 입력하면 그보다 일찍 마감된다. 마감 시점에 모든 생존자의 상태는 안전 확정·동시 입력·미입력 셋 중 하나로 확정된다.
2. **자동 진행 갈래는 생존자 수를 엄격히 줄인다.** 다음 라운드로 가는 조건은 |safe| ≥ 1이므로 생존자 수가 최소 1 감소한다. 감소는 되돌려지지 않는다.
3. **감소는 유한하다.** 초기 생존자 수를 m₀(3~10)이라 하면 자동 진행 갈래는 최대 m₀ − 2회 일어난다. 그 뒤에는 |remain| ≤ 1이 되어 종료 갈래로 들어간다. 자동 라운드 총수는 **최대 m₀ − 1**이다.
4. **무효 라운드는 자동 진행이 아니다.** |safe| = 0이면 서버가 멈추고 방장 입력을 기다린다. 방장이 다시 시작을 누르는 것은 사람의 행위이므로 서버의 상태 기계는 언제나 유한 단계 안에 정지한다.

**자동 진행 시간의 상한** — m₀ = 10 · 라운드 제한 시간 20초일 때 라운드당 최대 20초 + 판정 공개 3초 = 23초이고, 라운드는 최대 9회다. 가이드 3초와 최종 공개 3초를 더해 **213초**가 상한이다. 기본 설정(15초)에서 6명이면 대략 5라운드·90초 안팎이며, 목표 소요 90초는 이 값이다.

| **전원 동시 입력** | 생존자 4명이 판정창 안에 연쇄로 누름 | 안전 확정자 0 → 무효 라운드 |

| **전원 고립** | 생존자 3명이 각자 충분히 떨어져 누름 | safe 3 · remain 0 → 가장 늦게 누른 사람이 최후 1인. 라운드를 더 열지 않는다 |

| 이탈자만 남음 | 생존자 3명 중 2명이 안전 확정되고 남은 1명이 이미 이탈 | 그 이탈자가 최후 1인이다. 결과 화면에 이탈 표시와 함께 표시된다(원천 예시의 도윤과 같은 경로) |
| 안전 확정자가 다시 누름 | 확정 후 UP 재전송 | 버린다. 상태가 바뀌지 않는다(G-9) |

## 경계값 표

| 경계 | 동작 |
|------|------|
| **최소 인원 3** | 정상 진행한다. 첫 라운드에서 1명이 안전 확정되면 남은 2명이 다음 라운드를 하고, 2명이 안전 확정되면 남은 1명이 바로 뽑힌다 |
| **최대 인원 10** | 정상 진행한다. 자동 라운드는 최대 9회이며 라운드마다 생존자 수가 화면에 표시된다 |
| **전원 미입력** | 무효 라운드. 방장이 다시 시작·대기방으로를 고른다. 자동으로 다음 라운드를 열지 않는다 |
| **전원 동시 입력** | 무효 라운드. 위와 같다 |
| **1명 잔류** | 즉시 최후 1인으로 확정한다. **라운드를 한 번 더 열지 않는다** — 혼자 남은 사람에게는 겹칠 상대가 없어 반드시 안전 확정되고, 그러면 생존자 0이 되어 자기 자신이 다시 뽑히므로 라운드를 여는 의미가 없다 |
| **도중 이탈로 유효 인원이 최소 미만** | 접속자가 0명이 되어도 라운드 마감까지 기다린 뒤 판정한다. 이탈자는 매 라운드 미입력으로 남으므로 결국 최후 1인이 되며, 그때 게임이 끝난다. 방장 이탈이면 ABORTED |
| 생존자 전원이 라운드 시작 직후 동시에 누름 | 라운드가 조기 마감되고 전원이 동시 입력이 되어 무효 라운드다 |
| 판정창 0.5초에서 0.5초 정확히 차이 나는 두 입력 | 간격이 판정창을 **넘지 않으므로** 둘 다 동시 입력이다. 비교는 초과(>)이지 이상(≥)이 아니다 |
| 라운드 마감 1밀리초 뒤에 도착한 UP | 버린다. 그 참가자는 미입력이다 |

## 구현 대조

**frontend/src/games/Nunchi.tsx는 승패 구조가 정본과 정반대로 구현되어 있다.** 이는 구현 결함이며 문서를 구현에 맞추지 않는다. 정정 대상으로 [../01_overview/05_priorities_roadmap.md](../01_overview/05_priorities_roadmap.md)의 구현 정정 목록에 등재한다.

| 지점 | 프로토타입 | 본 문서(정본 D-34) |
|------|-----------|------------------|
| **승패 구조** | 겹친 사람을 **동시 탈락**시키고 혼자 누른 사람을 **통과**시킨다 | 혼자 누른 사람이 **안전 확정**되어 후보에서 빠지고 겹친 사람이 **남는다** |
| **미입력** | 시간 초과로 **탈락** 처리한다 | 안전 확정되지 못하고 **다음 라운드에 남는다** |
| **탈락자가 없는 라운드** | 마지막으로 누른 사람을 최후 잔류로 탈락시킨다 | 그런 규칙이 없다. 안전 확정자가 0명일 때만 무효 라운드다 |
| **그룹핑** | 앵커 방식 — 그룹 최초 입력에서 판정창 이내를 같은 그룹으로 묶는다 | 고립 판정 — 앞뒤 간격이 둘 다 판정창을 넘어야 안전 확정. 연결 성분은 표시에만 쓴다 |
| **1명 잔류** | 자동 확정하지 않고 라운드를 한 번 더 연다 | 즉시 최후 1인으로 확정한다 |
| **생존자 0** | 전원 탈락 모달을 띄운다 | 가장 늦게 누른 안전 확정자가 최후 1인이다 |
| **라운드 제한 시간** | 15초 고정 상수다 | 방장 설정값 10·15·20초를 따른다 |
| **판정 시각** | 클라이언트 타이머로 잰 상대 시각을 쓴다 | 서버 도착 시각을 쓴다 |

**승패 구조가 뒤집히면 게임 자체가 성립하지 않는다.** 겹치면 탈락하는 구조에서는 아무도 누르지 않는 것이 우세 전략이고, 실제로 프로토타입은 그 상황을 "탈락자가 없으면 마지막 입력자를 탈락"이라는 규칙으로 임시로 막고 있다. 정본 구조에서는 겹치는 것이 손해이므로 누르려는 압력이 자연히 생긴다.

## 인수 기준 후보

번호는 붙이지 않는다. 채번 정본은 [../03_requirements/10_acceptance_criteria.md](../03_requirements/10_acceptance_criteria.md)다.

- 판정창 0.3초·생존자 5명에서 입력이 2.10 · 5.40 · 7.00 · 7.12초로 도착하고 1명이 미입력이면 → 2.10과 5.40이 안전 확정, 7.00과 7.12가 동시 입력, 미입력자가 남아 다음 라운드 생존자가 3명이 된다.
- 판정창 0.3초에서 A가 2.00 · B가 2.20 · C가 2.40초에 누르면 → 셋 다 동시 입력으로 판정되고 안전 확정자가 0명이라 무효 라운드가 된다.
- 판정창 0.5초에서 두 입력의 간격이 정확히 0.500초면 → 둘 다 동시 입력이다.
- 판정창 0.5초에서 두 입력의 간격이 0.501초면 → 앞뒤에 다른 입력이 없는 한 둘 다 안전 확정이다.
- 혼자 누른 참가자는 → 그 라운드 이후 UP 버튼이 비활성이 되고 다음 라운드 화면에 나타나지 않는다.
- 안전 확정된 참가자가 UP을 다시 보내면 → 서버가 버리고 어떤 판정도 바뀌지 않는다.
- 같은 라운드에서 한 참가자가 UP을 두 번 보내면 → 최초 1회만 접수되고 두 번째는 버려진다.
- 생존자 3명 중 2명이 안전 확정되면 → 남은 1명이 즉시 최후 1인으로 확정되고 추가 라운드가 열리지 않는다.
- 생존자 3명이 각자 판정창 밖 간격으로 누르면 → 셋 다 안전 확정되고 그중 가장 늦게 누른 사람이 최후 1인이 된다.
- 생존자 전원이 제한 시간까지 누르지 않으면 → 무효 라운드가 되고 방장에게 다시 시작·대기방으로 선택이 표시되며 참가자 화면에서는 두 버튼이 비활성이다.
- 방장이 무효 라운드에서 다시 시작을 고르면 → 같은 생존자로 라운드가 다시 열리고 3초 가이드는 표시되지 않는다.
- 라운드 제한 시간을 20초로 설정하면 → 매 라운드의 남은 시간 표시가 20초에서 시작한다.
- 게임 도중 이탈한 참가자는 → 매 라운드 미입력으로 남고 마지막까지 남으면 최후 1인이 되어 결과 화면에 이탈 표시와 함께 표시된다.
- 게임이 끝나면 → 라운드별로 전원의 판정(안전 확정·동시 입력·미입력·최후 1인)과 서버 기준 입력 시각, 동시 입력 그룹이 표로 보인다.
- 같은 입력 시각 집합으로 판정을 다시 실행하면 → 안전 확정자·잔류자·표시 그룹이 모두 같다.
- 라운드 마감 시각 이후에 도착한 UP은 → 버려지고 그 참가자는 미입력으로 집계된다.
