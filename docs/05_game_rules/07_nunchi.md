# 눈치게임

> **대상**: 누르면 빠지는 서바이벌 구조의 상태 머신·혼자와 겹침의 판정 알고리즘·무효 라운드·최후 1인 확정·종료 증명·경계값
> **작성일**: 2026-08-02
> **개정일**: 2026-08-12 — 승패 구조를 **누르면 빠진다**로 뒤집는다(D-38 개정). 라운드를 끊는 트리거에 겹침과 생존자 한 명 남음을 더하고, 판정값을 ALONE·OVERLAP·NO_INPUT·LAST로, 라운드 명단을 넷으로 가른다. 종전 문서가 인용하던 D-34·D-35는 저격의 결정이므로 D-38·D-39로 바로잡는다
> **원천**: backend/app/domain/games/nunchi.py · backend/app/services/games/nunchi.py(구현 정본) · docs_legacy/requirements.md §2(용어: 판정창·무효 라운드) · §3.5.6 · §4.4 US-461~464 · §6 D-38·D-39 · [01_common.md](./01_common.md)

**누르면 빠지는 구조다**(D-38). 그 라운드에 UP을 누른 사람은 혼자였든 겹쳤든 후보에서 빠지고, 끝까지 누르지 못한 사람만 다음 라운드로 간다. 마지막까지 누르지 못한 한 명이 뽑힌다.

**겹치는 순간 라운드가 끝난다.** 아직 누르지 못한 사람들은 기회를 잃고 다음 라운드로 밀린다. 이 성질이 이 게임의 긴장을 만든다 — 늦으면 남는다.

## 게임 개요

| 항목 | 값 |
|------|-----|
| 결정 대상 | 사람 1인 |
| 인원 | 3~10명 |
| 입력 주체 | 전원(라운드마다 UP 1회) |
| 판정 주체 | 참가자 타이밍 |
| 목표 소요 | 90초 |
| 결과 화면 형태 | 기록형 |
| 방장 설정 | 주제 · 판정창(0.3·0.5초) · 라운드 제한 시간(10·15·20초) 3항 |

1. 라운드가 시작되면 제한 시간이 흐른다.
2. 각자 원하는 순간 UP을 **한 번** 누른다. 취소할 수 없다.
3. **누른 사람은 후보에서 빠진다.** 혼자 눌렀든 판정창 안에 겹쳐 눌렀든 결과는 같다.
4. **끝까지 누르지 못한 사람만 남는다.** 남은 사람들끼리 다음 라운드를 한다.
5. 생존자가 한 명이 되면 그 사람이 뽑힌다.

- 판정 기준은 **서버 도착 시각**이다(G-8). 시간초 잡기의 예외는 이 게임에 적용하지 않는다.
- 라운드마다 한 번만 누를 수 있고, 이미 빠진 사람과 재입력은 무시한다(G-9).
- 라운드가 길어질수록 배경이 붉게 점멸하고 텍스트가 흔들려 압박을 준다. **연출은 판정에 영향을 주지 않는다.**
- 최소 인원이 3인 이유는 2명이면 한 명이 누르는 순간 라운드가 끊겨 남은 한 명이 곧바로 뽑히므로 심리전이 성립하지 않기 때문이다.

## 라운드를 끊는 트리거 3종

라운드는 아래 셋 중 먼저 오는 것에서 끝난다. **어느 경로로 끝나든 판정 규칙은 같다.**

| 트리거 | 조건 | 왜 여기서 끊는가 |
|--------|------|-----------------|
| **겹침** | 직전에 접수한 입력과의 간격이 판정창 **이하** | 겹친 순간 라운드를 끝내야 아직 누르지 못한 사람들이 기회를 잃는다. 이 손실이 곧 늦게 누르는 것의 대가다 |
| **생존자 한 명 남음** | 접수한 입력 수가 생존자 수 − 1에 닿음 | 마지막 한 명에게 누를 기회를 주면, 안 누르면 뽑히는 처지라 눌러서 **생존자 0으로 판을 무르는 것**이 언제나 이득이 된다. 기회를 주지 않는 것으로 그 탈출구를 막는다 |
| **제한 시간 마감** | 방장 설정값(10·15·20초) 경과 | 아무도 누르지 않아도 라운드가 끝난다 |

## 혼자와 겹침의 판정

### 무엇을 판정하는가

**혼자와 겹침은 결과가 같다** — 둘 다 그 라운드에 빠진다. 나뉘어 있는 이유는 결과 화면이 "혼자 눌러 빠졌다"와 "겹쳐서 빠졌다"를 다르게 보여야 하기 때문이다.

판정은 각 입력에 대해 하나만 묻는다 — **내 입력 시각의 앞뒤 판정창 안에 다른 입력이 있는가.**

```
참가자 p의 입력 시각을 t(p)라 하고 판정창을 W라 할 때
p가 혼자로 판정될 조건:  인접한 어떤 입력 q에 대해서도  |t(p) − t(q)| > W
```

정렬한 배열에서는 **바로 앞·바로 뒤 입력과의 간격만** 보면 된다. 정렬된 배열에서 인접하지 않은 입력과의 간격은 인접 간격보다 항상 크기 때문이다.

**비교는 이하(≤)가 겹침이다.** 간격이 정확히 판정창이면 겹친 것이다.

### 겹침 집단은 한 라운드에 하나뿐이다

겹침이 라운드를 끊으므로 정상 경로에서 겹침 집단은 마지막 두 입력 하나뿐이다. 그럼에도 판정 함수는 **일반형으로 둔다** — 마감 경로와 조기 종료 경로가 같은 규칙을 타야 두 경로의 결과가 갈라지지 않는다.

## 라운드 결과의 네 갈래

라운드가 끝나면 안전 확정자 집합(누른 사람)과 잔류자 집합(못 누른 사람)이 정해진다. 다음 동작은 두 집합의 크기로만 결정된다.

| 조건 | 다음 동작 | 근거 |
|------|----------|------|
| 안전 확정자 0 | **무효 라운드** — 방장이 다시 시작·대기방으로를 고른다 | 아무도 누르지 않아 생존자 수가 줄지 않았다. 자동으로 다음 라운드를 열면 같은 상태가 반복된다(D-39) |
| 생존자 0 | **무효 라운드** — 위와 같다 | 전원이 눌러 뽑을 사람이 남지 않았다. 정상 경로로는 오지 않으며(생존자 한 명 남음에서 끊긴다) 그 불변식이 깨졌을 때를 위한 방어다 |
| 생존자 1 | **종료** — 끝까지 누르지 못한 그 한 명이 뽑힌다 | 규칙이 정의하는 정상 종료다 |
| 생존자 2 이상 | **다음 라운드** — 생존자를 못 누른 사람들로 줄인다 | 안전 확정자가 최소 1명이므로 생존자 수가 줄어 진전이 있다 |

**안전 확정자 0을 무효로 돌리는 것이 안 누르기를 막는 자리다.** 미입력을 후보 제외로 쳐 주면 전원이 가만히 있는 것이 우세 전략이 되어 게임이 성립하지 않는다.

**동점 개념이 없다.** 서버 도착 시각이 정확히 같은 밀리초라도 간격이 0이라 판정창 안이므로 둘 다 겹침이며, 어느 쪽이든 빠진다.

## 무효 라운드

**정의** — 생존자 수가 줄지 않았거나(안전 확정자 0) 뽑을 사람이 남지 않은(생존자 0) 라운드다.

| 사유 | 조건 | 안내 문구의 뜻 |
|------|------|--------------|
| 전원 미입력 | 생존자 중 아무도 누르지 않았다 | 아무도 누르지 않았다 |
| 전원 입력 | 생존자 전원이 눌러 아무도 남지 않았다 | 모두가 눌러 뽑을 사람이 없다 |

**처리는 둘 다 같다**(D-39). 방장에게 두 선택을 준다.

| 선택 | 동작 |
|------|------|
| 다시 시작 | 같은 생존자로 라운드를 다시 연다. 가이드는 띄우지 않는다(G-4) |
| 대기방으로 | 결과 없이 끝내고 전원이 대기방으로 돌아간다 |

참가자는 두 버튼이 비활성인 채 방장의 선택을 기다린다. **무효 라운드에는 횟수 상한을 두지 않는다** — 매 무효 라운드마다 방장이 직접 눌러야 진행되므로 자동 반복이 아니고, 종료 증명이 그 성질에 기댄다.

## 상태 머신

```
[GUIDE] ──3초──▶ [ROUND]

[ROUND] ──겹침 / 생존자 한 명 남음 / 라운드 마감──▶ 판정 ──▶ [ROUND_RESULT] ──3초──▶ 분기

분기 (안전 확정 = 누른 사람 · 잔류 = 못 누른 사람)
   ├─ 안전 확정 0 또는 잔류 0 ──▶ [VOID_ROUND]
   │                                ├─ 방장 선택: 다시 시작   ──▶ [ROUND] (같은 생존자)
   │                                └─ 방장 선택: 대기방으로 ──▶ [VOID]
   ├─ 생존 1                 ──▶ [REVEAL] ──3초──▶ [RESULT]   (그 한 명이 최후 1인)
   └─ 생존 2 이상            ──▶ [ROUND] (생존자를 못 누른 사람들로 줄인다)

어느 상태에서든 방장 이탈 ──▶ [ABORTED]
```

- **ROUND** — 입력을 받는다. 생존자 집합과 라운드 번호를 갖는다. 제한 시간은 방장 설정값이다.
- **ROUND_RESULT** — 그 라운드의 판정(혼자·겹침·미입력)을 3초간 공개한다. 서버 기준 입력 시각을 함께 보여준다.
- **VOID_ROUND** — 무효 라운드 모달. 타이머가 없고 방장 선택만 받는다.
- **REVEAL** — 최후 1인을 공개하고 3초 뒤 결과 화면으로 넘어간다(G-11).
- **VOID** — 방장이 대기방으로를 골라 결과 없이 끝난 상태.

|---------------|----------------|--------|-------------------|----------|-----------------|----------------|--------------|---------------------|------------|----------|
| **GUIDE** | → ROUND | 버린다(가드: 라운드 전) | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 스냅샷 유지·상태 불변 | → ABORTED |
| **ROUND** | 해당 없음 | 생존자면 접수(라운드당 최초 1회)·빠진 사람과 재입력은 버린다 | 판정 실행 | 판정 실행 | 판정 실행 | → ROUND_RESULT | 해당 없음 | 버린다 | 미입력으로 확정·상태 불변 | → ABORTED |

| **VOID_ROUND** | 해당 없음 | 버린다 | 미기동(자동 진행 없음) | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 다시 시작 → ROUND · 대기방으로 → VOID | 스냅샷 유지·상태 불변 | → ABORTED |
| **REVEAL** | 해당 없음 | 버린다(판 종료) | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | → RESULT | 버린다 | 스냅샷 유지·결과 불변 | → ABORTED |
| **RESULT** | 해당 없음 | 버린다 | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 스냅샷 유지·결과 불변 | → ABORTED |
| **VOID** | 해당 없음 | 버린다 | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 상태 불변 | → ABORTED |
| **ABORTED** | 해당 없음 | 버린다 | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 상태 불변 | 상태 불변 |

- 다시 시작으로 ROUND에 재진입하면 라운드 번호를 1 올리고 입력 기록을 비운다. 생존자 집합은 그대로다.
- **원점이 어디든 판정은 같다.** 혼자와 겹침의 구분은 입력 사이의 간격만 보므로 도착 시각의 원점이 무엇이든 결과가 바뀌지 않는다. 다만 저장하는 표시값은 라운드 시작을 원점으로 한다.

## 판정 알고리즘

```
입력:
  survivors[0..m-1]   # 이 라운드의 생존자. 명단 스냅샷의 부분집합
  presses             # 참가자 → 서버 도착 시각(라운드 시작 기준 상대 정수 밀리초)
                      #   라운드가 끊기기 전에 도착한 최초 1회만 담긴다
  windowMs            # 판정창. 300 또는 500
출력:
  { alone, overlapped, eliminated, surviving, verdicts, ordered }

judgeNunchiRound(survivors, presses, windowMs):
  # ── 1) 입력을 시각 오름차순으로 정렬 ─────────────────────────────
  pressed = [ (p, presses[p]) for p in survivors if p in presses ]
  ordered = sort(pressed, by (t, snapshotIndex(p)))      # 같은 밀리초면 스냅샷 순
  k = length(ordered)

  # ── 2) 혼자와 겹침을 가른다. 둘 다 안전 확정이며 표시만 다르다 ──────────
  alone = []; overlapped = []
  for i from 0 to k-1:
      prevGap = (i == 0)     ? INFINITY : ordered[i].t − ordered[i-1].t
      nextGap = (i == k - 1) ? INFINITY : ordered[i+1].t − ordered[i].t
      if prevGap > windowMs and nextGap > windowMs:
          alone.append(ordered[i].p);       verdicts[ordered[i].p] = ALONE
      else:
          overlapped.append(ordered[i].p);  verdicts[ordered[i].p] = OVERLAP

  # ── 3) 누른 사람은 전부 빠지고, 못 누른 사람만 남는다 ──────────────
  eliminated = alone + overlapped
  surviving = []
  for p in survivors where p not in presses:
      surviving.append(p);  verdicts[p] = NO_INPUT

  return { alone, overlapped, eliminated, surviving, verdicts, ordered }

# ── 라운드 결과에 따른 다음 동작 ────────────────────────────────
nextStep(eliminated, surviving):
  if length(eliminated) == 0:  return { kind: "무효 라운드" }   # 아무도 안 눌렀다
  if length(surviving) == 0:   return { kind: "무효 라운드" }   # 전원이 눌렀다
  if length(surviving) == 1:   return { kind: "종료", loserId: surviving[0] }
  return { kind: "다음 라운드", survivors: surviving }
```

- **결정성** — 입력은 정수 밀리초 배열과 판정창 하나뿐이다. 정렬 키에 스냅샷 인덱스를 넣어 같은 밀리초의 순서까지 고정하므로, 같은 입력이면 결과가 언제나 같다.
- **복잡도는 정렬이 지배한다.** m ≤ 10이므로 라운드 판정은 상수 시간에 가깝고 DB를 거치지 않는다. 입력 도착 시각·생존자 명단은 서버 인메모리에 둔다(전역 불변식의 상태 경계).
- 빠진 사람은 다음 라운드의 생존자에 들어가지 않으므로 그 이후 입력은 전부 버려진다.

### 라운드 기록의 모양

진행 중 판정 공개와 최종 결과가 **같은 모양**을 쓴다. 결과 화면이 라운드별 판정을 진행 화면과 같은 코드로 그릴 수 있게 하기 위해서다.

| 필드 | 내용 |
|------|------|
| roundNo | 라운드 번호. 1부터 센다 |
| presses | 참가자별 memberId · offsetMs · verdict. 미입력자는 offsetMs가 null이다 |
| aloneMemberIds | 혼자 눌러 빠진 사람 |
| overlappedMemberIds | 겹쳐 눌러 빠진 사람 |
| eliminatedMemberIds | 그 라운드에 빠진 사람 전체 |
| survivingMemberIds | 못 눌러 다음 라운드로 가는 사람 |

판정값은 **ALONE · OVERLAP · NO_INPUT · LAST** 넷이며, 최후 1인이 정해지는 라운드에서만 그 사람의 값이 LAST로 덮인다.

### 코드 이름과 문서 용어의 대응

**주의해서 읽어야 하는 자리다.** 구현의 eliminated는 후보에서 **빠진** 사람이고 이 게임에서 그것은 유리한 결과다. 문서는 [../10_glossary/01_domain_terms.md](../10_glossary/01_domain_terms.md)의 용어를 쓴다.

| 코드 | 문서 용어 | 뜻 |
|------|----------|-----|
| aloneMemberIds | 혼자 눌러 안전 확정 | 앞뒤 간격이 둘 다 판정창을 넘었다 |
| overlappedMemberIds | 겹쳐 눌러 안전 확정 | 인접 간격이 판정창 이하다 |
| eliminatedMemberIds | **안전 확정자** | 그 라운드에 누른 사람 전체. 후보에서 빠진다 |
| survivingMemberIds | **잔류자** | 못 누른 사람. 다음 라운드로 간다 |

**용어 사전이 빠지는 쪽을 안전 확정, 남는 쪽을 잔류로만 쓰게 한 이유가 여기 있다** — 빠지는 것이 유리하고 남는 것이 불리해 일상어로 부르면 뜻이 뒤집혀 읽힌다.

## 종료 증명

**주장** — 방장이 개입하지 않는 구간에서 이 게임은 유한 라운드 안에 최후 1인을 확정한다. 자동으로 무한히 도는 구간이 없다.

**논증** — 라운드 결과가 네 갈래뿐이고 그중 자동으로 다음 라운드를 여는 갈래는 하나이며, 그 갈래는 생존자 수를 반드시 줄인다.

1. **각 라운드는 반드시 끝난다.** 마감 타이머가 방장 설정값(10·15·20초)으로 고정되어 있고, 겹침이나 생존자 한 명 남음이 오면 그보다 일찍 끊긴다. 끝나는 시점에 모든 생존자의 상태는 ALONE·OVERLAP·NO_INPUT 셋 중 하나로 확정된다.
2. **자동 진행 갈래는 생존자 수를 엄격히 줄인다.** 다음 라운드로 가는 조건은 안전 확정자 ≥ 1이므로 생존자 수가 최소 1 감소한다. 감소는 되돌려지지 않는다.
3. **감소는 유한하다.** 초기 생존자 수를 m₀(3~10)이라 하면 자동 진행 갈래는 최대 m₀ − 2회 일어난다. 그 뒤에는 생존자가 1명이 되어 종료 갈래로 들어간다. 자동 라운드 총수는 **최대 m₀ − 1**이다.
4. **무효 라운드는 자동 진행이 아니다.** 안전 확정자 0이나 잔류자 0이면 서버가 멈추고 방장 입력을 기다린다. 방장이 다시 시작을 누르는 것은 사람의 행위이므로 서버의 상태 기계는 언제나 유한 단계 안에 정지한다.

**자동 진행 시간의 상한** — m₀ = 10 · 라운드 제한 시간 20초일 때 라운드당 최대 20초 + 판정 공개 3초 = 23초이고, 라운드는 최대 9회다. 가이드 3초와 최종 공개 3초를 더해 **213초**가 상한이다. 실제로는 겹침과 생존자 한 명 남음이 라운드를 일찍 끊으므로 이보다 훨씬 짧다.

### 반례 후보 검토

| 반례 후보 | 구체 조합 | 결과 |
|----------|----------|------|
| **동점** | 두 입력의 서버 도착 시각이 같은 밀리초 | 간격이 0이라 판정창 안이므로 둘 다 겹침이고 둘 다 빠진다. 동점이라는 상태가 정의되지 않으므로 동점 처리 규칙도 없다 |
| **전원 미입력** | 생존자 4명이 제한 시간까지 아무도 누르지 않음 | 안전 확정자 0 → 무효 라운드. 방장이 고른다 |
| **전원 입력** | 생존자 전원이 눌러 아무도 남지 않음 | 생존자 0 → 무효 라운드. 정상 경로로는 오지 않는다 — 생존자가 한 명 남는 순간 라운드가 끊기기 때문이다 |
| **마지막 한 명이 판을 무르려 함** | 생존자 2명 중 1명이 누른 순간 | 그 순간 라운드가 끊겨 남은 한 명은 누를 기회를 얻지 못하고 뽑힌다. 눌러서 생존자 0을 만드는 탈출구가 막힌다 |
| **전원 고립** | 생존자 3명이 각자 충분히 떨어져 누름 | 두 번째 입력이 도착하는 순간 생존자가 한 명 남으므로 라운드가 끊긴다. 못 누른 그 한 명이 뽑힌다 |
| 생존자 2명이 매번 겹침 | 둘이 계속 판정창 안에 누름 | 생존자 0이라 매번 무효 라운드다. 자동 반복이 아니라 방장이 매번 다시 시작을 눌러야 하며, 서버는 그 사이 정지해 있다 |
| 이탈자만 남음 | 생존자 3명 중 2명이 누르고 남은 1명이 이미 이탈 | 그 이탈자가 최후 1인이다. 결과 화면에 이탈 표시와 함께 표시된다 |
| 빠진 사람이 다시 누름 | 안전 확정 후 UP 재전송 | 버린다. 상태가 바뀌지 않는다(G-9) |

## 경계값 표

| 경계 | 동작 |
|------|------|
| **최소 인원 3** | 정상 진행한다. 두 명이 누르는 순간 라운드가 끊기고 남은 한 명이 뽑힌다 |
| **최대 인원 10** | 정상 진행한다. 자동 라운드는 최대 9회이며 라운드마다 생존자 수가 화면에 표시된다 |
| **전원 미입력** | 안전 확정자 0이므로 무효 라운드. 방장이 다시 시작·대기방으로를 고른다 |
| **전원 동시 입력** | 첫 겹침에서 라운드가 끊긴다. 그 시점까지 누른 사람만 빠지고 나머지는 남는다 |
| **1명 잔류** | 즉시 최후 1인으로 확정한다. 라운드를 한 번 더 열지 않는다 |
| **도중 이탈로 유효 인원이 최소 미만** | 접속자가 0명이 되어도 라운드가 끝날 때까지 기다린 뒤 판정한다. 이탈자는 매 라운드 미입력으로 남으므로 결국 최후 1인이 되며, 그때 게임이 끝난다. 방장 이탈이면 ABORTED |
| 판정창 0.5초에서 0.5초 정확히 차이 나는 두 입력 | 간격이 판정창을 **넘지 않으므로** 둘 다 겹침이다. 비교는 이하(≤)가 겹침이다 |
| 라운드가 끊긴 뒤 1밀리초 뒤에 도착한 UP | 버린다. 그 참가자는 미입력이며 다음 라운드로 간다 |

## 우세 전략과 그 한계

**정직하게 적는다.** 누르면 빠지는 구조에서 **먼저 누르는 것이 언제나 안전하다** — 혼자여도 겹쳐도 빠지므로 겹칠 위험을 감수할 이유가 없다. 그래서 이 게임은 타이밍 심리전이 아니라 **반응 속도와 결단의 게임**에 가깝다.

| 전략 | 막혔는가 | 어떻게 |
|------|---------|--------|
| 안 누르기 | **막혔다** | 미입력은 후보에서 빠지지 않는다. 안전 확정자 0인 라운드는 무효라 생존자가 줄지 않으므로 버티기가 이득이 되지 않는다 |
| 판 무르기 | **막혔다** | 생존자가 한 명 남는 순간 라운드가 끊겨 마지막 한 명은 누를 기회를 얻지 못한다 |
| 먼저 누르기 | **막지 않는다** | 이 구조에서 우세 전략이며 규칙으로 없앨 수 없다. 겹침에 벌칙을 붙이면 일부러 겹치는 것이 이득이 되어 다른 붕괴가 생긴다([../11_fairness/03_anti_cheat.md](../11_fairness/03_anti_cheat.md)) |

**늦게 누르는 것의 대가가 라운드 종료로 구현된다.** 겹침이 라운드를 끊으므로, 남들이 이미 누른 뒤에 누르려던 사람은 기회를 잃고 다음 라운드로 밀린다. 판정창은 그 대가가 발생하는 폭을 정한다 — 넓을수록 라운드가 일찍 끊겨 늦은 사람이 더 자주 남는다.

## 구현 대조

**backend/app/domain/games/nunchi.py와 backend/app/services/games/nunchi.py가 구현 정본이다.** 본 문서는 그 구현을 서술한다.

| 지점 | 종전 문서(폐기) | 현행 |
|------|---------------|------|
| **승패 구조** | 혼자 누르면 안전 확정되어 빠지고 겹친 사람이 남는다 | **누르면 빠진다.** 혼자든 겹쳤든 같다 |
| **미입력** | 남는다 | 남는다(변화 없음) |
| **라운드 종료** | 마감 · 생존자 전원 입력 | 마감 · **겹침** · **생존자 한 명 남음** |
| **판정값** | 안전 확정 · 동시 입력 · 미입력 · 최후 1인 | ALONE · OVERLAP · NO_INPUT · LAST |
| **라운드 명단** | safeMemberIds · remainingMemberIds | aloneMemberIds · overlappedMemberIds · eliminatedMemberIds · survivingMemberIds |
| **무효 라운드** | 안전 확정자 0 | 안전 확정자 0 **또는 생존자 0** |
| **생존자 0** | 가장 늦게 누른 안전 확정자가 최후 1인 | 무효 라운드. 정상 경로로는 오지 않는다 |

**frontend/src/screens/Game/games/NunchiGame.tsx는 아직 종전 규칙을 읽는다.** 안전 확정자 명단과 SAFE 판정값을 참조하므로 지금 붙이면 화면이 깨진다. 프론트 연동에서 함께 고친다.

## 인수 기준 후보

번호는 붙이지 않는다. 채번 정본은 [../03_requirements/10_acceptance_criteria.md](../03_requirements/10_acceptance_criteria.md)다.

- 판정창 0.3초·생존자 5명에서 두 사람이 0.2초 간격으로 누르면 → 그 순간 라운드가 끊기고 둘 다 겹침으로 빠지며 나머지 3명이 다음 라운드로 간다.
- 생존자 3명에서 두 사람이 충분히 떨어져 누르면 → 두 번째 입력에서 라운드가 끊기고 못 누른 한 명이 최후 1인이 된다.
- 판정창 0.5초에서 두 입력의 간격이 정확히 0.500초면 → 둘 다 겹침이다.
- 판정창 0.5초에서 두 입력의 간격이 0.501초면 → 앞뒤에 다른 입력이 없는 한 둘 다 혼자다. 결과는 같게 빠진다.
- 누른 참가자는 → 그 라운드 이후 UP 버튼이 비활성이 되고 다음 라운드 화면에 나타나지 않는다.
- 이미 빠진 참가자가 UP을 다시 보내면 → 서버가 버리고 어떤 판정도 바뀌지 않는다.
- 같은 라운드에서 한 참가자가 UP을 두 번 보내면 → 최초 1회만 접수되고 두 번째는 버려진다.
- 생존자 전원이 제한 시간까지 누르지 않으면 → 안전 확정자 0이라 무효 라운드가 되고 방장에게 다시 시작·대기방으로 선택이 표시되며 참가자 화면에서는 두 버튼이 비활성이다.
- 방장이 무효 라운드에서 다시 시작을 고르면 → 같은 생존자로 라운드가 다시 열리고 3초 가이드는 표시되지 않는다.
- 라운드 제한 시간을 20초로 설정하면 → 매 라운드의 남은 시간 표시가 20초에서 시작한다.
- 게임 도중 이탈한 참가자는 → 매 라운드 미입력으로 남고 마지막까지 남으면 최후 1인이 되어 결과 화면에 이탈 표시와 함께 표시된다.
- 게임이 끝나면 → 라운드별로 전원의 판정(혼자·겹침·미입력·최후 1인)과 서버 기준 입력 시각이 표로 보인다.
- 같은 입력 시각 집합으로 판정을 다시 실행하면 → 혼자·겹침·안전 확정·잔류 네 명단이 모두 같다.
- 라운드가 끊긴 뒤에 도착한 UP은 → 버려지고 그 참가자는 미입력으로 집계된다.
