본 폴더는 "누가 이기는가"의 단일 출처다. 화면 연출·통신 규약이 아니라 **판정 규칙**을 확정하며, 여기서 정해진 값이 다른 폴더의 기능·요구사항·API·테이블이 참조하는 원본이다. 각 게임 문서는 산문 규칙만으로 끝내지 않고 **상태 머신 · 판정 알고리즘 · 종료 증명 · 경계값 표 · 인수 기준 후보** 다섯을 전부 담는다. 하나라도 비면 구현자가 임의로 메우게 되고 그것이 결함이 된다.

## 스펙 시트

6종을 같은 축으로 비교한다. 값의 정본은 각 게임 문서이며 본 표는 개괄이다.

| 항목 | 운명의 룰렛 | 사다리타기 | 킹메이커 | 시간초 잡기 | 익명 저격 | 눈치게임 |
|------|------------|-----------|---------|------------|----------|---------|
| **판정 주체** | 서버 난수 | 서버 난수 | 참가자 투표 | 참가자 감각 | 참가자 투표 | 참가자 타이밍 |
| **결정 대상** | 사람 1인 | 전원 역할 | 안건 1개 | 사람 1인 | 사람 1인 | 사람 1인 |
| **인원** | 2~10 | 2~10 | 3~10 | 2~10 | 3~10 | 3~10 |
| **목표 소요** | 20초 | 40초 | 3분 30초 | 30초 | 30초 | 90초 |
| **입력 주체** | 방장만 | 방장만 | 전원 | 전원 | 전원 | 전원 |
| **동점 처리** | 발생하지 않음 | 발생하지 않음 | 결선 투표 최대 3회 | 동점자 재대결 최대 3회 | 결선 투표 최대 3회 | 발생하지 않음 |
| **미입력 처리** | 방장 미조작 시 30초 뒤 서버 자동 실행 | 방장 미조작 시 30초 뒤 서버 자동 실행 | 기권(0표) | 미시작·미정지로 구분해 최하위군 | 기권(0표) | 남아서 다음 라운드 |
| **방장 설정 수** | 1 | 2 | 3 | 3 | 4 | 3 |
| **결과 화면 형태** | 승자형 | 배정형 | 개표형 | 승자형 | 승자형 | 기록형 |

- **인원**은 명단 스냅샷 시점의 참가자 수다. 게임 시작 후 이탈해도 스냅샷 인원은 줄지 않는다.
- **목표 소요**는 설계 목표이지 강제 상한이 아니다. 각 게임의 실제 상한은 게임 문서의 종료 증명이 확정한다.
- **미입력 처리**의 "방장 미조작"은 룰렛·사다리가 참가자 입력을 받지 않는 게임이라 생기는 경우다. 원천에는 정의가 없어 본 문서군이 정했다.
- 게임 구성은 **서버 난수 2 · 참가자 투표 2 · 참가자 실력 2**이며 이 분류는 문서상 구분이다. **화면에는 표시하지 않는다**(D-21).

## 공통 기준 요약

전 게임이 어길 수 없는 기준이다. 전문은 [01_common.md](./01_common.md), 전역 불변식의 정본은 [../README.md](../README.md)다.

| 기준 | 내용 |
|------|------|
| 서버 판정 | 결과는 서버가 확정한다. 클라이언트는 이미 정해진 결과로 수렴하는 연출을 그린다 |
| 판정 기준 시각 | 시간·순서 판정은 **서버 도착 시각**이다. **유일한 예외는 시간초 잡기의 경과 시간**이며 서버가 허용 범위를 검증한다 |
| 명단 스냅샷 | 게임이 시작되면 참가자 명단이 고정된다. 도중 이탈해도 후보에 남고 결과에 표시된다 |
| 미입력 | 게임별 기본값으로 자동 처리한다. 한 명 때문에 판이 멈추지 않는다 |
| 멱등 | 같은 입력은 최초 1회만 인정하고, 끝난 판·지난 라운드의 입력은 버린다 |
| 중간 집계 | 진행 중에는 아무에게도 보여주지 않는다. 완료·대기 상태만 보인다 |
| 반복 상한 | 동점 결선·동점자 재대결·무효 라운드는 자동으로 무한히 반복하지 않는다. 상한은 **3회**이며 초과하면 방장이 고른다 |
| 방장 이탈 | 방이 즉시 삭제되고 진행 중이던 판은 결과 없이 끝난다. 게임이 멈추는 경우는 이것뿐이다 |

## 게임 문서의 필수 요소

게임별 문서 6본은 모두 아래 H2를 **이 순서로** 갖는다. 형식이 같아야 빠진 것을 셀 수 있다. 게임 고유 규칙을 따로 세워야 하는 경우(킹메이커의 실효 투표 수 · 시간초의 경과 시간 검증 · 저격의 중복 투표 상한 · 눈치의 고립 판정)에는 **게임 개요와 상태 머신 사이에** 절을 추가한다.

| 순서 | H2 | 확인 기준 |
|:----:|----|----------|
| 1 | 게임 개요 | 결정 대상 · 인원 · 입력 주체 · 방장 설정 |
| 2 | 상태 머신 | phase 전이도(펜스 블록) + (상태 × 이벤트) 표. **모든 칸이 채워져 있다** |
| 3 | 판정 알고리즘 | 의사코드(펜스 블록). 입력에서 출력이 결정적으로 도출된다 |
| 4 | 종료 증명 | 동점 · 전원 미입력 · 전원 동시 입력을 반례 후보로 검토했다 |
| 5 | 경계값 표 | 최소 인원 · 10명 · 전원 미입력 · 전원 동시 입력 · 1명 잔류 · 도중 이탈 |
| 6 | 구현 대조 | frontend/src/games/의 프로토타입이 본 문서와 어긋나는 지점 |
| 7 | 인수 기준 후보 | 입력 → 기대 출력. **번호는 붙이지 않는다**(채번 정본은 03_requirements) |

**AC-NN · REQ-NN · F-ID는 본 폴더에서 채번하지 않는다.** 게임 규칙은 판정의 정의이고, 그것을 사용자가 조작하는 표면에 붙는 식별자는 [../02_features/README.md](../02_features/README.md) · [../03_requirements/README.md](../03_requirements/README.md)가 소유한다.
