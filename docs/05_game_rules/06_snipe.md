# 익명 저격

> **대상**: 익명 지목으로 1인을 뽑는 게임의 상태 머신·중복 투표 상한·결선 규칙과 자기 지목 금지의 충돌 처리·개표 알고리즘·종료 증명·경계값
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §3.2 · §3.4 · §3.5.5 · §4.4 US-451~452 · §6 D-23·D-27·D-28·D-29·D-30 · git 529e312 docs/games.md §6 · git ecceb11 docs/05_game_rules/05_snipe.md · frontend/src/games/Sniper.tsx(프로토타입 실측) · [01_common.md](./01_common.md)

질문 하나에 대해 서로를 익명으로 지목하는 게임이다. 규칙의 어려운 지점은 셋이다 — **중복 투표를 켰을 때 몇 명까지 지목할 수 있는가**, **결선에서 자기가 후보로 남았을 때 자기 지목 금지를 어떻게 적용하는가**, **아무도 지목하지 않았을 때 무엇을 결과로 내는가**. 원천 문서가 답하지 않은 이 셋을 본 문서가 확정한다.

## 게임 개요

| 항목 | 값 |
|------|-----|
| 결정 대상 | 사람 1인 |
| 인원 | 3~10명 |
| 입력 주체 | 전원(지목 1회) |
| 판정 주체 | 참가자 투표 |
| 목표 소요 | 30초 |
| 결과 화면 형태 | 승자형 |
| 방장 설정 | 주제(질문) · 투표 시간(5~60초, 기본 10초) · 중복 투표(불가·가능) 3항 |

1. 질문과 투표 시간이 공개된다.
2. 각자 후보 중에서 지목한다. **자기 자신은 후보 그리드에 나타나지 않고 지목할 수 없다**(D-27).
3. 가장 많이 지목된 사람이 뽑힌다.

- **후보는 명단 스냅샷 전원이다.** 도중 이탈자도 후보에 남고 뽑힐 수 있다. 각 참가자에게 보이는 후보 그리드에서 자기 자신만 빠진다.
- 지목하지 않으면 **기권**이다. 기권은 어떤 후보의 표도 늘리지 않는다.
- 최소 인원이 3인 이유는 2명이면 서로를 지목할 수밖에 없어 반드시 1:1 동점이 되고 지목이 익명이지 않기 때문이다.
- 투표가 진행되는 동안 중간 집계를 아무에게도 보여주지 않는다(G-10).

### 확정 조작

| 중복 투표 | 조작 | 확정 |
|-----------|------|------|
| 불가 | 후보 하나를 고른다 | 고르는 즉시 확정된다. 되돌릴 수 없다 |
| 가능 | 후보를 여럿 고른 뒤 발사를 누른다 | 발사를 누르면 확정된다. 그 전까지는 선택을 바꿀 수 있다 |

부분 지목을 허용한다. 상한까지 다 고르지 않아도 1명 이상이면 유효한 투표다. 0명으로 마감되면 기권이다.

## 중복 투표 상한

중복 투표를 켰을 때 한 사람이 지목할 수 있는 최대 인원은 다음과 같다.

```
후보 수      m = |명단 스냅샷| − 1        # 자기 자신을 뺀 수
지목 상한    Lmax = max(1, floor(m / 2))
```

| 방 인원 | 후보 수 m | 지목 상한 |
|:------:|:--------:|:--------:|
| 3 | 2 | 1 |
| 4 | 3 | 1 |
| 5 | 4 | 2 |
| 6 | 5 | 2 |
| 7 | 6 | 3 |
| 8 | 7 | 3 |
| 9 | 8 | 4 |
| 10 | 9 | 4 |

**근거는 표의 상쇄다.** 두 투표자의 지목 집합 A·B가 각각 후보의 절반을 넘으면(|A| > m/2 · |B| > m/2) 비둘기집 원리로 |A ∩ B| ≥ |A| + |B| − m > 0이 되어 반드시 겹친다. 지목 수가 후보의 절반을 넘는 순간 모든 투표자가 서로 겹치는 표를 던지게 되고 득표가 균등해져 변별력이 사라진다. 극단은 전원 지목이며, 그때는 모든 후보가 같은 표를 받아 어떤 정보도 남지 않는다. 절반 이하로 묶으면 서로 다른 선호가 표 차이로 드러난다.

- **방 인원이 5명 미만이면 중복 투표를 켜도 상한이 1이라 1인 1표와 같아진다.** 설정 화면에서 이 사실을 안내하되 설정 자체를 막지는 않는다 — 게임 도중 인원이 바뀌지 않으므로 시작 시점에 확정해 보여줄 수 있다.
- 상한을 넘긴 요청은 **전체를 거절**한다. 앞의 몇 개만 반영하지 않는다.
- 같은 후보를 여러 번 담은 요청도 거절한다. 한 후보에 표를 몰아줄 수 없다.

### 결선에서는 1명으로 고정한다

결선의 지목 상한은 중복 투표 설정과 무관하게 **1**이다.

**근거** — 결선 후보가 2명 남고 상한이 2면, 자기가 후보가 아닌 투표자는 두 후보를 모두 지목하게 되어 두 후보의 표가 같은 폭으로 늘어난다. 동점에서 시작한 결선이 **구조적으로 동점을 재생산한다.** 결선은 남은 후보 중 단일 선호를 묻는 단계이므로 다중 지목을 쓰지 않는다. 킹메이커의 결선 1표 고정과 같은 이유다.

## 결선과 자기 지목 금지

동점이면 **동점자만 후보로 남기고 명단 스냅샷 전원이 재투표한다**(US-452). 여기서 자기 지목 금지와 부딪치는 경우가 둘 생긴다.

| 상황 | 처리 | 근거 |
|------|------|------|
| 결선 후보에 자기가 남았다 | **자기 지목 금지를 그대로 적용한다.** 그 참가자의 후보 그리드에서 자기 카드만 빠지고 나머지 후보에만 지목할 수 있다 | 결선 후보는 동점 집합이므로 항상 2명 이상이고, 1인이 자기 자신인 경우는 최대 1명이다. 자기를 빼도 최소 1명이 남으므로 투표할 수 없는 참가자는 생기지 않는다 |
| 결선 후보에 자기만 있다(후보 1명) | **발생하지 않는다.** 방어적으로 서버가 이 상태를 만나면 즉시 그 후보로 확정한다 | 아래 논증 |

**후보 1명 결선이 발생하지 않는 논증** — 결선 후보 집합은 개표 결과의 최다 득표 동점 집합이며, 동점이라는 조건 자체가 원소 2개 이상을 뜻한다. 원소가 1개면 단독 최다이므로 결선을 열지 않고 확정한다. 유효표가 0이면 모든 후보가 0표로 동점이지만 그 경우는 결선을 열지 않고 난수로 확정한다(아래). 후보 집합은 명단 스냅샷에서 파생되고 스냅샷은 게임 중에 줄지 않으므로 후보가 사라지는 경로도 없다. 따라서 결선 진입 시 후보는 언제나 2개 이상이다.

**결선 투표 시간**은 본선 투표 시간의 절반이되 최소 5초다. 후보가 줄어 판단이 빨라지고, 킹메이커가 본선 60초에 결선 30초를 쓴 것과 같은 비율이다. 기본 설정 10초면 결선은 5초다.

## 유효표 0의 처리

전원이 기권해 유효표가 0이면 **결선을 열지 않는다.** 결선을 열어도 같은 0표 동점이 재생산되기 때문이다. 서버가 후보 중 한 명을 라운드 시드로 뽑아 확정하고 **표가 없었음을 결과 화면에 표시**한다(US-452-5).

이 규칙은 결선에서도 같다. 결선에서 전원이 기권하면 결선 후보 중 한 명을 난수로 확정한다.

## 상태 머신

```
[GUIDE] ──3초──▶ [VOTE]

[VOTE]   ──마감(설정값) / 전원 투표──▶ 개표
[RUNOFF] ──마감(절반)   / 전원 투표──▶ 개표

개표 결과로 분기
   ├─ 단독 최다 · 유효표 0   ──▶ [REVEAL] ──3초──▶ [RESULT]
   ├─ 동점 · 결선 3회 미만    ──▶ [TIE_NOTICE] ──3초──▶ [RUNOFF] ──▶ (개표로 되돌아감)
   └─ 동점 · 결선 3회 소진    ──▶ [DEADLOCK]
                                     ├─ 방장 선택: 다시 시작   ──▶ [VOTE]
                                     └─ 방장 선택: 대기방으로 ──▶ [VOID]

어느 상태에서든 방장 이탈 ──▶ [ABORTED]
```

- **VOTE** — 본선. 후보는 명단 스냅샷 전원이고 지목 상한은 설정에 따른다.
- **TIE_NOTICE** — 동점자 명단을 3초간 보여준다. **득표 수는 아직 공개하지 않는다**(G-10).
- **RUNOFF** — 결선. 후보가 동점자로 줄고 지목 상한이 1로 고정되며 투표 시간이 본선의 절반이다.
- **REVEAL** — 지목선 연출과 함께 후보별 피격 수를 공개하고 3초 뒤 결과 화면으로 넘어간다(G-11).
- **DEADLOCK** — 결선 3회를 소진하고도 단독 최다가 없어 자동 진행을 멈춘 상태.
- **VOID** — 방장이 대기방으로를 골라 결과 없이 끝난 상태.

## 판정 알고리즘

지목의 도착 시각 순서는 판정에 들어가지 않는다. 서버 도착 시각은 **마감 전후 판별과 멱등 처리에만** 쓴다.

```
입력:
  roster[0..n-1]      # 명단 스냅샷
  candidates          # 후보 집합. 본선은 roster 전체, 결선은 직전 동점자 집합
  ballots             # voterId → 지목 대상 ID 배열(마감 이전에 도착한 최초 1건)
  dupAllowed          # 중복 투표 설정. 결선에서는 무시한다
  runoffCount         # 지금까지 실시한 결선 횟수(0..3)
  seed
출력:
  { kind: "확정", winnerId, tally, byRandom }
  { kind: "결선", tiedIds }
  { kind: "교착", tiedIds }

# ── 접수 시 검증 — 하나라도 어기면 요청 전체를 거절한다 ──────────────
limitOf(voterId, candidates, dupAllowed, runoffCount):
  if runoffCount > 0: return 1                       # 결선은 1명 고정
  if not dupAllowed:  return 1
  m = |{ c in candidates : c != voterId }|
  return max(1, floor(m / 2))

acceptBallot(voterId, picks, candidates, ...):
  L = limitOf(voterId, candidates, dupAllowed, runoffCount)
  reject if 마감 시각 이후 도착
  reject if 이미 이 단계에서 확정된 투표가 있다        # 멱등 · 최초 1회
  reject if length(picks) == 0 or length(picks) > L
  reject if picks에 중복이 있다
  reject if picks의 어떤 원소가 candidates에 없다
  reject if voterId in picks                          # 자기 지목 금지
  accept

# ── 개표 ─────────────────────────────────────────────────────
judgeSnipe(candidates, ballots, runoffCount, seed):
  for c in candidates: tally[c] = 0
  for (voterId, picks) in ballots:
      for target in picks: tally[target] += 1

  total = sum(tally)

  # 유효표 0 — 결선을 열어도 같은 0표 동점이 재생산되므로 난수로 끊는다
  if total == 0:
      prng   = PRNG(seed)
      winner = candidates[ randomBelow(prng, |candidates|) ]
      return { kind: "확정", winnerId: winner, tally, byRandom: true }

  # 방어적 처리 — 정상 경로에서는 발생하지 않는다
  if |candidates| == 1:
      return { kind: "확정", winnerId: only(candidates), tally, byRandom: false }

  maxHits = max over c of tally[c]
  top     = { c : tally[c] == maxHits }

  if |top| == 1:            return { kind: "확정", winnerId: only(top), tally, byRandom: false }
  if runoffCount < 3:       return { kind: "결선", tiedIds: top }
  else:                     return { kind: "교착", tiedIds: top }
```

- **결정성** — 표를 세는 순서가 결과에 영향을 주지 않고(덧셈의 교환법칙), 동점 집합 top은 집합이라 순서에 의존하지 않는다. 난수를 쓰는 자리는 유효표 0 하나뿐이며 그것도 시드로 재현된다.
- **결선 진입 시** candidates를 top으로 줄이고 ballots를 비우며 runoffCount를 1 올린다. **재투표는 명단 스냅샷 전원이 한다** — 후보가 아닌 참가자도 투표권을 잃지 않는다.
- 거절된 요청은 미투표 상태로 되돌린다. 마감 전이면 다시 시도할 수 있고, 마감까지 유효한 투표를 남기지 못하면 기권이다.

## 종료 증명

**주장** — 어떤 입력 조합에서도 서버는 유한 시간 안에 RESULT · VOID · ABORTED 중 하나에 도달하거나 DEADLOCK에서 정지한다.

**논증** — 자동 진행 구간의 각 상태에 마감 타이머가 있고, 유일한 순환인 결선 고리에 상한이 있다.

| 상태 | 최대 체류 | 최대 진입 | 소계 |
|------|:--------:|:--------:|:----:|
| GUIDE | 3초 | 1 | 3초 |
| VOTE | 60초(설정 상한) | 1 | 60초 |
| TIE_NOTICE | 3초 | 3 | 9초 |
| RUNOFF | 30초(본선의 절반, 상한 기준) | 3 | 90초 |
| REVEAL | 3초 | 1 | 3초 |

투표 시간을 상한 60초로 설정했을 때 합 **165초**가 자동 진행의 상한이다. 기본 설정 10초·결선 없음이면 3 + 10 + 3 = 16초이며, 목표 소요 30초는 이 경로의 값이다.

**순환이 끊기는 지점** — VOTE·RUNOFF → 개표 → TIE_NOTICE → RUNOFF가 유일한 순환이다. 개표 함수는 runoffCount가 3에 닿으면 결선을 반환할 수 없다. runoffCount는 단조 증가하므로 순환은 최대 3회 돈다. **DEADLOCK은 타이머가 없는 정지 상태**이며 방장의 다시 시작은 사람의 행위이지 규칙의 자동 반복이 아니다.

### 반례 후보 검토

| 반례 후보 | 구체 조합 | 결과 |
|----------|----------|------|
| **동점 — 순환 지목** | 3명. A가 B를, B가 C를, C가 A를 지목. 전원 1표로 3중 동점 | 결선 후보가 3명 그대로이고 자기 지목 금지 아래 같은 선택이 유효하므로 반복될 수 있다. 3회 소진 후 DEADLOCK으로 정지한다. **이 조합이 상한 없는 결선을 폐기한 근거다** |
| **동점 — 기권 섞임** | 3명. A가 B를, B가 A를 지목하고 C는 기권. A·B가 각 1표 | 결선 후보 {A, B}에 전원이 재투표한다. C가 계속 기권하면 A는 B만, B는 A만 지목할 수 있어 1:1이 유지된다. 3회 소진 후 DEADLOCK |
| **전원 미입력** | 전원 기권. 유효표 0 | 결선을 열지 않고 후보 중 한 명을 난수로 확정한다. 결과 화면에 표가 없었음을 표시한다 |
| **전원 동시 입력** | 전원의 지목이 같은 밀리초에 서버 도착 | 도착 시각은 판정에 들어가지 않는다. 각각 1건으로 접수되고 표 합계가 같다 |
| 중복 투표로 전원 지목 시도 | 10명방에서 한 사람이 후보 9명 전부를 지목 | 상한 4를 넘으므로 요청 전체가 거절된다. 표를 균등하게 만들어 판을 무의미하게 하는 경로가 막힌다 |
| 결선 후보에 자기가 포함 | A·B 동점이고 A가 투표 | A는 B만 지목할 수 있다. 후보가 2명이므로 자기를 빼도 1명이 남아 투표 불능이 되지 않는다 |
| 후보 1명 결선 | — | 발생하지 않는다. 서버가 만나면 즉시 그 후보로 확정하는 방어 분기만 둔다 |

## 경계값 표

| 경계 | 동작 |
|------|------|
| **최소 인원 3** | 후보가 2명이므로 중복 투표를 켜도 상한이 1이다. 순환 지목으로 3중 동점이 나기 쉬운 인원이며 3회 결선 후 DEADLOCK 경로가 가장 잘 나타난다 |
| **최대 인원 10** | 후보 9명·지목 상한 4다. 후보 그리드는 스크롤 없이 한 화면에 담는다 |
| **전원 미입력** | 유효표 0 → 서버가 후보 중 한 명을 난수로 확정하고 표가 없었음을 표시한다 |
| **전원 동시 입력** | 지목 도착 시각이 모두 같아도 판정에 영향이 없다. 순서 의존이 없다 |
| **1명 잔류** | 접속자가 1명만 남아도 진행한다. 이탈자는 기권으로 확정되고 후보로는 남아 뽑힐 수 있다 |
| **도중 이탈로 유효 인원이 최소 미만** | 접속자가 2명 이하가 되어도 진행한다. 최소 인원 3은 시작 시점에만 검사한다. 방장 이탈이면 ABORTED |
| 지목 상한 초과 요청 | 요청 전체를 거절한다. 일부만 반영하지 않는다 |
| 자기 자신을 담은 요청 | 요청 전체를 거절한다. 후보 그리드에 자기 카드가 없으므로 정상 조작으로는 발생하지 않는다 |
| 투표 시간 5초 설정 | 결선 투표 시간이 최소값 5초로 유지된다(절반인 2.5초로 내려가지 않는다) |
| 마감 직후 도착한 지목 | 거절한다. 그 참가자는 기권이다 |

## 구현 대조

frontend/src/games/Sniper.tsx는 서버가 없는 프로토타입이며 아래 지점이 본 문서와 어긋난다. **문서가 정본이고 구현을 고친다.**

| 지점 | 프로토타입 | 본 문서 |
|------|-----------|--------|
| 결선 투표 | 단계가 없다. 동점이면 방장에게 재투표·대기방으로 모달을 띄운다 | 동점이면 결선을 자동으로 연다. 방장 개입은 3회 소진 후에만 있다 |
| 반복 상한 | 없다 | 결선 최대 3회. 소진하면 DEADLOCK |
| 중복 투표 상한 | 규칙이 없다. 설정값만 있고 지목 수를 제한하지 않는다 | max(1, floor(후보 수 / 2)). 결선은 1 고정 |
| 유효표 0 | 최다 득표가 0이어도 정렬 첫 번째 참가자를 승자로 확정한다 | 후보 중 한 명을 난수로 확정하고 표가 없었음을 표시한다 |
| 결선 투표 대상 | 동점자만 다시 붙이는 형태로 보인다 | 명단 스냅샷 전원이 재투표한다 |

**유효표 0 처리는 공정성 결함이다.** 아무도 투표하지 않았는데 정렬 순서가 승자를 정하면, 명단 순서를 아는 참가자에게 결과가 예측된다.

## 인수 기준 후보

번호는 붙이지 않는다. 채번 정본은 [../03_requirements/10_acceptance_criteria.md](../03_requirements/10_acceptance_criteria.md)다.

- 참가자 5명이 게임을 시작하면 → 각자의 화면에 자기를 뺀 후보 4명이 표시된다.
- 중복 투표가 불가일 때 후보 하나를 고르면 → 즉시 확정되고 다시 고를 수 없다.
- 참가자 5명·중복 투표 가능일 때 → 지목 상한이 2로 표시되고 3명을 담은 요청이 거절된다.
- 참가자 4명·중복 투표 가능일 때 → 지목 상한이 1이며 설정 화면에 1인 1표와 같아진다는 안내가 표시된다.
- 자기 자신을 담은 지목 요청을 보내면 → 서버가 요청 전체를 거절하고 미투표 상태로 되돌린다.
- 같은 후보를 두 번 담은 요청을 보내면 → 서버가 요청 전체를 거절한다.
- 개표 결과 A와 B가 같은 피격 수로 최다면 → 동점자 명단이 3초간 표시된 뒤 결선이 열리고 **득표 수는 표시되지 않는다**.
- 결선에서 후보가 A·B 둘이고 중복 투표가 가능으로 설정되어 있으면 → 결선 화면에서 1명만 고를 수 있다.
- 결선 후보에 자기가 포함된 참가자의 화면에서는 → 자기 카드가 후보에서 빠지고 나머지 후보만 고를 수 있다.
- 결선을 3회 실시하고도 동점이면 → 자동 진행이 멈추고 방장에게 다시 시작·대기방으로 선택이 표시된다.
- 전원이 기권해 유효표가 0이면 → 서버가 후보 중 한 명을 난수로 확정하고 결과 화면에 표가 없었음이 표시된다.
- 판이 끝나면 → 결과 화면에 피격 수만 보이고 지목선의 출발점이 가려지며 **서버 응답에도 지목 쌍이 담기지 않는다**. 이를 여는 설정은 없다.
- 투표 시간을 5초로 설정하면 → 결선 투표 시간도 5초로 유지된다.
- 투표 진행 중 다른 참가자의 화면을 보면 → 완료·대기 상태만 보이고 피격 수가 보이지 않는다.
- 투표 마감 시각 이후에 도착한 지목은 → 거절되고 그 참가자는 기권으로 집계된다.
- 이탈한 참가자가 최다 피격으로 뽑히면 → 결과 화면에 이탈 표시와 함께 선정자로 표시된다.
