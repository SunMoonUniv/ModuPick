전원이 한 번에 서로 다른 역할을 받는 유일한 게임이다. 규칙의 핵심은 **참가자와 도착 항목이 반드시 1:1로 대응하는 것**이며, 이 성질은 가로선을 무작위로 뿌린 뒤 기대하는 것이 아니라 **도착 순열을 먼저 뽑고 그 순열을 실현하는 가로선을 역산해서** 보장한다. 순서를 뒤집는 것이 이 문서의 가장 중요한 설계 결정이다.

## 게임 개요

| 항목 | 값 |
|------|-----|
| 결정 대상 | 전원 역할 배정 |
| 인원 | 2~10명 |
| 입력 주체 | 방장만(START 1회) |
| 판정 주체 | 서버 난수 |
| 목표 소요 | 40초 |
| 결과 화면 형태 | 배정형 |
| 방장 설정 | 주제(항목 목록) · 진행 속도 2항 |

- 세로선(레인) 수는 **참가자 수 n과 같다.** 참가자는 레인을 고르지 않고 **명단 스냅샷 순서대로** 자동 배치된다(D-33·US-421).
- 도착 항목 수도 **n과 같게 강제한다.** 항목이 부족하면 뒤에 X를 채우고, 넘치면 뒤에서부터 잘라낸다. 어떻게 맞춰졌는지 방장에게 보여준다(D-32·US-306).
- **X를 받은 참가자는 배정된 역할이 없다는 뜻**이며 결과 화면에 X로 표시된다.
- **진행 속도는 애니메이션 길이만 바꾸고 결과에 영향을 주지 않는다.** 빠르게 2000ms · 보통 3500ms · 느리게 5000ms다.

## 상태 머신

```
              방장 START / 자동 실행 마감(30초)
   [GUIDE] ──3초──▶ [ARMED] ─────────────────▶ [DRAWING]
                       │        판정 실행·구조 공개     │
                       │                             │ durationMs 경과
                       │                             ▼
                       │                        [REVEAL] ──3초──▶ [RESULT]
                       │                             │                │
                       └──────── 방장 이탈 ──────────┴────────────────┘
                                                     ▼
                                                 [ABORTED]
```

- **GUIDE** — 3초 규칙 가이드. 다시 하기로 진입하면 건너뛴다(G-4).
- **ARMED** — 상단 참가자·하단 항목이 배치된 채 방장의 START를 기다린다. 가로선은 아직 보이지 않는다. 진입 시각 + 30초가 자동 실행 마감이다.
- **DRAWING** — 서버가 확정한 가로선이 공개되고 **전원의 경로가 동시에** 그려진다(D-33). 참가자별 고유 색으로 구분한다.
- **REVEAL** — 참가자와 항목의 최종 연결이 확정 표시되고 3초 뒤 결과 화면으로 넘어간다(G-11).
- **RESULT** — 결과 화면. 참가자 → 역할 전체 배정을 표시한다.
- **ABORTED** — 방장 이탈로 결과 없이 끝난 상태(G-16).

### 상태 × 이벤트

| 상태 ＼ 이벤트 | 가이드 3초 경과 | 방장 START 도착 | 자동 실행 마감(30초) | durationMs 경과 | REVEAL 3초 경과 | 참가자 입력 도착 | 참가자 이탈 | 방장 이탈 |
|---------------|----------------|----------------|---------------------|----------------|----------------|-----------------|------------|----------|

| **ARMED** | 해당 없음 | 판정 실행 → DRAWING | 판정 실행 → DRAWING | 해당 없음 | 해당 없음 | 버린다 | 스냅샷 유지·상태 불변 | → ABORTED |

| **REVEAL** | 해당 없음 | 버린다 | 타이머 해제됨 | 해당 없음 | → RESULT | 버린다 | 스냅샷 유지·배정 불변 | → ABORTED |

| **ABORTED** | 해당 없음 | 버린다 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 상태 불변 | 상태 불변 |

레인 선택(구 스펙의 참가자 레인 지정)은 폐기됐으므로 참가자 입력은 어느 상태에서도 정의되지 않는다. 서버는 받되 버린다.

## 판정 알고리즘

**난수원은 도착 순열 하나뿐이다.** 항목 배치도 가로선 좌표도 별도 난수를 쓰지 않는다. 난수원이 하나여야 결과 분포를 논증할 수 있고 시드 재현이 성립한다.

```
입력:
  roster[0..n-1]   # 명단 스냅샷(입장 순서). 레인 i에 roster[i]가 선다
  items[0..k-1]    # 방장이 입력한 도착 항목(입력 순서)
  seed             # 라운드 시드(64비트)
출력:
  slots[0..n-1]    # 하단에 놓인 도착 항목
  rungs            # 가로선 목록. 각 원소는 (레벨 인덱스, 갭 인덱스)
  assign[0..n-1]   # 참가자 i가 도착하는 컬럼

judgeLadder(roster, items, seed):
  n = length(roster)

  # ── 1) 항목 정규화 — 개수를 n에 맞춘다 ────────────────────────────
  if length(items) > n:  slots = items[0 .. n-1]              # 뒤에서부터 잘라낸다
  elif length(items) < n: slots = items + repeat("X", n - length(items))
  else: slots = items
  # 항목은 섞지 않는다. 방장이 설정 화면에서 본 순서 그대로 하단에 놓는다.

  # ── 2) 도착 순열 추출 — 유일한 난수 소비 지점 ──────────────────────
  prng = PRNG(seed)
  perm = [0, 1, ..., n-1]
  for i from n-1 down to 1:                    # Fisher–Yates
      j = randomBelow(prng, i + 1)
      swap(perm[i], perm[j])
  # perm[i] = 참가자 i가 도착할 컬럼. n! 가지가 균등하다.

  # ── 3) 순열을 인접 전치의 열로 분해 ─────────────────────────────
  cur    = [0, 1, ..., n-1]        # cur[c] = 지금 컬럼 c를 지나는 참가자
  target = inverse(perm)           # target[c] = 컬럼 c에 도착해야 하는 참가자
  swaps  = []                      # 갭 인덱스의 열. 순서가 의미를 갖는다
  for c from 0 to n-1:
      d = index in [c, n) such that cur[d] == target[c]
      for e from d-1 down to c:
          swap(cur[e], cur[e+1])
          swaps.append(e)          # 갭 e는 컬럼 e와 e+1을 잇는다
  # 길이는 최대 n(n-1)/2 (n=10이면 45)

  # ── 4) 레벨 패킹 — 순서를 보존하며 높이를 줄인다 ─────────────────
  levels = []                      # 각 원소는 그 레벨에 놓인 갭 집합
  cursor = {}
  for g in swaps:                  # 열 순서를 지킨다. 앞으로 당기지 않는다
      if cursor is empty or (for all h in cursor: |g - h| >= 2):
          cursor.add(g)            # 서로 떨어진 갭의 전치는 교환 가능하다
      else:
          levels.append(cursor); cursor = {g}
  if cursor is not empty: levels.append(cursor)

  # ── 5) 최소 레벨·장식 가로선 — perm을 바꾸지 않는다 ────────────────
  while length(levels) < 5: levels.append({})          # 빈 레벨로 높이를 채운다
  if count(rungs in levels) < 2 or n == 2:
      (L, g) = 연속한 두 빈 레벨 L, L+1과 임의의 갭 g를 고른다
      levels[L].add(g); levels[L+1].add(g)
      # 같은 갭의 전치를 사이에 아무것도 없이 두 번 적용하면 항등이다

  # ── 6) 경로 계산과 자기 검증 ──────────────────────────────────
  for i from 0 to n-1:
      c = i
      for level in levels (위에서 아래로):
          for g in level:                      # 레벨 안 순서는 결과에 무관하다
              if   g == c:     c = c + 1
              elif g == c - 1: c = c - 1
      assign[i] = c
  assert assign == perm            # 어긋나면 판정을 폐기하고 시드를 다시 뽑는다

  return { slots, rungs: levels, assign }
```

### 1:1 대응이 보장되는 이유

**주장** — assign은 항상 전단사(순열)다. 서로 다른 참가자가 같은 항목에 도착하는 일은 일어나지 않는다.

**논증** — 셋으로 나뉜다.

1. **가로선 하나는 인접 두 레인의 전치다.** 갭 g의 가로선은 컬럼 g에 있던 것과 컬럼 g+1에 있던 것을 맞바꾼다. 전치는 전단사다.
2. **한 레벨 안에서는 레인이 겹치지 않는다.** 패킹 규칙이 같은 레벨의 갭 사이 거리를 2 이상으로 강제하므로, 갭 g가 건드리는 레인 {g, g+1}과 갭 h가 건드리는 레인 {h, h+1}은 서로소다. 따라서 한 레벨은 서로소인 전치들의 곱이고 그것도 전단사이며, **레벨 안에서 어떤 순서로 적용해도 결과가 같다**.
3. **전단사의 합성은 전단사다.** 사다리 전체는 레벨을 위에서 아래로 합성한 것이므로 전단사다.

여기에 6단계의 자기 검증이 더해진다. 경로를 실제로 따라가 얻은 assign이 2단계에서 뽑은 perm과 다르면 그 판정을 폐기한다. 알고리즘이 옳다면 이 검증은 절대 실패하지 않으며, 실패한다면 그것은 구현 결함이므로 결과를 내보내지 않는 편이 낫다.

### 균등성

도착 순열은 Fisher–Yates로 뽑으므로 n!가지가 **균등**하다. 가로선을 먼저 무작위로 뿌리고 경로를 사후에 계산하는 방식은 이 성질을 갖지 않는다 — 그 방식에서 도착 분포는 레벨 수와 가로선 생성 확률에 따라 치우치고, 인접 레인으로 갈 확률이 먼 레인으로 갈 확률보다 커진다. 순서를 뒤집은 이유가 이것이다.

**항목을 섞지 않는 것도 같은 이유다.** 무작위성을 순열 하나에 모으면 "방장이 화면에서 본 항목 순서가 결과의 항목 순서와 같다"는 검증 가능한 성질이 덤으로 따라온다. 항목까지 섞으면 난수원이 둘이 되고 어느 쪽이 결과를 만들었는지 설명할 수 없다.

### 참가자가 2명일 때

갭이 하나(갭 0)뿐이고 가능한 순열은 항등과 전치 둘이다. 각 1/2 확률로 뽑힌다.

| perm | 3단계 분해 | 5단계 장식 | 최종 가로선 수 | 도착 |
|------|-----------|-----------|:-------------:|------|
| 항등 | 빈 열 | 갭 0에 2개 | 2 | 각자 자기 항목 |
| 전치 | 갭 0 하나 | 갭 0에 2개 | 3 | 서로 맞바꿈 |

장식 가로선이 없으면 항등일 때 가로선이 0개가 되어 사다리로 보이지 않는다. 장식 쌍은 **연속한 두 빈 레벨의 같은 갭**에 놓이므로 사이에 다른 전치가 끼지 않고 반드시 상쇄된다. 관찰자는 가로선 개수의 홀짝을 세어야 결과를 알 수 있으며, 그것은 애니메이션이 끝나면 어차피 드러나는 정보다.

## 종료 증명

**주장** — 어떤 입력 조합에서도 이 게임은 게임 시작으로부터 최대 41초 안에 RESULT 또는 ABORTED에 도달한다.

**논증** — 상태 전이도에 순환이 없고 각 상태의 체류 시간에 상한이 있다.

| 상태 | 최대 체류 | 근거 |
|------|----------|------|
| GUIDE | 3초 | 서버 타이머 고정값(G-4) |
| ARMED | 30초 | 자동 실행 마감 |
| DRAWING | 5초 | 진행 속도의 최댓값(느리게 5000ms) |
| REVEAL | 3초 | 결과 전환 지연 고정값(G-11) |

3 + 30 + 5 + 3 = **41초**가 상한이다.

**판정 알고리즘 자체도 유한하다.** 2단계는 n−1회, 3단계는 최대 n(n−1)/2회, 4단계는 swaps 길이만큼, 6단계는 n × 총 가로선 수만큼 도는 유한 루프이며 어느 것도 조건부 재시도를 하지 않는다. randomBelow의 거부 표본추출만 이론상 반복하지만 각 시행의 성공 확률이 1/2 이상이므로 기대 반복 횟수는 2회 미만이다.

### 반례 후보 검토

| 반례 후보 | 이 게임에서의 결과 | 왜 종료하는가 |
|----------|------------------|-------------|
| **동점** | 발생하지 않는다 | 판정 출력이 순열이므로 순위나 득표라는 개념이 없다. 동점 처리 규칙을 두지 않는다 |
| **전원 미입력** | 참가자에게 입력이 없다 | 방장이 START를 누르지 않는 경우가 여기 대응하며 30초 뒤 서버가 자동 실행한다 |
| **전원 동시 입력** | 발생하지 않는다 | 참가자 입력이 정의되어 있지 않다. 방장의 START 연타는 최초 1회만 인정한다(G-9) |
| 항목이 0개 | 시작할 수 없다 | 항목은 최소 1개여야 하며 설정 화면에서 검사한다. 시작 버튼이 비활성이다 |
| 항목이 참가자보다 많음 | 뒤에서부터 잘라내고 진행한다 | 1단계가 항상 개수를 n으로 맞추므로 이후 단계가 인원 불일치를 만나지 않는다 |
| 자기 검증 실패 | 판정을 폐기하고 시드를 다시 뽑는다 | 재시도는 최대 1회로 제한하고 두 번째도 실패하면 서버 오류로 판을 중단한다. 무한 재시도를 두지 않는다 |

**반복 규칙이 없으므로 반복 상한도 필요 없다.** 룰렛과 함께 [01_common.md](./01_common.md)의 3회 상한을 쓰지 않는 두 게임이다.

## 경계값 표

| 경계 | 동작 |
|------|------|
| **최소 인원 2** | 레인 2개·갭 1개. 순열 2가지가 각 1/2이다. 장식 쌍이 반드시 붙어 가로선이 최소 2개다 |
| **최대 인원 10** | 레인 10개·갭 9개. 분해 길이가 최대 45이고 패킹 후 레벨 수는 대체로 10 안팎이다. 화면 높이가 모자라면 레벨 간격을 줄이되 레벨 수는 줄이지 않는다 |

| **1명 잔류** | 도중 이탈로 접속자가 1명만 남아도 레인 n개가 그대로 그려지고 이탈자도 역할을 배정받는다. 결과 화면에 이탈 표시가 붙는다 |
| **도중 이탈로 유효 인원이 최소 미만** | 접속자가 0명이 되어도 판정은 실행된다. 최소 인원 2는 시작 시점에만 검사한다. 방장 이탈이면 ABORTED다 |
| 항목 1개 · 참가자 10명 | 항목 1개 + X 9개가 하단에 놓인다. 1명만 역할을 받고 9명은 X다 |
| 항목 12개 · 참가자 6명 | 앞 6개만 쓰고 뒤 6개를 잘라낸다. 잘린 항목을 방장 화면에 표시한다 |

## 구현 대조

frontend/src/games/Ladder.tsx는 서버가 없는 프로토타입이며 아래 지점이 본 문서와 어긋난다. **문서가 정본이고 구현을 고친다.**

| 지점 | 프로토타입 | 본 문서 |
|------|-----------|--------|
| 생성 순서 | 가로선을 확률 0.5로 먼저 뿌리고 경로를 사후 계산한다 | 도착 순열을 먼저 뽑고 그것을 실현하는 가로선을 역산한다 |
| 도착 분포 | 균등하지 않다. 인접 레인으로 갈 확률이 크다 | Fisher–Yates로 n!가지가 균등하다 |
| 항목 배치 | 항목을 무작위로 섞어 슬롯에 넣는다 | 방장 입력 순서 그대로 놓는다. 난수원은 순열 하나다 |
| 부족분 표기 | 빈 슬롯(null)으로 두고 라벨이 없다 | X로 채우고 결과 화면에도 X로 표시한다 |
| 초과 항목 | 앞에서 n개만 쓰고 잘린 항목을 알리지 않는다 | 뒤에서부터 잘라내고 잘린 항목을 방장에게 보여준다 |
| 자기 검증 | 없다 | 경로 계산 결과가 뽑은 순열과 같은지 확인한다 |
| 자동 실행 마감 | 없다 | ARMED 진입 30초 뒤 서버가 자동 실행한다 |

## 인수 기준 후보

번호는 붙이지 않는다. 채번 정본은 [../03_requirements/10_acceptance_criteria.md](../03_requirements/10_acceptance_criteria.md)다.

- 참가자 6명·항목 6개로 게임을 시작하면 → 세로선 6개와 도착 항목 6개가 그려지고 참가자가 입장 순서대로 상단에 배치된다.
- 참가자 6명·항목 4개로 게임을 시작하면 → 하단이 항목 4개 + X 2개로 채워지고 방장 화면에 자동으로 채웠다는 표시가 나타난다.
- 참가자 6명·항목 9개로 게임을 시작하면 → 앞 6개만 쓰이고 뒤 3개가 잘렸다는 표시가 방장 화면에 나타난다.
- 같은 시드·같은 명단·같은 항목으로 판정을 다시 실행하면 → 가로선 배치와 배정 결과가 모두 같다.
- 판정 결과 assign을 집계하면 → 도착 컬럼이 0부터 n−1까지 정확히 한 번씩 나타난다(중복·누락 0).
- 참가자 2명이고 뽑힌 순열이 항등이면 → 가로선이 2개 이상 그려지고 두 참가자가 각자 자기 컬럼 항목에 도착한다.
- 폭 360px 기기와 폭 1280px 기기가 같은 판에 참여하면 → 경로의 픽셀 좌표는 다르되 최종 배정 결과가 같다.
- 진행 속도를 빠르게·보통·느리게로 각각 설정해 같은 시드로 실행하면 → 애니메이션 길이만 2000·3500·5000ms로 달라지고 배정 결과는 같다.
- 방장이 게임 시작 후 30초 동안 START를 누르지 않으면 → 서버가 자동으로 판정을 실행하고 경로가 그려진다.
- 참가자가 애니메이션 도중 방을 나가면 → 그 참가자의 경로가 끝까지 그려지고 결과 화면에 이탈 표시와 함께 배정 항목이 표시된다.
- 방장이 애니메이션 도중 방을 나가면 → 방이 즉시 삭제되고 그 판의 결과는 남지 않는다.
