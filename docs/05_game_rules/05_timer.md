# 시간초 잡기

> **대상**: 목표 시간 오차로 1인을 뽑는 게임의 상태 머신·경과 시간 측정 예외와 서버 검증·미시작과 미정지의 구분·재대결 규칙·종료 증명·경계값
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §3.2 · §3.4 · §3.5.4 · §4.4 US-441~442 · §6 D-05·D-23·D-31 · §5 NFR-03 · git 529e312 docs/games.md §5 · git ecceb11 docs/05_game_rules/04_timer.md · frontend/src/games/TimeCatch.tsx(프로토타입 실측) · [../README.md](../README.md)(전역 불변식 판정 기준) · [01_common.md](./01_common.md)

**서버 도착 시각 원칙의 유일한 예외를 담은 게임이다.** 밀리초 단위 오차로 순위를 가르는데 네트워크 지터가 그 해상도보다 크기 때문에, 경과 시간만은 클라이언트의 단조 시계가 재고 서버가 자기가 관측한 도착 시각으로 그 값을 검증한다. 예외의 범위와 허용 오차, 그리고 검증에 실패했을 때의 처리를 이 문서가 확정한다.

## 게임 개요

| 항목 | 값 |
|------|-----|
| 결정 대상 | 사람 1인 |
| 인원 | 2~10명 |
| 입력 주체 | 전원(START 1회 · STOP 1회) |
| 판정 주체 | 참가자 감각 |
| 목표 소요 | 30초 |
| 결과 화면 형태 | 승자형 |
| 방장 설정 | 주제 · 목표 시간(5·7·10초) · 판정 기준(가장 가까운 사람·가장 먼 사람) 3항 |

1. 각자 START를 눌러 **자기 타이머**를 시작한다. 다른 사람과 무관하게 흐른다.
2. **2.00초까지만 숫자가 보이고 이후 가려진다.**
3. 목표 시간이라고 느낀 순간 STOP을 **한 번** 누른다. 되돌릴 수 없다.
4. 목표 시간과의 오차로 순위를 매긴다.

```
절대 오차 = |정지 시간 − 목표 시간|      ← 판정용
시간 차이 = 정지 시간 − 목표 시간        ← 화면 표시용(부호 포함)
```

- 판정 기준이 가장 가까운 사람이면 절대 오차 **최소**가, 가장 먼 사람이면 **최대**가 뽑힌다.
- 시간은 부동소수점이 아니라 **정수 밀리초**로 기록한다.
- 다른 사람의 진행 상황은 완료·대기만 보이고 기록은 보이지 않는다(G-10).

### 마감 시각 셋

| 마감 | 값 | 기준 |
|------|----|------|
| START 마감 | 게임 시작 + 10초 | 라운드 공통. 이 시각까지 START가 서버에 닿지 않으면 **미시작** |
| 개인 제한 | 그 참가자의 START 도착 시각 + (목표 시간 + 3초) | 참가자마다 다르다. 이 시각까지 STOP이 닿지 않으면 **미정지** |
| 라운드 마감 | 게임 시작 + 10초 + (목표 시간 + 3초) | 가장 늦게 START한 참가자의 개인 제한과 같다. 이 시각에 라운드가 반드시 끝난다 |

**세 마감의 판정은 전부 서버 도착 시각으로 한다.** 예외는 경과 시간 값 하나뿐이며, 마감 판정에까지 예외를 넓히지 않는다.

## 경과 시간의 측정과 검증

### 왜 예외를 두는가

서버 도착 시각의 차이로 경과 시간을 계산하면, 그 값은 **실제 경과 시간 + (STOP 편도 지연 − START 편도 지연)** 이 된다. 모바일 환경의 편도 지연은 수십 밀리초 규모로 흔들리고, 그 흔들림이 순위를 가르는 밀리초 오차보다 크다. 그러면 감각이 아니라 회선의 균일성이 승자를 정하게 되어 게임의 전제가 무너진다. 그래서 **측정은 클라이언트 단조 시계에 맡기고 검증은 서버가 한다.**

### 규약

```
클라이언트:
  START를 누른 순간   t0 = performance.now()      # 단조 시계. 시스템 시계 조작에 영향받지 않는다
  STOP을 누른 순간    t1 = performance.now()
  서버로 보낸다        elapsedClient = round(t1 − t0)   # 정수 밀리초

서버:
  s0 = START 요청을 받은 시각(서버 단조 시계)
  s1 = STOP  요청을 받은 시각(서버 단조 시계)
  elapsedServer = s1 − s0

  accept  if |elapsedClient − elapsedServer| ≤ TOLERANCE_MS
  reject  otherwise
```

- **TOLERANCE_MS = 300**(±0.300초)로 둔다.
- 근거는 정직한 클라이언트가 만들 수 있는 최대 불일치가 두 메시지의 **편도 지연 차이**뿐이라는 데 있다. 모바일 셀룰러에서 편도 지연이 수십 밀리초대에서 150밀리초대까지 흔들리는 것을 전제하면 그 차이의 상한을 200밀리초 수준으로 보고, 여기에 브라우저 이벤트 루프 지연과 타이머 해상도 여유 100밀리초를 더해 300밀리초로 정한다.
- **이 값은 실측이 아니라 설계 초기값이다.** 백엔드 통합 후 실제 도착 시각 분포를 측정해 재조정하며, 그때까지 300이라는 수를 검증된 값으로 인용하지 않는다.

### 이 예외가 남기는 조작 여지

정직하게 적는다. **허용 오차 안의 조작은 막지 못한다.** 클라이언트가 elapsedClient를 목표 시간 쪽으로 최대 300밀리초까지 당겨 신고해도 검증을 통과한다.

그럼에도 이 거래를 택한 이유는 이렇다. 서버 도착 시각을 쓰면 **막을 수 없는 무작위 불공정**(회선 품질이 결과를 좌우)이 남고, 클라이언트 측정에 검증을 붙이면 **상한이 정해진 조작 여지**가 남는다. 후자는 상한을 줄여 갈 수 있고 전자는 줄일 수 없다. 허용 오차를 실측으로 좁히는 것이 이 게임의 공정성 개선 경로다.

### 부가 검증

허용 오차 검사 외에 아래를 함께 본다. 하나라도 어기면 **거부**다.

| 검사 | 거부 조건 |
|------|----------|
| 형식 | elapsedClient가 정수가 아니거나 음수다 |
| 상한 | elapsedClient > (목표 시간 + 3초) + TOLERANCE_MS |
| 선행 | 그 참가자의 START가 서버에 도착한 적이 없다 |
| 마감 | STOP의 **서버 도착 시각**이 그 참가자의 개인 제한을 넘겼다 |
| 멱등 | 그 참가자의 STOP이 이미 확정되어 있다 |

거부된 STOP은 재시도를 받지 않는다. STOP은 라운드당 1회이므로, 거부는 곧 **그 라운드에서 유효 기록을 남기지 못했다**는 뜻이다.

## 미시작·미정지·거부의 구분

셋 다 유효 기록이 없고 셋 다 **승자 후보에서 제외**되지만, 결과 화면의 사유 표기와 최하위군 안의 순서가 다르다.

| 구분 | 조건 | 결과 표기 |
|------|------|----------|
| **미시작** | START 마감까지 START가 서버에 닿지 않았다 | 시작하지 않음 |
| **미정지** | START는 했으나 개인 제한까지 STOP이 닿지 않았다 | 시간 초과 |
| **거부** | START·STOP 모두 도착했으나 검증을 통과하지 못했다 | 기록 무효 |

- **셋 다 승자 후보에서 뺀다.** 판정 기준이 가장 먼 사람일 때 미입력자를 승자 후보에 남기면 아무것도 누르지 않는 것이 최적 전략이 되어 게임이 성립하지 않는다([01_common.md](./01_common.md)).
- 순위표에는 유효 기록자 뒤에 **미정지 → 거부 → 미시작** 순으로 붙인다. 유효 기록을 남기지 못한 사유를 시간을 놓친 것 · 기록을 믿을 수 없는 것 · 판에 참여하지 않은 것 순으로 늘어놓은 것이다.
- **같은 사유 안에서는 명단 스냅샷 인덱스 오름차순**으로 정렬한다. 순위 산출을 결정적으로 만들기 위한 규칙이며 다른 뜻은 없다.

## 상태 머신

```
[GUIDE] ──3초──▶ [RUNNING]

[RUNNING] ──라운드 마감 / 전원 확정──▶ 판정
[REMATCH] ──라운드 마감 / 전원 확정──▶ 판정

판정 결과로 분기
   ├─ 단독 승자              ──▶ [REVEAL] ──3초──▶ [RESULT]
   ├─ 동점 · 재대결 3회 미만  ──▶ [TIE_NOTICE] ──3초──▶ [REMATCH] ──▶ (판정으로 되돌아감)
   └─ 동점 · 재대결 3회 소진  ──▶ [DEADLOCK]
                                     ├─ 방장 선택: 다시 시작   ──▶ [RUNNING]
                                     └─ 방장 선택: 대기방으로 ──▶ [VOID]

어느 상태에서든 방장 이탈 ──▶ [ABORTED]
```

- **RUNNING** — 본판. 명단 스냅샷 전원이 대상이다.
- **REMATCH** — 동점자 재대결. 대상이 직전 판정의 동점자 집합으로 줄고 목표 시간·판정 기준은 그대로다. 이벤트 처리는 RUNNING과 같다.
- **TIE_NOTICE** — 동점자 명단을 3초간 보여준다. 기록 값은 아직 공개하지 않는다.
- **DEADLOCK** — 재대결 3회를 소진하고도 단독 승자가 없어 자동 진행을 멈춘 상태.
- **VOID** — 방장이 대기방으로를 골라 결과 없이 끝난 상태.

### 상태 × 이벤트

| 상태 ＼ 이벤트 | 가이드 3초 경과 | START 도착 | STOP 도착 | START 마감(10초) | 개인 제한 만료 | 라운드 마감·전원 확정 | 판정 완료(내부) | 연출 3초 경과 | 방장 교착 선택 | 참가자 이탈 | 방장 이탈 |
|---------------|----------------|-----------|----------|-----------------|---------------|---------------------|----------------|--------------|---------------|------------|----------|
| **GUIDE** | → RUNNING | 버린다(가드: 단계 전) | 버린다 | 미기동 | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 스냅샷 유지·상태 불변 | → ABORTED |
| **RUNNING** | 해당 없음 | 접수(최초만)·개인 제한 기동 | 검증 후 접수 또는 거부 | 미도착자 미시작 확정 | 해당자 미정지 확정 | 판정 실행 | → REVEAL · TIE_NOTICE · DEADLOCK | 해당 없음 | 버린다 | 미입력으로 확정·상태 불변 | → ABORTED |
| **TIE_NOTICE** | 해당 없음 | 버린다(아직 재대결 전) | 버린다 | 미기동 | 미기동 | 해당 없음 | 해당 없음 | → REMATCH | 버린다 | 스냅샷 유지·상태 불변 | → ABORTED |
| **REMATCH** | 해당 없음 | 동점자면 접수·아니면 버린다 | 동점자면 검증 후 접수·아니면 버린다 | 미도착 동점자 미시작 확정 | 해당자 미정지 확정 | 판정 실행 | → REVEAL · TIE_NOTICE · DEADLOCK | 해당 없음 | 버린다 | 미입력으로 확정·상태 불변 | → ABORTED |
| **REVEAL** | 해당 없음 | 버린다(판 종료) | 버린다 | 미기동 | 미기동 | 해당 없음 | 해당 없음 | → RESULT | 버린다 | 스냅샷 유지·결과 불변 | → ABORTED |
| **DEADLOCK** | 해당 없음 | 버린다 | 버린다 | 미기동 | 미기동 | 해당 없음(자동 진행 없음) | 해당 없음 | 해당 없음 | 다시 시작 → RUNNING · 대기방으로 → VOID | 스냅샷 유지·상태 불변 | → ABORTED |
| **RESULT** | 해당 없음 | 버린다 | 버린다 | 미기동 | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 스냅샷 유지·결과 불변 | → ABORTED |
| **VOID** | 해당 없음 | 버린다 | 버린다 | 미기동 | 미기동 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 상태 불변 | → ABORTED |
| **ABORTED** | 해당 없음 | 버린다 | 버린다 | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 해당 없음 | 버린다 | 상태 불변 | 상태 불변 |

다시 시작으로 RUNNING에 재진입하면 재대결 카운터를 0으로 초기화하고 가이드를 띄우지 않는다(G-4).

## 판정 알고리즘

```
입력:
  entrants[0..m-1]   # 이 라운드의 대상자. 본판은 명단 스냅샷 전원, 재대결은 동점자 집합
  targetMs           # 목표 시간(5000 · 7000 · 10000)
  criteria           # "가장 가까운 사람" 또는 "가장 먼 사람"
  records            # 참가자 → { status, elapsedMs }
                     #   status ∈ { 유효, 미정지, 거부, 미시작 }
  rematchCount       # 지금까지 실시한 재대결 횟수(0..3)
출력:
  { kind: "확정", winnerId, ranking }
  { kind: "재대결", tiedIds, ranking }
  { kind: "교착", tiedIds, ranking }

judgeTimer(entrants, targetMs, criteria, records, rematchCount):
  valid = []
  for p in entrants:
      r = records[p]
      if r.status == 유효:
          absErr  = abs(r.elapsedMs − targetMs)      # 판정용. 정수 밀리초
          diffMs  = r.elapsedMs − targetMs           # 표시용. 부호 포함
          valid.append({ p, absErr, diffMs })

  # ── 순위표 — 유효 기록자 먼저, 그 뒤 미기록군 ──────────────────────
  sortKey(x) = (x.absErr, snapshotIndex(x.p))        # 오차 같으면 스냅샷 순
  ranking = sort(valid, by sortKey, ascending)       # 기준과 무관하게 오차 오름차순으로 늘어놓는다
  ranking += sort(records where status == 미정지, by snapshotIndex)
  ranking += sort(records where status == 거부,   by snapshotIndex)
  ranking += sort(records where status == 미시작, by snapshotIndex)

  # ── 승자 후보 — 유효 기록자만 ────────────────────────────────────
  if valid is empty:
      # 이 라운드가 진전을 만들지 못했다
      if rematchCount < 3: return { kind: "재대결", tiedIds: entrants, ranking }
      else:                return { kind: "교착",   tiedIds: entrants, ranking }

  best = (criteria == "가장 가까운 사람") ? min over valid of absErr
                                          : max over valid of absErr
  top  = { x.p : x.absErr == best }

  if |top| == 1:        return { kind: "확정", winnerId: only(top), ranking }
  if rematchCount < 3:  return { kind: "재대결", tiedIds: top, ranking }
  else:                 return { kind: "교착",   tiedIds: top, ranking }
```

- **결정성** — 입력은 정수 밀리초 배열과 설정값뿐이고 부동소수점 비교가 없다. 오차가 정확히 같을 때의 정렬 순서까지 스냅샷 인덱스로 고정하므로 같은 입력이면 같은 순위표가 나온다.
- **재대결 진입 시** entrants를 top으로 줄이고 records를 비우며 rematchCount를 1 올린다. 목표 시간과 판정 기준은 바꾸지 않는다.
- **재대결이 본판과 같은 목표 시간을 쓰는 이유** — 목표를 바꾸면 방장이 설정하지 않은 값으로 승부가 갈리고, 결과 화면의 목표 시간 축이 라운드마다 달라져 기록을 나란히 놓고 볼 수 없다.
- **재대결에서도 미시작·미정지·거부는 승자 후보에서 뺀다.** 재대결 대상자 전원이 유효 기록을 남기지 못하면 valid가 비고, 그 라운드는 진전을 만들지 못한 채 다음 재대결로 넘어간다(횟수는 소진된다).

## 종료 증명

**주장** — 어떤 입력 조합에서도 서버는 유한 시간 안에 RESULT · VOID · ABORTED 중 하나에 도달하거나 DEADLOCK에서 정지한다.

**논증** — 라운드마다 마감 타이머가 있고, 유일한 순환인 재대결 고리에 상한이 있다.

| 상태 | 최대 체류 | 최대 진입 | 소계 |
|------|:--------:|:--------:|:----:|
| GUIDE | 3초 | 1 | 3초 |
| RUNNING | 10 + 목표 + 3 = 최대 23초 | 1 | 23초 |
| TIE_NOTICE | 3초 | 3 | 9초 |
| REMATCH | 최대 23초 | 3 | 69초 |
| REVEAL | 3초 | 1 | 3초 |

목표 시간이 10초일 때 합 **107초**가 자동 진행의 상한이다. 목표 시간 5초·재대결 없음이면 3 + 18 + 3 = 24초이며, 목표 소요 30초는 이 경로의 값이다.

**라운드가 반드시 끝나는 이유** — 라운드 마감은 게임(또는 재대결) 시작 + 10 + (목표 + 3)초로 서버가 고정한다. 참가자가 아무 입력도 하지 않아도 START 마감이 미시작을 확정하고, START만 하고 멈추지 않아도 개인 제한이 미정지를 확정한다. 어떤 참가자의 상태도 라운드 마감 시점에는 네 값 중 하나로 확정되어 있다.

**순환이 끊기는 지점** — RUNNING·REMATCH → 판정 → TIE_NOTICE → REMATCH가 유일한 순환이다. 판정 함수는 rematchCount가 3에 닿으면 재대결을 반환할 수 없다. rematchCount는 단조 증가하므로 순환은 최대 3회 돈다. **DEADLOCK은 타이머가 없는 정지 상태**이며 방장의 다시 시작은 사람의 행위이지 규칙의 자동 반복이 아니다.

### 반례 후보 검토

| 반례 후보 | 구체 조합 | 결과 |
|----------|----------|------|
| **동점** | 2명이 목표 5000ms에 각각 4880ms·5120ms로 정지해 절대 오차가 둘 다 120ms | 재대결이 열린다. 같은 목표로 다시 하며 정수 밀리초까지 같을 확률이 낮아 대개 한 판에 갈린다. 그래도 3회 반복되면 DEADLOCK |
| **전원 미입력** | 전원이 START도 누르지 않음 | 유효 기록이 0건이므로 승자 후보가 없다. 재대결이 열리고 3회 소진 후 DEADLOCK으로 정지한다. **무작위로 승자를 만들지 않는다** — 아무도 참여하지 않은 판에 결과를 붙이지 않는다 |
| **전원 동시 입력** | 전원의 STOP이 같은 밀리초에 서버 도착 | 도착 시각은 순위 판정에 쓰지 않는다. 각자 자기 START 이후의 경과 시간이 다르므로 오차도 다르다. 도착 시각이 같아도 결과가 흔들리지 않는다 |
| 유효 기록이 1건 | 9명이 미입력이고 1명만 유효 | 그 1명이 단독 승자다. 판정 기준이 가장 먼 사람이어도 유효 기록이 하나뿐이므로 그 사람이 최대이자 최소다 |
| 기록 무효가 전원 | 전원이 검증에 걸림 | 전원 미입력과 같게 다룬다. 재대결 3회 후 DEADLOCK |
| 재대결 대상자가 도중 이탈 | 동점자 2명 중 1명이 이탈 | 이탈자는 재대결에서 미시작으로 확정되고 승자 후보에서 빠진다. 남은 1명이 유효 기록을 남기면 단독 승자다 |

## 경계값 표

| 경계 | 동작 |
|------|------|
| **최소 인원 2** | 정상 진행한다. 동점이면 2명 재대결이다 |
| **최대 인원 10** | 정상 진행한다. 개인 제한이 참가자마다 다르므로 라운드 마감은 가장 늦게 START한 사람 기준이다 |
| **전원 미입력** | 유효 기록 0건. 재대결 3회를 소진한 뒤 DEADLOCK으로 정지하고 방장이 고른다. 난수 확정을 하지 않는다 |
| **전원 동시 입력** | START·STOP이 같은 밀리초에 도착해도 각자의 경과 시간이 다르면 오차도 다르다. 도착 순서는 판정에 들어가지 않는다 |
| **1명 잔류** | 접속자가 1명만 남아도 진행한다. 이탈자는 미시작으로 확정되고 승자 후보에서 빠진다 |
| **도중 이탈로 유효 인원이 최소 미만** | 접속자가 0명이 되어도 라운드 마감까지 기다린 뒤 판정한다. 유효 기록이 없으면 위 전원 미입력과 같다. 방장 이탈이면 ABORTED |
| STOP이 개인 제한 1밀리초 뒤에 도착 | 거절한다. 그 참가자는 미정지다 |
| START가 START 마감 1밀리초 뒤에 도착 | 거절한다. 그 참가자는 미시작이며, 이후 도착한 STOP도 선행 검사에서 거부된다 |
| elapsedClient가 서버 관측보다 301밀리초 작음 | 거부한다. 그 참가자는 기록 무효다 |
| elapsedClient가 목표 + 3초 + 300밀리초를 초과 | 거부한다. 개인 제한 안에 도착했더라도 값 자체가 상한을 넘는다 |

## 구현 대조

frontend/src/games/TimeCatch.tsx는 서버가 없는 프로토타입이며 아래 지점이 본 문서와 어긋난다. **문서가 정본이고 구현을 고친다.**

| 지점 | 프로토타입 | 본 문서 |
|------|-----------|--------|
| 측정 방식 | performance.now() 차이를 정수 밀리초로 기록한다 | **같다.** 클라이언트 단조 시계 측정은 본 문서의 규약과 일치한다 |
| 서버 검증 | 없다. 서버가 없어 값을 그대로 쓴다 | 서버가 관측한 START·STOP 도착 시각 차이와 대조해 ±300밀리초 밖이면 거부한다 |
| START 마감 | 없다. START를 누르지 않으면 라운드가 끝나지 않는다 | 게임 시작 10초 뒤 미시작으로 확정한다 |
| 개인 제한 | 목표 + 3초를 타임라인 표시에만 쓴다. 만료 처리가 없다 | 만료 시 미정지로 확정한다 |
| 미입력 구분 | 없다 | 미시작 · 미정지 · 거부 셋으로 나눈다 |
| 승자 후보 | 전원이 STOP을 누를 때까지 기다렸다가 순위를 낸다 | 유효 기록자만 승자 후보다. 미기록군은 순위표 꼬리에만 나온다 |
| 동점 재대결 | 없다 | 최대 3회. 소진하면 DEADLOCK |

## 인수 기준 후보

번호는 붙이지 않는다. 채번 정본은 [../03_requirements/10_acceptance_criteria.md](../03_requirements/10_acceptance_criteria.md)다.

- 목표 시간 5초·판정 기준 가장 가까운 사람에서 A가 4910ms·B가 5030ms·C가 5420ms로 정지하면 → 절대 오차가 90·30·420ms로 계산되고 B가 선정되며 화면에는 −0.09·+0.03·+0.42초로 표시된다.
- 같은 기록에서 판정 기준이 가장 먼 사람이면 → C가 선정된다.
- START 후 2.00초가 지나면 → 경과 시간 숫자가 가려지고 STOP을 누를 때까지 다시 보이지 않는다.
- STOP을 두 번 누르면 → 최초 1회만 접수되고 두 번째는 상태를 바꾸지 않는다.
- 게임 시작 후 10초 동안 START를 누르지 않으면 → 그 참가자가 미시작으로 확정되고 순위표 맨 뒤에 시작하지 않음으로 표시되며 승자로 선정되지 않는다.
- START 후 목표 + 3초가 지나도록 STOP을 누르지 않으면 → 미정지로 확정되고 시간 초과로 표시되며 승자로 선정되지 않는다.
- 판정 기준이 가장 먼 사람인 판에서 한 참가자가 아무것도 누르지 않으면 → 그 참가자가 선정되지 않고 유효 기록자 중 오차가 가장 큰 사람이 선정된다.
- 클라이언트가 실제보다 1000ms 작은 경과 시간을 보내면 → 서버가 도착 시각 차이와 대조해 거부하고 그 참가자를 기록 무효로 처리한다.
- 클라이언트가 실제보다 100ms 작은 경과 시간을 보내면 → 허용 오차 안이므로 접수된다(이 사실을 공정성 문서가 한계로 등재한다).
- START를 보내지 않고 STOP만 보내면 → 서버가 선행 검사에서 거부한다.
- 두 참가자의 절대 오차가 밀리초까지 같으면 → 동점자 명단이 3초간 표시된 뒤 같은 목표 시간으로 재대결이 시작되고 가이드는 표시되지 않는다.
- 재대결을 3회 실시하고도 동점이면 → 자동 진행이 멈추고 방장에게 다시 시작·대기방으로 선택이 표시된다.
- 전원이 START를 누르지 않은 채 라운드가 마감되면 → 승자를 난수로 정하지 않고 재대결로 넘어가며, 3회 소진 후 방장 선택으로 끝난다.
- 진행 중 다른 참가자의 화면을 보면 → 완료·대기 상태만 보이고 정지 시간·오차가 보이지 않는다.
- 같은 기록 집합으로 판정을 다시 실행하면 → 순위표의 순서가 동일하다(오차 동률의 정렬까지 같다).
