## 1. 공통 진행 규칙

### 1.1 참여 및 권한

- 게임은 **최소 2명, 최대 10명**이 대기방에 있어야 시작할 수 있다.
- 대기방 인원이 최대 정원보다 적어도, **전원이 준비 완료면 시작할 수 있다**([D-12](../DECISIONS.md#d-12)).
- **방장만** 게임 종류·게임 옵션·시작 여부를 정한다. 참여자는 볼 수만 있다.
- 방장이 게임을 시작하면 **모든 참가자 화면이 동시에** 해당 게임으로 전환된다.
- **게임 시작 시점의 참가자 목록을 그 회차의 참가자로 고정**한다.
- 게임이 진행 중인 방에는 새로 들어올 수 없다(`M-04`).

### 1.2 게임 시작 절차

1. 방장이 대기방에서 게임을 고른다.
2. 방장이 게임별 옵션을 설정한다.
3. 참여자 전원이 `준비 완료` 상태가 된다([D-12](../DECISIONS.md#d-12)).
4. 방장이 `게임 시작`을 누른다.
5. 전원 화면에 **가이드 팝업(`M-01`)이 3초간** 표시된다.
   ⚠️ 자동 노출된 가이드는 **`✕`로 닫을 수 없다**([D-10](../DECISIONS.md#d-10), 승인 대기).
6. 가이드가 사라지면 **서버 기준으로** 게임이 시작된다.
7. 게임 중에는 좌상단 `?`로 가이드를 다시 열 수 있고, 이때는 `✕`로 닫힌다.

### 1.3 실시간 동기화 및 판정

- 게임 상태와 결과는 **모든 참가자 화면에서 동일**해야 한다.
- **무작위 결과는 서버가 생성**한다. 클라이언트가 결과를 다시 정하지 않는다([D-13](../DECISIONS.md#d-13)).
- **시간 기반 게임은 화면 애니메이션이 아니라 서버 수신 시각으로 판정**한다([D-14](../DECISIONS.md#d-14)).
- 동일한 입력이 재전송되어도 **한 번만 처리**한다.
- 이미 종료된 회차에 도착한 입력은 판정에 반영하지 않는다.

### 1.4 게임 종료 절차

1. 서버가 최종 당첨자·탈락자·역할 배정을 확정한다.
2. 게임 화면에서 결과를 먼저 연출한다.
3. **3초 뒤 결과 발표 화면으로 자동 이동**한다.
4. 결과 발표 화면에 최종 결과를 크게 표시한다.
5. **모든 참가자**가 결과를 **PNG 이미지로 저장**할 수 있다. (xlsx 미지원)
6. **방장만** `↻ 다시 하기` 또는 `← 대기방으로`를 선택한다.
7. `다시 하기`는 **사전 설정 그대로** 새 라운드를 시작한다.
8. 참여자는 방장이 조작할 때까지 결과 화면에서 대기한다.

### 1.5 이탈 처리

- **이미 확정된 결과는 참가자의 이탈로 변경되지 않는다.**
- 투표·입력을 제출하지 않은 채 이탈하면 **자동 기권**으로 처리하고 라운드는 계속 진행한다([D-15](../DECISIONS.md#d-15)).
- ⚠️ **재접속 경로가 없다.** 소켓이 끊기면 즉시 방에서 제거되고, 새로고침해도 마찬가지다([D-04](../DECISIONS.md#d-04), 승인 대기).

## 2. 게임별 방장 설정 요약

[`06_api/02_socket.md`](../06_api/02_socket.md)의 `configSchema`는 이 표를 근거로 정의한다.

| 게임 | 설정 항목 | 값 | 기본값 |
|---|---|---|---|
| 룰렛 | 결과 항목 | 직접 입력 (역할·벌칙) | — |
| 사다리 | 결과 항목 | 직접 입력, **개수 ≤ 참가자 수** | — |
| 사다리 | 진행 속도 | `빠르게` \| `보통` \| `느리게` | `보통` |
| 킹메이커 | 투표 결과 공개 | `익명` \| `실명` | `익명` |
| 시간초 | 무엇을 정할까 | 프리셋 \| 직접 입력 | — |
| 시간초 | 목표 시간 | `5초` \| `7초` \| `10초` | `5초` |
| 시간초 | 선정 기준 | `오차가 적은 사람` \| `오차가 큰 사람` | `오차가 적은 사람` |
| 저격 | 질문 | 프리셋 \| 직접 입력 | — |
| 저격 | 투표 시간 | 기본 `10초` \| 직접 입력 | `10초` |
| 눈치 | 동시 입력 판정 시간 | `0.3초` \| 하드 `0.5초` | `0.3초` |
| 눈치 | **종료 방식** | `첫 탈락 발생 시 종료` \| `최후의 1명까지 반복` | `첫 탈락 발생 시 종료` |

전 게임 공통으로 `무엇을 정할까?`(팀장 정하기 · 발표자 · 주제 정하기 등)를 대기방 우측 패널에서 설정한다.

> **삭제된 설정** — 킹메이커의 `1인당 투표 수`([D-19](../DECISIONS.md#d-19))와 `최종 결정 방식`([D-21](../DECISIONS.md#d-21))은 구 문서에만 있던 항목으로, 구현하지 않는다.
> **신설된 설정** — 눈치게임의 `종료 방식`([D-25](../DECISIONS.md#d-25))은 두 종료 방식이 정의돼 있는데 고를 수단이 없어 추가했다.

## 3. 동점 · 전원 탈락 공통 처리

### 3.1 동점 (`M-02`)

**대상**: 킹메이커(최다 득표 동점) · 시간초 잡기(절대 오차 동점) · 익명 저격(최다 피격 동점)

방장에게 두 가지 선택지를 준다([D-11](../DECISIONS.md#d-11)).

| 버튼 | 동작 |
|---|---|
| `◀ 대기방으로` | 결정을 포기하고 대기방으로 복귀 |
| `🎲 동점자끼리 다시!` | **동점자만 후보로 두고** 같은 게임을 재진행 |

- 재진행은 **새 라운드가 아니라 같은 `roundId` 안의 `TIE` 단계**다.
- 참여자 화면에서는 두 버튼이 회색 비활성이고 `⏳ 방장이 선택하는 중…`이 표시된다.
- **재투표 횟수에 상한이 없다**([D-16](../DECISIONS.md#d-16)). 무한 반복이 싫으면 방장이 `대기방으로`를 고른다.

### 3.2 전원 탈락 (`M-03`)

**대상**: 눈치게임에서 전원이 동시 입력으로 탈락한 경우

| 버튼 | 동작 |
|---|---|
| `🚪 대기방으로` | 대기방으로 복귀 |
| `🔄 처음부터 다시!` | 같은 설정으로 게임을 처음부터 재시작 |

참여자 화면 처리는 §3.1과 동일하다.
