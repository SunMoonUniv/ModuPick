# 공통 응답 규격

> REST와 WebSocket이 함께 쓰는 규격이다. [`01_rest.md`](01_rest.md) · [`02_socket.md`](02_socket.md)가 이 문서를 따른다.
> 최종 수정: 2026-07-26

---

성공이든 실패든 **모든 응답은 같은 형태**로 내려간다.
소켓의 S→C 이벤트도 이 객체로 감싸며, 각 이벤트의 페이로드는 `data` 안에 들어간다.

**성공**

```json
{
  "success": true,
  "code": "OK",
  "message": null,
  "data": { },
  "timestamp": "2026-07-26T15:04:05+09:00"
}
```

**실패**

```json
{
  "success": false,
  "code": "ROOM_ALREADY_PLAYING",
  "message": "이미 진행 중인 방입니다",
  "data": null,
  "timestamp": "2026-07-26T15:04:05+09:00"
}
```

### 규칙

- **날짜 포맷**: ISO 8601 + 타임존 포함으로 통일한다.
- **HTTP 상태 코드는 그대로 사용**하되, 화면 분기는 `code` 문자열로 판단한다.
  상태 코드는 거들 뿐이고 실제 분기 기준은 항상 `code`다.
- **`message`는 그대로 팝업·토스트에 띄울 수 있는 한글 문구**로 내려준다.
  프론트가 코드별 문구를 따로 관리하지 않아도 되게 한다.
- 소켓 S→C 이벤트의 `data`에는 항상 **`roomVersion`**(증가 정수)이 포함된다.
  클라이언트는 마지막으로 반영한 번호보다 작거나 같은 이벤트를 무시한다.
