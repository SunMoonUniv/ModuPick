# ROOM 계열 화면 — 표지·방 만들기·프로필 설정

> **대상**: ROOM-LANDING · ROOM-CREATE · ROOM-PROFILE 3본과 그 화면 내 요소 1종
> **작성일**: 2026-08-02
> **원천**: frontend/src/screens/Landing.tsx · CreateRoom.tsx · Profile.tsx · frontend/src/components/Modals.tsx · Avatar.tsx · frontend/src/lib/store.ts · data.ts · docs_legacy/requirements.md §4.1 US-101~105 · [../02_features/01_room_join.md](../02_features/01_room_join.md)(F-ROOM 17건) · [01_standards.md](./01_standards.md)

방 밖에서 시작해 대기방 명단에 오르기까지의 표면이다. 로그인·회원가입이 없으므로 이 세 화면이 참여 절차의 전부이며, 설계 목표는 표지에서 대기방까지의 단계를 최소로 줄이는 것이다. 입장은 두 단계로 나뉜다 — **슬롯 선점**(자리를 잡고 토큰을 받는다)과 **프로필 확정**(명단에 등장한다)이며, ROOM-PROFILE이 그 사이에 놓인다. 화면 블록 형식은 [01_standards.md](./01_standards.md) §2를 따른다.

## ROOM-LANDING — 표지

| 항목 | 내용 |
|------|------|
| 화면코드 | ROOM-LANDING |
| 진입 조건 | screen=landing. 앱 최초 진입 · 방 삭제·강퇴·자진 퇴장 후 복귀 |
| 접근 권한 | 전원(방 밖). 역할 개념이 없다 |
| 우선순위 | P0 |
| 구현 상태 | 🔶 |

**목적**: 방을 만들거나 코드로 들어가는 두 경로를 한 화면에 두고, 게임 6종이 무엇인지 눌러 보지 않고도 알게 한다.

**진입경로**: 앱을 열면 처음 보는 화면이다. 방장 이탈·방 삭제·강퇴·자진 퇴장은 전부 이 화면으로 되돌린다. 나가는 길은 둘 — 방 만들기(ROOM-CREATE)와 코드 입장(ROOM-PROFILE)이다.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 표지 구성 | 히어로 문구 · 새 방 만들기 · 코드 입력 · 게임 6종 소개를 한 화면에 둔다 | F-ROOM-01 |
| 게임 6종 미리보기 | 게임 카드 6장을 가로로 흘리고, 카드를 가리키면 옆 패널의 데모가 그 게임으로 바뀐다 | F-ROOM-01 |
| 코드 입력 | 숫자 6자리만 받는다. MODU- 접두어는 고정 표기라 입력 대상이 아니다. 6자리가 차야 참여 버튼이 활성된다 | F-ROOM-06 |
| 입장 실패 안내 | 없는 방·정원 초과·만료는 입력 옆 인라인, 진행 중인 방은 오버레이로 알린다. **어느 경우에도 입력값을 지우지 않는다** | F-ROOM-06 |
| 코드 검증 조회 | 코드로 방 존재·제목·상태·정원·현재 인원을 조회한다(서버) | F-ROOM-05(서버) |
| 입장 검증·슬롯 선점 | 통과하면 대기 상태 슬롯과 참가자 토큰을 발급한다(서버) | F-ROOM-08(서버) |
| 초대 링크 진입 | 초대 링크로 들어오면 코드가 자동 입력된 상태로 프로필 화면을 연다. 거절 조건은 코드 입장과 같다 | F-ROOM-07 |

**주요 UI 요소**: 로고 · 상단 러닝 밴드(가로 마퀴) · 히어로 배지 · 3줄 헤드라인(옐로·핑크·화이트) · 새 방 만들기 버튼 · 코드 입력 필드(고정 접두어 + 숫자 6칸 + 참여 버튼) · 인라인 실패 안내 · 게임 데모 패널(게임별 미니 연출 6종 + 더미 참가자 목록 + 재생 진행 바) · 게임 카드 캐러셀 6장(번호 · 아이콘 · 이름 · 한 줄 부제 · 게임별 틴트) · 진행 중 방 입장 거절 안내 오버레이.

**레이아웃·스크롤·모바일**: 데스크톱은 좌 히어로 + 우 데모 패널 2열이고 하단에 게임 카드 캐러셀이 흐른다. 360px에서는 1열 세로 스택으로 바꿔 히어로 · 방 만들기 · 코드 입력 · 게임 카드 순으로 놓고, **데모 패널은 접어 두었다가 카드를 눌렀을 때만 편다.** 게임 카드 캐러셀은 자체 가로 스크롤 컨테이너 안에서만 흐르며 페이지 가로 스크롤을 만들지 않는다. 페이지 세로 스크롤은 모바일에서만 허용한다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 코드 검증 응답을 기다리는 동안 참여 버튼을 비활성으로 바꾸고 진행 표시를 넣는다. 화면 자체는 서버 데이터를 표시하지 않으므로 스켈레톤을 두지 않는다 |
| 빈 상태 | 해당 없음 — 표지는 서버에서 받아 오는 목록이 없다. 데모 패널의 참가자 목록은 고정 예시이며 실제 접속자가 아니다 |
| 에러 | room.not_found(404) · room.full(409) · room.expired(410)은 코드 입력 옆 인라인 문구로, room.already_playing(409)은 오버레이로 띄운다. 문구는 사유별로 다르게 적고 **입력값은 남긴다** |
| 권한거부 | 해당 없음 — 방 밖 화면이라 역할이 없고 방장 전용 동작도 없다 |

**데이터 연동**

- 참여 버튼 → 코드 검증 조회(F-ROOM-05) → 통과 시 슬롯 선점(F-ROOM-08)으로 토큰 발급 → ROOM-PROFILE 전환.
- 새 방 만들기 → 서버 호출 없이 ROOM-CREATE로 전환한다. 방은 ROOM-CREATE에서 만든다.
- 초대 링크 진입 → 링크의 코드로 F-ROOM-05를 먼저 호출하고 결과에 따라 ROOM-PROFILE 또는 실패 안내로 간다.

**담은 기능ID**: F-ROOM-01 · F-ROOM-05(서버) · F-ROOM-06 · F-ROOM-07 · F-ROOM-08(서버) · F-CMN-07

**비고**

- **코드 입장 경로가 구현되어 있지 않다.** frontend/src/lib/store.ts의 tryJoin은 특정 코드 하나를 진행 중인 방으로 처리하고 나머지는 전부 없는 방으로 돌려준다. 서버가 없어 실제로 들어갈 방이 없기 때문이며, 표지 아래에 그 코드를 알려 주는 데모용 안내 문구도 함께 떠 있다. 정본은 F-ROOM-05·F-ROOM-08의 서버 검증이다.
- **초대 링크 진입 경로가 없다.** 라우터를 두지 않아 링크로 들어올 방법 자체가 없다(F-ROOM-07 미착수).
- 러닝 밴드와 게임 카드 캐러셀은 무한 가로 마퀴다. 모션 저감 선호 시 정지하고 정적 목록으로 대체한다([01_standards.md](./01_standards.md) §7-3).
- 데모 패널의 미니 연출 6종은 실제 게임 화면이 아니라 표지 전용 축약 연출이다. 실제 게임 화면과 규칙 표현이 어긋나지 않게 유지한다 — 눈치게임 데모의 "겹치면 둘 다 탈락" 문구는 정본 규칙과 반대이므로 "혼자 누르면 안전 확정"으로 고친다.

### ROOM-LANDING 내 요소 — 진행 중 방 입장 거절 안내

**노출 조건**: 진행 중인 방의 코드로 입장을 시도하면 열린다(room.already_playing). 배경 클릭 · Esc · 닫기 버튼으로 닫힌다. 액션 버튼을 두지 않는다 — 지금 할 수 있는 일이 없기 때문이다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 진행 중 방 거절 안내 | 게임이 끝날 때까지 기다려야 함을 알린다. 관전 경로를 두지 않으므로 대안을 제시하지 않는다 | F-CMN-07 |
| 입력값 보존 | 닫아도 입력한 코드를 지우지 않는다. 잠시 후 그대로 다시 시도할 수 있다 | F-CMN-07 |

**주요 UI 요소**: 딤 배경 · 확인 모달 프레임 · 상태 배지 · 제목 · 보조 문구 · 닫기 버튼.

**상태·에러**: 이 오버레이는 이미 에러 응답을 받은 결과이므로 자체 로딩·빈 상태·에러가 없다. 권한거부도 해당 없다(방 밖 화면). 닫히면 ROOM-LANDING의 코드 입력 상태로 돌아간다.

**데이터 연동**: F-ROOM-05·F-ROOM-08이 room.already_playing(409)을 돌려주면 열린다. 오버레이가 서버를 다시 호출하지 않는다.

## ROOM-CREATE — 새 방 만들기

| 항목 | 내용 |
|------|------|
| 화면코드 | ROOM-CREATE |
| 진입 조건 | screen=create. 표지의 새 방 만들기 |
| 접근 권한 | 전원(방 밖). 이 화면을 마치는 사람이 그 방의 방장이 된다 |
| 우선순위 | P0 |
| 구현 상태 | 🔶 |

**목적**: 방 제목과 정원만 정해 방을 만들고 초대 코드를 즉시 발급받는다.

**진입경로**: ROOM-LANDING의 새 방 만들기로 들어오고, 홈으로 버튼으로 되돌아간다. 방 만들기를 누르면 ROOM-PROFILE로 넘어가며 이때 방장 슬롯이 대기 상태로 함께 만들어진다.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 방 제목 입력 | 1~30자. 실시간 글자 수 표시. 30자에서 입력을 막는다. **비우면 기본값을 넣는다** | F-ROOM-02 |
| 정원 선택 | 2~10명. 스테퍼 · 빠른 선택 칩 · 슬라이더 **세 컨트롤이 같은 값을 가리킨다.** 어느 하나를 움직이면 나머지 둘이 따라온다 | F-ROOM-02 |
| 정원 확정 고지 | 정원은 방 생성 시 정하고 이후 바꿀 수 없음을 입력 옆과 상태 밴드에 함께 적는다 | F-ROOM-02 |
| 생성 미리보기 | 입력한 제목·정원이 대기방에서 어떻게 보일지 카드로 보여 준다. 코드 자리는 자동 발급 예정 표시로 둔다 | F-ROOM-02 |
| 진행 안내 | 코드 공유 → 코드 입력 입장 → 대기방에서 시작의 3단계를 미리 보여 준다 | F-ROOM-02 |
| 방 생성 | 제목·정원을 보내 방을 만들고 **방장 멤버를 대기 상태로 함께 생성**해 방장 토큰을 받는다(서버) | F-ROOM-03(서버) |
| 초대 코드 발급 | 서버가 숫자 6자리를 발급한다. 살아 있는 방과 충돌하지 않게 정하며 방장이 지정할 수 없다 | F-ROOM-04(서버) |

**주요 UI 요소**: 화면 헤더(제목 · 부제 · 홈으로 버튼) · 방 제목 카드(라벨 · 글자 수 카운터 · 입력) · 정원 카드(스테퍼 · 빠른 선택 칩 5개 · 슬라이더 · 양끝 라벨) · 안내 띠 · 미리보기 카드 · 3단계 안내 카드 · 상태 밴드(유효성 문구 + 방 만들기 버튼).

**레이아웃·스크롤·모바일**: 데스크톱은 좌 폼 + 우 미리보기 2열이다. 360px에서는 1열 세로 스택으로 바꾸고 미리보기를 폼 아래로 내린다. 정원 컨트롤은 **스테퍼와 슬라이더 2종만 남기고 빠른 선택 칩은 접는다** — 칩 5개를 한 줄에 두면 표적이 44px 아래로 내려간다. 스크롤은 모바일의 페이지 세로 스크롤 하나뿐이다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 방 생성 요청 중에는 방 만들기 버튼을 비활성으로 바꾸고 진행 표시를 넣어 중복 생성을 막는다 |
| 빈 상태 | 제목을 입력하기 전에는 미리보기 카드가 자리 표시 문구를 보여 준다. **비어 있어도 방을 만들 수 있다** — 제목이 비면 기본값이 들어간다 |
| 에러 | common.validation_failed(400)는 해당 입력 옆에 인라인으로 띄우고 입력값을 지우지 않는다. 코드 발급 충돌은 서버가 재시도로 흡수하므로 화면에 노출하지 않는다 |
| 권한거부 | 해당 없음 — 방을 만들기 전이라 역할이 없다 |

**데이터 연동**

- 방 만들기 → F-ROOM-03으로 방과 방장 대기 슬롯을 만들고 방장 토큰과 초대 코드(F-ROOM-04)를 받는다 → ROOM-PROFILE 전환.
- 정원 값은 이 요청에서 확정되며 이후 어떤 화면도 바꾸지 않는다.

**담은 기능ID**: F-ROOM-02 · F-ROOM-03(서버) · F-ROOM-04(서버)

**비고**

- **제목이 비면 만들기 버튼이 비활성이다.** 정본은 비워도 기본값을 넣는 것이므로(F-ROOM-02) 구현을 고친다.
- **정원 기본값이 8이다.** 정본 기본값은 10이다([../05_game_rules/01_common.md](../05_game_rules/01_common.md) 방 생성 시 설정).
- **초대 코드를 클라이언트가 난수로 만든다.** 정본은 서버 발급이다(F-ROOM-04).
- 미리보기 카드는 실제 대기방 카드와 같은 형태를 써서 어긋나지 않게 유지한다.

## ROOM-PROFILE — 프로필 설정

| 항목 | 내용 |
|------|------|
| 화면코드 | ROOM-PROFILE |
| 진입 조건 | screen=profile. 방 생성 직후(방장) · 코드·링크 입장 검증 통과 직후(참가자) |
| 접근 권한 | 슬롯을 선점한 사람. 토큰 없이는 열리지 않는다 |
| 우선순위 | P0 |
| 구현 상태 | 🔶 |

**목적**: 결과 화면에서 자기를 알아볼 수 있도록 닉네임·아바타·소개 태그를 한 번에 정하고 대기방 명단에 오른다.

**진입경로**: ROOM-CREATE에서 방을 만들었거나 ROOM-LANDING에서 코드 검증을 통과하면 들어온다. 입장하기를 누르면 LOBBY-MAIN으로 가고, 뒤로 가면 슬롯을 반납하고 ROOM-LANDING으로 돌아간다. **프로필은 여기서 한 번만 확정하며 대기방에 들어간 뒤에는 바꿀 수 없다.**

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 닉네임 입력 | 1~8자. 실시간 글자 수 표시. 공백만으로는 확정할 수 없다 | F-ROOM-09 |
| 닉네임 중복 안내 | **중복을 거절하지 않는다.** 같은 닉네임이 있으면 서버가 접미 숫자를 붙여 확정하므로, 화면은 그렇게 될 수 있음을 입력 옆에 미리 알리고 확정 뒤에는 **서버가 돌려준 닉네임**을 쓴다 | F-ROOM-12 |
| 아바타 선택 | 30종을 5×3 격자에 두고 좌우로 페이지를 넘긴다. 페이지를 넘겨도 선택은 유지된다 | F-ROOM-09 |
| 아바타 랜덤 뽑기 | 아직 선점되지 않은 아바타 중 하나를 뽑아 넣는다 | F-ROOM-09 |
| 소개 태그 입력 | 최대 24자. 비워 둘 수 있다 | F-ROOM-09 |
| 프로필 미리보기 | 고른 아바타·닉네임·소개 태그가 대기방 카드에서 어떻게 보일지 실시간으로 보여 준다. 참가 순번도 함께 표시한다 | F-ROOM-09 |
| 입장 게이팅 | 닉네임이 1~8자면 입장 버튼이 활성된다. **아바타를 고르지 않아도 막지 않는다** — 서버가 남은 것 중 하나를 배정한다 | F-ROOM-09 |
| 아바타 선점 현황 | 30종 각각의 선점 여부를 내려주고 **다른 사람이 확정하는 순간 잠근다.** 잠긴 타일은 회색·점선으로 바꾸고 누가 가져갔는지 적으며 선택할 수 없게 한다 | F-ROOM-10(서버) |
| 프로필 확정 | 닉네임 규칙·중복·아바타 선점을 검증하고 대기 상태를 활성 상태로 올려 명단에 등장시킨다 | F-ROOM-11(서버) |
| 닉네임 중복 처리 | 같은 방에 같은 닉네임이 있으면 뒤에 숫자를 붙여 구분한다. 판정 기준은 서버가 가진 명단이다 | F-ROOM-12(서버) |
| 아바타 자동 배정 | 아바타를 고르지 않고 확정하면 남은 것 중 하나를 서버가 배정한다 | F-ROOM-13(서버) |
| 프로필 변경 잠금 | 확정 이후 이 화면으로 되돌아오는 경로를 두지 않는다 | F-ROOM-14 |
| 미확정 슬롯 회수 | 유예 시간 안에 확정하지 않으면 서버가 슬롯을 풀어 정원을 되돌린다. 회수되면 사유와 함께 ROOM-LANDING으로 보낸다 | F-ROOM-15(서버) |

**주요 UI 요소**: 배지 · 제목 · 부제 · 방 정보 표기(방 이름 · 코드) · 뒤로가기 · 플레이어 카드(헤더 · 순번 배지 · 아바타 히어로 · 닉네임 · 소개 태그 · 참가 순번 문구) · 입장 버튼 · 안내 pill · 닉네임 입력(카운터 · 중복 경고) · 소개 태그 입력 · 아바타 격자 5×3 · 페이지 표시 · 좌우 페이징 버튼 · 랜덤 뽑기 버튼.

**레이아웃·스크롤·모바일**: 데스크톱은 좌 플레이어 카드 + 우 입력·아바타 격자 2열이다. 360px에서는 1열로 바꿔 플레이어 카드를 상단 축약 띠로 줄이고, 아바타 격자를 **3열 × N행**으로 편다. 타일 한 변은 96px 이상을 확보한다. 페이징 버튼은 44 × 44 표적 상자를 갖고 격자 아래 중앙에 둔다 — 좌우 끝에 두면 한 손 조작 범위를 벗어난다. 스크롤은 모바일의 페이지 세로 스크롤 하나뿐이며 아바타 격자에 자체 스크롤을 만들지 않는다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 아바타 선점 현황이 도착하기 전에는 격자 타일을 스켈레톤으로 그린다. 확정 요청 중에는 입장 버튼을 비활성으로 바꾸고 진행 표시를 넣는다 |
| 빈 상태 | 닉네임·아바타를 고르기 전 플레이어 카드가 자리 표시 상태로 보인다. **선택 가능한 아바타가 하나도 남지 않는 경우는 없다** — 정원 10명 < 아바타 30종이므로 항상 남는다 |
| 에러 | member.nickname_invalid(400) · member.bio_too_long(400)은 해당 입력 옆, member.avatar_taken(409) · member.avatar_invalid(400)은 해당 타일 위, room.full(409) · room.expired(410) · common.session_expired(401)는 화면 전체 안내로 띄우고 ROOM-LANDING으로 보낸다. **중복 닉네임은 에러가 아니다** — 거부 코드를 두지 않는다 |
| 권한거부 | 해당 없음 — 자기 프로필만 다루므로 방장 전용 동작이 없다 |

**데이터 연동**

- 화면 진입 → 아바타 선점 현황 구독(F-ROOM-10). 다른 사람이 확정할 때마다 잠금 상태가 밀려 들어온다.
- 입장하기 → 프로필 확정(F-ROOM-11). 서버가 닉네임 중복(F-ROOM-12)·아바타 자동 배정(F-ROOM-13)을 여기서 적용한다 → LOBBY-MAIN 전환 + 명단 등장 브로드캐스트.
- 뒤로가기 → 슬롯 반납(F-ROOM-17) → ROOM-LANDING.
- 유예 시간 초과 → 서버가 슬롯을 회수(F-ROOM-15)하고 사유와 함께 ROOM-LANDING으로 보낸다.

**담은 기능ID**: F-ROOM-09 · F-ROOM-10(서버) · F-ROOM-11(서버) · F-ROOM-12(서버) · F-ROOM-13(서버) · F-ROOM-14 · F-ROOM-15(서버)

**비고**

- **닉네임 중복을 입력 단계에서 거절한다.** 하드코딩된 봇 목록과 대조해 경고를 띄우고 입장 버튼을 잠근다. 정본은 거절하지 않고 서버가 접미 숫자를 붙여 확정하는 것이며(F-ROOM-12) 그래서 거부 에러 코드도 두지 않는다.
- **아바타 선점 현황이 봇 스크립트다.** 방을 만든 뒤 정해진 시간에 세 개가 순서대로 잠긴다. 정본은 서버 구독이다(F-ROOM-10).
- **아바타를 고르지 않고는 입장할 수 없다.** 정본은 고르지 않아도 서버가 배정하는 것이다(F-ROOM-13). 입장 게이팅 조건에서 아바타를 빼고 자동 배정을 안내 문구로 알린다.
- **미확정 슬롯 회수가 없다.** 유예 시간·회수 경로가 구현되어 있지 않아 들어오다 만 사람이 자리를 영구히 점유한다(F-ROOM-15).
- 아바타 이미지는 직접 제작한 캐릭터 30종을 쓰고 이모지로 대체하지 않는다. 이미지 자체는 장식이므로 대체 텍스트를 비우고 이름은 옆 텍스트가 담당한다.
