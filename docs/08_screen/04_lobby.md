사람이 모이고 무엇을 어떻게 할지 정하는 화면이다. 두 화면은 데스크톱에서 같은 표면에 병치되지만 다루는 일이 다르다 — **LOBBY-MAIN은 누가 있고 무슨 이야기를 하는가**, **SETUP-GAME은 무슨 게임을 어떤 설정으로 할 것인가**다. 조작 축도 다르다. 대기방은 전원이 쓰고, 게임 선택·설정은 방장만 조작하며 참가자는 읽기 전용으로 본다. 화면 블록 형식은 [01_standards.md](./01_standards.md) §2를 따른다.

## LOBBY-MAIN — 실시간 대기방

| 항목 | 내용 |
|------|------|
| 화면코드 | LOBBY-MAIN |
| 진입 조건 | screen=lobby. 프로필 확정 직후 · 결과 화면에서 대기방 복귀 |
| 접근 권한 | 방장·참가자 전원. 강퇴·나가기 버튼만 역할에 따라 다르다 |
| 우선순위 | P0 |
| 구현 상태 | 🔶 |

**목적**: 누가 들어왔고 누가 준비됐는지 한눈에 보이게 하고, 기다리는 시간을 대화로 채운다.

**진입경로**: ROOM-PROFILE에서 프로필을 확정하면 들어온다. RESULT-MAIN에서 방장이 대기방으로를 고르면 전원이 되돌아온다. 나가는 길은 셋 — 게임 시작(게임 화면) · 나가기(ROOM-LANDING) · 방 삭제(ROOM-LANDING)다.

**주요 UI 요소**: 화면 헤더(방 이름 · 실시간 부제 · 방장 표시 · 코드 배지 · 인원/READY 배지) · 참가자 무대(라벨 + 카드 목록 + 빈자리 점선 행) · 참가자 카드(아바타 · 왕관 · 닉네임 · 소개 태그 · 상태 배지 · 강퇴 버튼) · 채팅 패널(제목 · 메시지 목록 3종 · 입력 중 표시 · 입력창 + 글자 수 + 전송 버튼) · 상태 밴드(SETUP-GAME과 공유) · 오버레이 4종.

**레이아웃·스크롤·모바일**: 데스크톱은 좌 참가자 + 중 채팅 + 우 게임 선택·설정 3열이고 세 열의 상단선을 맞춘다. 스크롤 소유자는 참가자 목록과 채팅 로그 둘이며 페이지 스크롤을 만들지 않는다.

360px에서는 **탭 3개(참가자 · 채팅 · 게임)로 분리한다.** 상단에 방 코드·인원·READY 요약 띠를 고정하고 하단에 액션 바(방장은 게임 시작 · 참가자는 준비 완료, 공통으로 나가기)를 고정한다. 다른 탭에서 일어난 일은 탭 배지로 알린다 — 새 메시지 수 · 새 입장 · 방장의 게임 변경. **탭이 바뀌어도 하단 액션 바는 자리를 지킨다.** 채팅 입력창이 열리면 키보드 높이만큼 목록을 밀어 올려 입력창이 가려지지 않게 한다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 방 스냅샷이 도착하기 전에는 참가자 카드와 채팅 목록을 스켈레톤으로 그린다. 준비 토글·채팅 전송 중에는 해당 컨트롤만 비활성으로 바꾼다 |
| 빈 상태 | **사유를 구분한다.** 나 혼자 있으면 "아직 아무도 안 왔어요 · 코드를 공유해 보세요"로 코드 복사를 유도하고, 채팅이 비어 있으면 "첫 메시지를 남겨 보세요"로 안내한다. 정원이 다 차면 빈자리 행 자체를 그리지 않는다 |
| 에러 | common.validation_failed(400)는 채팅 입력 옆, member.not_host(403)는 토스트, common.session_expired(401) · room.expired(410)는 화면 전체 안내 후 표지 이동. 클립보드 복사 실패는 토스트로 알리고 코드를 선택 가능한 텍스트로 노출해 손으로 복사할 길을 남긴다 |
| 권한거부 | 참가자가 강퇴를 시도하면 member.not_host(403)를 **보낸 사람에게만** 토스트로 알린다. 애초에 참가자 화면에는 강퇴 버튼을 그리지 않는다 |

**데이터 연동**

- 화면 진입 → 방 스냅샷 수신(참가자 명단 · 정원 · 준비 수 · 선택된 게임 · 설정) 후 실시간 구독 시작.
- 준비 토글(F-LOBBY-04) → 서버가 준비 수를 다시 세어 전원에게 브로드캐스트. **클라이언트가 목록을 세어 표시하지 않는다.**
- 채팅 전송(F-LOBBY-07) → 서버 중계 → 전원 수신. 저장하지 않는다.
- 강퇴(F-LOBBY-11) → 서버 검증(방장 여부 · 대상이 자기 자신이 아님 · 방 상태가 대기) → 명단 갱신 브로드캐스트 + 대상은 표지로.
- 나가기(F-ROOM-17) → 방장이면 방 삭제 → 전원에게 방장 이탈 안내. 참가자면 본인 명단 제거 브로드캐스트.
- 무활동 만료(F-LOBBY-13) → 서버가 방을 삭제하고 사유와 함께 전원을 표지로 보낸다.

**담은 기능ID**: F-LOBBY-01 · F-LOBBY-02 · F-LOBBY-03(서버) · F-LOBBY-04 · F-LOBBY-05 · F-LOBBY-07 · F-LOBBY-08 · F-LOBBY-09 · F-LOBBY-10 · F-LOBBY-11 · F-LOBBY-12(서버) · F-LOBBY-13(서버) · F-ROOM-16 · F-ROOM-17 · F-CMN-05 · F-CMN-06 — 합 **16건**

**비고**

- **참가자 시점이 구현되어 있지 않다.** 프로토타입은 방장 한 명의 시점으로만 만들어졌고 나머지는 봇이다. 그래서 **준비 완료 토글 표면 자체가 없고**, 대신 발표용 보조 조작(단축키로 봇 전원을 준비 상태로 만드는 장치)이 들어 있다. 참가자 시점의 준비 토글·읽기 전용 게이팅·나가기가 전부 미착수다.
- **참가자 목록·채팅·준비가 전부 시간 지연 스크립트다.** 정해진 순서로 봇이 들어오고 말하고 준비한다. 서버 구독이 아니다.
- **강퇴 버튼이 27 × 27이다.** 파괴적 동작인데 표적이 규격의 3분의 1이고 옆 배지와 붙어 있다([01_standards.md](./01_standards.md) §5-5).
- **초대 코드만 복사한다.** 정본은 초대 링크 복사 + 공유 시트다(F-ROOM-16).
- 상태 밴드의 안내 문구가 "2명 이상이면 시작할 수 있어요"로 고정되어 있으나 게임별 최소 인원은 2 또는 3이다. 선택된 게임의 최소 인원을 그대로 적는다.
- 무활동 만료 표시가 없다. 남은 시간을 상시 노출하면 대기 자체가 압박이 되므로, **만료 2분 전부터만** 상태 밴드에 안내를 띄우고 아무 조작에나 갱신되게 한다.

### LOBBY-MAIN 내 요소 — 방장 이탈·방 삭제 안내

**노출 조건**: 방장이 나가거나 연결이 끊기거나 무활동으로 방이 만료되면 남은 전원에게 열린다. **오버레이 중 우선순위가 가장 높아** 다른 오버레이가 열려 있으면 치우고 대체한다. LOBBY-MAIN · SETUP-GAME · 게임 6종 · RESULT-MAIN 어디서든 뜬다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 방 삭제 사유 안내 | 방장 이탈 · 마지막 참가자 이탈 · 무활동 만료 중 **어느 것인지 구분해** 적는다 | F-CMN-06 |
| 표지 복귀 | 확인을 누르면 방 상태를 전부 비우고 표지로 보낸다. 진행 중이던 판은 결과 없이 끝난다 | F-LOBBY-12(서버) · F-LOBBY-13(서버) |

**주요 UI 요소**: 딤 배경 · 안내 카드 프레임 · 대형 배지 원 · 제목 · 사유 문구 · 표지로 돌아가기 버튼.

**상태·에러**: 이 오버레이는 서버가 보낸 종료 통지의 결과이므로 자체 로딩·빈 상태·에러가 없다. 권한거부도 해당 없다 — 전원에게 똑같이 뜬다. **닫는 경로는 표지 복귀 하나뿐이다.** 배경 클릭으로 닫아도 표지로 가며 방이 남아 있는 것처럼 보이는 상태를 만들지 않는다.

**데이터 연동**: 서버의 방 종료 통지 수신 → 오버레이 표시 → 확인 시 로컬 방 상태 초기화 → ROOM-LANDING. 클라이언트가 서버를 다시 호출하지 않는다.

**비고**: 현행 구현은 사유가 방장 이탈 하나로 고정되어 있고, 발표 시연용 단축키로 열린다. 무활동 만료·마지막 참가자 이탈 경로가 없다.

### LOBBY-MAIN 내 요소 — 참가자 강퇴 확인

**노출 조건**: 방장이 참가자 카드의 강퇴 버튼을 누르면 열린다. **방 상태가 대기일 때만** 열리며 게임 진행 중에는 버튼 자체가 없다 — 명단 스냅샷이 고정되기 때문이다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 강퇴 확인 | 대상 닉네임을 문구에 넣어 누구를 내보내는지 분명히 한다. 취소가 기본 위치, 실행이 강조 위치다 | F-LOBBY-11 |
| 재입장 가능 고지 | 내보낸 사람이 같은 코드로 다시 들어올 수 있음을 함께 적는다. **영구 차단 목록을 두지 않는다** | F-LOBBY-11 |

**주요 UI 요소**: 딤 배경 · 확인 모달 프레임 · 경고 배지 · 대상 닉네임을 담은 제목 · 재입장 안내 문구 · 취소 버튼 · 실행 버튼.

**상태·에러**: 실행 중에는 두 버튼을 함께 잠가 중복 요청을 막는다. 빈 상태는 해당 없다. member.not_host(403) · game.invalid_action(409, 진행 중 시도)은 오버레이를 닫고 토스트로 알린다. 권한거부는 방장에게만 열리는 표면이라 정상 경로에서 발생하지 않으며, 발생하면 세션이 바뀐 경우이므로 방 스냅샷을 다시 받는다. **배경 클릭으로 닫히지 않는다**(§3-1).

**데이터 연동**: 실행 → 강퇴 요청(F-LOBBY-11) → 서버 검증 → 명단 갱신 브로드캐스트 + 시스템 메시지. 대상에게는 사유와 함께 표지 이동 통지가 간다.

### LOBBY-MAIN 내 요소 — 방장 나가기 확인

**노출 조건**: 방장이 나가기를 누르면 열린다. LOBBY-MAIN · SETUP-GAME · 게임 6종 · RESULT-MAIN 어디서든 같은 형태로 뜬다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 방 삭제 경고 | 나가면 방이 사라지고 전원이 표지로 간다는 사실을 확인 문구에 넣는다. 게임 진행 중이면 **판이 결과 없이 끝난다**는 것도 함께 적는다 | F-ROOM-17 |
| 방 삭제 실행 | 확인하면 방·참가자·결과·시드를 지우고 초대 코드를 무효화한다 | F-ROOM-17 |

**주요 UI 요소**: 딤 배경 · 확인 모달 프레임 · 경고 배지 · 제목 · 결과 설명 · 취소 버튼 · 실행 버튼.

**상태·에러**: 실행 중 두 버튼을 잠근다. 빈 상태·권한거부는 해당 없다(방장 전용 표면). common.session_expired(401)면 이미 방이 없는 것이므로 오버레이를 닫고 표지로 보낸다. 배경 클릭으로 닫히지 않는다.

**데이터 연동**: 실행 → 나가기 요청(F-ROOM-17, 방장) → 서버가 방을 삭제 → 남은 전원에게 방장 이탈 안내 브로드캐스트 → 본인은 표지로.

### LOBBY-MAIN 내 요소 — 참가자 나가기 확인

**노출 조건**: 참가자가 나가기를 누르면 열린다. 방장의 것과 **문구도 결과도 다르다**([01_standards.md](./01_standards.md) §3-3).

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 나가기 확인 | 다시 들어오려면 코드를 새로 입력해야 함을 알린다. **재접속 경로가 없다** | F-ROOM-17 |
| 진행 중 경고 | 게임 진행 중이면 후보로 남아 미입력 처리된다는 사실을 함께 적는다. 나가도 결과에서 사라지지 않는다 | F-ROOM-17 |

**주요 UI 요소**: 딤 배경 · 확인 모달 프레임 · 배지 · 제목 · 결과 설명 · 취소 버튼 · 실행 버튼.

**상태·에러**: 실행 중 두 버튼을 잠근다. 빈 상태·권한거부는 해당 없다. common.session_expired(401)면 이미 나간 상태이므로 표지로 보낸다. 배경 클릭으로 닫히지 않는다.

**데이터 연동**: 실행 → 나가기 요청(F-ROOM-17, 참가자) → 서버가 명단에서 제거(진행 중이면 후보로 유지하고 이탈 표시) → 남은 전원에게 명단 갱신 브로드캐스트 → 본인은 표지로.

**비고**: **이 오버레이는 표면이 없다.** frontend/src/lib/types.ts의 오버레이 종류 목록에 나가기 확인이 선언되어 있으나 frontend/src/components/Modals.tsx에 대응 분기가 없어 어디서도 열리지 않는다. 참가자 시점 자체가 미구현인 것과 같은 뿌리다.

## SETUP-GAME — 게임 선택·설정

| 항목 | 내용 |
|------|------|
| 화면코드 | SETUP-GAME |
| 진입 조건 | screen=lobby의 게임 선택·설정 표면. 데스크톱은 LOBBY-MAIN과 병치, 360px은 탭 전환 |
| 접근 권한 | **방장 조작 / 참가자 읽기 전용**(비활성 + 사유 표시) |
| 우선순위 | P0 |
| 구현 상태 | 🔶 |

**목적**: 무슨 게임을 어떤 조건으로 할지 방장이 정하고, 참가자는 그것을 보면서 무엇이 정해지는지 알게 한다.

**진입경로**: LOBBY-MAIN과 같은 상태값에 놓인 표면이므로 대기방에 들어오면 바로 보인다. 360px에서는 게임 탭으로 들어온다. 게임 시작을 누르면 선택한 게임의 화면으로 전원이 동시에 넘어간다.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 게임 카탈로그 | 6종을 아이콘·이름·한 줄 설명·최소 인원과 함께 보여 준다. **서버 난수·투표·실력 분류는 표시하지 않는다** | F-SETUP-01 |
| 최소 인원 미달 잠금 | 현재 인원으로 시작할 수 없는 게임은 고를 수 없게 잠그고 **몇 명부터 가능한지** 카드 위에 적는다 | F-SETUP-02 |
| 게임 선택 동기화 | 방장이 카드를 누르면 전원 화면에 반영되고 해당 게임의 기본 설정값이 함께 내려온다. 시스템 메시지가 채팅에 남는다 | F-SETUP-03 |
| 랜덤 게임 선택 | 시작 가능한 게임만 후보로 두고 **서버가** 무작위로 고른다. 뽑힌 뒤에도 설정을 조절하거나 다시 뽑을 수 있다 | F-SETUP-04 |
| 주제 템플릿 칩 | 게임 종류에 맞는 템플릿 계열을 칩으로 노출하고 맨 오른쪽에 직접 입력 진입을 둔다 | F-SETUP-05 |
| 주제 직접 입력 | 직접 입력은 12자, **질문형(익명 저격)만 30자**다. 공백만으로는 확정할 수 없다 | F-SETUP-06 |
| 게임별 설정 패널 | 선택된 게임의 설정 항목만 노출한다. 항목·타입·범위는 서버가 준 규격을 따르고 참가자에게는 읽기 전용으로 보인다 | F-SETUP-07 |
| 설정 변경 동기화 | 방장의 변경이 전원 화면에 즉시 반영된다. 잦은 입력은 묶어 보내되 최종 값은 반드시 일치시킨다 | F-SETUP-08 |
| 게임 교체 시 설정 초기화 | 게임을 바꾸면 주제를 포함한 모든 설정이 기본값으로 돌아간다. 그 사실을 설정 패널에 상시 표시한다 | F-SETUP-09 |
| 설정값 서버 검증 | 항목·타입·범위·게임 일치를 서버가 다시 검사하고 위반하면 거절한다. **화면이 막았다는 사실을 신뢰하지 않는다** | F-SETUP-10(서버) |
| 참가자 읽기 전용 | 참가자에게는 전 컨트롤을 비활성으로 두고 잠금 표시와 "방장이 고르는 중" 사유를 함께 보인다. **감추지 않는다** | F-SETUP-07 |
| 규칙 열람 | 게임을 고르면 한 줄 요약·진행 단계·판정 기준을 열어 볼 수 있다. **방장뿐 아니라 전원**이 연다 | F-SETUP-13 |
| 시작 게이트 | 방장을 제외한 참가자 전원이 준비 완료가 아니면 시작 버튼을 막고 남은 인원과 이유를 보인다 | F-LOBBY-06 |
| 게임 시작 | 방장 전용. 시작 조건을 검사하고 **참가자 명단을 스냅샷으로 고정**한 뒤 전원을 동시에 게임 화면으로 보낸다 | F-SETUP-11 |
| 룰렛 설정 | 주제 하나를 정한다 | F-WHEEL-01 |
| 사다리 설정 | 도착 항목 목록(세트 선택 또는 직접 편집)과 진행 속도 3단을 정한다. 항목당 12자, 최소 1개다 | F-LADDER-01 |
| 사다리 항목 수 자동 맞춤 | 항목이 참가자보다 적으면 채우고 많으면 뒤에서부터 잘라낸 뒤 **어떻게 맞춰졌는지 방장에게 보여 준다** | F-LADDER-02 |
| 킹메이커 설정 | 주제 · 1인 투표 수 · 결과 실명 공개 여부를 정한다 | F-KING-01 |
| 시간초 설정 | 주제 · 목표 시간 · 판정 기준을 정한다 | F-TIMER-01 |
| 저격 설정 | 질문 주제 · 투표 시간 · 중복 투표 허용 · 지목자 공개 여부를 정한다 | F-SNIPE-01 |
| 눈치 설정 | 주제 · 판정창 폭 · 라운드 제한 시간을 정한다 | F-NUNCHI-01 |

**주요 UI 요소**: 섹션 제목 · 조작 주체 안내 · 게임 카드 6장(아이콘 타일 · 이름 · 부제 · 선택 표시 · 최소 인원 배지) · 설정 패널(게임 이름 · 초기화 안내 · 주제 칩 열 + 직접 입력 · 게임별 설정 칩 열 · 사다리 항목 편집기) · 상태 밴드(LOBBY-MAIN과 공유 — 랜덤 게임 버튼 · 게임 시작 버튼 · 나가기 버튼).

**레이아웃·스크롤·모바일**: 데스크톱은 대기방 3열의 우측 열이며 게임 카드 2열 그리드 위에 설정 패널을 둔다. 스크롤 소유자는 설정 패널 하나다. 360px에서는 게임 탭 전체를 차지하고 **게임 카드를 1열로 편다** — 2열로 두면 카드 높이가 44px 아래로 눌린다. 설정 패널은 카드 목록 아래에 이어 붙이고 페이지 세로 스크롤로 흐른다. 게임 시작 버튼은 하단 고정 액션 바에 두어 스크롤과 무관하게 항상 닿게 한다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 방 스냅샷 도착 전에는 게임 카드를 스켈레톤으로 그린다. 설정 변경 요청 중에는 해당 컨트롤만 잠근다 |
| 빈 상태 | **사유를 구분한다.** 게임을 아직 고르지 않았으면 설정 패널에 "게임을 고르면 설정이 여기에 나타나요"를, 인원이 모자라 고를 수 있는 게임이 없으면 "3명부터 시작할 수 있는 게임이에요 · 한 명만 더 오면 돼요"를 띄운다. 사다리 항목이 비면 최소 1개가 필요함을 알린다 |
| 에러 | game.not_enough_members(409) · game.invalid_config(400) · game.invalid_action(409)은 해당 컨트롤 옆 또는 상태 밴드에 띄우고 **선택·설정 값을 되돌리지 않는다.** 서버가 값을 거부하면 직전 유효값으로 되돌리고 사유를 적는다 |
| 권한거부 | 참가자가 게임 선택·설정·시작·랜덤 선택을 시도하면 member.not_host(403)를 **보낸 사람에게만** 토스트로 알린다. 참가자 화면의 컨트롤은 이미 비활성 + 잠금 표시 상태다 |

**데이터 연동**

- 게임 선택(F-SETUP-03) → 서버 검증(방장 여부 · 방 상태 대기 · 인원 ≥ 최소 인원) → 선택 게임 + 기본 설정 브로드캐스트.
- 랜덤 선택(F-SETUP-04) → **서버가 후보를 추리고 뽑아** 결과만 브로드캐스트. 클라이언트가 뽑지 않는다.
- 설정 변경(F-SETUP-08) · 사다리 항목 편집(F-LADDER-01) → 서버 검증(항목·범위) → 전원 브로드캐스트. 사다리는 서버가 인원 수에 맞춘 결과를 함께 내려준다.
- 게임 시작(F-SETUP-11) → 서버 검증 → **참가자 명단 스냅샷 고정** + 전원 동시 화면 전환. 이후 새 입장을 받지 않는다.

**담은 기능ID**: F-SETUP-01 · F-SETUP-02 · F-SETUP-03 · F-SETUP-04 · F-SETUP-05 · F-SETUP-06 · F-SETUP-07 · F-SETUP-08 · F-SETUP-09 · F-SETUP-10(서버) · F-SETUP-11 · F-SETUP-13 · F-LOBBY-06 · F-WHEEL-01 · F-LADDER-01 · F-LADDER-02 · F-KING-01 · F-TIMER-01 · F-SNIPE-01 · F-NUNCHI-01 — 합 **20건**

**비고**

- **설정 항목이 정본 16항 중 13항만 있다.** 빠진 셋은 아래와 같으며 전부 정본에 있는 항목이다.

| 게임 | 빠진 설정 | 정본 |
|------|-----------|------|
| 익명 저격 | 투표 시간 | 기본 10초 · 5~60초 직접 입력. 현행은 값이 고정되어 컨트롤 자체가 없다 |
| 익명 저격 | 지목자 공개 | 비공개(기본) · 공개. 현행에 없다 |
| 눈치게임 | 라운드 제한 시간 | 10 · 15 · 20초. 현행은 15초로 코드에 박혀 있고 설정 항목에도 없다 |

- **킹메이커 1인 투표 수의 범위가 다르다.** 현행은 1회·2회 2단이고 정본은 1·2·3표 3단이다.
- **참가자 읽기 전용 게이팅이 없다.** 방장 시점만 구현되어 있어 비활성·잠금 표시·사유 문구가 전부 미착수다. 서버 재검증도 없다.
- **랜덤 게임 선택을 클라이언트가 뽑는다.** 정본은 서버 추첨이다(F-SETUP-04).
- **규칙 열람 표면이 대기방에 없다.** 지금은 게임이 시작된 뒤 가이드로만 볼 수 있어 "몰라서 지지 않게 한다"는 목적을 시작 전에 달성하지 못한다. 게임 카드에 규칙 보기 진입점을 둔다(F-SETUP-13).
- 주제 직접 입력 상한이 16자다. 정본은 12자이며 질문형만 30자다.
- 사다리 항목이 인원 수에 맞춰지는 과정을 방장에게 보여 주지 않는다. 정본은 부족분 자동 채움·초과분 잘림을 화면에 표시하는 것이다(F-LADDER-01).
