게임 6종의 화면이다. 여섯은 같은 골격을 쓴다 — 화면 헤더(주제·게임 이름·가이드 재열기) · 진행 상황 · 연출 영역 · 입력 요소 · 상태 밴드다. 게임마다 다른 것은 연출과 입력뿐이며 나머지는 [01_standards.md](./01_standards.md)의 공통 패턴을 그대로 따른다.

**이 문서는 판정 규칙을 정의하지 않는다.** 규칙의 정본은 [../05_game_rules](../05_game_rules/README.md)이며 본 문서는 그 규칙이 화면에 어떻게 드러나는가만 확정한다. 규칙과 화면이 어긋나 보이면 규칙이 이긴다.

## 여섯이 공유하는 것

| 항목 | 규격 |
|------|------|
| 진입 | screen=game으로 전환되면 selectedGame 값이 여섯 중 하나를 고른다. 전원이 서버 기준으로 **동시에** 넘어온다 |
| 가이드 | 시작 직후 3초간 자동으로 뜬다. 다시 하기·결선·재대결·무효 라운드 재시작에서는 뜨지 않는다. 게임 중에는 헤더의 가이드 버튼으로 다시 연다 |
| 이탈 | 참가자가 나가도 게임은 계속되고 그 사람은 후보로 남아 미입력 처리된다. **방장이 나가면 방이 삭제되고 판은 결과 없이 끝난다** — 게임이 멈추는 경우는 이것뿐이다 |
| 중간 집계 | 완료·대기 상태만 보인다. 입력 내용·기록·득표는 마감 전까지 **누구에게도** 보이지 않으며 이 제한은 방장에게도 같다 |
| 결과 전환 | 결과 연출이 끝나 결과가 공개된 시점부터 3초 뒤에 전원이 RESULT-MAIN으로 넘어간다 |
| 나가기 | 상태 밴드에 나가기를 두고 역할에 따라 다른 확인 오버레이를 연다([04_lobby.md](./04_lobby.md)) |
| 모바일 | 헤더 · 진행 상황 · 연출 영역 · **하단 고정 입력 버튼** 순으로 배치한다. 입력 버튼은 스크롤과 무관하게 항상 화면 안에 있다([01_standards.md](./01_standards.md) §6) |

**게임 6종 공통이 담은 기능ID**: F-PLAY-01(서버) · F-PLAY-02(서버) · F-PLAY-03(서버) · F-PLAY-04 · F-PLAY-05 · F-PLAY-06 · F-PLAY-07(서버) · F-PLAY-08(서버) · F-PLAY-09(서버) · F-PLAY-10 · F-PLAY-11 · F-SETUP-12 — 합 **12건**.

여섯이 똑같이 담는 기능은 여기서 한 번만 센다. 게임별 화면 블록의 담은 기능ID에는 넣지 않으며, 화면별 집계에서도 **게임 6종 공통** 한 줄로 계상한다 — 그렇게 하지 않으면 같은 기능이 여섯 번 세어져 화면별 무게가 왜곡된다([02_traceability.md](./02_traceability.md)).

## WHEEL-PLAY — 운명의 룰렛

| 항목 | 내용 |
|------|------|
| 화면코드 | WHEEL-PLAY |
| 진입 조건 | screen=game · selectedGame=roulette |
| 접근 권한 | **방장 입력(PICK 1회) / 참가자 관람**(버튼 비활성 + 대기 문구) |
| 우선순위 | P0 |
| 구현 상태 | 🔶 |

**목적**: 참가자 전원을 같은 크기의 조각에 올려 놓고, 서버가 이미 정한 한 명으로 룰렛이 수렴하는 것을 다 같이 본다.

**진입경로**: SETUP-GAME에서 방장이 룰렛을 고르고 시작하면 들어온다. 당첨 공개 3초 뒤 RESULT-MAIN으로 넘어간다.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 주제 표시 | 무엇을 뽑는 판인지 헤더 부제와 배지에 상시 노출한다 | F-WHEEL-01 |
| 조각 배치·내 조각 강조 | 참가자 수만큼 **같은 확률**의 조각으로 나누고 **입장 순서로** 배치한다. 조각마다 아바타와 이름을 얹고 각자 자기 조각을 강조한다 | F-WHEEL-02 |
| 팀 멤버 로스터 | 좌측에 참가자 카드를 세로로 두고 접속 상태와 방장을 표시한다 | F-WHEEL-02 |
| 룰렛 실행 | 방장 전용. 최초 1회만 인정하며 회전 중에는 다시 눌리지 않는다 | F-WHEEL-03 |
| 당첨자·시드 확정 | 서버가 당첨자와 난수 시드를 **연출보다 먼저** 정해 전원에게 보낸다 | F-WHEEL-04(서버) |
| 회전 연출 수렴 | 서버가 준 당첨 인덱스·회전 수·회전 시간으로 정지 각도를 계산해 그 지점으로 감속 수렴한다. **연출이 결과를 바꾸지 않는다** | F-WHEEL-05 |
| 카운트다운 | 남은 시간을 허브 중앙에 큰 숫자로 센다. **표시한 숫자와 실제 정지 시각을 일치시킨다** | F-WHEEL-05 |
| 당첨 공개 | 당첨 조각을 강조하고 배너에 당첨자 이름을 띄우며 로스터의 해당 카드도 함께 강조한다 | F-WHEEL-05 |
| 자동 실행 | 방장이 30초 안에 실행하지 않으면 서버가 대신 돌린다. 남은 시간을 상태 밴드에 표시한다 | F-WHEEL-03 |

**주요 UI 요소**: 화면 헤더(게임 이름 · 영문 라벨 · 주제 부제 · 가이드 버튼) · 접속 인원 배지 · 주제 배지 · 팀 멤버 로스터 · 룰렛 휠(조각 · 조각별 아바타와 이름 · 림 장식 · 중앙 허브 · 포인터) · 당첨 배너 · 상태 밴드(단계 문구 + 실행 버튼 + 공정성 pill).

**레이아웃·스크롤·모바일**: 데스크톱은 좌 로스터 + 우 휠 2열이다. **로스터가 7명부터 상태 밴드를 침범하고 8명부터 콘텐츠 영역을 넘어간다** — 정원이 10명이므로 로스터를 자체 스크롤 영역으로 두거나 2열로 접어야 한다. 360px에서는 휠을 min(폭 − 32, 가용 높이) 정사각으로 잡아 화면 중앙에 두고 로스터는 휠 아래 칩 열로 내린다. 실행 버튼은 하단 고정이다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 라운드 스냅샷이 오기 전에는 휠 자리를 스켈레톤 원판으로 그린다. 실행 요청 중에는 버튼을 잠근다 |
| 빈 상태 | 해당 없음 — 명단 스냅샷이 고정된 뒤 진입하므로 조각이 비는 경우가 없다. 최소 인원 2는 시작 시점에 이미 검사됐다 |
| 에러 | member.not_host(403) · game.already_submitted(409) · game.round_already_ended(409)는 토스트로 알리고 회전 상태를 바꾸지 않는다 |
| 권한거부 | 참가자가 실행을 시도하면 member.not_host(403)를 보낸 사람에게만 토스트로 알린다. 참가자 화면의 실행 버튼은 이미 비활성 + "방장이 돌려요" 사유 표시 상태다 |

**데이터 연동**

- 화면 진입 → 라운드 스냅샷 수신(명단 스냅샷 · 조각 배치 순서 · 단계).
- 실행(F-WHEEL-03) → 서버 검증(방장 여부 · 라운드 유효 · 최초 1회) → 당첨 인덱스 · 회전 수 · 회전 시간 · 시작 시각을 전원에게 브로드캐스트 → 각 화면이 같은 값으로 같은 연출을 그린다.
- 30초 무조작 → 서버 자동 실행. 클라이언트가 타이머로 대신 실행하지 않는다.

**담은 기능ID**: F-WHEEL-01(표시) · F-WHEEL-02 · F-WHEEL-03 · F-WHEEL-04(서버) · F-WHEEL-05 — 합 **5건**(게임 6종 공통 12건은 별도)

**비고**

- **실행 버튼에 방장 가드가 없다.** 참가자 화면에서도 눌린다. 정본은 방장 전용이며 서버가 다시 검증한다(F-WHEEL-03).
- **당첨자를 클라이언트가 난수로 뽑는다.** 회전 수 5바퀴·회전 시간 4.2초도 클라이언트 상수다. 정본은 서버가 시드로 정하고 회전 시간은 3~5초 범위다.
- **카운트다운과 회전 길이가 어긋난다.** 3초를 세는데 회전은 4.2초라 "0초 후 공개"가 1.2초 동안 떠 있다. 서버가 준 회전 시간으로 카운트다운을 만든다.
- **자동 실행 마감이 없다.** 방장이 누르지 않으면 화면이 영원히 멈춘다.
- **림 장식이 광과민 위험이다.** 고대비 점 20개가 회전 초기 약 3.9회전/초로 돌아 3~60Hz 대역을 통과한다([01_standards.md](./01_standards.md) §7-4).

## LADDER-PLAY — 사다리타기

| 항목 | 내용 |
|------|------|
| 화면코드 | LADDER-PLAY |
| 진입 조건 | screen=game · selectedGame=ladder |
| 접근 권한 | **방장 입력(START 1회) / 참가자 관람** |
| 우선순위 | P0 |
| 구현 상태 | 🔶 |

**목적**: 전원의 경로를 동시에 그려 역할 배정이 조작되지 않았음을 눈으로 확인하게 한다.

**진입경로**: SETUP-GAME에서 사다리를 고르고 시작하면 들어온다. 전원 확정 3초 뒤 RESULT-MAIN으로 넘어간다.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 레인 자동 배치 표시 | 위에는 참가자, 아래에는 도착 항목을 같은 개수로 놓고 참가자가 **입장 순서로** 배치됐음을 보인다. 레인을 직접 고르지 않는다 | F-LADDER-06 |
| 항목 수 맞춤 표시 | 항목이 모자라 자동으로 채워졌거나 넘쳐 잘렸으면 그 사실을 화면에 남긴다. 채운 자리는 **X**로 표시한다 | F-LADDER-02 |
| 사다리 실행 | 방장 전용. 최초 1회만 인정한다 | F-LADDER-03 |
| 사다리 구조 생성 | 서버가 가로선 배치를 만든다. 인접한 두 세로선 사이에만 놓고 같은 높이에서 겹치지 않게 한다 | F-LADDER-04(서버) |
| 경로 계산·배정 확정 | 서버가 참가자별 최종 도착 항목을 확정하고 서로 다른 참가자가 같은 항목에 도착하지 않음을 보장한다 | F-LADDER-05(서버) |
| 동시 경로 연출 | 서버가 준 구조로 **전원의 경로를 한꺼번에** 그린다. 순차 공개를 두지 않는다 | F-LADDER-07 |
| 참가자별 색 구분 | 레인·주자·도착 항목을 같은 퍼슨 컬러로 잇되 **이름을 함께 표시한다.** 색만으로 잇지 않는다 | F-LADDER-07 |
| 매칭 현황 | 우측에 참가자별 배정 상태를 두고 확정 전에는 미확정임을 명시한다 | F-LADDER-06 |
| 주제·진행 속도 표시 | 도착 항목 목록과 방장이 고른 진행 속도를 반영한다. 속도는 연출 길이만 바꾸고 **결과는 속도와 무관하다** | F-LADDER-01 |
| 자동 실행 | 방장이 30초 안에 실행하지 않으면 서버가 대신 돌린다 | F-LADDER-03 |

**주요 UI 요소**: 화면 헤더 · 진행 상태 배지 · 접속 인원 배지 · 실행 버튼 · 사다리 무대(레인 · 가로선 · 주자 아바타와 이름칩 · 도착 항목 칩) · 매칭 현황 패널 · 상태 밴드(확정 수 + 공정성 pill).

**레이아웃·스크롤·모바일**: 데스크톱은 좌 사다리 무대 + 우 매칭 현황 2열이다. **도착 항목 칩이 8명부터 서로 겹치고 10명에서는 59px씩 파고든다** — 레인 간격이 인원에 반비례하기 때문이다. 칩 폭을 레인 간격에 맞춰 줄이거나 두 줄로 어긋나게 배치한다.

360px에서는 **사다리를 90도 회전해 가로 진행으로 바꾼다.** 참가자를 왼쪽 세로 열, 도착 항목을 오른쪽 세로 열에 두고 경로가 좌→우로 흐른다. 행 높이 44px × 10명 = 440px이므로 세로 스크롤 없이 들어가고 이름·항목이 가로로 읽힌다. 세로 배치를 유지하면 10레인의 간격이 22px가 되어 경로를 따라갈 수 없다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 구조가 오기 전에는 레인과 항목 칩 자리를 스켈레톤으로 그린다. 실행 요청 중에는 버튼을 잠근다 |
| 빈 상태 | 해당 없음 — 항목이 모자라도 서버가 X로 채워 슬롯이 비지 않는다. 최소 인원 2는 시작 시점에 검사됐다 |
| 에러 | member.not_host(403) · game.already_submitted(409) · game.round_already_ended(409)는 토스트로 알린다. 구조 수신 실패는 연출을 시작하지 않고 재수신을 기다린다 |
| 권한거부 | 참가자가 실행을 시도하면 member.not_host(403)를 보낸 사람에게만 토스트로 알린다. 참가자 화면의 실행 버튼은 비활성 + 사유 표시다 |

**데이터 연동**

- 화면 진입 → 라운드 스냅샷 수신(레인 배치 · 도착 항목 목록 · 맞춤 결과).
- 실행(F-LADDER-03) → 서버 검증 → **가로선 좌표와 참가자별 도착 인덱스**를 전원에게 브로드캐스트 → 각 화면이 같은 구조로 같은 경로를 그린다.
- 연출 종료 → 배정 확정 표시 → 3초 뒤 RESULT-MAIN.

**담은 기능ID**: F-LADDER-01(표시) · F-LADDER-03 · F-LADDER-04(서버) · F-LADDER-05(서버) · F-LADDER-06 · F-LADDER-07 — 합 **6건**(게임 6종 공통 12건은 별도)

**비고**

- **실행 버튼에 방장 가드가 없다.** 정본은 방장 전용이다(F-LADDER-03).

- **자동 실행 마감이 없다.**
- 도착 항목 칩에 이름이 없어 퍼슨 컬러 매칭에만 의존한다. 색 단독 의존 금지(D-48)에 어긋난다.

- **제한 시간이 만료돼도 아무 일도 일어나지 않는다.** 카운트다운은 0까지 세지만 마감 처리가 없어, 내가 제출하지 않으면 제출 단계에, 투표하지 않으면 투표 단계에 영원히 머문다.
- **결선 안내를 닫으면 진행이 완전히 멈춘다.** 다시 열 경로가 없다.
- **1인 2표 이상을 지원하지 않는다.** 설정에는 표 수가 있고 화면에도 표기되지만 내부적으로 한 표만 담을 수 있다. 정본은 1·2·3표이며 서로 다른 안건에 분산한다(F-KING-04).
- **안건 1개·0개 예외가 없다.** 정본은 1개면 투표를 건너뛰고 0개면 판을 끝낸다.
- **익명 모드에서도 결과 데이터에 투표자 식별자가 실려 나간다.** 화면이 그리지 않을 뿐이라 익명성이 렌더 정책에만 의존한다. 정본은 서버가 익명 구간에서 식별 정보를 아예 내려보내지 않는 것이다.
- 화면 문구가 주제와 무관하게 팀명으로 고정되어 있다. 주제 설정이 팀장·발표 주제 등으로 바뀌어도 "우리 팀, 뭐로 할까?"가 그대로 뜬다.
- 1위 표시가 막대 색에만 의존한다. 순위 문자와 확정 표시를 함께 둔다(D-48).

| 로딩 | 라운드 스냅샷이 오기 전에는 상태 칩과 타임라인을 스켈레톤으로 그린다. 시작·정지 요청 중에는 버튼을 즉시 잠근다 |

| 에러 | game.already_submitted(409, 재입력) · game.round_already_ended(409, 마감 후 도착)는 토스트로 알리고 이미 기록된 값을 바꾸지 않는다. 경과 시간이 허용 범위를 벗어나 서버가 거부하면 그 사실과 최하위 처리됨을 알린다 |
| 권한거부 | 해당 없음 — 시작·정지는 전원 동작이다. 동점 3회 초과 시의 다음 동작 선택만 방장 전용이며 참가자에게는 비활성 + 사유 표시로 보인다 |

**데이터 연동**

- 시작(F-TIMER-02) → 서버가 도착 시각을 기록하고 **그 사람의 상태만** 진행 중으로 브로드캐스트.
- 정지(F-TIMER-04) → 클라이언트 단조 시계가 잰 경과 시간을 함께 보낸다 → **서버가 자신이 관측한 시작·정지 도착 시각의 차이와 대조해 허용 범위 안일 때만 인정**하고 범위 밖이면 거부한다([../05_game_rules/01_common.md](../05_game_rules/01_common.md)) → 기록 완료 상태만 브로드캐스트.
- 전원 마감 → 서버가 순위를 확정해 한 번에 공개 → 3초 뒤 RESULT-MAIN.

**담은 기능ID**: F-TIMER-01 · F-TIMER-02 · F-TIMER-03 · F-TIMER-04 · F-TIMER-05(서버) · F-TIMER-06(서버) · F-TIMER-07(서버) · F-TIMER-08 · F-TIMER-09 · F-PLAY-12 — 합 **10건**(게임 6종 공통 12건은 별도)

**비고**

- **미입력자가 승자 후보에 남는다.** 자동 마감된 사람이 최하위 기록으로 후보에 남아 있어, 판정 기준이 "오차가 큰 사람"이면 **아무것도 누르지 않는 것이 확실한 우승 전략**이 된다. 정본은 미입력자를 최하위군에 두되 승자 후보에서 제외하는 것이다.
- **시작하지 않으면 판이 영원히 끝나지 않는다.** 시작 지연 마감이 없어 한 명이 시작 버튼을 누르지 않으면 전원이 대기 상태에 머문다.
- **동점 재대결이 없다.** 정렬 결과의 첫 번째를 그대로 승자로 삼는다. 정본은 밀리초까지 같으면 재대결이며 상한 3회다.
- **상태 밴드 문구와 실제 전환 시각이 다르다.** "3초 후"라고 적고 2.6초 뒤에 넘어간다.
- 정지 버튼이 계속 크기를 진동한다. 표적 크기가 변하면 조준이 어려워지므로 강조는 색·테두리로만 준다([01_standards.md](./01_standards.md) §7-4).
- 목표 시간이 커질수록 타임라인의 허용 범위가 시각적으로 좁아 보인다(제한 시간이 목표 + 3초라 분모가 커지기 때문이다). 허용 범위의 표시 폭을 고정하고 축척을 목표 기준으로 정규화한다.

**레이아웃·스크롤·모바일**: 데스크톱은 좌 후보 그리드 3열 + 우 내 지목 패널 2열이다. **후보가 7명 이상이면 3행이 되어 카드 영역을 넘어간다** — 정원 10명이면 후보가 최대 9명이므로 실제로 발생한다. 그리드 열 수를 후보 수에 따라 늘리거나 카드 높이를 줄인다.

360px에서는 질문을 상단 고정, 후보 그리드를 **2열**로 두고 카드 최소 높이 96px를 확보한다. 내 지목 패널은 별도 열을 두지 않고 그리드 카드 자체를 지목 대상으로 쓴다 — 같은 후보를 두 곳에 그릴 폭이 없다. 발사 버튼은 하단 고정이다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 라운드 스냅샷이 오기 전에는 후보 카드를 스켈레톤으로 그린다. 지목 요청 중에는 버튼을 잠근다 |
| 빈 상태 | 해당 없음 — 최소 인원 3이 시작 시점에 검사되므로 본인을 빼도 후보가 2명 이상 남는다. 결선에서 동점자가 좁혀져도 최소 2명이다 |
| 에러 | vote.self_not_allowed(403) · vote.limit_exceeded(409) · game.round_already_ended(409)를 토스트 또는 해당 카드 옆에 띄운다. 이미 확정한 지목을 되돌리지 않는다 |
| 권한거부 | 해당 없음 — 지목은 전원 동작이다. 결선 3회 초과 시의 다음 동작 선택만 방장 전용이며 참가자에게는 비활성 + 사유 표시로 보인다 |

**데이터 연동**

- 지목(F-SNIPE-03) → 서버 검증(자기 지목 차단 · 중복 설정에 따른 표 수 상한 · 라운드 일치) → **완료 수만** 브로드캐스트.
- 마감 → 서버가 개표해 피격 수와 최다 피격자를 한 번에 공개. **지목자 공개가 비공개면 지목자 식별 정보를 아예 내려보내지 않는다.**
- 동점 → 결선 안내 오버레이. 3회 도달 시 방장 선택(F-PLAY-12). 유효표 0이면 난수 확정 결과와 사유를 함께 내려준다.

**담은 기능ID**: F-SNIPE-01(표시) · F-SNIPE-02 · F-SNIPE-03 · F-SNIPE-04(서버) · F-SNIPE-05(서버) · F-SNIPE-06 · F-SNIPE-07(서버) · F-SNIPE-08 · F-PLAY-12 — 합 **9건**(게임 6종 공통 12건은 별도)

**비고**

- **중복 투표 설정이 동작하지 않는다.** 설정 화면에는 있으나 화면이 한 명만 담을 수 있어 "가능"을 골라도 한 명만 지목된다(F-SNIPE-03).
- **지목자 공개 설정 자체가 없다.** 설정에도 화면에도 없어 항상 비공개로 동작한다. 정본은 방장이 고르고 개표 후에만 풀리는 것이다.
- **결선이 무제한 반복된다.** 상한 검사가 없어 같은 동점이 계속 재생산되면 끝나지 않는다. 정본은 최대 3회 후 방장 선택이다(D-26).
- **결선이 후보를 좁히지 않는다.** 안내 문구는 "동점 후보를 유지하고 다시 투표한다"이지만 실제로는 전체 후보로 처음부터 다시 한다. 정본은 동점자만 남기는 것이다.
- **전원 기권을 동점으로 처리한다.** 유효표가 0일 때 전원을 동점자로 놓고 결선을 열어, 같은 0표 동점이 무한히 재생산된다. 정본은 난수 확정 + 사유 표시다.
- **결선 안내 오버레이의 버튼이 전원에게 활성이다.** 정본은 방장 전용이고 참가자는 기다린다.
- 후보 카드의 선택 표시가 테두리 색과 두께 1px 차이뿐이다. 문자 또는 형태를 병기한다(D-48).

## NUNCHI-PLAY — 눈치게임

| 항목 | 내용 |

| 진입 조건 | screen=game · selectedGame=nunchi |
| 접근 권한 | 전원 입력(UP, 라운드당 1회). 무효 라운드 처리만 방장 전용 |
| 우선순위 | P0 |
| 구현 상태 | 🔶 |

**목적**: 남과 겹치지 않는 순간에 눌러 빠져나가고, 끝까지 남은 한 명을 정한다.

**진입경로**: SETUP-GAME에서 눈치게임을 고르고 시작하면 들어온다. 최소 인원은 3명이다. 최후 1인 확정 3초 뒤 RESULT-MAIN으로 넘어간다.

**규칙 축**: **혼자 누른 사람은 안전 확정되어 후보에서 빠진다.** 판정창 안에 둘 이상이 누르면 그들은 남고, 제한 시간까지 누르지 않은 사람도 남는다. 남은 사람들끼리 다음 라운드를 진행해 최후 1인이 뽑힌다(D-38). 화면의 모든 표현이 이 축을 따른다 — **"탈락"이라는 말을 쓰지 않는다.** 빠지는 것은 안전이고 남는 것이 위험이다.

| 규칙 요약 | 혼자 누르면 안전 · 겹치면 남음 · 미입력도 남음 · 마지막 1인이 당첨을 한 줄로 상단에 둔다 | F-NUNCHI-02 |

| 라운드 반복 | 남은 사람이 2명 이상이면 다음 라운드로 넘어간다. 사이에 짧은 카운트다운을 둔다. **가이드는 다시 띄우지 않는다** | F-NUNCHI-02 |

| 압박 연출 | 라운드가 길어질수록 압박 연출을 강화한다. **판정에는 영향을 주지 않으며** 점멸·흔들림 대신 진행 바와 문자로 표현한다 | F-NUNCHI-08 |
| 라운드 기록 집계 | 라운드별 판정과 서버 기준 입력 시각·동시 입력 그룹을 모아 결과 화면에 넘긴다 | F-NUNCHI-09(서버) |

**주요 UI 요소**: 화면 헤더 · 남은 후보·안전 확정 배지 · 규칙 요약 띠 · 참가자 보드(아바타 · 이름 · 상태 문자) · 라운드 무대(현재 순번 안내 · 남은 시간 진행 바 · UP 버튼) · 눌린 순서 패널 · 무효 라운드 안내 오버레이 · 상태 밴드.

**레이아웃·스크롤·모바일**: 데스크톱은 참가자 보드 가로 배치 + 좌 무대 + 우 눌린 순서 2열이다. 참가자 보드는 인원이 늘수록 칸이 좁아지므로 10명이면 2행으로 접는다.

360px에서는 참가자 보드를 상단 격자(3열)로 올리고 **UP 버튼을 하단 고정**으로 두고 폭 100%(좌우 여백 16) · 높이 120px로 잡는다. 눌린 순서 패널은 UP 버튼 위 축약 목록으로 두고 최근 3건만 보인다. 남은 시간 진행 바는 헤더 바로 아래에 고정한다. **UP 버튼과 그 조상 요소에는 이동·크기 변화 애니메이션을 걸지 않는다** — 순간 입력이 순위를 가르는 게임에서 표적이 움직이면 공정성 문제가 된다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 라운드 스냅샷이 오기 전에는 참가자 보드를 스켈레톤으로 그리고 UP 버튼을 비활성으로 둔다. 입력 요청 중에는 버튼을 즉시 잠근다 |
| 빈 상태 | 해당 없음 — 최소 인원 3이 시작 시점에 검사되고 남은 사람은 항상 1명 이상이다. 잔류 구조에서는 남은 사람이 0이 되는 상태가 존재하지 않는다 |
| 에러 | game.already_submitted(409, 라운드당 2회 입력) · game.not_eligible(403, 안전 확정자의 입력) · game.round_already_ended(409, 마감 후 도착)를 토스트로 알리고 라운드 상태를 바꾸지 않는다 |
| 권한거부 | 참가자가 무효 라운드의 다음 동작을 고르려 하면 member.not_host(403)를 보낸 사람에게만 알린다. 참가자 화면에서는 두 버튼이 비활성이고 "방장이 고르는 중"으로 보인다 |

**데이터 연동**

- UP(F-NUNCHI-03) → 서버가 도착 시각을 기록하고 **누가 눌렀다는 사실과 순서만** 브로드캐스트. 판정은 라운드 마감 후에 한다.
- 라운드 마감 → 서버가 판정창 기준으로 그룹을 묶어 안전 확정자를 가려내고 결과를 한 번에 브로드캐스트 → 다음 라운드 또는 최후 1인 확정.
- 무효 라운드(F-NUNCHI-07) → 방장 선택을 서버가 검증(방장 여부 · 무효 라운드 상태) → 다시 시작이면 같은 인원으로 새 라운드, 대기방으로면 결과 없이 종료.

**담은 기능ID**: F-NUNCHI-01(표시) · F-NUNCHI-02 · F-NUNCHI-03 · F-NUNCHI-04(서버) · F-NUNCHI-05(서버) · F-NUNCHI-06(서버) · F-NUNCHI-07 · F-NUNCHI-08 · F-NUNCHI-09(서버) — 합 **9건**(게임 6종 공통 12건은 별도)

**비고**

- **판정 방향이 정본과 정확히 반대로 구현되어 있다. 이 문서군에서 가장 큰 구현 정정 대상이다.**

| 상황 | 정본(D-38 · F-NUNCHI-05) | 현행 구현 |
|------|-----------|-----------|
| 혼자 누름 | **안전 확정 — 후보에서 빠진다** | 통과로 표시하고 **다음 라운드에 그대로 남긴다** |
| 판정창 안에 둘 이상 | **남는다** | 동시 탈락으로 **제거한다** |
| 제한 시간까지 미입력 | **남는다** | 시간 초과로 **제거한다** |
| 아무도 겹치지 않은 라운드 | 전원 안전 확정 | 정본에 없는 규칙으로 **가장 늦게 누른 사람을 강제로 제거한다** |
| 남은 전원이 겹침 | 무효 라운드 — 방장이 고른다 | 생존자 0명 · 전원 탈락으로 처리해 **아무도 뽑히지 않는 판**을 만든다 |

  D-38이 겹침 탈락 구조를 폐기한 이유가 그대로 재현된다 — **일부러 겹치는 것이 지배 전략**이 되어 뽑히기 싫은 사람들이 담합하면 판이 성립하지 않는다. 화면 문구도 함께 고친다. 시간 초과 안내가 "탈락했어요"로 떠 있어 규칙 반전을 사용자에게 그대로 고지하고 있다.

- **라운드 제한 시간이 설정 항목이 아니라 코드에 15초로 박혀 있다.** 정본은 10 · 15 · 20초 중 방장이 고른다(D-40).
- **최후 1인에게 추가 라운드를 요구한다.** 혼자 남은 사람이 UP을 눌러야 확정되는데 **시간 제한이 없어** 그 사람이 누르지 않으면 게임이 영원히 멈춘다. 정본은 한 명이 남으면 그대로 뽑히고 끝나는 것이다.
- **무효 라운드의 다음 동작을 전원이 고를 수 있다.** 정본은 방장 전용이고 참가자는 기다린다(F-NUNCHI-07).
- **입력 시각이 클라이언트 시계 값인데 화면은 서버 도착 시각이라고 단언한다.** 눌린 순서 패널에 "서버 도착 시각 기준 · 네트워크와 무관하게 공정"이 적혀 있으나 실제 값은 브라우저가 잰 값이다. **화면이 사실과 다른 공정성을 주장하는 것은 표시 결함 중에서도 무겁다.**
- **광과민·전정기관 위험이 두 곳에 있다.** 화면 하단 상태 밴드가 1.25Hz로 무한 명멸하고, UP 버튼을 품은 무대 카드가 2Hz로 무한히 흔들린다. 둘 다 라운드 2 이상이면 라운드 내내 계속되며 모션 저감 대응이 없다. **판정 상태를 점멸로 알리지 않는다**([01_standards.md](./01_standards.md) §7-3·§7-4).
- 눌린 순서 목록의 행이 배경색만으로 판정을 나타내고 판정 문자가 없다. 문자를 병기한다(D-48).
- 판정 라벨 넷을 정본 용어로 통일한다 — **안전 확정 · 겹침 잔류 · 미입력 잔류 · 최후 1인**이다. 용어집이 빠지는 쪽을 안전 확정, 남는 쪽을 잔류로 못박았다. 현행의 통과 · 동시 탈락 · 시간 초과 · 최후 잔류는 뜻이 어긋나며, 특히 최후 잔류는 강제 제거된 사람과 최종 선정된 사람 양쪽에 같이 쓰이고 있어 결과 화면에서 구분되지 않는다.

## 게임 화면 공통 요소

아래 여섯은 게임 6종이 공유하는 화면 내 요소다. 소속 화면마다 되풀이 기술하지 않고 여기에 한 번만 둔다.

### 게임 6종 내 요소 — 채팅 패널

**노출 조건**: 게임 6종 전부에 상시 노출된다. 게임 종류나 단계에 따른 예외를 두지 않으며 **킹메이커 제출·투표와 익명 저격 투표 중에도 열려 있다**(D-45). 기본은 접힌 상태이고 헤더의 채팅 버튼으로 편다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 메시지 전송 | 1~200자. 공백만이면 보내지 않는다. 서버가 중계하고 저장하지 않는다 | F-LOBBY-07 |
| 메시지 수신 | 전원의 메시지를 도착 순서대로 쌓는다. 접혀 있으면 채팅 버튼에 새 메시지 수를 배지로 표시한다 | F-LOBBY-07 |
| 로컬 보관 | 각자 브라우저에 쌓아 대기방으로 돌아가도 이어진다 | F-LOBBY-08 |
| 익명 구간 발신자 표기 | 익명 구간에서는 **닉네임만** 적고 아바타·퍼슨 컬러를 붙이지 않는다 | F-LOBBY-07 |

**주요 UI 요소**: 헤더 채팅 버튼(새 메시지 배지) · 접힘·펼침 패널 · 메시지 목록 · 입력창 · 전송 버튼.

**상태·에러**: 대화가 없으면 "아직 대화가 없어요"를 표시한다 — 서버에 이력이 없어 나중에 들어온 사람에게는 항상 이 상태로 시작한다. 길이 초과는 입력창 옆에 알리고 입력값을 지우지 않는다. 권한거부는 해당 없다(전원 허용).

**데이터 연동**: 전송 → chat:send → 서버가 messageId·sentAt을 붙여 chat:message로 전원에게 되돌린다. 본인 메시지도 서버를 다녀오므로 전원의 순서가 같다.

**비고**: **펼친 상태가 게임 조작 표적을 가리지 않는다.** 360px에서 눈치 UP 버튼과 시간초 STOP 버튼은 화면 하단의 주 조작 영역을 차지하므로, 채팅 패널은 그 위 영역에서 펼쳐지고 상태 밴드와 겹치지 않는다([01_standards.md](./01_standards.md) §5). 입력 순간이 순위를 가르는 두 게임에서는 **입력창에 포커스가 있어도 UP·STOP 버튼이 가려지지 않는 배치**가 요구사항이다. 익명 구간에서 아바타·퍼슨 컬러를 떼는 이유는 색만으로 사람이 식별되기 때문이며, 이는 공통 패턴의 익명 표기 규약을 채팅에 적용한 것이다.

**익명성의 한계를 화면이 과장하지 않는다.** 채팅이 열려 있으므로 참가자가 스스로 "내가 A 냈어"라고 밝힐 수 있다. 제품이 보장하는 것은 **서버가 식별 정보를 공개하지 않는 것**까지이며, 화면 문구도 "아무도 알 수 없어요"가 아니라 "제출자는 공개되지 않아요"처럼 주체를 밝혀 적는다([../11_fairness/02_anonymity.md](../11_fairness/02_anonymity.md)).

### 게임 6종 내 요소 — 게임 가이드 모달

**노출 조건**: 게임이 시작되면 3초간 자동으로 뜬다(D-24). 게임 중에는 화면 헤더의 가이드 버튼으로 언제든 다시 연다. **다시 하기 · 동점 결선 · 동점자 재대결 · 무효 라운드 재시작에서는 뜨지 않는다**(D-25). 자동 노출은 조기에 닫아도 게임 시작 시각을 바꾸지 않는다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 규칙 안내 | 한 줄 요약 · 진행 단계 · 판정 기준을 게임별로 보여 준다. 단계 수는 게임마다 2~4단계다 | F-SETUP-13 |
| 자동 시작 카운트다운 | 남은 초를 버튼에 표시하고 0이 되면 닫힌다. 먼저 닫아도 된다 | F-SETUP-13 |
| 재노출 억제 | 다시 보지 않기를 켜면 그 게임의 자동 노출을 접는다. 헤더 버튼으로는 계속 열 수 있다 | F-SETUP-13 |
| 전원 열람 | 방장뿐 아니라 모든 참가자가 연다 | F-SETUP-13 |

**주요 UI 요소**: 딤 배경 · 모달 카드 · 헤더(게임 아이콘 · 이름 · 단계 수 · 닫기) · 한 줄 요약 띠 · 단계 카드 목록 · 팁 띠 · 자동 시작 버튼 · 다시 보지 않기 체크.

**상태·에러**: 게임 메타는 클라이언트가 이미 갖고 있으므로 로딩·빈 상태·에러가 없다. 권한거부도 해당 없다(전원 열람). **이 오버레이만 본문 세로 스크롤을 허용한다**([01_standards.md](./01_standards.md) §3-2) — 헤더와 자동 시작 버튼은 스크롤 밖에 고정한다.

**데이터 연동**: 없다. 서버를 호출하지 않으며 다시 보지 않기 설정은 브라우저에만 남는다.

**비고**: 자동 노출 시 게임판이 뒤에서 이미 돌아가지 않도록 서버가 가이드 종료 시각을 기준으로 라운드를 연다. 현행 구현은 가이드와 게임 진행이 별개로 흘러 가이드를 보는 동안 봇이 이미 입력을 넣는다.

### 게임 6종 내 요소 — 진행 상황 패널

**노출 조건**: 입력형 게임 네 종(KING-PLAY · TIMER-PLAY · SNIPE-PLAY · NUNCHI-PLAY)에 상시 노출된다. 입력을 받지 않는 WHEEL-PLAY · LADDER-PLAY에는 두지 않고 대신 접속 인원만 표시한다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 완료·대기 표시 | 참가자별로 **완료했는가 아닌가만** 보여 준다. 입력 내용·기록·득표는 보이지 않는다 | — |
| 완료 수 집계 | 완료 수와 전체 수를 함께 적는다. **서버가 세어 내려준 값**을 쓴다 | — |
| 이탈자 표시 | 게임 도중 나간 사람을 목록에서 지우지 않고 이탈 표시와 함께 남긴다 | — |
| 상태 문자 병기 | 상태를 색만으로 구분하지 않고 문자를 함께 적는다 | — |

**주요 UI 요소**: 참가자 칩·카드 목록(아바타 · 이름 · 상태 문자) · 완료 수 표시.

**상태·에러**: 명단 스냅샷이 오기 전에는 스켈레톤으로 그린다. 명단이 고정된 뒤 진입하므로 빈 상태는 발생하지 않는다. 자체 에러가 없고 권한거부도 해당 없다 — 전원이 같은 것을 본다.

**데이터 연동**: 각 게임의 입력 이벤트가 완료 상태만 브로드캐스트한다. 클라이언트가 목록을 세어 표시하지 않는다.

### 게임 6종 내 요소 — 단계 타이머

**노출 조건**: 제한 시간이 있는 단계에 노출된다 — 킹메이커 제출·투표, 익명 저격 투표, 시간초 시작 지연·개인 제한, 눈치 라운드다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 남은 시간 표시 | 서버가 준 단계 마감 시각까지 남은 시간을 숫자와 진행 바로 함께 보여 준다. **전원에게 같은 값이 보인다** | — |
| 마감 임박 표시 | 남은 시간이 적어지면 강조한다. **점멸로 알리지 않고** 진행 바 감소와 문자·한 번의 색 전환으로 표현한다 | — |
| 조기 마감 | 전원이 입력을 마치면 시간이 남아도 즉시 다음 단계로 넘어간다 | — |

**주요 UI 요소**: 남은 시간 숫자 · 진행 바 · 마감 임박 강조.

**상태·에러**: 마감 시각이 오기 전에는 진행 바를 비활성으로 둔다. 빈 상태·권한거부는 해당 없다. 서버와 시각이 어긋나면 **남은 시간을 늘리지 않고** 0에서 멈춰 마감 통지를 기다린다 — 클라이언트가 마감을 스스로 정하지 않는다.

**데이터 연동**: 서버가 단계 진입 시 마감 시각을 내려주고 주기적으로 시각을 맞춘다. 마감 처리는 서버가 하고 클라이언트는 그리기만 한다.

**비고**: 현행 구현은 클라이언트가 초를 세고 **0이 되어도 아무 일도 하지 않는다.** 킹메이커·익명 저격에서 판이 멈추는 원인이 이것이다.

### KING-PLAY · SNIPE-PLAY · TIMER-PLAY 내 요소 — 동점 결선·교착 해소 안내

**노출 조건**: 최다 득표·최다 피격이 동점이거나 절대 오차가 밀리초까지 같으면 열린다. 결선·재대결이 **3회에 도달하면** 자동 반복을 멈추고 방장에게 선택을 요구하는 형태로 바뀐다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 동점 사실 안내 | 동점자·동점 안건을 칩으로 나열한다 | — |
| 반복 횟수 표시 | 몇 번째 결선인지와 남은 횟수를 함께 적는다 | F-PLAY-12 |
| 다음 동작 선택 | 3회 도달 시 방장이 다시 시작 · 대기방으로 중에서 고른다. **참가자에게는 두 버튼이 비활성이고 방장이 고르는 중임이 표시된다** | F-PLAY-12 |

**주요 UI 요소**: 딤 배경 · 확인 모달 프레임 · 상태 배지 · 제목 · 동점자 칩 목록 · 횟수 표시 · 두 개의 동작 버튼.

**상태·에러**: 실행 중 두 버튼을 잠근다. 로딩·빈 상태는 해당 없다. member.not_host(403) · game.invalid_action(409)는 오버레이를 닫지 않고 토스트로 알린다. **권한거부는 화면이 먼저 막는다** — 참가자 화면에서는 처음부터 비활성이다. 배경 클릭으로 닫히지 않는다. 닫아도 진행이 멈추지 않도록 상태 밴드에 다시 열기를 남긴다.

**데이터 연동**: 서버가 동점 판정과 반복 횟수를 내려준다. 방장 선택(F-PLAY-12)은 서버가 검증한 뒤 전원에게 결과를 브로드캐스트한다.

**비고**: 현행 구현은 **반복 상한이 없고**, 오버레이의 두 버튼이 전원에게 활성이며, 닫으면 다시 열 경로가 없어 진행이 완전히 멈춘다. 셋 다 고친다.

### NUNCHI-PLAY 내 요소 — 무효 라운드 안내

**노출 조건**: 남은 전원이 같은 판정창에 눌러 **아무도 안전 확정하지 못하면** 열린다. 잔류 구조에서는 남은 사람이 0이 되는 상태가 없으므로 전원 탈락 상태는 존재하지 않는다.

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 무효 라운드 안내 | 이번 라운드가 무효임을 알린다. **아무도 안전 확정하지 못했을 뿐 후보가 줄지도 늘지도 않았다**는 사실을 함께 적는다 | F-NUNCHI-07 |
| 다음 동작 선택 | 방장이 다시 시작 · 대기방으로 중에서 고른다. 참가자에게는 두 버튼이 비활성이고 방장이 고르는 중임이 표시된다 | F-NUNCHI-07 |
| 반복 안내 | 같은 인원으로 다시 하면 또 겹칠 수 있음을 알린다. 자동 재시작을 두지 않는 이유다 | F-NUNCHI-07 |

**주요 UI 요소**: 딤 배경 · 확인 모달 프레임 · 상태 배지 · 제목 · 남은 후보 칩 목록 · 두 개의 동작 버튼.

**상태·에러**: 실행 중 두 버튼을 잠근다. 로딩·빈 상태는 해당 없다. member.not_host(403) · game.invalid_action(409)는 토스트로 알린다. 권한거부는 화면이 먼저 막는다. 배경 클릭으로 닫히지 않는다 — 닫으면 진행이 멈추기 때문이다.

**데이터 연동**: 서버가 무효 라운드 판정과 남은 후보 목록을 내려준다. 방장 선택(F-NUNCHI-07)은 서버가 검증한 뒤 새 라운드 또는 대기방 복귀로 이어진다.

**비고**: 현행 구현은 이 오버레이가 "모두 탈락했어요 · 생존자 0명"을 알리는 전원 탈락 안내이며 두 버튼이 전원에게 활성이다. 명칭·문구·게이팅을 전부 고친다.
