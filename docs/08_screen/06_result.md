> **대상**: RESULT-MAIN 1본과 결과 카드 4변형 · 결과 이미지 저장 규격
> **작성일**: 2026-08-02
> **원천**: [../02_features/06_result.md](../02_features/06_result.md)(F-RESULT 9건) · frontend/src/screens/Result.tsx · frontend/src/lib/types.ts(결과 4변형 자료 구조) · frontend/src/lib/store.ts · docs_legacy/requirements.md §4.5 US-501~504 · [../01_overview/06_design_decisions.md](../01_overview/06_design_decisions.md) D-41·D-42·D-43·D-44 · [../02_features/08_permission_matrix.md](../02_features/08_permission_matrix.md) · [01_standards.md](./01_standards.md)

판이 끝나고 결과를 함께 보는 화면이다. 화면은 하나지만 **결과 카드가 게임 성격에 따라 네 가지 모습**을 갖는다 — 승자형 · 배정형 · 개표형 · 기록형이다. 네 변형은 같은 셸(헤더 · 결과 카드 · 액션 패널)을 쓰고 카드 본문만 바뀌므로 독립 화면 코드를 두지 않는다. 이 화면의 마지막 단계는 이미지 저장이며, 단톡방에 올려 공유하는 것이 실제 사용 흐름의 끝이다.

## RESULT-MAIN — 결과 발표

| 항목 | 내용 |
|------|------|
| 화면코드 | RESULT-MAIN |
| 진입 조건 | screen=result. 게임 화면에서 결과가 공개된 시점부터 3초 뒤 전원 자동 전환 |
| 접근 권한 | **전원 열람·이미지 저장 / 다음 동작(다시 하기 · 대기방으로)은 방장** |
| 우선순위 | P0 |
| 구현 상태 | 🔶 |

**목적**: 무엇을 정한 판이었고 누가·무엇이 정해졌는지를 한 장으로 보여 주고, 그 한 장을 이미지로 가져가게 한다.

**진입경로**: 게임 6종 어디에서든 결과 공개 3초 뒤 전원이 동시에 들어온다(D-41). 나가는 길은 셋 — 다시 하기(같은 게임 화면) · 대기방으로(LOBBY-MAIN) · 나가기(ROOM-LANDING)다. **대기방으로 돌아가면 그 판의 결과를 다시 열어볼 수 없다.**

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 결과 화면 전환 | 연출이 끝나 결과가 공개된 시점부터 3초 뒤 전원의 화면을 넘긴다. **참가자 간 전환 시각 편차를 두지 않는다** | F-RESULT-01 |
| 판의 맥락 표시 | 주제 · 게임 이름 · 뽑힌 대상을 크게 싣고 방 코드를 헤더에 함께 둔다. **결과만 보고 무슨 판이었는지 알 수 없으면 저장해 공유할 이유가 없다** | F-RESULT-02 |
| 결과 화면 4종 | 게임 성격에 맞는 형태로 결과를 보여 준다. 승자형 · 배정형 · 개표형 · 기록형이며 아래 절에서 각각 규정한다 | F-RESULT-02 |
| 요약 수치 | 게임별 요약 수치를 3~4개 타일로 함께 보여 준다 | F-RESULT-02 |
| 이탈자 표시 | 게임 도중 나간 사람도 결과에 나오며 이탈 표시를 함께 단다. 뽑힌 사람이 이탈자여도 결과에서 빼지 않는다 | F-RESULT-09 |
| 결과 이미지 저장 | 결과를 이미지 파일로 내려받는다. 주제·게임 이름·결과·참가자·날짜를 담으며 **방장뿐 아니라 전원**이 저장한다 | F-RESULT-03 |
| 결과 공유 | 공유 API를 지원하는 환경에서 저장 대신 바로 공유하는 선택지를 제공한다 | F-RESULT-04 |
| 제출자 실명 공개 | 킹메이커 설정이 실명일 때만, 그것도 **개표 후에만** 안건 제출자를 드러낸다. 익명이면 끝까지 공개하지 않는다 | F-KING-09 |
| 다시 하기 | 방장 전용. 같은 게임·같은 설정으로 새 판을 시작한다. **가이드는 띄우지 않는다**(D-25). 그 시점의 참가자로 새 스냅샷을 만들며 인원이 최소 미만이면 비활성 + 사유를 표시한다 | F-RESULT-05 |
| 대기방 복귀 | 방장 전용. 전원이 대기방으로 돌아가고 **준비 상태가 초기화된다.** 채팅 이력은 유지된다 | F-RESULT-06 |
| 참가자 대기 안내 | 참가자에게는 두 버튼을 조작 불가로 두고 **방장의 다음 동작을 기다리는 중**임을 보인다. 감추지 않는다 | F-RESULT-07 |
| 결과·시드 보관과 삭제 | 확정 결과와 난수 시드를 방이 살아 있는 동안 서버에 보관하고 방이 사라질 때 함께 지운다. **참가자에게 다시 보여 주는 경로는 없다** | F-RESULT-08(서버) |

**주요 UI 요소**: 화면 헤더(결과 발표 제목 · 영문 라벨 · 게임 이름 · 주제 · 방 코드) · 축하 연출 · 결과 카드(4변형 중 하나) · 요약 수치 타일 · 승자형 전용 하단 띠(비껴간 사람) · 액션 패널(이미지 저장 버튼 + 안내 · 구분선 · 다음 동작 제목 · 다시 하기 버튼 · 대기방으로 버튼 + 안내) · 채팅 패널(헤더 채팅 버튼 + 접힘·펼침 · 요소 정본은 [05_game_screens.md](./05_game_screens.md)) · 방장 이탈 안내 오버레이 · 나가기 확인 오버레이 2종.

**채팅은 결과 화면에서도 열린다**(D-45). 결과를 보며 대화하는 것이 이 제품의 마지막 사용 흐름이고, 게임 중 채팅을 허용한 이상 결과 화면만 닫을 이유가 없다. 이미지 저장 버튼과 다음 동작 버튼을 가리지 않는 위치에서 펼친다.

**레이아웃·스크롤·모바일**: 데스크톱은 좌 결과 카드 + 우 액션 패널 2열이고, 승자형만 아래에 비껴간 사람 띠가 폭 전체로 붙는다. 스크롤 소유자는 개표 목록과 라운드 기록 둘이며 다른 변형에는 스크롤이 없다.

360px에서는 1열로 편다. 결과 카드가 위, 액션 버튼 세 개가 아래 세로 스택이고 각 버튼 높이는 64px 이상이다. **이미지 저장 버튼을 맨 위에 둔다** — 이 화면에서 전원이 하는 유일한 동작이기 때문이다. 개표 목록·라운드 기록은 자체 세로 스크롤 영역으로 두고 페이지 가로 스크롤을 만들지 않는다. 승자형의 비껴간 사람 띠는 칩 가로 스크롤 컨테이너로 바꾼다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 결과 데이터는 화면 전환과 함께 도착하므로 별도 로딩 구간이 거의 없다. **이미지 굽는 중에는 저장 버튼을 비활성으로 바꾸고 진행 표시를 넣는다** — 굽는 동안 화면을 잠그지 않는다 |
| 빈 상태 | **사유를 구분한다.** 결과 자체가 비는 경우는 없다. 다만 배정형에서 항목이 모자라 채워진 자리는 배정 없음으로, 개표형에서 득표가 0인 후보는 0표로 **지우지 않고 남긴다.** 기록형에서 라운드가 1회로 끝났으면 그 사실을 적는다 |
| 에러 | 이미지 저장 실패는 토스트로 알리고 재시도 경로를 남긴다. 화면 상태는 바꾸지 않는다. 다시 하기 실패는 member.not_host(403) · game.not_enough_members(409) · game.invalid_action(409)로 나뉘며 사유를 액션 패널에 적는다 |
| 권한거부 | 참가자가 다시 하기·대기방 복귀를 시도하면 member.not_host(403)를 보낸 사람에게만 토스트로 알린다. 참가자 화면의 두 버튼은 이미 비활성 + "방장이 고르는 중" 사유 표시 상태다. **이미지 저장에는 권한 제한이 없다** |

**데이터 연동**

- 화면 진입 → 게임 화면에서 받은 확정 결과를 그대로 쓴다. 결과를 다시 조회하지 않는다.
- 이미지 저장(F-RESULT-03) → 서버를 호출하지 않고 클라이언트가 전용 캔버스에 그려 내려받는다.
- 다시 하기(F-RESULT-05) → 서버 검증(방장 여부 · 방 상태가 결과 · 직전 설정 유효 · 최소 인원) → 새 라운드 시작을 전원에게 브로드캐스트 → 게임 화면 전환. 반복 횟수는 0으로 초기화한다.
- 대기방 복귀(F-RESULT-06) → 서버 검증(방장 여부 · 방 상태가 결과) → 방 상태를 대기로 되돌리고 **준비 상태를 초기화**해 전원에게 브로드캐스트 → LOBBY-MAIN 전환.

**담은 기능ID**: F-RESULT-01 · F-RESULT-02 · F-RESULT-03 · F-RESULT-04 · F-RESULT-05 · F-RESULT-06 · F-RESULT-07 · F-RESULT-08(서버) · F-RESULT-09 · F-KING-09 — 합 **10건**

## 결과 카드 4변형

네 변형은 **같은 셸에 본문만 다르다.** 어느 게임이 어느 변형을 쓰는지는 [../05_game_rules/README.md](../05_game_rules/README.md)의 스펙 시트가 정본이며 본 표는 그것을 화면 형태로 옮긴다.

| 변형 | 쓰는 게임 | 결정 대상 | 하단 띠 |
|------|-----------|-----------|:-------:|
| **승자형** | 운명의 룰렛 · 시간초 잡기 · 익명 저격 | 사람 1인 | 비껴간 사람 띠 |
| **배정형** | 사다리타기 | 전원 역할 | 없음 |
| **개표형** | 킹메이커 | 안건 1개 | 없음 |
| **기록형** | 눈치게임 | 사람 1인(라운드 누적) | 없음 |

### 승자형

**구성**: 상단 당첨 배너 → 후광 + 왕관 + 아바타 히어로 → 뽑힌 사람 이름(가장 큰 글자) → 게임 이름 · 주제 당첨 pill → 요약 수치 타일 3개.

**하단 비껴간 사람 띠**: 뽑히지 않은 사람 전원을 칩으로 나열하고 각자의 한 줄 결과를 붙인다. 룰렛은 세이프 표시, 시간초는 부호를 포함한 오차, 익명 저격은 피격 수다. **이 띠는 결과 카드 밖이 아니라 저장 대상 안에 들어간다**(§이미지 저장 규격).

**요약 수치**: 룰렛은 참가자 수 · 당첨 확률 · 결정까지 걸린 시간, 시간초는 목표 시간 · 1위 기록 · 1위 오차, 익명 저격은 최다 피격 수 · 총 지목 수 · 투표 시간이다.

**비고**: 익명 저격은 지목자 공개 설정이 비공개면 **누가 지목했는지를 어떤 형태로도 싣지 않는다** — 피격 수만 남긴다.

### 배정형

**구성**: 상단 배분 결과 제목 + 주제 → 참가자 → 역할 카드 격자 → 요약 수치 칩 → 확정 안내.

**카드 한 장**: 아바타 · 이름 · 화살표 · 역할 배지다. **항목이 모자라 자동으로 채워진 자리는 X로 표시하고 빈칸으로 두지 않는다** — 배정이 누락된 것이 아니라 채워진 것임을 구분해야 한다.

**요약 수치**: 배정 인원 · 역할 항목 수 · 진행 속도다.

**비고**: 참가자 수와 항목 수가 항상 같으므로 1:1 대응이 깨진 상태가 결과에 나올 수 없다. 초과분이 잘렸으면 그 사실을 함께 적는다.

### 개표형

**구성**: 상단 확정 안건 배너 → 공개 모드 표시(익명 · 실명) → 득표 목록 → 요약 수치 칩.

**득표 한 줄**: 순위 · 안건 텍스트 · 득표 막대 · 표 수다. **득표가 0인 후보도 목록에서 빼지 않고 0표로 남긴다.** 1위는 막대 색뿐 아니라 순위 문자와 확정 표시로도 구분한다.

**공개 범위**: 방장이 실명을 골랐으면 **개표 후에** 안건별 제출자를 공개한다. 익명이면 끝까지 비공개다(D-10). **투표자는 어느 설정에서도 공개하지 않는다** — 방장 설정이 규정하는 것은 제출자 공개 여부뿐이다.

**요약 수치**: 후보 수 · 총 투표 수 · 1위 득표율이다.

**비고**: 결선을 거쳤으면 몇 번째 결선의 결과인지 적는다. 유효표가 0이어서 난수로 확정된 판이면 **표가 없었음을 결과에 명시한다.**

### 기록형

**구성**: 상단 최종 선정 배너(아바타 + 이름) → 판정 범례 → 라운드별 판정 기록 → 요약 수치 칩.

**라운드 한 블록**: 라운드 번호와 그 라운드 참가자별 판정이다. 판정은 **안전 확정 · 겹침 · 미입력 · 최후 1인** 넷이며 색과 문자를 함께 쓴다. 각 판정에 서버 도착 시각 기준 입력 시각과 같은 판정창에 묶인 그룹을 함께 표시해 **왜 그렇게 갈렸는지를 검증할 수 있게 한다.**

**요약 수치**: 라운드 수 · 판정창 · 최종 선정자다.

**비고**: 무효 라운드가 있었으면 그 라운드도 기록에 남기고 무효였음을 표시한다. 판정 라벨은 위 넷으로 통일하며 같은 라벨을 서로 다른 뜻으로 쓰지 않는다.

## 결과 이미지 저장 규격

이 화면의 마지막 단계이자 **전원이 하는 유일한 동작**이므로 별도 규격을 둔다.

| 항목 | 규격 |
|------|------|
| 캔버스 | 뷰포트와 무관한 고정 규격 **1080 × 1350**(4:5). 화면 레이아웃을 그대로 캡처하지 않는다 — 그러면 360px 사용자와 1920px 사용자가 서로 다른 이미지를 갖는다 |
| 필수 내용 | **주제 · 게임 이름 · 결과 · 참가자 · 날짜** 다섯을 모두 담는다(D-42). 승자형의 비껴간 사람 띠도 참가자에 해당하므로 함께 넣는다 |
| 방 식별 | 방 코드를 넣는다. 방이 사라진 뒤에도 어느 판의 결과였는지 알 수 있게 한다 |
| 배율 | 2배로 굽는다. 메신저 재압축 후에도 글자가 뭉개지지 않는다 |
| 파일명 | 게임과 날짜를 담아 저장함에서 구분되게 한다 |
| 렌더 | 화면 밖 전용 렌더 트리에 그린다. 화면 표시용 결과 카드와 컴포넌트를 공유하되 레이아웃 값은 캔버스 규격을 따른다 |
| 실패 | 토스트로 알리고 재시도 경로를 남긴다. 화면 상태를 바꾸지 않는다 |
| 권한 | 방장·참가자 구분 없이 전원이 저장한다(D-42) |
| 익명 경계 | **익명 구간의 식별 정보를 이미지에 넣지 않는다.** 킹메이커 익명 모드의 제출자, 익명 저격의 지목자는 이미지에도 나오지 않는다 |

## 비고 — 구현 정정 대상

frontend/src/screens/Result.tsx가 본 명세와 어긋나는 지점이다. **문서를 구현에 맞추지 않고 구현을 고친다.**

| 지점 | 현행 구현 | 명세 |
|------|-----------|------|
| 저장 이미지 규격 | 화면에 그려진 결과 카드 DOM(가로형)을 그대로 굽는다. 뷰포트에 따라 결과물이 달라진다 | 1080 × 1350 고정 캔버스에 별도로 그린다 |
| 저장 이미지 내용 | **날짜가 없다.** 승자형의 **비껴간 사람 띠가 카드 밖에 있어 저장 범위에서 빠진다** — 뽑힌 한 명만 남고 나머지 참가자가 이미지에 없다. 방 코드도 헤더에만 있어 빠진다 | 주제 · 게임 이름 · 결과 · 참가자 · 날짜 · 방 코드를 모두 담는다 |
| 다음 동작 권한 | 액션 패널에 "방장만 조작"이라고 적혀 있으나 **버튼에 방장 가드가 없어 누구나 누른다.** 참가자용 비활성·대기 안내가 없다 | 방장 전용이며 서버가 다시 검증한다(F-RESULT-05 · F-RESULT-06) |
| 다시 하기 최소 인원 | 검사하지 않는다. 사람이 빠져 최소 인원 아래로 내려가도 그대로 시작된다 | 그 시점 참가자로 새 스냅샷을 만들며 최소 미만이면 비활성 + 사유 표시 |
| 개표형 실명 모드 | 제출자와 **투표자를 함께 공개한다** | 제출자만 공개한다. 투표자는 어느 설정에서도 공개하지 않는다 |
| 개표형 익명 모드 | 결과 데이터에 투표자 식별자가 실려 있고 화면이 그리지 않을 뿐이다 | 서버가 익명 구간의 식별 정보를 아예 내려보내지 않는다 |
| 기록형 판정 라벨 | 통과 · 동시 탈락 · 시간 초과 · 최후 잔류 넷을 쓰며 **최후 잔류가 강제 제거된 사람과 최종 선정자 양쪽에 같이 쓰인다** | 안전 확정 · 겹침 · 미입력 · 최후 1인으로 통일한다. 판정 방향 자체의 정정은 [05_game_screens.md](./05_game_screens.md) NUNCHI-PLAY를 따른다 |
| 이탈자 표기 | 없다. 나간 사람이 결과에 어떻게 나오는지 처리가 없다 | 이탈 표시와 함께 그대로 남긴다 |
| 결선·무효 라운드 표시 | 없다. 몇 번째 결선의 결과인지, 유효표 0으로 난수 확정됐는지 알 수 없다 | 결선 횟수 · 난수 확정 사유 · 무효 라운드를 결과에 남긴다 |
| 방장 이탈 | 결과 화면에서도 방이 삭제되고 전원이 표지로 간다 | 정본과 같다. **구 스펙의 "결과 화면에서는 방장이 나가도 화면을 유지한다"는 폐기됐다** — 방 수명 규칙에 예외를 두지 않는다 |
| 축하 연출 | 26조각이 무한 반복으로 떨어진다. 모션 저감 대응이 없다 | prefers-reduced-motion을 존중해 정적 배경으로 대체한다([01_standards.md](./01_standards.md) §7-3) |
