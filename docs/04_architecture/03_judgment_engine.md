> **대상**: 서버 판정 엔진의 구조 · 난수와 시드 생성 · 입력 수집과 도착 시각 기록 · 멱등 처리 · 게임별 판정 호출 규약

> **원천**: docs_legacy/requirements.md §3.1 G-2·G-7·G-8·G-9·G-10 · §3.2 스펙 시트 · §3.5 게임별 규칙 · §6 설계 결정 · git 529e312 docs/db.md §11~12 · §13(게임별 JSON 스키마) · git ecceb11 docs/03_architecture/01_data_model.md §2.3 · [../README.md](../README.md)(전역 불변식) · [../05_game_rules/README.md](../05_game_rules/README.md)

**결과는 서버가 확정한다.** 클라이언트는 이미 정해진 결과로 수렴하는 연출을 그릴 뿐이고, 화면·기기·네트워크 속도가 결과를 바꾸지 못한다. 판정 엔진은 그 확정을 담당하는 계층이며, 게임 6종의 규칙을 **결정론적 순수 함수**로 구현한다.

순수 함수로 두는 이유는 세 가지다 — 같은 입력이 같은 결과를 내야 사후 검증이 가능하고, 시각을 함수 안에서 읽지 않아야 테스트가 실시간에 의존하지 않으며, DB·소켓을 모르는 함수는 밀리초 경로에 왕복을 끼워 넣을 수 없기 때문이다. 게임 규칙 자체(누가 이기는가)의 정본은 [../05_game_rules/README.md](../05_game_rules/README.md)이며, 본 문서는 **그 규칙을 서버가 어떤 계약으로 호출하는가**를 정한다.

## 계층 구조

| 계층 | 책임 | 접근 가능 |
|------|------|-----------|
| 수집기 | 프레임 수신 즉시 도착 밀리초를 찍고 주체를 소켓 바인딩으로 확정한다 | 소켓 · 라운드 상태 |
| 검증기 | 멱등·문맥 일치·자격·마감을 검사해 입력을 수용하거나 버린다 | 라운드 상태 · 명단 스냅샷 |
| 라운드 상태 | 단계 · 마감 · 반복 회차 · 입력 배열 · 판정창 그룹 · 생존자 명단을 보관한다 | 인메모리 전용 |
| **판정 엔진** | 규칙을 적용해 판정 결과를 낸다 | **인자로 받은 값만** |
| 반영기 | 판정 결과를 라운드 상태에 반영하고 영속 대상을 저장한 뒤 브로드캐스트를 요청한다 | 라운드 상태 · 영속 계층 · 브로드캐스터 |

**판정 엔진은 현재 시각을 읽지 않고 DB에 접근하지 않으며 소켓을 모른다.** 이 세 금지가 지켜지지 않으면 결정론이 깨진다.

## 입력 수집과 도착 시각 기록

```
on_frame(socket, frame):
    arrived_ms = monotonic_ms()          # 프로세스 단조 시계. 파싱 전에 찍는다
    seq        = next_seq()              # 프로세스 전역 단조 증가 수신 순번
    actor      = binding_of(socket)      # 참가자·방·방장 여부. 페이로드를 믿지 않는다
    payload    = parse(frame)            # 실패하면 개인 거부 후 소켓 종료
    dispatch(actor, payload, arrived_ms, seq)
```

- **도착 시각은 파싱·검증 전에 찍는다.** 파싱 비용이 사람마다 다른 값으로 판정에 섞이지 않게 한다.
- 시각은 **프로세스 단조 시계의 정수 밀리초**이며 라운드 시작 시각을 원점으로 하는 상대 값으로 저장한다. 벽시계는 표시·감사용이다(ADR-13).
- **수신 순번**은 도착 밀리초가 같을 때만 쓰는 결정론적 보조 축이다. 순번 자체를 순위로 삼지 않는다.
- 도착 시각 배열은 **인메모리 전용**이다. DB에 개별 입력 시각을 쓰지 않는다(ADR-04).

## 멱등 처리

같은 입력은 **최초 1회만** 인정하고, 이미 끝난 판·지난 회차에 도착한 입력은 버린다. 두 겹으로 강제한다(ADR-17).

### 1겹 — 요청 식별자

| 대상 | 강제 수단 |
|------|-----------|
| 영속 입력(투표·안건 제출) | DB의 요청 식별자 UNIQUE 제약. 위반은 성공으로 처리하고 최초 결과를 돌려준다 |
| 인메모리 입력(눈치 누르기·시간초 시작·정지·룰렛·사다리 실행) | 라운드 상태의 처리 완료 집합. 이미 있으면 무시하고 최초 결과를 돌려준다 |

### 2겹 — 문맥 일치

입력에 실린 값이 서버의 현재 값과 **모두** 같을 때만 수용한다.

| 검사 축 | 불일치 시 |
|---------|-----------|
| 라운드 식별자 | 버린다. 지난 판의 입력이다 |
| 단계 | 버린다. 제출 단계 입력이 투표 단계에 왔다 |
| 반복 회차 | 버린다. 직전 결선의 입력이 새 결선에 왔다 |
| 명단 스냅샷 포함 여부 | 거부한다. 게임 시작 후 들어온 사람은 후보가 아니다 |
| 마감 이전 도착 | 버린다. 마감은 서버가 선언한다 |
| 1인 허용 횟수 | 초과분을 거부한다. 킹메이커 표 수·저격 중복 투표 설정이 상한을 준다 |
| 게임별 금지 조건 | 거부한다. 자기 안건 투표·자기 자신 지목 등 |

**버린다와 거부한다는 다르다.** 버리는 경우는 조용히 무시하고 발신자에게만 처리 완료를 알린다(사용자 잘못이 아니다). 거부하는 경우는 발신자에게만 에러 코드를 돌려준다. 어느 쪽도 **브로드캐스트하지 않는다** — 중간 상황이 다른 사람 화면에 새는 것을 막기 위해서다. 코드의 정본은 [../10_glossary/02_error_codes.md](../10_glossary/02_error_codes.md)다.

## 난수와 시드

```
create_round(room, game_id, config, roster):
    seed = crypto_random_bytes(16)            # 암호학적 난수원. 시각·방 코드에서 유도하지 않는다
    round = Round(id=new_id(), game=game_id, config=config,
                  roster=roster,               # 명단 스냅샷 — 이후 변하지 않는다
                  seed=seed, phase=..., repeat=0)
    persist(round)                             # game_rounds에 시드를 함께 저장
    return round

derive(seed, purpose, n):                      # 결정론적 도출
    stream = prng(seed || purpose)             # 같은 시드·용도면 같은 수열
    return take(stream, n)
```

| 규칙 | 내용 |
|------|------|
| 생성 시점 | 라운드 생성 시 1회. 결선·재대결은 같은 라운드 안에서 **용도 문자열에 회차를 넣어** 다른 수열을 뽑는다 |
| 난수원 | 암호학적 난수. 시각·방 코드·참가자 수에서 유도하지 않는다 — 유도하면 예측할 수 있다 |
| 결정성 | 같은 시드·용도면 같은 결과다. 사후 재현과 검증이 가능하다 |
| 노출 시점 | **판정 확정 전에는 클라이언트에 내려보내지 않는다.** 미리 내려보내면 결과를 먼저 계산할 수 있다 |
| 확정 후 | 결과와 시드를 함께 내려보내 연출을 재현하게 한다 |
| 수명 | 방 수명 동안만 보관하고 방과 함께 삭제한다 |
| 쓰는 게임 | 서버 난수 판정 2종(운명의 룰렛 · 사다리타기). 투표·타이밍 게임은 판정에 난수를 쓰지 않는다 |

**사다리타기는 순열을 먼저 뽑고 그 순열이 나오도록 가로줄을 구성한다.** 가로줄을 무작위로 놓고 결과를 읽는 방식은 항목 배분이 균등하지 않다. 상세는 [../05_game_rules/README.md](../05_game_rules/README.md)가 확정한다.

## 게임별 판정 호출 규약

전 게임이 같은 시그니처를 갖는다. 형식이 같아야 새 게임을 붙일 때 빠진 처리를 셀 수 있다.

```
judge(ctx, inputs) -> Verdict          # 순수 함수. 시각을 읽지 않고 DB·소켓에 접근하지 않는다

ctx (판정 문맥):
    round_id        라운드 식별자
    game_id         게임 종류
    config          방장 설정 — 주제 · 목표 시간 · 판정창 · 투표 시간 · 표 수 · 공개 여부 등
    roster          명단 스냅샷 — 게임 시작 시 고정된 참가자 목록
    alive           생존자 명단 — 눈치게임처럼 라운드가 이어지는 게임에서만 쓴다
    seed            라운드 시드
    phase           현재 단계
    repeat          반복 회차 (0부터. 결선·재대결·무효 재시작마다 1 증가)
    started_ms      단계 시작 시각 (라운드 시작 원점의 상대 정수 밀리초)
    deadline_ms     단계 마감 시각. 제한이 없으면 없음으로 둔다
    tie_pool        직전 회차의 동점자 집합. 첫 회차에는 비어 있다

inputs (수용된 입력의 배열. 도착 순으로 정렬되어 있다):
    participant_id  주체 — 소켓 바인딩에서 온 값
    kind            입력 종류 (제출 · 투표 · 지목 · 시작 · 정지 · 누르기 · 실행)
    payload         입력 값
    arrived_ms      서버 도착 시각 (정수 밀리초)
    seq             수신 순번 (같은 밀리초의 결정론적 보조 축)

Verdict (판정 결과):
    outcome         DECIDED | TIE | VOID | HOST_CHOICE
    winner          단독 승자 (DECIDED이고 1인 선정 게임일 때)
    assignments     전원 배정 (사다리타기)
    tally           개표 결과 (킹메이커 · 익명 저격)
    survivors       다음 회차 생존자 (눈치게임)
    tie_pool        다음 회차 동점자 집합 (TIE일 때)
    next_phase      다음 단계
    next_deadline   다음 단계의 제한 시간 (밀리초. 없으면 없음)
    persist         영속 대상 — 확정 결과 본문과 승자 식별자
    reveal          공개 범위 — 익명 게임에서 무엇을 내려보내도 되는지
```

### 결과 종류의 뜻

| outcome | 뜻 | 다음 동작 |
|---------|-----|-----------|
| DECIDED | 단독 승자 또는 전원 배정이 확정됐다 | 결과를 저장하고 방을 결과 상태로 옮긴다 |
| TIE | 동점이라 다음 회차가 필요하다 | 반복 회차를 1 올리고 같은 라운드 안에서 재진입한다. **3회에 도달하면 엔진이 HOST_CHOICE를 낸다** |
| VOID | 판이 성립하지 않았다(눈치게임 전원 미입력 등) | 방장 선택 대기로 간다 |
| HOST_CHOICE | 자동 진행을 멈추고 방장이 골라야 한다 | 방장에게 선택지를 보내고 다른 참가자는 대기 표시를 본다 |

**TIE는 무한히 이어지지 않는다.** 반복 회차가 상한(3회)에 도달하면 엔진이 TIE 대신 HOST_CHOICE를 내며, 이것이 종료 증명의 근거가 된다(ADR-19). 종료 증명 자체는 각 게임 문서가 담는다.

### 호출 시점

```
판정을 트리거하는 것은 둘뿐이다.
  ① 마감 타이머 만료 — 서버 타이머가 선언한다
  ② 전원 입력 완료 — 수용된 입력의 주체 집합이 명단(또는 생존자)을 덮으면 즉시 판정한다

on_trigger(round):
    inputs = accepted_inputs_of(round)
    fill_defaults(inputs, round)             # 미입력자를 게임별 기본값으로 채운다
    verdict = judge(ctx_of(round), inputs)
    apply(round, verdict)                    # 인메모리 상태 갱신
    if has_persist(verdict): persist_in_tx(verdict)   # 라운드·결과 저장 후 commit
    broadcast(public_view_of(verdict))       # commit 이후에만
```

- **미입력자는 판정 전에 기본값으로 채운다.** 판정 함수가 결측을 다루지 않게 해 규칙이 단순해진다. 기본값은 게임별로 다르다 — 킹메이커·익명 저격은 기권(0표), 시간초 잡기는 최하위군, 눈치게임은 다음 회차 생존.
- **전원 입력 완료로 조기 판정한다.** 마지막 사람이 누르면 남은 제한 시간을 기다리지 않는다. 다만 눈치게임처럼 시간 자체가 규칙인 게임은 예외이며 게임 문서가 정한다.
- **판정 결과의 공개 뷰는 엔진이 정한 reveal 범위 안에서만 만든다.** 익명 게임의 제출자·지목자 식별 정보는 공개 설정이 켜지고 개표가 끝난 뒤에만 페이로드에 들어간다.

## 판정 확정과 영속의 순서

```
1. 판정 결과 산출          (인메모리 · 순수 함수)
2. 라운드 상태 갱신        (인메모리)
3. 트랜잭션 시작
     라운드 행 잠금 → 이미 확정됐으면 기존 결과를 그대로 쓴다(멱등)
     확정 결과 저장 · 라운드 종료 표시 · 방 상태 갱신
   커밋
4. 방 상태 버전 증가
5. 브로드캐스트
```

- **3번 안에서 소켓 전송을 하지 않는다.** 커밋 실패 시 전송이 이미 나가 있으면 되돌릴 수 없다.
- **라운드당 확정 결과는 1건이다.** 중복 종료 요청은 기존 결과를 그대로 돌려준다.
- 커밋 이후 전송이 전부 실패해도 DB를 되돌리지 않는다(ADR-11).

| 익명 저격 | 참가자 투표 | 지목 배열 · 중복 투표 설정 · 공개 설정 | 미사용 | 결선 최대 3회 |
| 눈치게임 | 참가자 타이밍 | 누르기 도착 시각 배열 · **판정창 그룹핑** · 생존자 명단 | 미사용 | 발생하지 않는다 |

**시간초 잡기만 클라이언트가 만든 값을 판정에 쓴다.** 그 값은 엔진에 들어가기 전에 검증기가 서버 도착 시각 차이로 범위를 확인하며, 범위를 벗어나면 입력을 무효로 처리해 미입력 기본값으로 바꾼다. 검증 방법은 [04_time_and_timing.md](./04_time_and_timing.md)가 확정한다.
