# 05 방 상태 머신

> **대상**: 방 상태 4종의 전이 · (상태 × 이벤트) 전표 · 각 상태에서 허용·거부되는 동작
> **작성일**: 2026-08-02
> **원천**: git 529e312 docs/db.md §11(상태 머신·기본 처리 원칙) · git ecceb11 docs/03_architecture/01_data_model.md §2.1 · docs_legacy/requirements.md §3.1 G-5·G-6·G-16 · §4.2~4.6 · §6 설계 결정 · frontend/src/lib/store.ts(화면 전환 실측) · [../README.md](../README.md)(전역 불변식) · [../02_features/08_permission_matrix.md](../02_features/08_permission_matrix.md)

방은 **대기 · 진행 · 결과 · 폐기** 네 상태를 갖는다. 상태의 **의미와 전이**는 본 문서가 정본이며, 컬럼 자료형과 라벨 표기는 [../06_database/README.md](../06_database/README.md)와 [../10_glossary/README.md](../10_glossary/README.md)가 확정한다.

**방 상태와 라운드 단계는 다른 축이다.** 방 상태는 방 전체가 무엇을 하는 중인가를, 라운드 단계는 한 판 안에서 어디까지 왔는가를 말한다. 진행 상태의 방 안에서 라운드 단계가 여러 번 바뀌고, 동점 재진행은 **새 라운드가 아니라 같은 라운드의 반복 회차 증가**다. 라운드 단계 전이의 정본은 [../05_game_rules/README.md](../05_game_rules/README.md)다.

## 상태 정의

| 상태 | 뜻 | 라운드 | 신규 입장 | 방 행 |
|------|-----|:------:|:---------:|-------|
| **대기** | 대기방. 사람을 모으고 게임과 설정을 고르는 중이다 | 없다 | **받는다**(정원 안에서) | 있다 |
| **진행** | 한 판이 돌아가는 중이다. 명단 스냅샷이 고정돼 있다 | 있다(진행 중) | 받지 않는다 | 있다 |
| **결과** | 판정이 확정돼 결과를 보는 중이다 | 있다(종료됨) | 받지 않는다 | 있다 |
| **폐기** | 방이 사라졌다. 소켓을 전부 닫고 방 행과 하위 데이터를 삭제한다 | 취소됨 | 받지 않는다 | **없다** |

**폐기는 되돌아오지 않는 종단 상태다.** 초대 코드는 방 삭제와 함께 회수되어 이후 새 방이 쓸 수 있다.

## 전이도

```
        방 생성
           │
           ▼
      ┌─────────┐   게임 시작(방장·전원 준비·최소 인원)   ┌─────────┐
      │  대기   │ ─────────────────────────────────────▶ │  진행   │
      │         │ ◀───────────────────────────────────── │         │
      └─────────┘        대기방 복귀(방장)                └─────────┘
           ▲                                                  │
           │                                     판정 확정      │  동점(회차<3) · 상한 도달 대기
           │  대기방 복귀(방장)                               ▼   ↺ 같은 라운드 안에서 회차 증가
           │                                            ┌─────────┐
           └───────────────────────────────────────────  │  결과   │
                                                         └─────────┘
                                     다시 하기(방장) ──────────┘
                                        (결과 → 진행)

    대기 · 진행 · 결과 어디에서든
        방장 이탈 확정 · 마지막 참가자 이탈 · 10분 무활동 · 서버 재기동
                                   │
                                   ▼
                              ┌─────────┐
                              │  폐기   │  (종단 — 방 행 삭제 · 코드 회수)
                              └─────────┘
```

## (상태 × 이벤트) 전표

**모든 칸을 채운다.** 빈 칸이 남으면 구현자가 임의로 메우고 그것이 결함이 된다. 전이가 일어나는 칸은 **굵게** 표시한다.

| # | 이벤트 | 대기 | 진행 | 결과 | 폐기 |
|:-:|--------|------|------|------|------|
| 1 | 새 참가자 입장 요청 | 정원·닉네임 중복 검사 후 수락. 슬롯 배정 | 거부 — 판이 끝날 때까지 기다리라고 안내한다 | 거부 — 결과를 보는 중이라 명단이 고정돼 있다 | 거부 — 방이 없다 |
| 2 | 소켓 핸드셰이크 | 토큰·방 일치 검증 후 수락. 방 스냅샷 1회 발신 | 거부 후 소켓 종료 | 거부 후 소켓 종료 | 거부 후 소켓 종료 |
| 3 | 프로필 확정 | 활성으로 전환하고 입장을 브로드캐스트한다 | 거부 — 새 참가자가 없다 | 거부 | 거부 — 방이 없다 |
| 4 | 준비 완료 토글 | 참가자만 반영·브로드캐스트. 방장이 보내면 무시한다 | 무시 — 진행 중에는 준비 개념이 없다 | 무시 — 대기방 복귀 후 다시 누른다 | 무시 |
| 5 | 채팅 전송 | 중계한다. 서버에 저장하지 않는다 | 중계한다 — 채팅은 방 전 구간에서 열린다(D-45) | 중계한다 | 거부 — 방이 없다 |
| 6 | 게임 선택 | 방장만. 최소 인원 확인 후 반영하고 설정을 기본값으로 초기화한다 | 거부 | 거부 — 대기방 복귀 후에 고른다 | 거부 |
| 7 | 게임 설정 변경 | 방장만. 항목·범위 검증 후 반영·브로드캐스트 | 거부 | 거부 | 거부 |
| 8 | 게임 시작 | 방장만. 방장 제외 전원 준비·최소 인원·설정 유효를 확인하고 **명단 스냅샷을 고정한 뒤 진행으로 전이** | 거부 — 이미 진행 중이다 | 거부 — 다시 하기를 쓴다 | 거부 |
| 9 | 게임 입력 도착 | 거부 — 라운드가 없다 | 멱등·문맥 일치 검사 후 수용하거나 버린다. 마감 이후 도착은 버린다 | 버린다 — 끝난 판의 입력이다 | 소켓이 이미 닫혀 도달하지 않는다 |
| 10 | 판정 확정(단독 승자·전원 배정) | 발생하지 않는다 — 라운드가 없다 | 결과를 저장하고 **결과로 전이**한다 | 발생하지 않는다. 중복 종료 요청에는 기존 결과를 그대로 돌려준다 | 발생하지 않는다 |
| 11 | 판정 동점(반복 회차 3 미만) | 발생하지 않는다 | 같은 라운드에서 반복 회차를 1 올려 재진입한다. **상태는 진행 그대로** | 발생하지 않는다 | 발생하지 않는다 |
| 12 | 반복 상한 도달·무효 라운드 | 발생하지 않는다 | 자동 진행을 멈추고 방장 선택 대기로 둔다. **상태는 진행 그대로** | 발생하지 않는다 | 발생하지 않는다 |
| 13 | 방장 선택 수신 | 거부 — 선택 대기가 아니다 | 방장만. 선택지에 따라 재진행(진행 유지) · **결과로 전이** · **대기로 전이** 중 하나를 실행한다 | 거부 | 거부 |
| 14 | 다시 하기 | 거부 — 직전 결과가 없다 | 거부 | 방장만. 최소 인원을 다시 확인하고 같은 설정으로 새 라운드를 만들어 **진행으로 전이** | 거부 |
| 15 | 대기방 복귀 | 거부 — 이미 대기다 | 거부 — 진행 중 취소 경로를 두지 않는다 | 방장만. 준비 상태를 전원 해제하고 **대기로 전이**. 채팅 이력은 각자 브라우저에 남는다 | 거부 |
| 16 | 참가자 강퇴 | 방장만. 대상을 이탈 확정하고 소켓을 닫는다 | 거부 — 명단 스냅샷이 고정돼 있다 | 거부 | 거부 |
| 17 | 참가자 명시적 나가기 | 즉시 이탈 확정. 명단에서 빼고 슬롯을 돌려준다 | 즉시 이탈 확정하되 **후보로 남기고** 미입력 기본값으로 처리한다 | 즉시 이탈 확정. 결과의 명단 표시는 그대로 둔다 | 무시 — 이미 정리됐다 |
| 18 | 참가자 이탈 확정(유예 만료) | 명단에서 빼고 슬롯을 돌려준다 | 후보로 남기고 미입력 기본값으로 처리한다 | 결과의 명단 표시는 그대로 둔다 | 무시 |
| 19 | 방장 명시적 나가기 | **폐기로 전이** | **폐기로 전이.** 판은 결과 없이 끝난다 | **폐기로 전이** | 무시 |
| 20 | 방장 이탈 확정(유예 만료) | **폐기로 전이** | **폐기로 전이.** 판은 결과 없이 끝난다 | **폐기로 전이** | 무시 |
| 21 | 마지막 참가자 이탈 | **폐기로 전이** | **폐기로 전이** | **폐기로 전이** | 무시 |
| 22 | 10분 무활동 만료 | **폐기로 전이** | **폐기로 전이** | **폐기로 전이** | 대상이 없다. 무시 |
| 23 | 서버 재기동 | **폐기로 전이** — 기동 정리가 삭제한다 | **폐기로 전이** — 진행 중 라운드를 취소로 닫고 삭제한다 | **폐기로 전이** | 정리 대상이 없다 |

**거부와 무시와 버린다는 다르다.** 거부는 발신자에게만 에러 코드를 돌려준다. 무시는 아무 응답도 하지 않고 상태를 바꾸지 않는다. 버린다는 정상 흐름에서 생길 수 있는 늦은 입력을 조용히 없애고 발신자에게 처리 완료만 알린다. **셋 다 브로드캐스트하지 않는다.**

## 상태별 허용·거부 요약

| 동작 | 대기 | 진행 | 결과 | 주체 |
|------|:----:|:----:|:----:|------|
| 새 입장·프로필 확정 | 허용 | 거부 | 거부 | 신규 참가자 |
| 준비 토글 | 허용 | 무시 | 무시 | 참가자 전용 |
| 채팅 | 허용 | 허용 | 허용 | 전원 |
| 게임 선택·설정 변경 | 허용 | 거부 | 거부 | 방장 |
| 게임 시작 | 허용 | 거부 | 거부 | 방장 |
| 게임 입력 | 거부 | 허용 | 버림 | 명단 스냅샷의 참가자 |
| 방장 선택(상한·무효) | 거부 | 허용 | 거부 | 방장 |
| 다시 하기 | 거부 | 거부 | 허용 | 방장 |
| 대기방 복귀 | 거부 | 거부 | 허용 | 방장 |
| 강퇴 | 허용 | 거부 | 거부 | 방장 |
| 나가기 | 허용 | 허용 | 허용 | 전원 |
| 결과 이미지 저장 | — | — | 허용 | 전원 |

- **강퇴가 대기에서만 허용되는 이유**는 명단 스냅샷 고정 때문이다. 진행·결과에서 사람을 빼면 후보 집합이 판정 도중·판정 후에 바뀐다.
- **진행 중 취소 경로를 두지 않는다.** 판을 멈추는 사건은 방장 이탈뿐이다.
- 각 동작의 서버 검증 지점과 에러 코드는 [../02_features/08_permission_matrix.md](../02_features/08_permission_matrix.md)가 갖는다.

## 폐기로 가는 네 경로

| 경로 | 판정 주체 | 지연 | 진행 중 라운드 처리 |
|------|-----------|------|--------------------|
| 방장 이탈 | 명시적 나가기는 즉시 · 연결 끊김은 이탈 유예 60초 만료 시 | 최대 120초(하트비트 60 + 유예 60) | 취소로 닫는다. 결과를 저장하지 않는다 |
| 마지막 참가자 이탈 | 활성 참가자 수가 0이 되는 순간 | 즉시(유예를 거친 뒤) | 취소로 닫는다 |
| 10분 무활동 | 만료 스위퍼(60초 주기) | 최대 10분 + 60초 | 취소로 닫는다 |
| 서버 재기동 | 기동 정리 절차 | 기동 시 1회 | 취소로 닫는다 |

**폐기 시 동작은 네 경로가 같다** — 진행 중 라운드 취소 → 방 행 삭제(하위 데이터 함께 삭제) → 남은 소켓에 사유를 담은 종료 통지 후 닫기 → 인메모리 방 상태 제거 → 초대 코드 회수. 삭제는 요청 트랜잭션 안에서 즉시 처리하며 지연 삭제 큐를 두지 않는다.

**폐기 사유는 화면에 알린다** — 방장 이탈 · 마지막 참가자 이탈 · 10분 무활동 · 서버 재기동 넷을 구분해 표지 화면으로 안내한다.

## 무활동의 정의

10분 만료의 기준이 되는 마지막 활동 시각은 다음 사건에서 갱신한다.

| 갱신하는 사건 | 갱신하지 않는 사건 |
|---------------|-------------------|
| 참가자 입장·프로필 확정·나가기 | 하트비트 ping과 pong |
| 준비 토글 · 채팅 · 게임 선택 · 설정 변경 | 서버가 발행한 타이머 알림 |
| 게임 시작 · 게임 입력 · 판정 확정 | 만료 스위퍼의 스캔 |
| 다시 하기 · 대기방 복귀 · 강퇴 | 연결 상태 전이(연결 ↔ 의심) |

**하트비트를 활동으로 세지 않는 이유**는 아무도 조작하지 않는 방이 소켓만 붙어 있다는 이유로 영원히 살아남기 때문이다. 사람이 무언가를 한 것만 활동으로 센다.
