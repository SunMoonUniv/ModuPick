# REQ-PLAY — 게임 진행 공통

> **대상**: 게임 진행 공통(PLAY) 도메인 요구사항 15항(REQ-PLAY-01~15)
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §4.4 US-401~403 · [../02_features/04_play_common.md](../02_features/04_play_common.md)(F-PLAY-01~12) · [../05_game_rules/01_common.md](../05_game_rules/01_common.md)(판정의 결정성·미입력 처리·반복 상한과 교착 해소) · [../01_overview/06_design_decisions.md](../01_overview/06_design_decisions.md) D-05~D-09·D-15·D-18·D-19·D-26 · [01_global_rules.md](./01_global_rules.md)

게임 6종이 공유하는 판정 기반이다. [01_global_rules.md](./01_global_rules.md)가 **무엇이 규칙인가**를 정한다면 본 문서는 그 규칙을 **서버의 어느 표면이 어떻게 집행하는가**를 정한다. 서버 전용 요구사항이 많아 화면으로 확인할 수 없는 항목이 여럿이며, 그런 항목의 검증 방법은 응답 페이로드 대조·저장 행 조회·코드 경로 확인으로 적었다.

## 요구사항

|----|----------|-----------|-----------|:--------:|
| **REQ-PLAY-01** | 판정 엔진이 승자·배정·순위를 서버에서 확정해 전원에게 같은 값으로 내려보내고, 클라이언트가 만든 값을 판정에 넣지 않는다 | 게임 6종 각각에서 결과 확정 응답이 서버 계산 결과인지 코드 경로로 확인한다. 클라이언트가 결과 필드를 조작해 보내도 다른 참가자 화면의 결과가 바뀌지 않는지 확인한다 | F-PLAY-01 | P0 |
| **REQ-PLAY-02** | 라운드 시드를 서버가 뽑아 결정적 의사난수 생성기에 넣고, 화면에 그리는 난수 값(회전 각도·가로선 좌표)도 그 시드나 인덱스에서 결정적으로 계산하게 한다 | 같은 시드로 판정을 재실행해 결과가 같은지 확인한다. 클라이언트 코드의 난수 호출이 파티클 같은 장식에만 있고 좌표·각도 계산에 없는지 확인한다 | F-PLAY-01 | P0 |

| **REQ-PLAY-07** | 남은 시간을 서버가 정한 마감 시각 기준으로 전원에게 동일하게 내려주고 클라이언트는 그 시각까지 남은 시간을 그린다 | 서로 다른 두 기기의 남은 시간 표시가 같은지 확인한다. 클라이언트가 마감 시각을 스스로 정하는 경로가 없는지 확인한다 | F-PLAY-05 | P0 |

| **REQ-PLAY-13** | 게임 6종의 화면에서 주제·남은 시간·참가자별 완료 대기·규칙 다시 열기를 같은 자리에 같은 모양으로 둔다 | 게임 6종 화면을 나란히 놓고 네 요소의 위치와 형태가 같은지 확인한다 | F-PLAY-11 | P0 |
| **REQ-PLAY-14** | 동점 결선과 동점자 재대결의 실시 횟수를 라운드 단위로 서버가 세고 3회를 넘겨 자동으로 여는 일이 없게 하며, 다시 하기로 새 판을 시작하면 0으로 초기화한다 | 동점을 연속으로 만들어 4번째 반복이 자동으로 열리지 않는지 확인한다. 다시 하기 후 카운터가 0인지 저장 값으로 확인한다 | F-PLAY-12 | P0 |

## 반복 상한과 교착 해소

| 항목 | 규칙 | 근거 요구사항 |
|------|------|---------------|
| 상한 | 결선·재대결 최대 3회. 본선 1회 + 결선 3회 = 최대 4회 투표다 | REQ-PLAY-14 · REQ-GLB-22 |
| 적용 대상 | 킹메이커 결선 투표 · 익명 저격 결선 재투표 · 시간초 잡기 동점자 재대결 | REQ-KING-11 · REQ-SNIPE-07 · REQ-TIMER-13 |
| 상한 도달 | 자동 반복을 멈추고 방장 선택을 기다린다. 서버는 이 상태에서 타이머를 돌리지 않는다 | REQ-PLAY-15 |
| 방장 선택지 | **다시 시작 · 대기방으로 두 가지다** | REQ-PLAY-15 |
| 가이드 | 결선·재대결 진입에서는 띄우지 않는다 | REQ-SETUP-15 |

**선택지를 둘로 둔 이유**는 종료 증명이 이 성질에 기대기 때문이다. 다시 시작은 방장이 매번 눌러야 진행되는 사람의 행위이지 규칙의 자동 반복이 아니므로 서버의 상태 기계는 언제나 유한 단계 안에 정지한다. [../02_features/04_play_common.md](../02_features/04_play_common.md)의 반복 상한 표는 선택지를 셋으로 적고 있으나, 판정 규칙의 정본인 [../05_game_rules/01_common.md](../05_game_rules/01_common.md)의 교착 해소 표와 킹메이커·시간초의 상태 머신은 둘만 정의한다. **본 요구사항은 둘을 확정한다.**

## 중간 집계 비공개

| 대상 | 진행 중 노출 | 개표 후 노출 |
|------|:------------:|--------------|
| 참가자별 완료·대기 | 예 | 예 |
| 남은 시간 | 예 | — |
| 남은 인원(눈치게임) | 예 | 예 |
| 입력 내용(안건 본문·지목 대상·정지 시간) | **아니오** | 게임별 규칙에 따라 |
| 득표 수·순위 | **아니오** | 예 |
| 제출자·지목자 신원 | **아니오** | 방장 설정이 공개일 때만 |

이 제한은 **방장에게도 똑같이 적용된다** — 방장 권한은 진행 권한이지 열람 권한이 아니다.

**이 표는 서버가 무엇을 내려보내는가를 규정한다.** 참가자가 자기 입력을 채팅이나 육성으로 스스로 밝히는 것은 규정 대상이 아니며 막을 수도 없다. 채팅은 게임 진행 중에도 열리므로(REQ-LOBBY-08) 그 경로를 닫아 비공개를 만드는 방식을 쓰지 않는다. 보장 범위의 정본은 [01_global_rules.md](./01_global_rules.md)의 익명성과 중간 집계 비공개의 보장 범위 절이다.
