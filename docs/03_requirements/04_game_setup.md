# REQ-SETUP — 게임 선택·설정

> **대상**: 게임 선택·설정(SETUP) 도메인 요구사항 16항(REQ-SETUP-01~16)
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §3.3 주제 템플릿 · §3.4 방장 설정 항목 · §4.3 US-301~307 · [../02_features/03_game_setup.md](../02_features/03_game_setup.md)(F-SETUP-01~13) · [../05_game_rules/01_common.md](../05_game_rules/01_common.md)(주제 템플릿 4계열·방장 설정 전수 15항) · [../01_overview/06_design_decisions.md](../01_overview/06_design_decisions.md) D-21~D-25 · [01_global_rules.md](./01_global_rules.md)

방장이 게임을 고르고 주제와 세부 설정을 정한 뒤 판을 시작하기까지의 요구사항이다. **선택과 설정은 방장만 하고 결과는 전원에게 즉시 반영되며, 참가자는 같은 값을 읽기 전용으로 받는다.** 이 도메인은 설정 항목이 존재하고 누가 바꾸며 언제 초기화되는지를 확정하고, 값이 판정에 어떻게 쓰이는지는 [06_games.md](./06_games.md)와 [../05_game_rules](../05_game_rules/README.md)가 맡는다.

## 요구사항

| ID | 요구사항 | 검증 방법 | 관련 기능 | 우선순위 |
|----|----------|-----------|-----------|:--------:|
| **REQ-SETUP-01** | 게임 6종의 이름·한 줄 설명·최소 인원을 목록으로 제공한다 | 카탈로그 응답이 6건이고 각 항목에 세 필드가 있는지 확인한다. 최소 인원이 룰렛 2 · 사다리 2 · 킹메이커 3 · 시간초 2 · 저격 3 · 눈치 3인지 확인한다 | F-SETUP-01 | P0 |
| **REQ-SETUP-02** | 현재 인원이 게임 최소 인원에 못 미치면 그 게임을 고를 수 없게 잠그고 필요한 인원을 함께 보인다 | 2명인 방에서 킹메이커·저격·눈치 카드가 잠기고 필요 인원이 표시되는지 확인한다. 잠긴 게임을 직접 선택 요청해 game.not_enough_members로 거절되는지 확인한다 | F-SETUP-02 | P1 |
| **REQ-SETUP-03** | 방장의 게임 선택을 전원 화면에 반영하고 해당 게임의 기본 설정값을 함께 내려준다 | 방장이 게임을 고른 뒤 참가자 화면에 같은 게임과 같은 기본값이 보이는지 확인한다. 참가자가 선택 요청을 보내 member.not_host로 거절되는지 확인한다 | F-SETUP-03 | P0 |
| **REQ-SETUP-04** | 랜덤 게임 선택을 서버가 수행하고 현재 인원으로 시작할 수 없는 게임을 후보에서 뺀다 | 2명인 방에서 랜덤 선택을 반복해 킹메이커·저격·눈치가 한 번도 뽑히지 않는지 확인한다. 뽑힌 값이 전원에게 같은지 확인한다. 뽑은 뒤에도 설정 변경과 재추첨이 가능한지 확인한다 | F-SETUP-04 | P1 |
| **REQ-SETUP-05** | 게임 종류에 맞는 주제 템플릿 계열을 칩으로 노출하고 맨 오른쪽에 직접 입력 진입을 둔다 | 게임 6종을 각각 골라 A 계열(룰렛·시간초·눈치) · B 계열(사다리) · C 계열(킹메이커) · D 계열(저격)이 나오는지 확인한다. 각 계열 맨 오른쪽에 직접 입력이 있는지 확인한다 | F-SETUP-05 | P1 |
| **REQ-SETUP-06** | 주제 직접 입력을 최대 12자로 받되 질문형(익명 저격)만 최대 30자를 허용하고, 공백만으로는 확정하지 않는다 | 룰렛에서 13자를 입력해 차단되고 12자는 통과하는지 확인한다. 저격에서 31자가 차단되고 30자가 통과하는지 확인한다. 공백 3자로 확정을 시도해 거절되는지 확인한다 | F-SETUP-06 | P0 |
| **REQ-SETUP-07** | 선택된 게임의 설정 항목만 노출하고 참가자에게는 읽기 전용으로 보인다 | 게임을 바꿔 가며 노출 항목이 방장 설정 전수 15항 중 해당 게임 몫과 정확히 일치하는지 확인한다. 참가자 화면에서 설정 조작이 불가능하고 값은 보이는지 확인한다 | F-SETUP-07 | P0 |
| **REQ-SETUP-08** | 방장의 설정 변경을 전원 화면에 반영하고, 잦은 입력을 묶어 보내더라도 마지막 값은 전원에게 동일하게 맞춘다 | 슬라이더를 빠르게 여러 번 움직인 뒤 방장 화면과 참가자 화면의 최종 값이 같은지 확인한다 | F-SETUP-08 | P0 |
| **REQ-SETUP-09** | 게임을 다른 종류로 바꾸면 주제를 포함한 모든 설정을 기본값으로 되돌린다 | 저격에서 투표 시간을 60초로 바꾼 뒤 킹메이커로 바꿨다가 저격으로 되돌아와 투표 시간이 10초인지 확인한다. 주제도 그 계열 기본값으로 돌아왔는지 확인한다 | F-SETUP-09 | P1 |
| **REQ-SETUP-10** | 설정 항목·타입·범위·대상 게임 일치 여부를 서버가 다시 검사하고 위반하면 거절한다 | 화면이 막는 값(저격 투표 시간 4초·61초, 킹메이커 1인 투표 수 4표)을 직접 전송해 game.invalid_config로 거절되는지 확인한다. 다른 게임의 설정 키를 보내 거절되는지 확인한다 | F-SETUP-10 | P0 |
| **REQ-SETUP-11** | 게임 시작 요청에서 방장 여부·방 상태 대기·게임 선택 여부·최소 인원·방장 제외 전원 준비·설정 유효성 여섯 조건을 모두 검사하고 하나라도 어긋나면 시작하지 않는다 | 여섯 조건을 하나씩 어긋나게 만들어 각각 member.not_host · game.invalid_action · game.invalid_action · game.not_enough_members · game.invalid_action · game.invalid_config로 거절되는지 확인한다 | F-SETUP-11 | P0 |
| **REQ-SETUP-12** | 시작이 확정되면 명단 스냅샷 고정 → 라운드 식별자 발급 → 방 상태 진행 전환 → 전원 시작 통지 순으로 처리한다 | 시작 처리 직후 도착하도록 입장 요청을 보내 확실히 거절되는지 확인한다. 서버 로그에서 네 단계의 순서를 확인한다 | F-SETUP-11 | P0 |
| **REQ-SETUP-13** | 게임이 시작된 방은 새 입장을 거절하고 관전 경로를 두지 않는다 | 진행 중인 방 코드로 입장을 시도해 room.already_playing으로 거절되는지 확인한다. 관전 진입 경로가 API 목록에 없는지 확인한다 | F-SETUP-11 · F-CMN-07 | P0 |
| **REQ-SETUP-14** | 게임 첫 시작 직후 규칙 가이드를 3초간 자동으로 띄우고 게임 도중에도 다시 열 수 있게 한다 | 첫 시작에서 가이드가 자동으로 뜨고 3초 뒤 사라지는지 확인한다. 게임 화면의 가이드 재열기 버튼이 동작하는지 확인한다 | F-SETUP-12 | P1 |
| **REQ-SETUP-15** | 다시 하기·결선 투표·동점자 재대결·무효 라운드 재시작에서는 가이드를 띄우지 않는다 | 네 경로를 각각 만들어 가이드가 표시되지 않는지 확인한다 | F-SETUP-12 | P1 |
| **REQ-SETUP-16** | 게임 6종의 한 줄 요약·진행 단계·판정 기준 문안을 제공하고 방장뿐 아니라 전원이 열어볼 수 있게 한다 | 참가자 계정으로 규칙 보기를 열어 세 항목이 모두 보이는지 확인한다. 게임 6종 전부에 문안이 있는지 확인한다 | F-SETUP-13 | P1 |

## 주제 템플릿 4계열

계열별 칩 문구와 기본값의 정본은 [../05_game_rules/01_common.md](../05_game_rules/01_common.md)이며 본 표는 요구사항이 검사하는 축만 싣는다.

| 계열 | 쓰는 게임 | 직접 입력 상한 | 기본값 |
|:----:|-----------|:--------------:|--------|
| A · 사람 1명 | 운명의 룰렛 · 시간초 잡기 · 눈치게임 | 12자 | 팀장 |
| B · 전원 역할 | 사다리타기 | 항목 하나당 12자 | 조별과제 |
| C · 안건 1개 | 킹메이커 | 12자 | 팀명 |
| D · 질문 | 익명 저격 | **30자** | 발표를 제일 잘할 것 같은 사람은? |

B 계열의 항목 수 맞춤은 이 도메인이 아니라 REQ-LADDER-03이 소유한다 — 항목 수를 참가자 수에 맞추는 것은 설정 표면의 동작이 아니라 판정 전 정규화이기 때문이다.

## 게임 시작 조건

REQ-SETUP-11이 검사하는 여섯 조건이다.

| 조건 | 판정 근거 | 실패 코드 |
|------|-----------|-----------|
| 요청자가 방장인가 | 서버가 보관한 방장 멤버 식별자와 대조 | member.not_host |
| 방 상태가 대기인가 | 방 상태 머신 | game.invalid_action |
| 게임이 선택되었는가 | 선택 값 존재 | game.invalid_action |
| 현재 인원이 최소 인원 이상인가 | 활성 참가자 수 대조 | game.not_enough_members |
| 방장 제외 참가자 전원이 준비 완료인가 | 서버가 센 준비 수 | game.invalid_action |
| 설정값이 규격에 맞는가 | 설정 규격 재검증 | game.invalid_config |
