# REQ-RESULT — 결과·저장

> **대상**: 결과·저장(RESULT) 도메인 요구사항 10항(REQ-RESULT-01~10)
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §4.5 US-501~504 · [../02_features/06_result.md](../02_features/06_result.md)(F-RESULT-01~09) · [../01_overview/06_design_decisions.md](../01_overview/06_design_decisions.md) D-41~D-44 · [../08_screen/01_standards.md](../08_screen/01_standards.md)(결과 이미지 캔버스 규격) · [01_global_rules.md](./01_global_rules.md)

게임이 끝난 뒤 결과를 전원이 같은 순간에 확인하고, 남기고 싶은 사람은 이미지로 저장한 다음, 방장이 다음 동작을 고르는 구간이다. **결과를 다시 열어볼 경로를 두지 않는다** — 대기방으로 돌아가면 그 판의 결과는 참가자에게 다시 보이지 않으며 서버에만 방 수명 동안 남는다. 이 도메인의 검증 부담은 전환 타이밍의 동시성과 저장 권한의 평등에 있다.

## 결과 형태 4종

| 형태 | 쓰는 게임 | 담는 것 |
|------|-----------|---------|
| 승자형 | 운명의 룰렛 · 시간초 잡기 · 익명 저격 | 뽑힌 사람 한 명을 크게 · 나머지 참가자 · 게임별 요약 수치 |
| 배정형 | 사다리타기 | 참가자 ↔ 항목 1:1 대응 전체. X를 받은 참가자는 배정 없음으로 표시한다 |
| 개표형 | 킹메이커 | 확정 안건 · 안건별 득표를 많은 순으로. 설정이 실명일 때만 제출자를 함께 싣는다 |
| 기록형 | 눈치게임 | 라운드별 전원의 판정(안전 확정·동시 입력·미입력·최후 1인)과 서버 기준 입력 시각 |

- 킹메이커·익명 저격의 유효표 0 판정은 각 형태에 **표가 없었음**을 함께 표시한다(REQ-KING-13 · REQ-SNIPE-08).
- 지목자 공개가 비공개면 누가 누구를 지목했는지 결과 화면에서도 드러나지 않는다(REQ-SNIPE-09).

## 방장의 다음 동작

| 선택 | 근거 요구사항 | 결과 |
|------|---------------|------|
| 다시 하기 | REQ-RESULT-06 | 같은 게임·설정으로 새 라운드. 가이드 생략 |
| 대기방으로 | REQ-RESULT-07 | 방 상태가 대기로 복귀. 다른 게임을 고를 수 있다. 준비 상태는 전원 해제 |
| 방장 이탈 | REQ-GLB-21 | 방 삭제. 전원이 표지로 이동 |

**참가자가 결과 화면에서 할 수 있는 것은 이미지 저장과 채팅이다.** 채팅은 방 전 구간에서 열리므로 결과 화면에서도 닫지 않는다(REQ-LOBBY-08). 방장의 다음 동작을 기다리는 동안 결과를 두고 이야기하는 것이 이 구간의 실제 사용 흐름이다.
