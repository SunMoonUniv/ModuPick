## 1. 문서 읽는 법

### 1.1 세 문서의 관계

```
requirements.md   사용자가 무엇을 하고 싶은가        US-1xx
      ↓
features.md       그러려면 무엇을 만들어야 하는가     F-1xx
      ↓
screens.md        그 기능이 어느 화면에 들어가는가    S-01 ~ C-05   ← 이 문서
```

**화면 단위 규격(픽셀·문구·예외 처리)의 정본은 Notion 화면설계서다.** 이 문서는 그것을 대체하지 않고, 화면과 기능을 잇는 **색인** 역할만 한다.

### 1.2 표 읽는 법

| 열 | 뜻 |
| --- | --- |
| **화면** | 화면 ID와 이름. [`draft_design/draft_design_spec.md`](draft_design/draft_design_spec.md) 체계를 따른다 |
| **권한** | 방장 전용 / 참여자 전용 / 전체 |
| **넣어야 할 기능** | [`features.md`](features.md)의 `F-` 번호. **이 목록이 곧 그 화면의 작업 범위다** |
| **구현** | `mvp/` 안의 담당 파일. 없으면 미착수 |

`H`(Host) = 방장, `P`(Player) = 참여자. **Figma 프레임명이 반대로 붙어 있으니 주의한다**(`542:422`는 이름이 `S-04P`지만 내용은 방장 화면 — [정본 수정 요청 1번](requirements.md#101-notion-화면설계서)).

## 2. 화면 흐름

```
S-01 표지 ─┬─ [새 방 만들기] ─→ S-02 방 만들기 ─→ S-03 프로필 ─→ S-04H 대기방(방장)
           │
           └─ [코드 입력 + 참여] ─────────────→ S-03 프로필 ─→ S-04P 대기방(참여자)
                    └─ 진행 중인 방 → C-04 팝업

S-04H/P ──[방장: 게임 선택 → 설정 → 시작]──→ 게임 화면 (S-05 ~ S-10)
   ↑                                              │
   │                              C-01 가이드 3초 자동 노출 (S-0Xa)
   │                                              ↓
   └───[대기방으로]─── 결과 화면 (S-0Xb) ←── 결과 확정 후 3초
                          └─[다시 하기]→ 같은 설정으로 재시작 (가이드 미노출)

예외: 동점 → C-02 · 눈치 전원 탈락 → C-03 · 방장 이탈 → 결과 화면이면 유지(D-44), 아니면 표지
```

## 8. 구현 현황과 남은 화면

`mvp/`는 **방장 한 명의 시점**으로만 만들어져 있고 나머지 참가자는 봇 5인이 대신한다.

| 화면 | 상태 | 비고 |
| --- | --- | --- |
| S-01 · S-02 · S-03 | ✅ | 코드 입장은 `427132` 예외 연출만 있고 **실제 입장 플로우는 없다** |
| S-04H 대기방(방장) | ✅ | |
| **S-04P 대기방(참여자)** | ❌ **미착수** | 읽기 전용 잠금(F-309) · 준비 버튼(F-209) · 참여자 밴드(F-211)가 전부 여기 있다 |
| S-05 ~ S-10 게임 6종 | ✅ | 방장 시점 · 봇 입력 시뮬레이션 |
| 결과 4변형 | ✅ | `S-07b-2`(실명 모드)는 데이터 구조만 있고 화면 분기 확인 필요 |
| C-01 ~ C-05 | ✅ | |
| **방 만료 · 연결 종료 · 이탈 경고** | ❌ **미착수** | F-602 · F-603 · F-604 — 데모에서 한 번도 재현된 적이 없다 |
| **결과 화면 방장 이탈**(F-601a) | ❌ **미착수** | 2026-07-29 신규 확정([D-44](requirements.md#7-확정된-설계-결정)) |

### 8.1 실제 API 연동 전에 해야 할 일

1. **S-04P를 먼저 만든다.** 참여자 시점은 요구사항의 절반을 차지하는데 화면이 없다. 백엔드 연동과 동시에 만들면 두 축이 같이 흔들려 원인 분리가 안 된다.
2. **실제 입장 플로우를 mock으로 완성한다.** 지금은 `tryJoin`이 "없는 방 / 진행 중인 방"만 반환하고 성공 경로가 없다.
3. **예외 흐름을 mock으로 한 번씩 재현한다.** 방 만료·연결 종료·방장 이탈은 코드가 아니라 시나리오 문제라 백엔드 없이도 검증할 수 있다.
