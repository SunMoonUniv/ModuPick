# 사용자 흐름 (User Flow)

> 화면별로 사용자가 무엇을 할 수 있는지 정의한다.
> **화면 ID는 [`04_requirements/01_screen_map.md`](01_screen_map.md)를 따른다.** 시각 규격은 [`07_design/00_foundation.md`](../07_design/00_foundation.md), 게임 규칙은 [`05_game_rules/00_common.md`](../05_game_rules/00_common.md)를 본다.
> 최종 수정: 2026-07-26

---

## 전체 흐름

```
S-01 표지 ─┬─[새 방 만들기]→ S-02 방 만들기 ─┐
           │                                  ├→ S-03 프로필 설정 ─┬→ S-04-HOST  (방장)
           └─[코드 입력·참여]─────────────────┘                    └→ S-04-GUEST (참여자)
                                                                            │
                    ┌───────────────────────────────────────────────────────┘
                    ▼  방장이 [게임 시작] · 전원 READY 필수
              M-01 가이드 팝업 (3초) → 게임 진행 → 결과 발표 → 대기방 복귀 / 다시 하기
```

---

## S-01 · 표지 (메인 랜딩)

**진입 경로**: 최초 접속 · 방 종료 후 복귀 · 강퇴됨

- `새 방 만들기`와 `초대 코드 입력` 두 버튼이 나란히 놓인다.
  - `새 방 만들기`를 누른 사용자가 그 방의 **방장**이 된다.
  - 초대 코드를 입력해 들어온 사용자는 **참여자**가 된다.
- 코드 입력란은 뒤 **4자리 숫자만** 받는다. `MODU-` 접두어는 입력하지 않는다([D-01](../DECISIONS.md#d-01)).
- 하단에 게임 슬라이드 카드가 좌 → 우로 흐른다.
  - 카드에 마우스를 올리면 **우측 시연 영상이 해당 게임 영상으로 실시간 전환**된다.
  - 시연 영상 대시보드에는 재생·일시정지 버튼이 있다.
- **여기서 게임을 고르지는 않는다.** 게임 선택은 대기방(`S-04-HOST`)에서 방장만 한다.

**입장 실패 분기**

| 상황 | 결과 |
|---|---|
| 없는 코드 · 이미 폭파된 방 | 코드 입력란에 에러 (`ROOM_NOT_FOUND`) |
| **게임이 진행 중인 방** | `M-04` 차단 팝업 — 새로 참가할 수 없다 |
| 정원이 이미 찬 방 | 입장 실패 (`ROOM_FULL`) |

---

## S-02 · 방 만들기 (방장 전용)

**진입 경로**: `S-01`에서 `새 방 만들기`

- **방 이름**: 최대 30자. 직접 입력만 지원한다(프리셋 칩 없음 — [D-33](../DECISIONS.md#d-33)).
- **최대 인원**: 2명 ~ 10명.
  - ⚠️ **여기서 정한 값이 최종이다.** 대기방에서 인원을 바꾸는 기능은 없다([D-32](../DECISIONS.md#d-32)).
- `방 만들기`를 누르면 **초대 코드가 자동 발급**된다.
  - 형식은 `MODU-####` — `MODU-` + 숫자 4자리([D-01](../DECISIONS.md#d-01)).
  - **방장이 코드를 직접 지정할 수 없다.**
- 발급 후 바로 `S-03` 프로필 설정으로 넘어간다.

---

## S-03 · 프로필 설정 (방장·참여자 공통)

**진입 경로**: 방장은 `S-02` 완료 후 · 참여자는 `S-01`에서 코드 검증 성공 후

- **좌측 미리보기**: 내 프로필이 팀원들에게 어떻게 보일지 실시간으로 보여준다.
- **우측 입력**:

  | 항목 | 규칙 |
  |---|---|
  | 닉네임 | **1~8자 · 필수 · 같은 방 안에서 중복 불가** |
  | 한 줄 소개 | 0~24자 · **선택** |
  | 아바타 | 개발자가 제작한 동물 캐릭터 **15종** · 5×3 그리드 · 중복 불가([D-08](../DECISIONS.md#d-08)) |

- **이미 선점된 아바타**는 회색·점선으로 비활성화되고 잠금 라벨(`서연 선택`)이 붙어 클릭할 수 없다.
- 아바타 선점은 **클릭하는 순간이 아니라 `대기방 입장하기`를 눌러 프로필이 확정되는 순간** 확정된다.
  두 사람이 동시에 같은 아바타를 고르면 **늦게 확정한 쪽이 실패**하고 다시 고른다.
- 무작위로 아바타를 뽑아주는 기능은 없다([D-09](../DECISIONS.md#d-09)).
- 하단 `대기방 입장하기`를 누르면 대기방으로 들어간다.

> 이 화면에 머무는 동안에도 **다른 사람의 아바타 선점 현황이 실시간으로 갱신**된다.

## S-04-HOST · 대기방 (방장 시점)

### 참가자 관리
- 참가자를 **강제 퇴장**시킬 수 있다. 카드의 `✕`를 누르면 `M-05` 확인 모달이 뜬다.
- **나가기**를 누르면 `M-06` 확인 후 **방이 폭파**된다 — 전원이 밖으로 나가고 방이 삭제된다([D-05](../DECISIONS.md#d-05)).

### 채팅
- 대기방 채팅에 메시지를 입력할 수 있다.
- 입퇴장은 시스템 메시지로 표시된다.
- 채팅은 저장되지 않는다. 과거 메시지를 위로 스크롤해 불러올 수 없다([D-07](../DECISIONS.md#d-07) · [D-28](../DECISIONS.md#d-28)).

### 게임 선택 · 설정 (우측 패널)
- 6종 중 하나를 고른다. `랜덤 게임` 버튼으로 서버에 무작위 선택을 맡길 수도 있다.
- 고른 게임의 **설정 패널이 함께 바뀐다.** 게임마다 설정 항목이 다르다([`05_game_rules/00_common.md`](../05_game_rules/00_common.md) 참조).
- `무엇을 정할까?`(팀장 정하기 · 발표자 · 주제 정하기 등)를 **이 패널 안에서** 설정한다. 별도 화면으로 분리하지 않는다.
- 설정을 바꾸면 **참여자 화면에도 실시간으로 반영**된다(참여자는 보기만 가능).

### 게임 시작
- 방장은 **항시 준비 완료 상태**로 간주된다. 별도로 READY를 누르지 않는다.
- **참여자 전원이 READY여야** `게임 시작`을 누를 수 있다([D-12](../DECISIONS.md#d-12)).
- 최소 2명이면 시작할 수 있다. **최대 정원을 다 채우지 않아도 된다.**

---

## S-04-GUEST · 대기방 (참여자 시점)

- 하단 `준비 완료` 버튼으로 스스로 READY 상태를 토글한다. 누르기 전에는 `준비 중`이다.
- 채팅은 방장과 동일하게 사용할 수 있다.
- 우측 패널은 **열람 전용**이다. 방장이 고른 게임과 설정을 볼 수 있지만 바꿀 수 없다.
  - 패널에 `방장이 고르는 중 · 참여자는 선택할 수 없어요` 안내가 표시된다.
- `나가기`를 누르면 `M-07` 확인 후 방에서 나간다. 방은 유지된다.

**방장만 할 수 있는 것**: 게임 선택 · 게임 설정 · 랜덤 게임 · 게임 시작 · 강퇴 · 방 폭파

---

## 게임 시작 시 공통 (M-01 가이드 팝업)

방장이 `게임 시작`을 누르면 6종 모든 게임에 공통으로 적용된다.

1. **방장·참여자 전원 화면**에 해당 게임의 가이드 팝업이 뜬다.
2. **3초 카운트다운이 끝나면 자동으로 사라진다.**
3. ⚠️ 자동 노출된 가이드는 **`✕`로 닫을 수 없다** — 전원이 규칙을 보게 하기 위함([D-10](../DECISIONS.md#d-10), 승인 대기).
4. 가이드가 사라지면 **서버 기준으로** 게임이 시작된다.
5. 게임 진행 중 화면 좌상단의 `?` 버튼으로 가이드를 다시 열 수 있다.
   - 이렇게 다시 연 가이드는 **`✕`로 언제든 닫힌다.**
6. `이 게임 가이드 다시 보지 않기`를 체크하면 이 브라우저에서만 기억된다. 서버에 저장하지 않는다([D-17](../DECISIONS.md#d-17)).
7. 게임 화면 좌측 상단에는 게임 제목 헤드라인이 고정 표시된다.

> ⚠️ [D-10](../DECISIONS.md#d-10)은 승인 대기 항목이다. `✕` 즉시 닫기를 허용하는 대안이 채택되면 3번이 바뀐다.

---

## 게임 종료 시 공통 (결과 화면)

1. 서버가 최종 결과를 확정한다. 클라이언트는 그 결과를 연출로 보여줄 뿐이다([D-13](../DECISIONS.md#d-13)).
2. 게임 화면에서 결과를 먼저 연출한 뒤, **3초 후 결과 발표 화면으로 자동 이동**한다.
3. **모든 참가자**가 결과를 **PNG 이미지로 저장**할 수 있다. (xlsx 저장은 지원하지 않는다)
4. **방장만** 다음 두 가지를 할 수 있다.
   - `↻ 다시 하기` — 사전 설정 그대로 새 라운드를 시작한다
   - `← 대기방으로` — 전원을 대기방으로 되돌린다
5. **참여자는 방장이 조작할 때까지 결과 화면에서 대기**한다. 참여자 화면의 두 버튼은 비활성 상태다.

> **미결정** ([U-01](../DECISIONS.md#h-아직-결정되지-않은-것)): 방장이 `다시 하기` / `대기방으로`를 누를 때
> 참여자 전원의 동의를 받아야 하는지. **현재 규칙은 동의 절차 없음 — 참여자는 단순 대기.**

---

## 게임 중 이탈

| 상황 | 처리 |
|---|---|
| 참가자가 나가거나 연결이 끊김 | 방에서 즉시 제거. **이미 확정된 결과는 바뀌지 않는다** |
| 투표·입력을 안 한 채 이탈 | **자동 기권**으로 처리하고 라운드는 계속 진행([D-15](../DECISIONS.md#d-15)) |
| 새로고침 | ⚠️ **방에서 빠진다** — 재접속 경로가 없다([D-04](../DECISIONS.md#d-04), 승인 대기) |
| 방장이 이탈 | 방 폭파 — 전원이 `S-01`로 이동([D-05](../DECISIONS.md#d-05)) |
