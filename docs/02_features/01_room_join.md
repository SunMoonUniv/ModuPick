# ROOM — 방 만들기·입장

> **대상**: 방 만들기·입장(ROOM) 기능 명세
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §4.1 US-101~105 · §3.4 방 생성 설정 · §6 D-01·D-02·D-03·D-13 · docs_legacy/features.md §2(구 F-101~F-112) · git 529e312 docs/api.md(REST 방·멤버 엔드포인트) · frontend/src/screens/Landing.tsx · frontend/src/screens/CreateRoom.tsx · frontend/src/screens/Profile.tsx · frontend/src/lib/store.ts

방을 만들고 코드·링크로 들어와 프로필을 확정하기까지의 표면이다. 로그인·회원가입이 없으므로 **초대 코드와 닉네임이 참여 절차의 전부**이며, 이 도메인의 설계 목표는 표지에서 대기방까지의 단계를 최소로 줄이는 것이다. 입장은 두 단계로 나뉜다 — 먼저 슬롯을 선점해 토큰을 받고(대기 상태), 그다음 프로필을 확정해 대기방 명단에 나타난다(활성 상태). 정원 판정은 대기 상태 인원까지 포함해 세므로 프로필을 입력하는 중인 사람도 자리를 차지한다.

## 입장 2단계 모델

정원을 정확히 지키려면 "코드가 맞다"와 "명단에 올랐다" 사이에 자리를 잡아 두는 단계가 필요하다. 이 도메인은 그 사이를 두 상태로 나눈다.

| 단계 | 상태 | 무엇이 끝났나 | 다른 사람에게 보이나 | 정원에 세나 |
|------|------|---------------|:--------------------:|:-----------:|
| 코드 검증 | 없음 | 방이 있고 들어갈 수 있는지 확인(F-ROOM-05) | 아니오 | 아니오 |
| 슬롯 선점 | 대기 | 토큰 발급·자리 확보(F-ROOM-08) | 아니오 | **예** |
| 프로필 확정 | 활성 | 닉네임·아바타·소개 굳힘(F-ROOM-11) | 예 | 예 |

- 대기 상태 인원을 정원에 세는 이유는, 세지 않으면 프로필 입력이 겹칠 때 정원을 넘겨 활성화되기 때문이다.
- 대기 상태로 방치된 슬롯은 F-ROOM-15가 회수한다. 회수가 없으면 들어오다 만 사람이 자리를 영구히 점유한다.
- **재접속 경로를 두지 않는다.** 나갔다 들어오면 새 참가자이며 같은 토큰으로 다시 붙는 경로가 없다.

## 입력 규칙

| 항목 | 규칙 | 위반 시 |
|------|------|---------|
| 방 제목 | 1~30자. 비우면 기본값을 넣는다 | 길이 초과는 입력 단계에서 차단 |
| 정원 | 2~10 정수. **방 생성 시 정하며 이후 변경할 수 없다** | 범위 밖은 거절 |
| 초대 코드 | 숫자 6자리. 표시할 때만 MODU- 접두어를 붙이고 전송에는 숫자만 쓴다 | room.not_found |
| 닉네임 | 1~8자. 공백만 입력하면 진행할 수 없다 | member.nickname_invalid · member.nickname_duplicated |
| 아바타 | 30종 중 1개. 이미 확정된 아바타는 고를 수 없다 | member.avatar_taken |
| 소개 태그 | 최대 24자. 비워 둘 수 있다 | 길이 초과는 입력 단계에서 차단 |

수치의 최종 정본은 [../03_requirements/README.md](../03_requirements/README.md)의 해당 도메인 문서이며, 본 표는 기능이 무엇을 검사하는지를 보인다.

## 에러 코드

| 코드 | HTTP | 발생 조건 |
|------|:----:|-----------|
| room.not_found | 404 | 없는 코드이거나 이미 삭제된 방(F-ROOM-05·08) |
| room.already_playing | 409 | 게임 진행 중인 방에 입장 시도. 관전 경로를 두지 않는다(F-ROOM-08) |
| room.full | 409 | 정원 초과. 대기 상태 인원을 포함해 판정한다(F-ROOM-08) |
| room.expired | 410 | 무활동 만료로 사라진 방에 접근(F-ROOM-05·08) |
| member.nickname_invalid | 400 | 닉네임 길이·공백 규칙 위반(F-ROOM-11) |
| member.nickname_duplicated | 409 | 같은 방에 동일 닉네임 존재(F-ROOM-11·12) |
| member.avatar_taken | 409 | 이미 확정된 아바타 선택(F-ROOM-11) |
| common.validation_failed | 400 | 방 제목·정원·소개 태그 등 입력 스키마 위반(F-ROOM-03) |
| common.session_expired | 401 | 토큰 만료·무효 상태에서의 호출(F-ROOM-17) |

전수·최종 채번 정본은 [../10_glossary/02_error_codes.md](../10_glossary/02_error_codes.md)다.

## 구현 정정 대상

frontend/src가 본 명세와 어긋나는 지점이다. **문서를 구현에 맞추지 않고 구현을 고친다.**

| 지점 | 현행 구현 | 명세 |
|------|-----------|------|
| 코드 입장 | frontend/src/lib/store.ts의 tryJoin이 특정 코드 하나만 진행 중으로 처리하고 나머지는 전부 없는 방으로 돌려준다 — 입장 경로가 없다 | F-ROOM-08이 서버 검증으로 판정한다 |
| 초대 코드 | 코드를 클라이언트가 난수로 만든다 | F-ROOM-04가 서버 발급이다 |
| 닉네임 중복 | 하드코딩된 봇 닉네임 목록과만 대조한다 | F-ROOM-12가 서버 명단과 대조한다 |
| 방 제목 기본값 | 제목이 비면 생성 버튼이 비활성이다 | F-ROOM-02는 비우면 기본값을 넣는다 |
| 초대 공유 | 대기방에서 **초대 코드**만 클립보드로 복사한다 | F-ROOM-16은 초대 링크를 복사하고 공유 시트를 제공한다 |
| 초대 링크 | 라우터가 없어 링크 진입 경로 자체가 없다 | F-ROOM-07 |

정정 항목의 등재 정본은 [../01_overview/05_priorities_roadmap.md](../01_overview/05_priorities_roadmap.md)다.
