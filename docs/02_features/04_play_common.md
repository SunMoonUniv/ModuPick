# PLAY — 게임 진행 공통

> **대상**: 게임 진행 공통(PLAY) 기능 명세
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §3.1 G-2·G-5~G-11 · §4.4 US-401~403 · §6 D-04·D-05·D-06·D-07·D-10·D-11·D-22 · docs_legacy/features.md §5(구 F-401~F-409) · git 529e312 docs/api.md(game:action·game:phase·game:tick·game:progress·game:result) · [../README.md](../README.md)(전역 불변식)

게임 6종이 공유하는 판정 기반이다. 게임마다 규칙은 다르지만 **누가 결과를 정하는가·무엇을 기준으로 시간을 재는가·같은 입력이 두 번 오면 어떻게 하는가·한 명이 입력하지 않으면 판을 어떻게 굴리는가**는 전부 같다. 이 도메인이 그 공통 축을 소유하며, 게임별 기능은 여기서 정한 규칙 위에 자기 입력 표면만 얹는다. 서버 전용 기능이 많아 화면이 없는 항목은 설명에 그렇게 적었다.

---

## 기능 목록

| ID | 기능 | 설명 | 레이어 | 우선순위 | 상태 |
|----|------|------|--------|:--------:|:----:|
| **F-PLAY-01** | 판정 엔진 | 난수와 시드를 만들고 승자·배정·순위를 서버에서 확정한다. 클라이언트는 확정된 결과로 수렴하는 연출만 그린다. **화면 없음** | BE | P0 | ⬜ |
| **F-PLAY-02** | 서버 도착 시각 기록 | 모든 입력의 서버 도착 시각을 **정수 밀리초**로 남긴다. 클라이언트가 보낸 시각은 참고 값이며 판정에 쓰지 않는다. **화면 없음** | BE | P0 | ⬜ |
| **F-PLAY-03** | 입력 멱등 처리 | 같은 입력은 최초 1회만 인정하고, 끝난 판·이전 라운드에 도착한 입력은 버린다. **화면 없음** | BE | P0 | ⬜ |
| **F-PLAY-04** | 라운드 단계 전이 | 라운드의 진행 단계를 서버가 전이시키고 전환 시각·마감 시각을 전원에게 알린다. 클라이언트는 이 통지만 보고 화면을 바꾼다 | BE·RT | P0 | ⬜ |
| **F-PLAY-05** | 제한 시간 동기화 | 남은 시간을 전원에게 동일하게 내려준다. 클라이언트는 최초 오차를 재고 주기 신호로 보정하며 자체 타이머를 돌린다 | FE·RT | P0 | 🔶 |
| **F-PLAY-06** | 진행 상황 동기화 | 참가자별 **완료/대기 상태만** 브로드캐스트한다. 입력 내용과 중간 집계는 방장을 포함해 아무에게도 내려가지 않는다 | RT | P0 | ⬜ |
| **F-PLAY-07** | 조기 진행 | 대상 전원이 입력을 마치면 제한 시간이 남아도 다음 단계로 넘긴다. **화면 없음** | BE | P1 | ⬜ |
| **F-PLAY-08** | 이탈자 후보 유지 | 이탈·연결 끊김이 나도 그 참가자를 명단 스냅샷에 남겨 후보로 유지하고 결과에 이탈 표시를 붙인다. 방장 이탈만 예외다. **화면 없음** | BE | P0 | ⬜ |
| **F-PLAY-09** | 미입력 자동 처리 | 입력하지 않은 참가자를 게임별 기본값(기권·최하위·잔류)으로 자동 처리해 판이 멈추지 않게 한다. **화면 없음** | BE | P0 | ⬜ |
| **F-PLAY-10** | 결과 확정 브로드캐스트 | 확정된 결과를 전원에게 동시에 전달한다. 먼저 아는 사람을 만들지 않는다 | BE·RT | P0 | ⬜ |
| **F-PLAY-11** | 게임 화면 공통 프레임 | 주제·남은 시간·참가자별 완료/대기·규칙 다시 열기를 게임 6종이 같은 자리에 같은 모양으로 둔다 | FE | P0 | 🔶 |
| **F-PLAY-12** | 반복 상한과 방장 선택 | 동점 결선·동점자 재대결을 **최대 3회**로 제한하고, 3회에도 단독 승자가 없으면 방장이 다음 동작을 고르게 한다 | FE·BE·RT | P0 | ⬜ |

12건 — P0 11 · P1 1 · P2 0.

## 시간 판정 기준

| 축 | 기준 | 근거 |
|----|------|------|
| 입력 순서·동시성 | **서버 도착 시각**(F-PLAY-02) | 네트워크가 빠른 사람이 유리해지지 않게 한다 |
| 제한 시간 | 서버가 정한 마감 시각. 클라이언트는 표시만 한다(F-PLAY-05) | 화면마다 남은 시간이 갈리지 않게 한다 |
| 기록 단위 | 정수 밀리초. 부동소수점을 쓰지 않는다 | 밀리초 동점 판정이 표현 오차로 흔들리지 않게 한다 |
| 유일한 예외 | 시간초 잡기의 경과 시간은 클라이언트 단조 시계가 재고, 서버가 자신이 관측한 시작·정지 도착 시각 차이로 허용 범위를 검증한다. 범위 밖이면 거부한다 | 예외의 근거와 검증 방법은 [../11_fairness/01_server_authority.md](../11_fairness/01_server_authority.md)에 둔다 |

**클라이언트가 보낸 시각을 판정에 쓰지 않는다.** 개발자 도구로 값을 고칠 수 있어 공정성이 성립하지 않기 때문이다.

## 명단 스냅샷과 이탈

| 상황 | 처리 |
|------|------|
| 게임 시작 | 참가자 명단을 고정한다. 이후 명단은 판이 끝날 때까지 바뀌지 않는다 |
| 참가자 도중 이탈 | 후보에 그대로 남고 미입력으로 자동 처리된다. 결과에도 이탈 표시와 함께 나온다 |
| 참가자 재입장 | 새 참가자이며 **진행 중인 판에는 낄 수 없다.** 이전 자리로 돌아오는 경로가 없다 |
| 결과 대상이 이탈자 | 그대로 확정한다. 결과를 다시 뽑지 않는다 |
| 방장 이탈 | 유일한 예외다. 판이 결과 없이 끝나고 방이 삭제된다([02_lobby.md](./02_lobby.md) F-LOBBY-12) |

명단을 고정하는 이유는 먹튀 방지다 — 불리해지면 창을 닫아 판정을 피하는 경로를 막는다.

## 반복 상한

동점이 계속되면 판이 끝나지 않는 조합이 실제로 존재한다. 그래서 반복에는 상한과 탈출 경로를 둔다.

| 항목 | 규칙 |
|------|------|
| 상한 | 동점 결선·동점자 재대결은 **최대 3회**다 |
| 적용 대상 | 킹메이커 결선 투표 · 익명 저격 결선 재투표 · 시간초 잡기 동점자 재대결 |
| 상한 도달 | 자동 반복을 멈추고 방장에게 선택을 요구한다 |
| 방장 선택지 | 남은 동점자 중에서 정하거나 · 같은 설정으로 새 판을 시작하거나 · 대기방으로 돌아간다 |
| 참가자 | 방장의 선택을 기다린다 |
| 가이드 | 결선·재대결 진입에서는 규칙 가이드를 띄우지 않는다 |

구 스펙의 "단독 승자가 나올 때까지 상한 없이 반복"은 **폐기**했다. 종료가 보장되지 않는 규칙을 두지 않는다는 것이 전역 불변식이다.

## 중간 집계 비공개

| 대상 | 진행 중 노출 | 개표 후 노출 |
|------|:------------:|--------------|
| 참가자별 완료/대기 | 예 | 예 |
| 남은 시간 | 예 | — |
| 남은 인원(눈치게임) | 예 | 예 |
| 입력 내용(안건 본문·지목 대상·정지 시간) | **아니오** | 게임별 규칙에 따라 |
| 득표 수·순위 | **아니오** | 예 |
| 제출자·지목자 신원 | **아니오** | 방장 설정이 공개일 때만 |

표 쏠림과 눈치 보기를 유도하지 않기 위해서다. 이 제한은 **방장에게도 똑같이 적용된다** — 방장 권한은 진행 권한이지 열람 권한이 아니다.

| 코드 | HTTP | 발생 조건 |
|------|:----:|-----------|
| game.round_not_found | 404 | 존재하지 않거나 이미 정리된 라운드에 접근(F-PLAY-03) |
| game.round_already_ended | 409 | 마감 후 도착한 입력. 판정에 반영하지 않고 버린다(F-PLAY-03) |
| game.already_submitted | 409 | 1회 제한 입력의 재전송(F-PLAY-03) |
| game.invalid_action | 400 | 현재 단계에서 허용되지 않는 입력(F-PLAY-04) |
| game.eliminated | 403 | 이미 판정이 끝나 후보에서 빠진 참가자의 추가 입력(F-PLAY-03) |
| member.not_host | 403 | 반복 상한 도달 후의 선택을 참가자가 시도(F-PLAY-12) |

## 구현 정정 대상

| 지점 | 현행 구현 | 명세 |
|------|-----------|------|
| 판정 주체 | 게임 6종 전부 브라우저 난수로 결과를 만들고 다른 참가자는 시간차로 움직이는 봇이다 | F-PLAY-01이 서버 확정이다 |
| 시각 기준 | 시각·순서 판정이 브라우저 타이머 기준이다 | F-PLAY-02가 서버 도착 시각 기준이다 |
| 멱등·마감 | 라운드 개념과 마감 후 입력 폐기가 없다 | F-PLAY-03 |
| 제한 시간 | 킹메이커의 제출·투표 카운트다운이 0이 되어도 아무 일도 일어나지 않는다 | F-PLAY-05·07·09 |
| 반복 상한 | 킹메이커·익명 저격의 재투표에 상한이 없고 방장 선택 경로도 없다 | F-PLAY-12 |
| 이탈 처리 | 연결 상태 필드가 있으나 값이 바뀌지 않아 이탈 개념이 없다 | F-PLAY-08 |
