# RESULT — 결과·저장

> **대상**: 결과·저장(RESULT) 기능 명세
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §3.1 G-11~G-14 · §4.5 US-501~504 · §6 D-36·D-37·D-38·D-39 · docs_legacy/features.md §7(구 F-501~F-507) · git 529e312 docs/api.md(game:result·round:close) · frontend/src/screens/Result.tsx

게임이 끝난 뒤 결과를 전원이 같은 순간에 확인하고, 남기고 싶은 사람은 이미지로 저장한 다음, 방장이 다음 동작을 고르는 구간이다. **결과를 다시 열어볼 경로를 두지 않는다** — 대기방으로 돌아가면 그 판의 결과는 참가자에게 다시 보이지 않으며 서버에만 방 수명 동안 남는다. 이 도메인의 설계 핵심은 전환 타이밍의 동시성과 저장 권한의 평등이다.

---

## 기능 목록

| ID | 기능 | 설명 | 레이어 | 우선순위 | 상태 |
|----|------|------|--------|:--------:|:----:|
| **F-RESULT-01** | 결과 화면 전환 | 연출이 끝나 결과가 공개된 시점부터 3초 뒤 전원의 화면을 결과 화면으로 넘긴다. 참가자 간 전환 시각 편차를 두지 않는다 | FE | P0 | 🔶 |
| **F-RESULT-02** | 결과 화면 4종 | 승자형·배정형·개표형·기록형 레이아웃을 게임 종류에 따라 고른다. 주제·게임 이름·뽑힌 대상을 크게 싣는다 | FE | P0 | ✅ |
| **F-RESULT-03** | 결과 이미지 저장 | 결과 화면을 이미지 파일로 내려받는다. 주제·게임 이름·결과·참가자·날짜를 포함하며 **방장뿐 아니라 전원**이 쓸 수 있다 | FE | P1 | ✅ |
| **F-RESULT-04** | 결과 공유 | 공유 API를 지원하는 환경에서 저장 대신 바로 공유하는 선택지를 제공한다 | FE | P2 | ⬜ |
| **F-RESULT-05** | 다시 하기 | 같은 게임·같은 설정으로 새 판을 연다. 가이드를 띄우지 않으며 명단은 현재 방 인원으로 다시 고정한다. 방장 전용 | FE·BE·RT | P0 | 🔶 |
| **F-RESULT-06** | 대기방 복귀 | 전원을 대기방으로 되돌리고 방 상태를 대기로 전환한다. 준비 상태는 전원 해제로 초기화한다. 방장 전용 | FE·BE·RT | P0 | 🔶 |
| **F-RESULT-07** | 참가자 대기 안내 | 참가자에게는 다시 하기·대기방 복귀 버튼을 조작 불가로 두고 **방장의 다음 동작을 기다리는 중**임을 보인다 | FE | P1 | 🔶 |
| **F-RESULT-08** | 결과·시드 보관과 삭제 | 확정 결과와 난수 시드를 방이 살아 있는 동안 서버에 보관하고 방이 사라질 때 함께 지운다. 참가자에게 다시 보여주는 경로는 없다. **화면 없음** | BE | P1 | ⬜ |
| **F-RESULT-09** | 이탈자 표시 | 결과에 뽑힌 대상이나 명단에 이탈자가 있으면 이탈 표시를 함께 보인다. 이탈했다고 결과에서 빼지 않는다 | FE | P1 | ⬜ |

## 결과 형태 4종

| 형태 | 쓰는 게임 | 담는 것 |
|------|-----------|---------|
| 승자형 | 운명의 룰렛 · 시간초 잡기 · 익명 저격 | 뽑힌 사람 한 명을 크게 · 나머지 참가자 · 게임별 요약 수치 |
| 배정형 | 사다리타기 | 참가자 ↔ 항목 1:1 대응 전체. 빈 항목을 받은 참가자는 배정 없음으로 표시한다 |
| 개표형 | 킹메이커 | 확정 안건 · 안건별 득표를 많은 순으로. 설정이 실명일 때만 제출자를 함께 싣는다 |
| 기록형 | 눈치게임 | 라운드별 전원의 판정(안전 확정·동시 입력·미입력·최후 1인)과 서버 기준 입력 시각 |

- 익명 저격의 유효표 0 판정은 승자형에 **표가 없었음**을 함께 표시한다.
- 누가 누구를 지목했는지 결과 화면에 드러나지 않는다.

## 전환과 보관

| 항목 | 규칙 |
|------|------|
| 전환 시점 | 결과 연출이 끝나 결과가 공개된 시점 기준 3초 뒤(F-RESULT-01) |
| 동시성 | 전환은 서버가 알린 시점을 기준으로 삼는다. 참가자 기기 성능이 전환 시각을 바꾸지 않는다 |
| 재열람 | 대기방으로 돌아가면 그 판의 결과를 다시 열 수 없다. 이전 판 목록을 두지 않는다 |
| 서버 보관 | 확정 결과와 난수 시드를 방 수명 동안 보관한다. 판정 근거가 방이 살아 있는 동안 유지되게 하기 위해서다 |
| 삭제 | 방이 사라지면 결과·시드·참가자가 함께 지워진다. 개인정보 보관 범위를 방 수명으로 묶는다 |
| 저장 권한 | 이미지 저장은 방장·참가자 구분 없이 전원이 할 수 있다. 결과 공유가 사용 흐름의 마지막 단계이기 때문이다 |

## 방장의 다음 동작

| 선택 | 기능 | 결과 |
|------|------|------|
| 다시 하기 | F-RESULT-05 | 같은 게임·설정으로 새 라운드. 가이드 생략 |
| 대기방으로 | F-RESULT-06 | 방 상태가 대기로 복귀. 다른 게임을 고를 수 있다. 준비 상태는 전원 해제 |
| 방장 이탈 | [02_lobby.md](./02_lobby.md) F-LOBBY-12 | 방 삭제. 전원이 표지로 이동 |

- 다시 하기는 시작과 같은 검사를 다시 통과해야 한다 — 인원이 줄어 최소 인원을 밑돌면 거절한다.
- 참가자는 결과 화면에서 이미지 저장 외에 다른 동작을 할 수 없고 방장의 선택을 기다린다(F-RESULT-07).

## 에러 코드

| 코드 | HTTP | 발생 조건 |
|------|:----:|-----------|
| member.not_host | 403 | 참가자가 다시 하기·대기방 복귀를 시도(F-RESULT-05·06) |
| game.invalid_action | 400 | 방 상태가 결과가 아닌데 다시 하기·복귀를 시도(F-RESULT-05·06) |
| game.not_enough_members | 400 | 인원이 줄어 다시 하기의 최소 인원을 채우지 못함(F-RESULT-05) |
| game.round_not_found | 404 | 이미 정리된 라운드의 결과에 접근(F-RESULT-08) |
| room.host_left | 410 | 결과 화면에 머무는 동안 방장이 이탈함 |

## 구현 정정 대상

| 지점 | 현행 구현 | 명세 |
|------|-----------|------|

| 결과 보관 | 결과가 브라우저 상태에만 있어 새로고침하면 사라진다 | F-RESULT-08 |
