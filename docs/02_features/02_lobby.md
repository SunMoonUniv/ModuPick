# LOBBY — 대기방

> **대상**: 대기방(LOBBY) 기능 명세
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §4.2 US-201~206 · §6 D-12·D-13·D-14·D-15·D-40 · docs_legacy/features.md §3(구 F-201~F-211) · git 529e312 docs/api.md(대기방 C→S 8종·S→C 11종) · frontend/src/screens/Lobby.tsx · frontend/src/lib/store.ts

게임을 고르기 전까지 전원이 머무는 화면이며, ModuPick에서 **실시간 동기화가 처음 걸리는 지점**이다. 참가자 목록·준비 상태·선택된 게임·설정·채팅이 한 화면에 있고, 이 중 채팅을 뺀 전부가 서버 상태를 그대로 비춘다. 서버는 연결 직후 방 스냅샷을 한 번 내려 화면 전체를 그리게 하고, 그 뒤로는 개별 이벤트로 부분만 갱신한다. 방장 이탈이 방 삭제로 이어지는 지점도 여기다.

|----|------|------|--------|:--------:|:----:|

| **F-LOBBY-02** | 참가자 목록 동기화 | 입장·퇴장·강퇴를 전원에게 브로드캐스트해 목록과 인원수를 갱신한다 | RT | P0 | ⬜ |
| **F-LOBBY-03** | 방 스냅샷 전달 | 소켓 연결 직후 **최초 1회** 방·참가자·선택된 게임·설정 전체를 내려 화면을 통째로 그리게 한다. 채팅은 담지 않는다 | BE·RT | P0 | ⬜ |
| **F-LOBBY-04** | 준비 완료 토글 | 방장이 아닌 참가자가 준비·해제를 전환하고 전원 화면에 반영한다. **방장에게는 준비 버튼이 없다** | FE·RT | P0 | ⬜ |
| **F-LOBBY-05** | 준비 현황 표시 | 준비 완료 인원과 대상 인원을 밴드에 보인다. 두 수는 **서버가 세어** 내려주며 클라이언트가 목록을 다시 세지 않는다 | FE | P1 | 🔶 |
| **F-LOBBY-06** | 시작 게이트 | 방장을 제외한 참가자 전원이 준비 완료가 아니면 시작 버튼을 막고 남은 인원과 이유를 보인다 | FE·BE | P0 | 🔶 |
| **F-LOBBY-07** | 채팅 전송·중계 | 200자 이내 메시지를 제출 즉시 전원에게 중계한다. 서버는 중계만 하고 저장하지 않으며 공백만 있는 메시지는 버린다 | FE·RT | P1 | 🔶 |
| **F-LOBBY-08** | 채팅 로컬 보관·복원 | 주고받은 메시지를 각자 브라우저에 쌓아 게임을 마치고 돌아와도 이전 대화를 복원한다. 나중에 들어온 사람은 이전 대화를 볼 수 없다 | LS·FE | P1 | ⬜ |
| **F-LOBBY-09** | 시스템 메시지 | 입장·퇴장·강퇴·게임 선택·게임 시작을 채팅 흐름에 시스템 말풍선으로 남긴다 | FE·RT | P1 | 🔶 |
| **F-LOBBY-10** | 입력 중 표시 | 누군가 채팅을 입력하는 중임을 본인 제외 전원에게 보인다. 저장하지 않는 휘발 상태이며 갱신이 끊기면 자동으로 해제한다 | FE·RT | P2 | 🔶 |
| **F-LOBBY-11** | 참가자 강퇴 | 방장이 확인 절차를 거쳐 참가자를 내보낸다. 내보낸 사람은 같은 코드로 대기방에 다시 들어올 수 있고 **진행 중에는 강퇴할 수 없다** | FE·BE·RT | P1 | 🔶 |
| **F-LOBBY-12** | 방장 이탈 폐기 | 방장의 퇴장·연결 끊김을 감지해 진행 중이던 판까지 결과 없이 끝내고, 방 폐기와 사유를 전원에게 알린 뒤 표지로 보낸다 | FE·BE·RT | P0 | 🔶 |
| **F-LOBBY-13** | 방 자동 정리 | 마지막 참가자 이탈 즉시 또는 10분 무활동이면 방·참가자·결과·시드를 삭제하고 코드를 무효화한다. **진행 중에는 무활동 타이머를 멈춘다** | BE | P0 | ⬜ |

## 준비 상태 모델

| 항목 | 규칙 |
|------|------|
| 대상 | **방장을 제외한 참가자**만 준비 상태를 갖는다. 방장은 상태 자체가 없어 준비 수의 분자에도 분모에도 들어가지 않는다 |
| 시작 조건 | 대상 전원이 준비 완료여야 방장이 시작할 수 있다. 참가자가 0명이면 조건을 만족할 수 없다 |
| 해제 | 준비는 다시 눌러 해제할 수 있다. 해제되면 시작 게이트가 다시 닫힌다 |
| 집계 권위 | 준비 수와 대상 수는 서버가 계산해 내려준다. 화면마다 값이 갈리지 않게 하기 위해서다 |
| 대기방 복귀 | 결과 화면에서 대기방으로 돌아오면 준비 상태를 **전원 해제**로 되돌린다. 이전 판의 준비가 다음 판의 시작 조건을 자동으로 만족시키지 않게 한다 |
| 잠김 해소 | 한 명이 준비하지 않아 대기방이 잠기는 상황은 방장의 강퇴(F-LOBBY-11)로 푼다 |

## 채팅 보관 정책

| 항목 | 규칙 |
|------|------|
| 서버 | 중계만 한다. 저장·조회 경로를 두지 않으며 방 스냅샷에도 담지 않는다 |
| 클라이언트 | 각자 브라우저에 쌓는다. 게임을 마치고 대기방으로 돌아와도 이전 대화가 남아 있다 |
| 나중 입장자 | 이전 대화를 볼 수 없다. 서버에 이력이 없기 때문이며 이는 결함이 아니라 설계다 |
| 수명 | 방이 사라지면 그 방의 로컬 대화도 함께 정리한다 |
| 범위 | **방 전 구간**이다. 대기방·게임 중·결과 화면 어디서나 열리며 게임 종류나 단계에 따른 예외를 두지 않는다(D-45) |

## 방 수명

| 종료 사유 | 트리거 | 전원에게 알리는 내용 |
|-----------|--------|----------------------|
| 방장 이탈 | 방장 퇴장·연결 끊김(F-LOBBY-12) | 방장이 나가 방이 사라졌음. 진행 중이던 판은 결과 없이 끝난다 |
| 마지막 이탈 | 남은 인원 0(F-LOBBY-13) | 통지 대상이 없다 |
| 무활동 만료 | 10분간 사용자 행동 없음(F-LOBBY-13) | 방이 만료돼 사라졌음 |

- 무활동 타이머는 **사용자 행동**(채팅·준비·설정 변경·게임 입력)으로만 갱신한다. 자동 갱신 신호로 방을 살려 두지 않는다.
- 게임 진행 중에는 타이머를 멈춘다 — 입력을 기다리는 동안 방이 사라지면 판정 중인 라운드가 통째로 날아간다.
- 방장 권한은 **어떤 경우에도 이양되지 않는다.** 정본은 [08_permission_matrix.md](./08_permission_matrix.md)다.

|------|:----:|-----------|
| member.not_host | 403 | 참가자가 강퇴·게임 선택·설정·시작 등 방장 전용 동작을 시도(F-LOBBY-11) |
| member.kicked | 403 | 강퇴 대상에게 통지하고 소켓을 닫는다(F-LOBBY-11) |

| game.invalid_action | 400 | 현재 방 상태에서 허용되지 않는 동작(진행 중 강퇴·진행 중 준비 토글 등) |
| common.validation_failed | 400 | 채팅 길이 초과 등 입력 스키마 위반(F-LOBBY-07) |
| common.session_expired | 401 | 토큰 무효 상태의 소켓 요청 |

## 구현 정정 대상

| 지점 | 현행 구현 | 명세 |
|------|-----------|------|
| 준비 토글 | 준비 버튼이 없다. 본인은 항상 방장이고 준비 완료로 고정이며 나머지는 스크립트가 준비시킨다(frontend/src/lib/store.ts) | F-LOBBY-04가 참가자 전용 토글을 제공한다 |

| 채팅 | 본인 메시지만 실제로 쌓이고 상대 메시지는 고정된 대사 스크립트다 | F-LOBBY-07이 서버 중계로 처리한다 |
| 채팅 보관 | 브라우저 저장을 전혀 쓰지 않아 새로고침하면 사라진다 | F-LOBBY-08 |
| 방장 이탈 | 디버그 키 입력으로 방장 이탈 안내를 띄운다 | F-LOBBY-12가 연결 상태로 감지한다 |
| 강퇴 | 목록에서 제거하고 시스템 메시지만 남긴다 | F-LOBBY-11이 서버 검증·대상 통지·브로드캐스트를 거친다 |
| 무활동 만료 | 만료 개념 자체가 없다 | F-LOBBY-13 |
