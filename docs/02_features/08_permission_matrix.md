# 권한 매트릭스

> **대상**: 방장·참가자 권한 구분과 각 동작의 서버 검증 지점(횡단 — 도메인 번호 없음)
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §4.2 US-203~205 · §4.3 US-305 · §4.5 US-503 · §6 D-12·D-14·D-15 · git 529e312 docs/api.md(소켓 권한 검증·NOT_HOST) · frontend/src/lib/store.ts · frontend/src/screens/Lobby.tsx · [../README.md](../README.md)(전역 불변식)

ModuPick의 역할은 **방장(Host)과 참가자(Member) 둘뿐**이며 방장도 참가자에 포함된다. 역할은 방을 만든 사람에게 한 번 부여되고 **다른 참가자에게 이양되지 않는다** — 방장이 나가면 권한이 넘어가는 대신 방이 삭제된다. 이 문서는 어떤 동작이 방장 전용이고 어떤 동작이 참가자의 것인지, 그리고 각 동작을 **서버가 어디서 다시 검증하는지**를 한 장으로 모은다. 화면에서 버튼을 감추는 것은 사용성 장치이고 판정은 서버가 한다 — 감춘 표면도 직접 호출하면 서버가 다시 거부한다.

본 문서의 기능 ID는 [README.md](./README.md)가 가리키는 도메인 파일이 채번한 값을 참조한 것이며, 이벤트명의 정본은 [../07_api/03_socket_events.md](../07_api/03_socket_events.md), 에러 코드의 정본은 [../10_glossary/02_error_codes.md](../10_glossary/02_error_codes.md)다.

## 역할 정의

| 역할 | 부여 | 권한 요약 | 준비 상태 |
|------|------|-----------|:---------:|
| **방장(Host)** | 방을 만든 사람에게 자동 부여. 이양·위임 경로가 없다 | 참가자 권한 전부 + 게임 선택·랜덤 선택·설정 변경·게임 시작·강퇴·다시 하기·대기방 복귀·무효 라운드 선택·동점 3회 초과 시 선택. 룰렛 PICK과 사다리 START도 방장만 누른다 | 갖지 않는다 |
| **참가자(Member)** | 초대 코드·링크로 입장해 프로필을 확정한 사람 | 준비 토글·채팅·게임 입력(안건 제출·투표·지목·START/STOP·UP)·결과 이미지 저장·규칙 열람·설정 읽기·나가기 | 갖는다 |

- 관전자·부방장·운영자 역할을 두지 않는다. 게임이 시작되면 새 입장을 받지 않으므로 방에 있는 사람은 전부 후보다.
- 방장 판정 근거는 방이 보유한 방장 멤버 식별자 하나이며, 클라이언트가 보낸 역할 값은 판정에 쓰지 않는다.
- 참가자가 방장 전용 동작을 보내면 **보낸 사람에게만** 거부를 돌려주고 브로드캐스트하지 않는다 — 거부 사실이 다른 참가자 화면을 흔들지 않게 한다.

**방장에게 없는 것도 규칙이다.** 방장은 준비 상태를 갖지 않으므로 준비 토글을 보내지 않으며, 보내더라도 서버가 무시한다. 게임 시작 조건은 **방장을 제외한** 참가자 전원의 준비 완료다 — 참가자가 0명이면 시작 조건을 만족할 수 없다.

## 참가자 동작

방장도 참가자이므로 아래 동작을 모두 할 수 있다. **참가자 전용**으로 표시한 것만 방장이 수행하지 않는다.

| 동작 | 기능 ID | 주체 | 서버 검증 지점 | 실패 코드 |
|------|---------|------|----------------|-----------|
| 준비 완료 토글 | F-LOBBY-04 | 참가자 전용 | 방장이 아님 · 방 상태가 대기. 준비 수와 대상 인원은 **서버가 세어** 내려준다 | game.invalid_action |
| 채팅 전송 | F-LOBBY-07 | 전원 | 길이 상한 · 공백만 입력 차단. 서버는 중계만 하고 저장하지 않는다 | common.validation_failed |
| 안건 제출 | F-KING-02 | 전원 | 라운드·단계 일치 · 길이 상한 · **1인 1건**(재제출 거부) · 제출 후 수정 불가 | game.round_already_ended · game.already_submitted · common.validation_failed |
| 안건 투표 | F-KING-04 | 전원 | 라운드·단계 일치 · **자기 안건 차단** · 1인 허용 표 수 초과 차단 · 서로 다른 안건에만 분산 | vote.self_not_allowed · vote.limit_exceeded · game.round_already_ended |
| 저격 지목 | F-SNIPE-03 | 전원 | 라운드·단계 일치 · **자기 지목 차단** · 중복 투표 설정에 따른 표 수 상한 | vote.self_not_allowed · vote.limit_exceeded · game.round_already_ended |
| 타이머 START | F-TIMER-02 | 전원 | 라운드 일치 · 최초 1회 · 시작 지연 상한 안에 도착했는지 | game.already_submitted · game.round_already_ended |
| 타이머 STOP | F-TIMER-04 | 전원 | 라운드 일치 · START 선행 · 최초 1회 · 제한 시간 안에 도착했는지 | game.already_submitted · game.round_already_ended |
| 눈치 UP 입력 | F-NUNCHI-03 | 전원 | 라운드 일치 · 라운드당 1회 · **안전 확정자의 입력은 무시** | game.already_submitted · game.eliminated · game.round_already_ended |
| 규칙 열람 | F-SETUP-13 | 전원 | 없음(공개 메타 조회) | — |
| 설정 열람 | F-SETUP-08 | 전원 | 없음. 참가자에게는 **읽기 전용**으로 내려간다 | — |
| 결과 이미지 저장 | F-RESULT-03 | 전원 | 없음(클라이언트에서 화면을 그려 내려받는다) | — |
| 방 나가기 | F-ROOM-17 | 전원 | 본인 여부. **방장이 호출하면 방 삭제로 이어진다** | common.session_expired |

- 게임 입력은 전부 **최초 1회만** 인정한다. 같은 입력이 다시 도착하거나 끝난 라운드에 도착하면 버린다.
- 진행 중에는 참가자별 **완료/대기 상태만** 브로드캐스트한다. 입력 내용·중간 집계는 누구에게도 내려가지 않으며, 이 제한은 방장에게도 똑같이 적용된다.

## 상태별 허용 동작

방 상태는 대기 · 진행 · 결과 셋이다. 같은 동작이라도 상태가 맞지 않으면 거부한다.

| 동작 | 대기 | 진행 | 결과 |
|------|:----:|:----:|:----:|
| 새 참가자 입장 | 허용(정원 내) | 거절(room.already_playing) | 거절(room.already_playing) |
| 준비 토글 | 허용 | 거부 | 거부 |
| 채팅 | 허용 | 허용(D-45 — 방 전 구간) | 허용 |
| 게임 선택·설정 | 허용(방장) | 거부 | 거부 |
| 게임 시작 | 허용(방장·전원 준비) | 거부 | — |
| 강퇴 | 허용(방장) | 거부 | 거부 |
| 게임 입력 | 거부 | 허용(단계 일치 시) | 거부 |
| 다시 하기·대기방 복귀 | — | 거부 | 허용(방장) |
| 나가기 | 허용 | 허용 | 허용 |

- 진행 중 강퇴를 막는 이유는 명단 스냅샷이다 — 시작 순간 고정된 후보 목록을 방장이 바꿀 수 있으면 판정 대상이 흔들린다.
- 참가자가 진행 중에 나가도 **후보로 남고** 결과에 이탈 표시와 함께 나온다. 방장 이탈만 예외로 방 자체를 끝낸다.

## 서버 검증 원칙

| 원칙 | 내용 |
|------|------|
| 단일 판정점 | 방장 여부는 서버가 보관한 방장 멤버 식별자와 요청자 토큰을 대조해 판정한다. 클라이언트가 보낸 역할·플래그를 신뢰하지 않는다 |
| 이중 검증 | 화면이 버튼을 감추더라도 서버가 같은 조건을 다시 검사한다. 화면 노출 제어는 사용성 장치이지 권한 경계가 아니다 |
| 조용한 거부 | 권한 위반은 **보낸 사람에게만** 통지한다. 브로드캐스트하지 않아 다른 참가자 화면 상태를 바꾸지 않는다 |
| 상태 게이트 | 권한 검사를 통과해도 방 상태·라운드 단계가 맞지 않으면 거부한다. 두 검사는 순서가 있으며 권한이 먼저다 |
| 멱등 | 권한을 가진 주체의 중복 요청도 최초 1회만 반영한다. 다시 하기·PICK·START도 같다 |
| 익명 경계 | 킹메이커 제출자와 저격 지목자의 식별 정보는 **방장에게도** 개표 전에는 내려가지 않는다. 방장 권한은 진행 권한이지 열람 권한이 아니다 |
| 집계 권위 | 준비 수·생존자 수·득표 수는 서버가 세어 내려준다. 클라이언트가 목록을 세어 표시하면 화면마다 값이 갈린다 |

## 권한 불변식

| 불변식 | 내용 | 근거 |
|--------|------|------|
| 이양 없음 | 방장 권한은 어떤 경로로도 다른 참가자에게 넘어가지 않는다 | 게임 선택·설정·시작·재실행이 전부 방장에 묶여 있고 룰렛·사다리는 입력 주체가 방장뿐이라, 원치 않는 사람에게 진행 책임을 떠넘기지 않는다 |
| 이탈 = 삭제 | 방장이 나가거나 연결이 끊기면 방이 **즉시 삭제**되고 진행 중이던 판은 결과 없이 끝난다 | 진행할 사람이 없는 방에 남아 기다리게 하지 않는다 |
| 준비 비대칭 | 방장은 준비 상태를 갖지 않고, 시작 조건은 **방장을 제외한** 전원 준비다 | 방장이 자기 자신을 기다리는 구조를 만들지 않는다 |
| 강퇴 대칭 | 강퇴된 참가자는 같은 코드로 대기방에 다시 들어올 수 있다. 영구 차단 목록을 두지 않는다 | 반응 없는 사람을 치우는 수단이지 제재 수단이 아니다 |
| 상한 후 선택 | 결선·재대결이 3회에 이르면 자동 반복을 멈추고 **방장이 다음 동작을 고른다** | 종료가 보장되지 않는 반복 규칙을 두지 않는다 |
| 저장 평등 | 결과 이미지 저장은 방장·참가자 구분 없이 전원이 할 수 있다 | 결과 공유가 사용 흐름의 마지막 단계다 |
