# CMN — 공통·오류

> **대상**: 공통·오류(CMN) 기능 명세
> **작성일**: 2026-08-02
> **원천**: docs_legacy/requirements.md §4.6 US-601~602 · §5 NFR-01~NFR-10 · docs_legacy/features.md §8(구 F-601~F-604) · git 529e312 docs/api.md(공통 응답 규격·연결 수명주기·roomVersion) · frontend/src/App.tsx · frontend/src/components/Modals.tsx · backend/app/main.py

한 도메인에 속하지 않고 전 화면·전 요청을 관통하는 표면이다. 실시간 연결의 수명주기, 방 상태 전이, 응답과 에러의 공통 규격, 사용자에게 보이는 오류 안내, 그리고 모바일에서의 사용성이 여기 있다. **오류 안내는 사용자가 다음에 무엇을 해야 하는지 알려주는 것이 목적**이므로 사유별로 문구를 나눈다 — 연결이 끊긴 것과 방이 사라진 것은 대응이 다르기 때문이다.

| **F-CMN-08** | 모바일 반응형 | 좁은 화면에서 가로 스크롤 없이 동작하고 세로·가로 어느 방향에서도 결과와 입력 요소가 잘리지 않는다 | FE | P0 | 🔶 |
| **F-CMN-09** | 방장 권한 검증 | 방장 전용 동작을 참가자가 호출하면 거절하고 **보낸 사람에게만** 통지한다. 브로드캐스트하지 않는다. **화면 없음** | BE | P0 | ⬜ |

## 연결 수명주기

재접속 개념이 없다는 점이 이 설계의 축이다. 상태 복구 로직이 필요 없는 대신 **연결이 끊기면 방에서 빠진다.**

| 단계 | 시점 | 일어나는 일 |
|------|------|-------------|
| 핸드셰이크 | 슬롯 선점 직후(참가자) · 프로필 확정 직후(방장) | 토큰·방 코드를 실어 인증한다. 실패하면 연결을 거부한다 |
| 스냅샷 수신 | 연결 직후 최초 1회 | 방·참가자·게임 상태 전체를 받아 화면을 그린다([02_lobby.md](./02_lobby.md) F-LOBBY-03) |
| 명단 등장 | 프로필 확정 시점 | 이때 비로소 다른 사람 화면에 보인다. 연결 시점과 다르다 |
| 연결 종료 | 소켓 끊김 | **즉시 퇴장으로 처리한다.** 같은 토큰으로 다시 붙는 경로가 없다 |
| 미연결 회수 | 슬롯 선점 후 유예 시간 경과 | 핸드셰이크가 없으면 슬롯을 해제한다([01_room_join.md](./01_room_join.md) F-ROOM-15) |

새로고침 한 번이면 방에서 빠지므로 **화면은 이탈 경고를 띄운다.** 이 경고는 F-CMN-05가 담당한다.

## 오류 안내 분기

| 상황 | 사용자가 해야 할 일 | 표시 방식 |
|------|---------------------|-----------|
| 없는 방 코드 | 코드를 다시 확인한다 | 코드 입력란 인라인 |
| 정원이 찬 방 | 자리가 날 때까지 기다린다 | 코드 입력란 인라인 |
| 진행 중인 방 | 게임이 끝날 때까지 기다린다 | 모달(F-CMN-07) |
| 닉네임 규칙 위반 | 닉네임을 고친다 | 입력란 인라인 |
| 아바타 선점됨 | 다른 아바타를 고른다 | 아바타 그리드 인라인 |
| 연결 끊김 | **재입장한다** | 모달(F-CMN-05) |
| 방장 이탈로 방 소멸 | 새 방을 만들거나 새 코드를 받는다 | 모달 후 표지 이동(F-CMN-06) |
| 무활동 만료로 방 소멸 | 위와 같다 | 모달 후 표지 이동(F-CMN-06) |
| 강퇴됨 | 다시 입장하거나 나간다 | 모달 후 표지 이동 |
| 방장 전용 동작 거절 | 방장에게 요청한다 | 토스트(보낸 사람에게만) |
| 입력 마감·중복 제출 | 다음 라운드를 기다린다 | 토스트 |

**연결 끊김과 방 소멸을 같은 문구로 묶지 않는다.** 전자는 재입장하면 되고 후자는 방 자체가 없어 재입장할 곳이 없다.

## 방 상태와 허용 동작

| 상태 | 뜻 | 새 입장 | 대기방 조작 | 게임 입력 | 결과 조작 |
|------|-----|:-------:|:-----------:|:---------:|:---------:|
| 대기 | 참가자를 모으고 게임을 고르는 중 | 허용 | 허용 | 거부 | 거부 |
| 진행 | 라운드가 열려 판정 중 | 거절 | 거부 | 허용 | 거부 |
| 결과 | 판정이 끝나 결과를 보는 중 | 거절 | 거부 | 거부 | 허용 |
| 폐기 | 방장 이탈·만료·마지막 이탈 | 거절 | 거부 | 거부 | 거부 |

상태 전이의 정본은 [../04_architecture/05_room_state_machine.md](../04_architecture/05_room_state_machine.md)이며 본 표는 기능 관점의 요약이다. 동작별 상세 판정은 [08_permission_matrix.md](./08_permission_matrix.md)가 소유한다.

| 실시간 통신 | frontend/src에 네트워크 호출이 전혀 없다. backend/app/main.py에는 헬스 체크와 소켓 배선 확인용 되울림 엔드포인트만 있다 | F-CMN-01 |

| 순서 보장 | 서버가 없어 버전 개념이 없다 | F-CMN-10 |
