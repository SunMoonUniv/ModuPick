## 1. 공통 진행 규칙

### 1.1 참여 및 권한

- 게임은 최소 2명, 최대 10명이 대기방에 입장해야 시작할 수 있다.
- 대기방에 접속한 인원이 최대 접속 가능 인원보다 적어도, 모두 준비완료 상태면 게임 시작 가능.
- 방장만 게임 종류, 게임 옵션, 게임 시작 여부를 설정할 수 있다.
- 팀원은 방장이 설정하는 내용을 볼 수 있지만 직접 변경할 수 없다.
- 방장이 게임을 시작하면 모든 참가자의 화면이 해당 게임으로 동시에 전환된다.
- 게임 시작 시점의 참가자 목록을 해당 회차의 참가자로 고정한다.
- 게임이 진행 중인 방에는 접속 불가.

> ※ **킹메이커와 익명 저격은 최소 3명**이다. 2명이면 지목·투표 대상이 하나뿐이라 익명성이 성립하지 않는다. 인원이 모자란 게임은 선택지에서 비활성화하고 사유를 표시한다. — 팀 확정 사항([D-25](requirements.md#7-확정된-설계-결정)), **정본 반영 필요**

### 1.2 게임 시작

1. 방장이 대기방에서 게임을 선택한다.
2. 방장이 게임별 옵션을 설정한다.
3. 참가자들이 `준비 완료` 상태인지 확인한다.
4. 방장이 `게임 시작`을 누른다.
5. 모든 참가자 화면에 3초간 게임 가이드를 표시한다.
6. 가이드가 사라지면 서버 기준으로 게임을 시작한다.
7. 게임 가이드는 게임 화면에서 다시 열어볼 수 있어야 한다.

> ※ 참여자 **전원이 준비 완료**여야 시작할 수 있다. 방장은 준비 대상이 아니므로 `READY n/m`의 분모에서 제외한다([D-06](requirements.md#7-확정된-설계-결정) · [D-22](requirements.md#7-확정된-설계-결정)).

### 1.3 실시간 동기화 및 판정

- 게임 상태와 결과는 모든 참가자의 화면에서 동일하게 보여야 한다.
- 무작위 결과는 서버에서 생성하며 클라이언트는 결과를 임의로 다시 결정하지 않는다.
- 시간 기반 게임은 화면 애니메이션이 아닌 서버 기준 시각을 사용한다.
- 동일한 입력이 재전송되더라도 한 번만 처리한다.
- 이미 종료된 회차에 전달된 입력은 판정에 반영하지 않는다.

### 1.4 게임 종료

1. 서버가 최종 당첨자, 탈락자 또는 역할 배정 결과를 확정한다.
2. 게임 화면에서 결과를 먼저 연출한다.
3. 게임별 결과 연출이 끝나고 결과를 공개한 시점부터 3초 후 결과 발표 화면으로 이동한다.
4. 결과 발표 화면에는 최종 결과를 크게 표시한다.
5. 참가자는 결과 화면을 이미지로 저장할 수 있다.
6. 방장은 `다시 하기` 또는 `대기방으로 복귀`를 선택한다.
7. 다시 하기를 누르면 사전 설정 그대로 게임을 다시 시작한다.
8. 동점자나 눈치게임의 전원 탈락, 다시 하기로 게임이 재시작 된 경우, 가이드를 표시하지 않는다.
9. 팀원은 방장의 다음 동작 전까지 결과 화면에서 대기한다.

> ※ 저장 수단은 **이미지(PNG) 하나뿐**이다. 표(xlsx) 저장과 SNS 공유는 제공하지 않는다([D-13](requirements.md#7-확정된-설계-결정)).

### 1.5 이탈 및 재접속

- 기본적으로 재접속은 불가. 이탈 후 재접속할 시, 새로운 참가자로 간주.

## 2. Game 1. 운명의 룰렛

### 2.1 게임 목적

참가자 중 팀장, 발표자, 벌칙 수행자처럼 한 명의 대상자를 무작위로 선정한다.

### 2.2 방장 설정

| 설정 | 설명 |
| --- | --- |
| 결과 항목 | 역할·벌칙을 직접 입력 |

### 2.3 진행 순서

1. 게임 시작 시 참가자 이름과 캐릭터를 룰렛 조각으로 배치된 화면이 뜬다.
2. 모든 조각은 기본적으로 동일한 당첨 확률을 갖는다.
3. 방장이 `PICK!`를 누른다.
4. 서버가 무작위 시드와 최종 당첨 결과를 생성한다.
5. 모든 참가자 화면에서 동일한 룰렛 회전 애니메이션을 재생한다.
6. 3~5초 후 룰렛이 멈추면서 당첨자를 공개한다.
7. 추첨이 끝나면 최종 당첨자와 결과항목을 결과 화면에 표시한다.

### 2.4 판정 규칙

- 룰렛 애니메이션은 결과를 표현하는 수단이며 실제 당첨 결과는 서버가 결정한다.
- 추첨 도중 참가자가 퇴장하더라도 시작 시 확정된 후보 목록과 결과는 유지한다.

> ※ 회전 중에는 조작이 차단되고 가이드만 열어볼 수 있다. 멈추는 각도는 서버가 미리 확정한 값이며 클라이언트가 난수를 만들지 않는다.

### 2.5 결과 데이터

- 추첨에 사용된 후보 목록
- 방장이 사전에 설정한 결과 항목
- 무작위 결과 재현용 서버 시드

## 3. Game 2. 랜덤 사다리

### 3.1 게임 목적

참가자들에게 PPT, 발표, 자료조사 등의 역할이나 벌칙을 한 번에 배분한다.

### 3.2 방장 설정

| 설정 | 설명 |
| --- | --- |
| 결과 항목 | 역할·벌칙을 직접 입력(추가 입력 가능. 최대는 참가자 인원 수로 제한된다) |
| 진행 속도 | 빠르게, 보통, 느리게 |

### 3.2.1 게임 시작 조건

1. 결과 항목은 최소 1개, 최대 참가자 수만큼 입력할 수 있다. 참가자 수보다 적은 경우 나머지 결과 칸은 X 글자로 채운다.

### 3.3 진행 속도

- **빠르게:** 경로 애니메이션을 짧게 표시하거나 결과로 빠르게 이동한다.
- **보통:** 일반적인 속도로 경로를 표시한다.
- **느리게:** 각 이동을 길게 보여주어 긴장감을 높인다.

### 3.4 진행 순서

1. 화면 상단에 참가자를 배치한다.
2. 화면 하단에 방장이 입력한 역할 또는 결과 항목을 배치한다.
3. 서버가 무작위 사다리 구조와 참가자별 경로를 생성한다.
4. 방장이 캐릭터를 클릭 또는 동시 시작 버튼을 선택해 순차 또는 동시에 진행한다.
5. 참가자의 캐릭터 또는 표시선이 사다리를 따라 이동한다.
6. 모든 경로가 끝나면 참가자와 결과의 최종 연결을 공개한다.
7. 결과 화면에 `참가자 → 역할` 형태로 전체 배정 결과를 표시한다.

> ※ 참가자는 출발 위치(레인)를 고르지 않는다. 사다리 구조와 배치를 모두 서버가 정한다([D-16](requirements.md#7-확정된-설계-결정)).

### 3.5 판정 규칙

- 기본 모드는 참가자와 결과 항목을 1:1로 연결한다.
- 사다리 애니메이션은 서버가 생성한 최종 매칭과 일치해야 한다.
- 화면 크기나 기기에 따라 경로가 다르게 보이더라도 최종 배정 결과는 같아야 한다.

### 3.6 결과 데이터

- 참가자별 배정 결과
- 결과 항목 목록
- 사다리 진행 속도
- 결과 재현용 서버 시드

## 4. Game 3. 킹메이커

### 4.1 게임 목적

팀명, 프로젝트명, 메뉴 등 참가자들이 제출한 여러 아이디어 의견 중 하나를 결정한다.

### 4.2 방장 설정

| 설정 | 설명 |
| --- | --- |
| 1인당 투표 수 | 1표, 2표 등 |
| 투표 결과 익명/실명 | 익명 또는 결과 발표 시 실명 공개 |
| 결과 항목 | 의견 주제 입력 |

### 4.3 진행 순서

1. 방장이 대기방에서 입력한 주제에 대해, 참가자들이 제한 시간 안에 아이디어를 익명으로 제출한다. 제출 제한 시간은 **2분**.
2. 제출이 끝나면 작성자 정보 없이 아이디어 텍스트만 공개한다.
3. 참가자들이 원하는 후보에 투표한다.
4. 자기 자신의 의견은 투표 불가하다. 투표 제한 시간은 **1분**.
5. 모두가 투표 완료하면 투표가 종료된다.
6. 최종 후보를 결과 화면에 표시한다.

### 4.4 최종 결정 방식

- **최다 득표:** 가장 많은 표를 받은 후보를 즉시 선정한다.
- **동점자**: 최다 득표 후보가 동점이면 동점 후보만 남기고 결선 투표를 진행한다. 기존 투표는 초기화하며 후보는 다시 제출하지 않는다. 단독 최다 득표 후보가 나올 때까지 결선 투표를 반복한다.

### 4.5 판정 규칙

- 익명 모드에서는 투표 결과 API와 화면에 투표자 정보를 노출하지 않는다.
- 중복 투표 방지를 위해 서버 내부에서는 투표자를 구분한다.
- 같은 참가자가 허용된 투표 수보다 많은 표를 행사할 수 없다.

> ※ 투표는 **후보 식별자**로 접수한다. 멤버 식별자로 받으면 누가 어떤 의견을 냈는지 알아야 투표할 수 있게 되어 익명성이 무너진다. 자기 의견 투표 금지도 서버가 후보와 작성자를 대조해 판정한다([D-21](requirements.md#7-확정된-설계-결정)).

### 4.6 익명

- 투표 중에는 모두 익명.
- 투표 결과는 방장이 투표 결과 익명/실명 여부에 따라 공개.

### 4.7 결과 데이터

- 후보별 득표 순위
- 후보별 득표수
- 최종 선정 후보 와 아이디어 제시자
- 동점 여부와 동점 처리 결과

## 5. Game 4. 시간초 잡기

### 5.1 게임 목적

방장이 정한 목표 시간에 가장 가깝거나 가장 멀게 타이머를 정지시킨 참가자를 선정한다.

### 5.2 방장 설정

| 설정 | 설명 |
| --- | --- |
| 무엇을 정할까 | 예: 팀장, 주제 발표, 직접 입력 |
| 타이머 (목표 시간) | 5초, 7초, 10초 |
| 선정 기준 | 목표 시간과 오차가 적은 사람 / 오차가 큰 사람 |

### 5.3 진행 순서

1. 모든 참가자 화면에 게임 가이드 팝업을 표시한다.
2. 게임 가이드 팝업이 끝나면, 참가자가 START 버튼을 누르고, 로컬 요청 기준으로 타이머를 시작한다. (참가자 별로 모두 별도의 타이머가 존재)
3. 참가자에게 타이머의 시간이 2초까지만 보이고 그 후는 시간을 숨긴다.
4. 참가자는 원하는 순간에 `STOP` 버튼을 한 번 누른다.
5. 서버가 각 참가자의 경과 시간을 요청 시간 기준으로, 밀리초 단위로 기록한다.
6. 모든 참가자가 입력을 완료하거나 제한 시간이 되면 입력을 마감하고 라운드를 종료한다.
7. 서버가 각 참가자의 목표 시간 오차를 계산한다.
8. 방장이 선택한 기준에 따라 참가자의 순위를 정한다.
9. 결과 화면에 정지 시간, 오차, 순위, 사전에 방장이 정한 기준의 승리자를 표시.

> ※ 다른 참가자에게는 **START 여부만** 보이고 경과 시간은 공개되지 않는다. 시간이 가려지는 순간 타임라인의 참가자 마커도 함께 사라진다.

### 5.4 오차 계산

```
절대 오차 = |참가자의 정지 시간 - 목표 시간|
시간 차이 = 참가자의 정지 시간 - 목표 시간
```

예를 들어 목표 시간이 5.00초일 때:

| 참가자 | 정지 시간 | 판정용 절대 오차 | 화면 표시 |
| --- | --- | --- | --- |
| A | 4.91초 | 0.09초 | -0.09초 |
| B | 5.03초 | 0.03초 | +0.03초 |
| C | 5.42초 | 0.42초 | +0.42초 |

- 가장 가까운 사람을 뽑으면 B가 선정된다.
- 가장 먼 사람을 뽑으면 C가 선정된다.

### 5.5 판정 규칙

- 화면에 표시된 애니메이션 시간이 아니라 서버 기준 경과 시간으로 판정한다.
- 시간 값은 부동소수점이 아닌 정수 밀리초 단위로 기록한다.
- 참가자는 `STOP` 버튼을 한 번만 누를 수 있다.
- 동일한 정지 요청이 재전송되어도 최초 입력만 인정한다.
- 타이머 시작후, 제한 시간은 [목표 시간 + 3초] 이다.
- 제한 시간까지 버튼을 누르지 않은 참가자는 자동으로 최하위 처리한다.
- 제한 시간이 지난 뒤 서버에 도착한 `STOP` 요청은 인정하지 않는다.

> ※ `START` 자체를 누르지 않은 참가자는 **회차 제한 시간이 마감될 때** 최하위로 처리한다. 회차 제한 시간의 값은 미확정([Q-17](requirements.md#8-미확정-항목--팀-확정-필요)).

### 5.6 동점 처리

밀리초 단위 오차까지 같으면 다음을 사용한다.

1. 동점자끼리 시간초 잡기를 한 번 더 진행한다.

### 5.7 결과 데이터

- 목표 시간
- 참가자별 정지 시간
- 참가자별 시간 차이 - 화면 표시용, 부호 포함
- 참가자별 절대 오차 - 판정용
- 1위 오차
- 순위
- 최종 선정자 또는 탈락자

## 6. Game 5. 익명 저격

### 6.1 게임 목적

특정 질문에 가장 어울리는 참가자를 익명 지목 방식으로 선정한다.

### 6.2 질문 예시

- 숨겨진 PPT 장인 관상은?
- 발표를 가장 잘할 것 같은 사람은?
- 가장 먼저 지각할 것 같은 사람은?
- 팀장을 맡기면 가장 든든할 것 같은 사람은?

### 6.3 방장 설정

| 설정 | 설명 |
| --- | --- |
| 질문 | 프리셋 선택 또는 직접 입력 |
| 투표 시간 | 기본 10초 또는 직접 입력 |
| 중복 투표 여부 | 중복 투표 불가 / 가능 |

### 6.4 게임 진행

1. 질문과 투표 시간이 공개된다.
2. 참가자는 제한 시간 안에 자신을 제외한 참가자를 타겟을 지목한다.
3. 투표 마감 후 참가자 별 피격 수를 집계한다.
4. 최다 득표자가 당첨자가 된다.
5. 최다 득표자가 여러 명일 경우, 동점자를 후보로 유지하고, 다시 시작할지, 아니면 대기방으로 돌아갈지 선택 가능한 팝업이 뜬다.
6. 모두가 투표하지않아서 동점자가 나오면 똑같이 대기방, 다시시작 선택 팝업이 뜬다.
7. 결과 화면에 질문, 득표 수, 최종 당첨자를 표시한다.

> ※ 본인 카드는 후보 그리드에서 **아예 제외**한다. 지목 내역은 서버에만 보관하고 클라이언트로 내려보내지 않는다([NFR-06](requirements.md#nfr-06--익명성)).

### 6.5 판정 규칙

- 타겟을 선택하지 않을 경우 미투표로 처리한다.
- 참가자는 자기 자신을 타겟으로 선택할 수 없다.

### 6.6 동점 처리

- 동점자만 후보로 유지하고 모든 참가자 전원이 재투표한다. 방장이 재투표 또는 대기방 복귀를 선택한다.

### 6.7 결과 데이터

- 질문
- 참가자별 피격 수
- 최종 선정자

## 7. Game 6. 눈치게임

### 7.1 게임 목적

참가자들이 서로의 타이밍을 피해서 `UP` 버튼을 눌러야 하는 심리전 게임이다.

### 7.2 방장 설정

| 설정 | 설명 |
| --- | --- |
| 동시 입력 판정 시간 | 기본 0.3초 / 하드 모드 0.5초 |

### 7.3 진행 순서

1. 모든 참가자 화면에 `UP` 버튼을 표시한다.
2. 게임이 시작되면 참가자들은 서로 눈치를 보며 제한 시간 15초 내에 버튼을 한 번 누른다.
3. 서버가 각 참가자의 클릭 시각과 클릭 순서를 기록한다.
4. 모든 참가자가 동시 입력으로 / 15초 이내에 아무도 입력을 안해서 탈락하면 방장이, 대기방으로 돌아간다 / 처음부터 다시 시작 중 선택한다.
5. 탈락자 발생 시, 탈락자를 제외하고 다음 라운드를 시작한다.
6. 게임이 길어질수록 배경 점멸과 텍스트 흔들림 효과로 압박감을 높인다.
7. 게임 종료 후 클릭 순서, 탈락자, 최종 생존자 또는 최종 결과를 공개한다.

### 7.4 동시 입력 판정 예시

판정 시간이 0.3초일 때:

| 참가자 | 클릭 시각 | 판정 |
| --- | --- | --- |
| A | 2.00초 | B와 동시 입력 |
| B | 2.12초 | A와 동시 입력 |
| C | 2.62초 | 정상 입력 |

A와 B의 클릭 간격은 0.12초이므로 두 사람 모두 탈락한다. C는 A·B와 0.3초 이상 차이가 나므로 정상 입력으로 인정한다.

### 7.5 종료 방식

#### 첫 탈락 발생 시 라운드 종료

- 최초로 동시 입력이 발생하면 해당 참가자를 탈락자로 정하고 게임을 종료한다.
- 동시 입력 없이 모두 순서대로 눌렀다면 마지막까지 남은 참가자 1명이 탈락한다.

#### 1명이 남을때까지 반복

- 각 라운드의 탈락자를 제거하고 다음 라운드를 진행한다.
- 서버는 라운드마다 클릭 여부와 순서를 초기화한다.
- 모두 통과하거나, 탈락하여 1명이 남을때까지 라운드를 반복한다.

#### 최종 종료 조건

- 라운드 종료이후 1명이 남으면 그 한 명은 탈락 처리하여 결과 화면 도출.

#### 전원 탈락 시

- 대기방으로 돌아간다 / 처음부터 다시 중 방장이 선택한다.

> ※ **끝까지 남아 탈락한 그 한 명이 이 게임이 뽑으려던 대상**이다(팀장·벌칙 등). 결과 화면에서는 최종 선정자로 표시하고, 나머지는 통과로 보여 준다([D-23](requirements.md#7-확정된-설계-결정)).

### 7.6 판정 규칙

- 각 참가자는 라운드마다 한 번만 버튼을 누를 수 있다.
- 동시 입력없이 혼자서 입력했으면, 통과.
- 동시 입력한 참가자는 전원 탈락한다.
- 동시 입력 그룹의 최초 클릭 시각을 기준으로 판정 시간 이내에 들어온 입력을 같은 그룹으로 처리한다.
- 두 명 이상이 설정된 판정 시간 안에 버튼을 누르면 해당 참가자들을 동시 입력으로 판정한다.
- 판정 시간 안에 입력한 참가자는 순서와 관계없이 모두 동시 입력으로 처리한다.
- 동일한 클릭 요청이 재전송되어도 한 번만 인정한다.
- 탈락한 참가자의 추가 입력은 무시한다.
- 게임 도중에 연결이 끊긴 인원은 바로 탈락 처리된다.
- 서버가 수신하고 보정한 입력 시각을 최종 판정 기준으로 사용한다.
- 동시 입력이 발생하지 않고, 모두 통과후, 끝까지 남은 마지막 참가자가 탈락한다.
- 제한 시간까지 버튼을 안 누른 남아있는 참가자 모두 탈락처리.

### 7.7 결과 데이터

- 전체 클릭 순서
- 참가자별 클릭 시각
- 동시 입력 그룹
- 라운드별 탈락자
